# Identity 密钥维护目标设计

状态：目标设计，尚未实施。本文规定 Identity 密钥材料与数据库元数据的换钥、技术重新加密、提交未知核对及旧键退役。材料装载和指纹见[密钥材料](../keys.md)，数据库身份与结构交付见[数据库](../database.md)。号码查找编码由[号码查找摘要](../identity/lookup.md)拥有，原请求与微信 code 摘要由[原输入证明](../identity/proofs.md)拥有。其他能力的材料由其所有者另定维护范围。

## 停写与提交

维护前准备并验证同时含有必需旧键和新键的候选材料。部署调用方停止新业务接纳，等待全部相关执行结束，并证明旧应用进程不能再提交。维护者以既有部署身份连接，不增加登录身份，也不使用应用进程内的准入队列。

维护事务取得与在线运行共享屏障对应的事务级独占锁，然后核对数据库当前密钥元数据。号码查找值按[现行编码](../identity/lookup.md)重算全部保留记录和当前身份证号占用；受保护字段按各所有者的信封与 AAD 规则技术重新加密。一个事务完成所需重算、唯一性检查、引用核验和活动键元数据切换，不提交部分转换。技术转换保持业务明文、归属、原办理、计数与时点，不创建实名新版本，也不重置会话或注册证明。

维护事务的初始预算为 300 秒，不放宽在线业务的数据库预算。超时或连接断开不能证明回滚。先停止发送新命令并结束原数据库驱动；驱动结束不单独证明后端已结束。新连接取得同一独占锁后，用新的 `READ COMMITTED` 语句读取密钥元数据及相关数据，核对原事务结局。首次初始化的已交付边界见[部署工具](../engineering/deployment.md#密钥初始化与核验)。结局未能证明前，保持停写并报告故障。

确认数据库提交后，才切换服务使用的材料并按[单进程启动与就绪](../architecture.md#启动后台与停止)完成启动核验。材料切换须保留可恢复的先前状态。数据库仍为旧元数据时使用匹配的旧材料；数据库已切为新元数据时使用包含相应新键及仍需旧键的材料。材料与元数据不匹配时拒绝就绪，不能尝试猜测哪组密钥可解密。部署调用方分别核对数据库提交和材料切换的结果。

## 保留与退役

C1 token 摘要采用独立 `challenge` 用途，其编码与版本核对见[原 token 证明](../identity/proofs.md#c1-原-token-证明)。原 token 不持久保存，换钥保留旧摘要及其材料，直至 Challenge 的占用和原结果证明依赖结束。新占用仍检查全部保留版本。当前已交付材料装载、证明计算和初始元数据；数据库换钥及退役核验尚未实施。

技术重新加密只改变相应密文，保持其他证明和查找摘要；注册 token 的原 SHA-256 证明不因重新封装而改变。输入、验证码和微信 code 的旧 HMAC 密钥在仍有原记录需要比较时保留。微信 code 不保存明文，不能通过换钥全量重算旧占用；新占用按所有保留版本查询，同一 code 不得再次交换。密钥元数据不按短期请求的期限清理；保留 key ID 也不意味着秘密材料永远保留。

AEAD 旧键须等所有仍需解密的引用已转换才可退役。输入和验证码 HMAC 旧键须等比较依赖结束。微信 code HMAC 旧键须等对应协议的占用与比较依赖结束。头像签名旧键停止签发后，至少保留到最后可能签发时点加允许的最长 24 小时；可信时间达到 `retire_after` 才能退役。各用途的实际引用和期限由其所有者证明，不能仅按材料年龄删除。

普通重启不统一作废会话、注册证明或次数。已有秘密按原截止释放，窗口内的控制记录继续参与判断。首次初始化入口见[部署工具](../engineering/deployment.md)，不承担轮换或退役。本文只处理正常事务与配置维护中断；运行预算和全量核验耗时仍须实测。

## 验收

用真实数据库事务验证停止接纳、旧进程退出证明、独占锁、全量转换及唯一性检查。覆盖事务回滚、提交回包丢失、材料切换中断、旧材料启动、新材料启动和元数据不匹配。核验原会话、证明期限、请求身份、计数及业务历史均未因维护改变。分别证明每个用途的退役条件；用不同版本的微信 code 占用验证不会重复外呼。记录实测耗时与预算余量。
