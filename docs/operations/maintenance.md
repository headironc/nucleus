# Access 与 Center 停机运维协议

本文拥有实例互斥、共同屏障、输入、恢复及输出边界；各动作拥有写入内容与原结果。初始化、指派、系统管理员实名更正及政治面貌停机更正均使用 `admin`。[密钥维护](keys.md)另有转换与退役步骤。

## 目标命令与互斥

命令为 `deployment admin <initialize|appoint|correct|correct-affiliation> --input FILE --operation UUID [--dry-run]`。密钥登记使用 `deployment keys init`。

每个数据库命令先取得[实例锁](../architecture.md#实例锁)：持锁期间应用不能启动，应用运行期间工具拒绝执行。取得实例锁后，命令在独占屏障内推进代次，等待旧事务结束。旧进程随后不能再开启事务，部署变更不会与旧工作重叠。工具崩溃后，应用启动屏障等待遗留事务结束。协议不依赖 systemd cgroup 停机证明、本机锁文件或 pending 标记。

`admin` 使用运行数据库身份，配置及凭据来源见[管理命令设置](../settings.md#管理命令)。入口要求真实的网站 AppId，执行与在线相同的全量启动核验并建立锚定。它不构造 HTTP 服务或供应商客户端。初始化以引导主体办理，指派、实名更正与政治面貌更正以系统主体办理。各动作复用共同执行器，先按原操作读取完成记录。同一输入返回原结果，异输入返回 `request_mismatch`；未命中才核对操作者、目标与动作前提。

`--input` 和 `--operation` 必填。新办理使用新的 UUID，重试与核对结局沿用原 UUID 与原输入。`--dry-run` 先核对原完成；命中相同输入时报告 `completed`。新办理执行相同的锁定、资格检查及判断，在写入业务事实前回滚并报告 `dry_run`。实例代次与可信时间仍按正常协议维护。命令行只传 UUID 与文件路径，不放入手机号、身份证号、资料值或摘要。

初始化输入为 JSON 对象，字段固定为 `mobile`、`name`、`idNumber`。指派输入包含 `operator: { "mobile": "…" }`、`accountId`、`revisionId` 和 `selection`。授予使用 `selection: { "action": "grant" }`；换下使用 `selection: { "action": "revoke", "roleId": "…" }`。实名更正输入包含 `operator: { "mobile": "…" }`、`target: { "personId": "…", "revisionId": "…" }`、`name` 和 `idNumber`。政治面貌更正输入包含 `operator: { "mobile": "…", "accountId": "…", "revisionId": "…" }`、`target: { "accountId": "…", "personId": "…", "revisionId": "…", "affiliationId": "…" }` 和 `affiliation`；政治面貌更正还要求 `affiliationId` 与当前取值一致。各输入均拒绝未知字段。目标账户、实名版本与政治面貌取值使用真实标识，不在命令行传资料内容。

输入文件必须由当前有效 UID 持有、模式恰为 0600，且为单链接常规文件。读取拒绝符号链接，FIFO 不等待写端。文件保留至结局查明；结果未知时，用原 UUID 和原输入重新执行同一命令。管理入口不生成计划或确认码。

管理命令的永久完成与业务事实固定真实办理人。stdout 摘要包含 `action`、脱敏 `subject`、`operation` 和 `result`；结果为 `completed`、`dry_run`、`failed` 或 `outcome_unknown`。摘要不含原手机号、身份证号、姓名或输入材料。入口关闭接纳并排空工作后输出、刷新 stdout，最后结束运行上下文并释放实例锁。输出或收尾失败使命令失败退出，已知业务结论仍保留。这个顺序不表示 stdout 提供持久审计保证。

## 执行边界

管理命令使用运行身份，不增加数据库角色或 HTTP 运维入口。操作者手机号只用于固定办理归属，不是独立认证凭据。执行权限仍由受控的停机运维环境及凭据访问承担。装载设置、凭据与密钥后，命令在专用连接上取得实例锁。取锁后推进代次并等待旧事务结束。业务写事务在共同屏障内核对本命令的代次；实例会话丢失且后来的进程已启动时，事务回滚并失败。实例会话使用独立连接，保留到最终 stdout 输出结束。工具不检查 systemd 或 cgroup，也不生成计划、确认码或 journal。

## 共同屏障与未知提交

管理命令的业务事务使用 `READ COMMITTED`，先取得 `(1314210636, 1)` 共享事务屏障，再由执行器取得原操作锁。事务屏障与[密钥维护](keys.md)使用同一键；实例锁保留至命令结束。执行器先按原 Operation-Id 读取完成记录，命中相同输入时报告原完成且不重复写；未命中才重查操作者、目标、动作前提并决定新写入。不得把原事实查询移到锁外：若上一执行仍在途，锁外查询会产生假阴性。

提交结局不明时保留原输入，用同一 Operation-Id 和同一 JSON 重新执行以核对原结果。工具退出或崩溃后不留下阻止应用启动的标记：应用可以启动，其启动独占屏障等待原事务结束；运维者此后停止应用，再用原输入重跑即可得知原结局。确认未提交时，本次尝试保留依赖失败；仍未知时报告 `outcome_unknown`。输入文件在结局查明前保留，此后按敏感文件处置。

## 验收

输入文件测试覆盖常规文件、有效 UID、0600、单链接，以及符号链接、硬链接和有界拒绝无写端 FIFO。实例互斥测试验证应用持锁时部署命令不执行任何变更、命令持锁时应用不能取锁，以及每个命令推进代次；应用实例会话被结束后，部署命令取得锁并推进代次，旧应用再开启事务即被拒绝。

管理入口验收核对全量启动核验、dry-run 零业务写入、原输入重放、实例锁、脱敏输出及输出收尾。故障验收还核对未知结局、同 UUID 的晚到完成、确认回滚和失败后锁释放；输出失败保留已知业务结论。验收使用虚构材料和隔离数据库；真实安装及日志持久性仍待部署演练。
