# Access 与 Center 停机运维协议

状态：目标设计，尚未实施。本文拥有 `operate-access` 与 `operate-center` 的停机证明、共同事务屏障、`inspect/apply` 计划、原结果恢复及输出边界。各动作拥有自己的资格、写入内容与原结果事实；[密钥维护](keys.md)拥有自己的转换与退役步骤。

## 执行边界

两种工具以既有迁移身份连接数据库，不增加第三个数据库角色，也没有 HTTP 运维入口。执行前必须证明应用固定 systemd unit 的 `ActiveState=inactive`，且所属 cgroup 不存在或其中无存活进程。cgroup 不存在是正常停止状态；`ActiveState=failed`、无法读取 unit 状态、仅发出停止信号或仅等待排空超时均不构成停止证明。工具不得在应用 unit 的 cgroup 内执行。部署须防止停止检查后至工具事务结束前应用重启；数据库锁不代替这一进程证明。

`apply` 写入前核对装载材料与[各用途密钥元数据](../keys.md#持久元数据)。指纹、用途或活动版本不一致时拒绝执行。任一前提失败时不写业务表。操作者身份由仅运维操作系统用户可读的 `--operator-file` JSON 文件提供，文件用于记录真实办理人，不作为独立防冒充凭据；执行者本就处于迁移凭据的信任边界。命令参数只传标识与文件路径，不放入手机号、身份证号、资料值、摘要或确认码。

## 共同屏障与未知提交

`apply` 使用 `READ COMMITTED` 事务，在其中取得 `(1314210636, 1)` 独占事务级锁，锁随事务结束释放，维护停机状态保留至结局已知。它与[密钥维护](keys.md)使用同一键，且排斥应用业务事务的共享屏障。锁被授予才证明前一个工具事务结束；`REPEATABLE READ` 可能在等待锁前固定旧快照，不符合原结果核对要求。

顺序固定为 `BEGIN → 事务锁 → 按计划 Operation-Id 查原事实 → 其余决定性读取 → 必要写入 → COMMIT`。原事实读取是取锁后的第一条决定性读取；命中且与计划相符时报告原完成，不重复写。未命中才在锁内重查操作者、目标、密钥、材料摘要和动作前提。不得把原事实查询移到锁外：若上一执行仍在途，锁外查询会产生假阴性。

提交结局不明时保留原计划，待原执行结束后用同一份计划重新 `apply`。不能重新 `inspect` 生成新 Operation-Id 再推断原事务失败。运维者通过同计划重试核对原结果；未收尾的维护阻止受影响能力启动。计划在结局查明前保留，此后按敏感文件处置。

## 两阶段计划

`inspect` 只读并检查动作前提，生成本次 UUID Operation-Id，使用 `--plan-out` 以 `0600` 创建 JSON 计划。前提失败时只报告原因，不产生计划。计划固定动作、脱敏操作者和目标、真实操作者绑定、写入材料规范内容的 SHA-256、目标当前状态的定位值、预分配的必要标识、Operation-Id 及规范计划的 SHA-256 确认码。各动作按其业务事实定义具体绑定：初始化没有旧账户，以操作者材料摘要绑定将建立的身份；现有账户动作绑定操作者账户及实名版本；更正还绑定目标的当前版本或最晚事实。

计划文件与材料文件同等敏感。短代码和身份证号等低熵输入的普通摘要可被持有计划者枚举；保密依赖文件权限和传输通道，不依赖摘要不可逆。摘要、确认码和预分配标识仅在计划内，不能进入 stdout、journal 或命令行。stdout 只显示脱敏操作者、目标、动作、规模及 Operation-Id。

`apply --plan` 读取原计划并要求其余参数与 inspect 一致，重新计算材料摘要与确认码。材料或参数改变导致绑定不符时拒绝，须重新 inspect。计划已固定 inspect 时的目标定位值；apply 时的新数据库状态不作为确认码重算输入，而由锁内重查与具体动作的冲突判断比较，不能误报确认码损坏。若原事实已提交，先按原标识完成原结果核对，不能把新状态误判为冲突。

每次 `apply` 的结果写入 systemd journal，包含有效 UID、主机、动作、脱敏操作者和目标、Operation-Id 与结果，不含材料、摘要或确认码。`inspect` 不写审计。工具必须验证对非目标业务表零写入。

## 验收

验证 unit inactive 且 cgroup 不存在或为空的正常路径，以及 failed、读状态失败、仍有进程、材料与活动密钥元数据不符时拒绝。验证计划 0600、操作者及材料改变、计划内容篡改、参数不一致、锁内当前状态改变、同计划原完成重放、提交未知和非目标表零写入。并发负例须让第一次 `apply` 持锁未提交，第二次开始后再提交第一次；锁外查询或先取得 `REPEATABLE READ` 快照的实现应暴露假阴性。时序使用显式同步，不以固定休眠代替。当前没有这些运行验证结果。
