# 密钥引用与退役范围目标设计

状态：已交付能力在启动时核对自身引用；跨能力停机换钥和退役工具尚未实施。本文列出根版本退役前必须核对的持久引用，引用按派生用途列出；每个字段的编码、权限和实际换钥事务仍由其所有者负责。根材料与派生用途见[密钥材料](../keys.md)，停写维护见[密钥维护](keys.md)，新工牌不增加逐文件密码封装或签名链接，见[本地文件](../storage/files.md#workforce-封装与换钥)。备份恢复材料保留其快照仍依赖的历史解密密钥，不能只按在线库当前引用删除备份密钥。不能仅按密钥创建时间或记录当前是否可见决定退役。

## 引用清单

| 范围                      | 保留及核对条件                                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity 当前值与短期证明 | 当前手机号、当前身份证号、待注册、挑战、注册受理、换号证明和会话按各自期限与当前归属核对；注销事实及实名历史按原身份保留，不把已注销者的当前查找摘要永久保存                                          |
| Identity 历史密文         | 实名版本及所有仍被引用的人名、手机号封装在原记录上换钥；原输入、次数和业务时点不变                                                                                                                    |
| Identity 实名版本封印     | 每份永久版本的明文封印保留原键引用；独立字段信封换钥不结束封印引用，见[人员与实名版本](../identity/person.md#封装与读取)                                                                              |
| 其余输入证明              | 各所有者扫描自己的原请求及永久接受证明；不能重算的原 HMAC 证明继续依赖旧根，直至其比较义务结束                                                                                                        |
| 小程序手机号占用          | Exchange 的原输入证明与 code 查找摘要分别保留 `proof` 和 `lookup` 根版本；全部保留版本参与新占用查找，原执行、恢复与父引用结束后再退役。原 code 不落库，不能重算旧摘要。                              |
| Center 人员档案           | 历次取值的信封永久保留；不保存状态封印或完成绑定。归[人员政治面貌](../center/affiliation.md#存储密码与维护)，注销不删原历史                                                                           |
| Access 角色与机构 Holder  | State（含角色删除及 Holder 注销墓碑）、永久角色变更、机构指派与注销投影的封印保留原键引用；沿[共同事实封印](../architecture.md#事实封印)核验，删除或注销不结束引用                                    |
| Workforce 工号            | 当前及撤销状态、四类记录与不可变版本的封印；分配、更正、恢复的永久完成保留规范输入信封及明文封印                                                                                                      |
| 共同完成                  | 角色、机构指派及初始化的永久完成，与 Workforce 配置完成的规范输入信封、明文封印；按[完成记录](../architecture.md#完成记录)保留，配置完成到期但尚未清理时仍须保留原键                                  |
| Workforce 邀请码          | 状态、创建、调整、作废与接纳的封印永久保留；原码信封、按版本保存的查找摘要，以及完整输入信封和明文封印保留原键引用。到期、作废或创建者结束不结束引用，见[邀请码](../access/invitations.md#秘密与保存) |
| 图片链接签名              | 现有头像链接使用 `link` 用途，从最后可能签发时刻起保留最大链接期限；数据密钥按实际密文引用退役，不借用签名期限                                                                                        |

## 启动与交付

实名版本的 `seal` 引用永久保留，并由版本所有者在启动时逐份核验。只重新加密姓名与身份证号，不改变版本封印，也不结束其旧键引用。后续停机重新封印必须保留版本 ID、人员归属和规范实名值，见[人员与实名版本](../identity/person.md#封装与读取)。注销或后续更正均不结束这项义务。

Center 启动扫描全部保留取值，鉴别信封、代码、时间与原办理人实名版本，不扫描已退出的状态或完成封印。角色与机构 Holder 的全部状态和永久记录继续核验封印，包含删除及注销墓碑。角色、机构指派、初始化和 Workforce 配置完成也参加封印核验。`institution_role`、`workforce_role`、`institution_appointment` 与 `initialization` 完成永久保留。完成输入按原信封 key ID 解封后核验明文封印。未来换钥保留各能力的事实及绑定；角色与 Holder 另保留对象身份、前驱、序号、版本及终态。Center 注销不结束取值解密引用，角色删除与 Holder 注销不结束封印引用。Workforce 配置仅在原完成被可靠清理后结束引用。完整换钥工具仍未交付。

[Workforce 准入、暂停恢复与管理结束](../access/grants.md#原结果)分别在 `access.grants`、`access.suspensions`、`access.resumptions`、`access.terminations` 保存完整原输入 HMAC 及 `proof` 用途的 key ID。自行退出没有该引用。启动核对旧材料，重放按原键比较；注销后永久事实仍保留，不能用新键重算旧摘要。完整维护工具必须纳入四种永久引用。

工号三类分配、更正与恢复使用永久共同完成，保留规范输入信封及覆盖明文的封印。状态、记录与不可变版本另保留各自封印。原输入比较不再依赖独立 `proof` HMAC。注销、撤销或后续更正均不结束上述密钥引用；换钥必须保留人员、原操作、记录顺序、状态版本及固定恢复集合。业务绑定见[工号](../workforce/numbers.md#存储与原结果)。

原号及新号验证码的 `identity.confirmations` 与 `identity.transfers`、`identity.rejections`、`identity.replacements` 都引用 `proof` 用途的根版本。启动扫描包含已过期但仍保留的事实，重放按原版本核对证明。会话失效或申请到期不结束密钥义务。Transfer 和 Rejection 沿[换号清理](../identity/mobile.md#事实与约束)释放引用。Completion 随账户保留，注销时释放引用。完整停机退役工具尚未交付。

账户注销在 `identity.cancellations.mobile` 保留独立 `encryption` 信封，身份及字段编码归[注销事实](../identity/cancellation.md#永久事实与数据库约束)。账户删除、同号码重新注册和会话清理均不结束该永久引用。内部恢复及启动完整扫描都鉴别原密文；缺少旧键或字段绑定不符时不能交付原成功或开放服务。后续停机换钥须原地转换，保持手机号、Cancellation ID、原操作和生效时刻。

账户暂停与恢复分别在 `identity.suspensions.mobile`、`identity.resumptions.mobile` 保存 `encryption` 用途的原手机号信封。两份密文永久保留；虽然行 ID 相同，AAD 字段不同，必须分别鉴别。编码归[暂停恢复事实](../identity/suspension.md#事实约束与权限)。原结果比较与启动扫描均读取各自旧键；恢复、再次暂停、会话清理及账户资料变化都不结束这一义务。停机换钥工具接入时必须分别在原行转换信封，保持明文、原标识、时点及个人顺序。这些原输入已有永久字段，不另加 `proof` HMAC 引用。

机构在线与停机指派使用永久共同完成记录，保存规范输入信封及覆盖明文的封印。初始化保存自身完成，R2 首条指派由注册完成关系确认，不另存机构指派 `proof` HMAC。机构 Holder、永久指派及注销投影保留各自的封印引用。原结果规则归[角色与指派](../access/roles.md#原请求与读取)。

领域在线更换仍在 `access.assignments` 保存 `proof` 用途的原输入 HMAC 及 key ID。首条由 Grant 保存准入证明。领域更换的原输入不另存明文或密文，因此不能用新键重算旧 HMAC。只要原比较义务存在，对应旧根必须保留。角色删除、目标再次更换、领域退出、注销或短期认证清理都不结束义务。

启动检查领域指派 HMAC 所引用的 key ID 元数据和装载材料，缺失则不开放服务。这项检查不持有原请求，也不证明 HMAC 与原输入匹配；实际重放才核验完整绑定。机构指派的完成输入则在启动时解封并核验明文封印，重放时另比较规范输入。材料集合仍受既有格式上限约束，永久引用不能通过删除旧材料腾出名额。换钥工具交付时必须纳入这些实际消费者。

启动核对唯一的根文件、固定结构版本、根指纹与仍被引用的旧根；缺少根文件或版本时不读取其他文件补足。已承诺能力不能因迁移缺失而静默消失。未迁移消费者的原操作按需核对；新工牌不增加 active Render、发布意图、删除状态或自动恢复扫描。未收尾的停写换钥维护及已发现的可信关系矛盾阻止依赖能力就绪。供应商局部故障仍按[单进程启动与就绪](../architecture.md#启动后台与停止)处理。

既有消费者迁移时核对全部真实密钥引用；只在最后引用退出后移除对应扫描。验证须故意留下一份每类旧根引用，证明过早退役被拒；确认全部可转换引用已转、所有未结工作已查明后，旧秘密才可退役。仍使用签名的消费者验证最后签发边界，既有历史验证注销后的密钥引用，维护操作按其实际提交合同验证。当前没有完整跨能力维护的执行结果。
