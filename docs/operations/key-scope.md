# 密钥引用与退役范围目标设计

状态：目标设计，尚未实施。本文列出跨能力密钥维护必须核对的持久引用；每个字段的编码、权限和实际换钥事务仍由其所有者负责。材料格式与用途见[密钥材料](../keys.md)，Identity 停写维护见[密钥维护](keys.md)，Workforce 文件换钥见[本地文件](../storage/files.md#workforce-封装与换钥)。不能仅按密钥创建时间或记录当前是否可见决定退役。

## 引用清单

| 范围                         | 保留及核对条件                                                                                                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity 当前值与短期证明    | 当前手机号、当前身份证号、待注册、挑战、注册受理、换号证明和会话按各自期限与当前归属核对；注销事实及实名历史按原身份保留，不把已注销者的当前查找摘要永久保存                                                           |
| Identity 历史密文            | 实名版本及所有仍被引用的人名、手机号封装在原记录上换钥；原输入、次数和业务时点不变                                                                                                                                     |
| Access 与 Workforce 输入证明 | 各所有者扫描自己的原请求及永久接受证明；不能重算的原 HMAC 证明继续依赖旧键，直至其比较义务结束                                                                                                                         |
| Center 人员档案              | 政治面貌历次取值与封装由[人员政治面貌](../center/affiliation.md#存储密码与维护)维护；注销不删原历史                                                                                                                    |
| Workforce 文件与固定输入     | 模板背景、字体、照片、成品、Badge Layout、Review、Render、Delivery Confirmation 及所属发布意图都参加扫描；`deleting` 和未知结局先核对原工作；已确认 `deleted` 且无工作依赖的资源只需旧键元数据，不需不存在字节的旧秘密 |
| 图片链接签名                 | `avatar_signature` 和 `workforce_link` 分别从最后可能签发时刻起保留各自最大链接期限；数据密钥按实际密文引用退役，不借用签名期限                                                                                        |

## 启动与交付

启动按实际交付能力核对各用途的必需文件、固定结构版本、材料指纹与仍被引用的旧键。密钥文件按用途独立装载，不能用其他用途的文件补足缺失材料。已承诺能力不能因迁移缺失而静默消失。原操作结局按需核对；后台分批发现 active Render、发布意图与删除状态，不依赖客户端再次访问。未收尾的停写换钥维护及已发现的可信关系矛盾阻止依赖能力就绪。供应商局部故障仍按[单进程启动与就绪](../architecture.md#启动后台与停止)处理。

后续迁移每引入一个所有者，就同时将其历史、原请求、清理和维护引用纳入全量扫描。验证须故意留下一份每类旧键引用，证明过早退役被拒；确认全部可转换引用已转、所有未结工作已查明后，旧秘密才可退役。还须验证已确认 `deleted` 文件的例外、签名最后签发边界、注销后历史引用与维护提交未知的恢复。当前没有这些执行结果。
