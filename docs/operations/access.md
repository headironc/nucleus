# Access 系统初始化与管理员指派

状态：目标设计，尚未实施。本文拥有 `operate-access initialize` 与 `operate-access appoint` 的动作资格、输入、写入结果和原事实。两种动作遵守[停机运维协议](maintenance.md)；工具的 `correct` 动作由[实名更正](../identity/correction.md#系统管理员的运维更正)拥有。

## 运维身份与命令

独立命令 `deployment operate-access` 使用既有迁移身份，不开放 HTTP 入口。操作者文件由 `--operator-file` 指定，只有运维操作系统用户可读。initialize 的文件包含操作者本人的手机号、完整姓名和身份证号，按注册规则校验后创建本人账户，首个实名版本成为本次全部事实的办理人。appoint 的文件只含操作者手机号，须精确定位当前正常账户并取其当前实名版本；找不到、已暂停或已注销均拒绝。

操作者文件用于归属和追责，不是独立的防冒充凭据。`inspect` 只读、`apply --plan` 依据原计划执行；停机证明、密钥元数据核对、计划权限、摘要绑定、事务锁后首读、未知提交及 journal 输出统一按[共同协议](maintenance.md)办理。`SyslogIdentifier` 为 `operate-access`。

## 初始化

initialize 只在数据库没有任何账户和角色时办理。inspect 核对操作者输入、默认头像素材、密钥元数据和空库前提，计划绑定操作者文件的规范内容摘要、将建立的身份及四个系统角色、预分配标识、Operation-Id 和“当前没有账户与角色”定位前提。材料在 inspect 后变化时 apply 拒绝；库内出现账户或角色时由锁内重查拒绝。

成功在同一维护事务中建立 Person、首个实名 Revision、Account、默认头像、机构“普通账户”与“系统管理员”、Workforce“普通成员”与“管理员”，以及四个角色的创建变更和必要权限历史。操作者本人机构当前角色为“系统管理员”，写入首条指派；全部办理人版本是本次首个实名版本，首条顺序为 1，操作标识取原计划。不能分步提交后留下无当前机构角色的账户。初始化成功后，操作者按普通短信认证登录，工具不签发会话。

系统角色的等级、权限全集、活定义和当前指派关系见[角色与指派](../access/roles.md)。数据库实际执行身份保护系统角色和“系统管理员”指派；不使用自报来源或可设置绕过标志。重复 initialize 的原计划先按原标识读回完成；新计划在已有账户或角色时拒绝，不能借初始化复用旧人员或覆盖旧事实。

## 指派与换下

appoint 的 inspect 以操作者手机号定位当前正常账户，并绑定其账户 ID 与实名版本。目标必须是已有正式账户且当前实名版本与 `--revision` 相同；命令以目标账户 ID 和实名版本固定目标，不接受纯手机号作为最终对象，不为不存在的账户预授权。计划固定原角色和当前指派定位，防止 inspect 后目标角色被别人换走又换回而静默办理。

| 形式                                                       | 结果                                                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| `--account <id> --revision <id> --grant`                   | 为目标写入一条“系统管理员”指派并更新其机构当前角色                         |
| `--account <id> --revision <id> --revoke --role <role_id>` | 将目标从“系统管理员”换为明确指定的现存机构角色；所选角色不能是“系统管理员” |

接替、增加和撤换由同一 appoint 动作办理。目标已是“系统管理员”却 grant，或目标已不是该角色却 revoke，均返回 `409 state_conflict`，不写空指派。目标账户、实名版本、原指派或所选角色发生变化时，apply 锁内拒绝旧计划。成功在同一事务追加永久指派、更新当前关系，不改角色定义，也不追溯修改旧指派。目标可以就是本次操作者；运维工具不将普通业务入口的自我管理限制误用到系统管理员维护。

每次计划持唯一 Operation-Id，原成功以指派事实识别；同计划重放返回原结果，不追加第二条。不同材料、目标或动作使用原标识返回 `409 request_mismatch`。提交结局不明时先沿[共同协议](maintenance.md#共同屏障与未知提交)核对原事实，不重新 inspect。运维日志只保留脱敏身份、动作、操作标识及结果。

## 验收

验证空库初始化的 Person、实名版本、账户、默认头像、四个系统角色、完整权限历史和首条指派共同提交；再次初始化、部分已有账户或角色、素材缺失和材料改变时无写入。验证 appoint 的 grant、revoke、接替、自我办理、目标暂停或注销、实名版本变化、角色指派变化及所选角色失效。用运行身份尝试伪造系统角色修改或“系统管理员”指派必须失败；用迁移身份验证对非目标表零写入。验证原计划重放、同键异输入、未知提交、计划文件与日志脱敏，并执行[共同协议验收](maintenance.md#验收)。当前没有这些运行或数据库验证结果。
