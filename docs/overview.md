## 项目术语

项目命名在代码、HTTP、存储和自有 SDK 封装中保持一致。供应商官方 wire 字段与协议名称保留原写法。

| 概念         | 项目用名    |
| ------------ | ----------- |
| 认证消息     | `message`   |
| 人机校验     | `challenge` |
| 手机号       | `mobile`    |
| 居民身份证号 | `id_number` |

认证事实及引用见[短信认证](identity/authentication.md#消息与校验事实)，身份证号的值与投影见[人员与实名版本](identity/person.md#构造与关系)。

## 业务路径

1. 停机初始化在空业务库建立系统角色和首个机构管理员。管理员通过正常认证登录，随后开放本人注册。
2. 机构管理者按当前权限与等级维护角色、指派管理职责。本人注册建立账户，不自动获得 Workforce 参与资格。
3. 准入管理者直接接纳，或本人使用有效邀请码，形成唯一未结束 Workforce 授权。
4. 本人按当前资格取得编号。目录和模板提供当前可选内容，本人确认实际科室、完整牌面、照片及领取地点。
5. 系统保存固定 Submission，批准与首个 Render 共同提交。后台形成并接纳永久 Badge。
6. 制作人员处理实体卡，有权发放者在系统可用时明确提交。只有 Delivery 保存成功才构成发放。
7. 实名更正、账户状态、角色变化、授权结束、编号撤销和注销分别由所有者办理。后续动作立即使用已提交事实，不等待后台改写历史。
8. 当前有权者读取永久历史。注销释放登录占用，保留原人员和必要历史；同号重新注册不继承旧资格。

政治面貌由 Center 独立办理，不作为 Workforce 准入或工牌申请条件。账户、授权和编号的变化不代替管理者审批，也不静默修改已经确认的打印内容。

网站和小程序共享服务端事实与资格，传递方式不改变权限。Schedule 不在当前设计和交付范围。后续接入遵守 [Schedule 的权威阅读路径](engineering/capacity.md#schedule-接入依据)，不得自行补定 Rota 业务规则。
