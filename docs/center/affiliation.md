# 人员政治面貌目标设计

状态：目标设计，尚未实施。本文拥有政治面貌的办理、授权、历史、HTTP 和持久事实。固定代码由[政治面貌固定值](values.md)拥有。Identity 提供人员锚点、当前账户和实名版本；Access 提供当前机构角色、权限和等级。

## 业务边界

政治面貌是 Center 维护的可选人员资料，归固定人员，不随登录账户分裂。未填写不影响注册、Workforce 准入、编号或工牌。导入不建立政治面貌；填写或更正也不改变上述业务资格、实名、账户头像和已保存的工牌事实。此能力不扩展为完整人事档案、任职或岗位历史。

本人凭当前合法代表该人员的账户，可首次填写并查看当前值和历次取值。本人只可填写一次，不可自行更正、撤回或清空。已有任一取值时，本人新写入返回 `409 state_conflict`。本人首次填写不要求机构档案权限。

机构权限 `institution.affiliations.read` 允许查看他人的当前值及历次取值，不比较机构等级。`institution.affiliations.correct` 允许为他人追加更正，也允许填写首个值；目标仍有账户时，办理人当前机构等级须严格高于目标，目标不得是本人。目标已无账户时不比较目标等级，仍须有当前更正权限。两项权限互不推定，不由账户管理、实名更正或 Workforce 权限推出，也不按岗位或具体用途增加条件。仅有更正权者的定位、写入结果和错误都不透露取值或是否已填写。角色定义与指派历史归 Access，不能保存资料值。

“系统管理员”没有等级更高的业务管理者。其资料填错时，由停机的 `operate-center correct` 追加一行；实际运维操作者可以就是目标本人。该工具不是普通人的备用更正入口，不赋予 HTTP 权限。运维更正与在线更正保留相同历史形状。

## 目标确认与读取

管理者按手机号精确取得有当前账户的候选，或按人员 ID 取得候选以办理已注销人员。候选只含脱敏身份及目标确认，不含取值、是否填写或历史。账户级目标固定账户、人员及实名版本；按手机号取得时还固定所用号码。人员级目标只用于无当前账户者，固定人员及其当前实名版本。写入时重查人员、目标形式、版本和适用号码；目标失效返回 `409 target_changed`。按人员 ID 的路径人员须与目标人员一致。新注册的同号账户属于新人员，不继承旧资料。

查看与资料读取在同一数据库快照内完成当前会话、账户、机构角色及权限复查。仅有更正权时，候选按可更正范围过滤：本人、同级或更高等级目标如同不存在，返回 `404 target_unavailable`；有查看权时，候选不比较等级。依赖失败不得变成空候选。目标账户暂停不阻止有权管理者读取或更正；办理人暂停、注销或失权后不得继续办理。已注销目标的历史仍归原人员，只有当前有权者能读取。

本人历史只返回取值和生效时间，不返回办理人身份。管理历史返回取值、生效时间及办理人的脱敏当时身份。办理人版本仍永久保存在事实中，用于有权审计；本人投影不因此多给办理人。当前值取同一人员最新一行；从无取值时返回 `404 affiliation_unset`，不返回 `null` 或“群众”。历史按时间倒序分页，`count` 是该人员全部取值行数。

## 写入与原结果

每次填写或更正均追加一行，不覆盖旧行；同值更正也追加。只持更正权的人不能通过“同值无变化”响应探测原值。办理人当前账户、权限、目标关系及机构等级在共同写入事务内重查，并对目标人员协调并发写入。本人首次填写在该协调内检查仍无任何行；两个本人并发写入最多一个成立。管理更正按提交顺序保留全部行，后提交的值成为当前值。

新行固定人员、[封闭代码](values.md)、办理人当时的实名版本、本次事务时间及 Operation-Id。时间必须严格晚于该人员已有最新取值；相等或时钟回退均回滚为 `503 dependency_unavailable`，不能提交一条成为“过去”的新更正。每人同一时间的唯一约束拦相等值，应用仍须拦更早时间。不分配通用永久 FactSequence。

Operation-Id 在取值行中唯一，行本身是永久完成事实。原请求重放先在有权办理的范围内核对原行办理人所属人员；不同人立即返回 `409 request_mismatch`，不能以提交 13 种代码探测原值。同一办理人再核对目标人员和代码，相同则交付原完成，不同则拒绝。不以当前值或最新实名版本替换原行。新办理按当前资格和业务条件判断。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对原事实。

## HTTP 契约

全部入口要求当前会话和 Operation-Id。JSON 使用标准 `code` 封套并禁止缓存。写入成功为 `200`，仅返回 `{ "code": "ok" }`，不回显取值、行 ID、请求标识或是否改变。写入正文的 `affiliation` 必须是[固定代码](values.md)；缺失、`null`、多选、自由文本及未知字段按[共同 JSON 协议](../http/api.md#json-结果与应用码)返回 `422 invalid_input`。

| 路由                                       | 权限与结果                                             |
| ------------------------------------------ | ------------------------------------------------------ |
| `GET /accounts/current/affiliation`        | 本人当前值；无值为 `404 affiliation_unset`             |
| `GET /accounts/current/affiliations`       | 本人历史，按时间倒序；不含办理人                       |
| `PUT /accounts/current/affiliation`        | 本人首次填写；已有值为 `409 state_conflict`            |
| `POST /affiliations/candidates`            | 查看或更正权，正文为必填手机号；返回账户级脱敏候选     |
| `GET /affiliations/candidates/{person_id}` | 查看或更正权；返回账户级或人员级脱敏候选               |
| `GET /persons/{id}/affiliation`            | 查看权，读取他人当前值                                 |
| `GET /persons/{id}/affiliations`           | 查看权，读取他人历史及办理人脱敏身份                   |
| `PUT /persons/{id}/affiliation`            | 更正权，正文含目标确认及取值；目标有账户时比较机构等级 |

所有错误不回显资料值。无权为 `403 permission_denied`，目标不存在或不可读为 `404 target_unavailable`，目标确认变化为 `409 target_changed`，同键异输入为 `409 request_mismatch`。仅本人入口可产生“已有值”拒绝；更正入口不因已有值或同值返回该错误。候选读取成功时返回对象，依赖故障为 `503`，不返回 `null`。本人和管理历史复用读取事实，但分别构造响应，避免本人误得办理人字段。

## 客户端呈现

本人页面允许自愿首次填写和读取历史；未填写时不预选代码，已有值时不提供再次填写。管理页面只在当前职责内定位并确认目标。只有更正权、没有查看权时，页面展示空白更正表单，不请求、缓存或推断当前值、历史及是否填写；成功只显示办理完成。页面完成、离页、失权或切换账户时移除内存中的取值和历史列表，不保存草稿历史、输入摘要或完成值副本。

## 存储、密码与维护

目标结构为 `center.affiliations`。每行有非空 UUID `id`、永久 `person_id`、密封的 `value`、永久 `operator_id`、`created_at` 和唯一 `operation_id`。人员引用 `identity.persons`；办理人引用 `identity.revisions`。`(person_id, created_at)` 唯一，按这组键倒序读取当前值和历史。运行身份只可读取及插入，不可更新或删除；注销核心不删除取值，也不调用 Center。操作者注销后，旧实名版本仍解释原办理。

政治面貌能力增加 `center_data` 密钥用途。两位代码使用[信封](../keys.md#52-信封)封装。AAD 的域固定为 `nucleus/center-affiliation/v1`，字段用途固定为 `affiliation.value`。业务身份是人员 ID 的 16 字节，紧接取值行 ID 的 16 字节；整体作为[单个 AAD 字段](../keys.md#54-封装边界目标设计)编码。读取和技术重加密均按此顺序从所属行重建身份，防止跨人或跨行替换。解密、密钥缺失或值域异常是依赖与完整性故障，不能解释成未填写。密钥维护扫描全部历史行，技术重加密只替换封装和密钥版本，保持明文、办理人、时间和顺序。旧键只有在全部仍需解密的行完成转换后才能退役。政治面貌值及其摘要不进入普通日志、访问记录、角色历史或通用 registry。

`operate-center correct` 遵守[停机运维协议](../operations/maintenance.md)。操作者受保护文件中的手机号须对应当前正常账户。`inspect` 核对目标仍是“系统管理员”、代码合法且与当前值不同；其计划固定新行 ID、Operation-Id、操作者账户和实名版本、值文件规范摘要及当前最晚行 ID。

`apply --plan` 按共同协议锁后先查原 Operation-Id。未命中才重查目标、操作者及当前最晚行，确认仍与计划一致后追加新行。迁移身份有结构权，验收须验证非目标表零写入。

## 验收

覆盖本人首次填写、并发双写、管理同值追加、权限读写分离、等级边界、失权、目标暂停与注销、两种目标确认、同号新人员、历史分页与本人投影。重放先核对办理人，再比较人员和代码；持更正权但无查看权者用他人的 Operation-Id 轮试全部代码不得取得原值。验证同一人员时间相等和更早两种回退均整笔失败，后续更正仍为当前值。

用真实运行身份验证六列、外键、唯一性、运行写权及禁止更新删除；验证封装跨人与跨行替换、密钥缺失、全量换钥及注销后的保留。运维验收覆盖停机证明、计划权限和材料绑定、锁后原行首读、同计划恢复、当前最晚行变化、日志脱敏及非目标表零写入。事务交错使用显式同步，不依赖固定休眠。当前没有政治面貌能力的运行或数据库验证结果。
