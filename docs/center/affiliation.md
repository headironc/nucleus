# 人员政治面貌

政治面貌以永久加密取值保存。当前值来自最新记录；读写使用当前资格与普通事务，不登记原操作或保存完成绑定。历史不因简化而删除，也不作为工牌前置条件。

本文拥有政治面貌的办理、授权、历史、HTTP 和持久事实。固定代码由[政治面貌固定值](values.md)拥有。Identity 提供人员锚点、当前账户和实名版本。Access 提供当前机构角色、权限和等级。

## 业务边界

政治面貌是 Center 维护的可选人员资料，归固定人员，不随登录账户分裂。未填写不影响注册、Workforce 准入、工号或工牌。导入不建立政治面貌；填写或更正也不改变上述业务资格、实名、账户头像和已保存的工牌事实。此能力不扩展为完整人事档案、任职或岗位历史。

本人凭当前合法代表该人员的账户，可首次填写并查看当前值和历次取值。本人只可填写一次，不可自行更正、撤回或清空。已有任一取值时，本人新写入返回 `409 state_conflict`。本人首次填写不要求机构档案权限。

机构权限 `institution.affiliations.read` 允许查看他人的当前值及历次取值，不比较机构等级。`institution.affiliations.correct` 允许为他人追加更正，也允许填写首个值；目标仍有账户时，办理人当前机构等级须严格高于目标，目标不得是本人。目标已无账户时不比较目标等级，仍须有当前更正权限。两项权限互不推定，不由账户管理、实名更正或 Workforce 权限推出，也不按岗位或具体用途增加条件。仅有更正权者的定位、写入结果和错误都不透露取值或是否已填写。角色定义与指派历史归 Access，不能保存资料值。

“系统管理员”没有等级更高的业务管理者。其资料填错时，由停机的 `deployment admin correct-affiliation` 追加一行；实际运维操作者可以就是目标本人，不要求具备管理员角色或 `institution.affiliations.correct` 权限。该工具不是普通人的备用更正入口，不赋予 HTTP 权限。运维更正与在线更正保留相同历史形状。

## 目标确认与读取

管理者按手机号精确取得有当前账户的候选，或按人员 ID 取得候选以办理已注销人员。候选只含脱敏身份及目标确认，不含取值、是否填写或历史。账户级目标固定账户、人员及实名版本；按手机号取得时还固定所用号码。人员级目标只用于无当前账户者，固定人员及其当前实名版本。写入时重查人员、目标形式、版本和适用号码；目标失效返回 `409 target_changed`。按人员 ID 的路径人员须与目标人员一致。新注册的同号账户属于新人员，不继承旧资料。

查看与资料读取在同一数据库快照内完成当前会话、账户、机构角色及权限复查。仅有更正权时，候选按可更正范围过滤：本人、同级或更高等级目标如同不存在，返回 `404 target_unavailable`；有查看权时，候选不比较等级。依赖失败不得变成空候选。目标账户暂停不阻止有权管理者读取或更正；办理人暂停、注销或失权后不得继续办理。已注销目标的历史仍归原人员，只有当前有权者能读取。

本人历史只返回取值和生效时间，不返回办理人身份。管理历史返回取值、生效时间及办理人的脱敏当时身份。办理人版本仍永久保存在事实中，用于有权审计；本人投影不因此多给办理人。当前值是同一人员最新一次取值；从无取值时返回 `404 affiliation_unset`，不返回 `null` 或“群众”。历史按时间倒序分页，`count` 是该人员全部取值行数。

## 写入与结果

每次填写或更正均追加一行，不覆盖旧行；同值更正也追加。只持更正权的人不能通过“同值无变化”响应探测原值。办理人当前账户、权限、目标关系及机构等级在共同写入事务内重查，并对目标人员协调并发写入。本人首次填写在该协调内确认仍未填写；两个本人并发写入最多一个成立。管理更正按提交顺序保留全部行，后提交的值成为当前值。

新行固定人员、[封闭代码](values.md)、办理人当时的实名版本及本次事务时间。时间必须严格晚于该人员已有最新取值；相等或时钟回退均回滚为 `503 dependency_unavailable`。

每次成功办理与[共同审计](../architecture.md#审计)同事务提交。动作区分 `fill`、`correct` 与 `system_correct`。审计固定办理人的稳定 Person ID，并以取值行 ID 定位目标。审计不保存政治面貌、姓名、手机号、证件、凭据、完整请求或资料摘要。事务失败不留下成功审计。

每次写入都按当前资格和业务条件判断。Operation-Id 仅用于共同诊断，不提供持久去重或原结果重放。提交未确认时返回 `503 outcome_unknown`，不宣称确定失败，不独立恢复或自动再次写入。用户通过当前有权读取刷新业务状态；刷新不证明某次请求的精确结局。本人刷新为 `404 affiliation_unset` 时，可重新选择、确认并发起一次新填写。仅有更正权者仍不能读取取值或是否填写。已知 `200 ok` 不因后续刷新失败改成未知。

## HTTP 契约

全部入口要求当前会话和 Operation-Id。JSON 使用标准 `code` 封套并禁止缓存。写入成功为 `200`，仅返回 `{ "code": "ok" }`，不回显取值、行 ID、请求标识或是否改变。写入正文的 `affiliation` 必须是[固定代码](values.md)；缺失、`null`、多选、自由文本及未知字段按[共同 JSON 协议](../http/api.md#json-结果与应用码)返回 `422 invalid_input`。

首次填写的选项和已有值的显示名称由[固定名称读取](values.md#固定名称读取)提供。该入口只返回封闭字典，不承担本人或管理资料读取。

本人当前值读取成功为 `200`，返回 `code: "ok"` 和 `affiliation: { value, createdAt }`。`value` 为两位固定代码；`createdAt` 为最新取值的原生效时间，使用标准日期时间字符串。没有查询参数或请求正文。额外查询或非空正文为 `400 invalid_input`，正文超过 8 KiB 为 `413 invalid_input`。HEAD 按相同资格及状态处理，不返回正文。GET/HEAD 沿[当前身份的同源条件](../identity/current.md#凭据选择与来源)。OpenAPI 描述这些条件，不另列 Origin 参数。

本人历史复用[共同分页](../http/lists.md)，成功返回 `code: "ok"`、`count` 和 `affiliations`。每项仅有 `value`、`createdAt`，按生效时间倒序。未填写时为 `200`、`count: 0` 和空数组；越界页保留实际总数。分页参数以外的查询或非空正文返回 `400 invalid_input`。正文超过 8 KiB 返回 `413 invalid_input`。HEAD、同源、缓存及 Cookie 行为与本人当前值相同。

管理候选成功返回 `code: "ok"` 和 `candidate: { target, name }`。`name` 使用固定脱敏规则。`target.type` 为 `account` 时含 `accountId`、`personId`、`revisionId`；为 `person` 时只含 `personId`、`revisionId`。手机号 POST 正文只接受必填的强类型 `mobile`，要求准确 Origin。客户端保留本次完整查询号码，更正时按[目标确认](#目标确认与读取)绑定该号码。候选响应不回显号码。

管理更正正文为 `{ target, affiliation }`，要求准确 Origin。`target` 沿候选的两种确认形状。手机号定位的账户确认另带 `mobile`；人员 ID 定位的账户确认省略该字段。显式 `null` 或非法手机号均为 `422 invalid_input`，人员确认不接受手机号。标识直接反序列化为所属类型。路径人员与确认不一致，或当前确认失效，返回 `409 target_changed`。

管理当前值与本人当前值使用相同的最小响应。不存在及本人目标为 `404 target_unavailable`，存在但未填为 `404 affiliation_unset`。管理候选和当前值的 GET/HEAD 不接受查询参数或正文。同源、空输入和大小限制沿本人当前读取协议。仅有更正权者读取取值始终为 `403 permission_denied`。

管理历史沿本人历史的分页、输入、同源及缓存协议，返回 `code`、`count` 和 `affiliations`。每项为 `{ value, createdAt, operator }`；`operator` 使用[固定脱敏身份](../identity/person.md)的 `{ personId, revisionId, name }`。不存在及本人目标为 `404 target_unavailable`；存在但未填时返回成功空集，越界页保留实际总数。仅有更正权不能读取管理历史，也不能获得是否已填写的信息。

| 路由                                                   | 权限与结果                                             |
| ------------------------------------------------------ | ------------------------------------------------------ |
| `GET/HEAD /api/v1/accounts/current/affiliation`        | 本人当前值；无值为 `404 affiliation_unset`             |
| `GET/HEAD /api/v1/accounts/current/affiliations`       | 本人历史，按时间倒序；不含办理人                       |
| `PUT /api/v1/accounts/current/affiliation`             | 本人首次填写；已有值为 `409 state_conflict`            |
| `POST /api/v1/affiliations/candidates`                 | 查看或更正权，正文为必填手机号；返回账户级脱敏候选     |
| `GET/HEAD /api/v1/affiliations/candidates/{person_id}` | 查看或更正权；返回账户级或人员级脱敏候选               |
| `GET/HEAD /api/v1/persons/{id}/affiliation`            | 查看权，读取他人当前值                                 |
| `GET/HEAD /api/v1/persons/{id}/affiliations`           | 查看权，读取他人历史及办理人脱敏身份                   |
| `PUT /api/v1/persons/{id}/affiliation`                 | 更正权，正文含目标确认及取值；目标有账户时比较机构等级 |

管理读取的原身份、当前机构权限、适用等级及返回事实在同一[只读快照](../http/lists.md)内确认；本人当前值与身份、本人历史的身份、总数和本页同样如此。旧身份或权限锚与读取快照错位时，在新快照重试一次，并重新核对全部资格。Center 取值不使用状态锚、序号或版本。必要人员、办理人、时间或保护材料损坏是技术失败并关闭接纳；普通查询失败返回安全的 `503` 并保持接纳。读取不登记操作，也不改变 Cookie 或会话期限。管理历史的办理人按原取值固定的实名版本鉴别后脱敏，后续实名更正或账户注销不替换原版本。

所有错误不回显资料值。无权为 `403 permission_denied`，目标不存在或不可读为 `404 target_unavailable`，目标确认变化为 `409 target_changed`。共同 HTTP 限流保留 `429 rate_limited` 和 `Retry-After`；连接池耗尽或数据库超时按实际依赖故障返回 `503 dependency_unavailable`。Center 不再占用原操作工作槽。仅本人入口可产生“已有值”拒绝；更正入口不因已有值或同值返回该错误。候选读取成功时返回对象，依赖故障为 `503`，不返回 `null`。本人和管理历史分别构造响应，避免本人误得办理人字段。

## 客户端呈现

本人页面允许自愿首次填写和读取历史；未填写时不预选代码，已有值时不提供再次填写。管理页面只在当前职责内定位并确认目标。只有更正权、没有查看权时，页面展示空白更正表单，不请求、缓存或推断当前值、历史及是否填写；成功只显示办理完成。页面完成、离页、失权或切换账户时移除内存中的取值和历史列表，不保存草稿历史、输入摘要或完成值副本。

## 存储、密码与维护

`center.affiliations` 是唯一取值事实，保存行 ID、人员 ID、加密代码、办理人当时的实名版本与生效时间。同一人员的取值时间唯一且严格递增。当前值是生效时间最新的一行；历史按时间倒序读取，总数来自该人的全部行。运行身份只可查询和追加，不可修改、删除或截断取值。注销不删除取值，也不调用 Center。操作者注销后，旧实名版本仍解释原办理。启动分批鉴别保留取值的信封、封闭代码、时间和原办理人实名版本；运行中读取也鉴别实际使用的事实。保护材料损坏时关闭接纳。特权者将有效事实改成另一合法事实的检测不属于本能力承诺，见[威胁模型](../architecture.md#威胁模型)。

政治面貌能力使用 `encryption` 派生用途，按[信封](../keys.md#52-信封)以政治面貌专属的域保护两位代码，并绑定所属人员与取值行，防止跨人或跨行替换。解密、密钥缺失或值域异常是依赖与完整性故障，不能解释成未填写。密钥维护扫描全部历史取值，技术重加密只替换保护材料和密钥版本，保持明文、办理人、时间和顺序。旧根只有在全部仍需解密的取值完成转换后，才可能满足退役条件。政治面貌值及其摘要不进入普通日志、访问记录、角色历史或通用 registry。

`deployment admin correct-affiliation --input FILE --operation UUID [--dry-run]` 遵守[停机运维协议](../operations/maintenance.md)。输入 JSON 固定为 `operator: { mobile, accountId, revisionId }`、`target: { accountId, personId, revisionId, affiliationId }` 和 `affiliation`，各层拒绝未知字段。操作者手机号定位当前正常账户。账户和实名版本必须与输入一致；暂停、注销或手机号变化时拒绝新办理。操作者不需要管理员角色。

目标必须保有当前账户和“系统管理员”角色。目标账户、人员与实名版本必须等于输入确认。目标暂停本身不取消角色资格。目标必须已有取值，且给定 `affiliationId` 等于当前取值。本次 `affiliation` 必须与当前代码不同；无值和同值均拒绝。

每次命令都核对当前操作者、目标、角色与预期取值，再追加更正。`--operation` 仅保留为输出诊断标识，不传入业务去重，也不恢复原结果。成功后原 `affiliationId` 已失效；相同输入再次执行返回 `target_changed`。新取值保留原办理人版本，生效时间严格晚于最新取值；相等或回退均回滚。成功更正与 `system_correct` 审计共同提交。

命令不生成计划、确认码或 journal。dry-run 对当前资格执行相同检查，在写入前结束并报告 `dry_run`，不写业务事实或审计。提交未知时报告 `outcome_unknown`；运维者先在受控停机环境核准确目标，再用现有运行身份只读查询最新记录的 `id` 与 `created_at`，不输出代码或密文。该查询只确认当前状态，不证明原操作结局。继续办理前重新人工确认目标、最新 `affiliationId` 和新值，不直接重跑旧输入。输出失败保留已知业务结论，见[停机运维协议](../operations/maintenance.md)。

## 验收

覆盖本人首次填写、并发双写最多一笔、管理同值追加、权限读写分离、等级边界、失权、目标暂停与注销、两种目标确认、同号新人员、历史分页与本人投影。持更正权但无查看权者不得通过候选、取值读取、成功或错误轮探资料。验证时间相等和回退均整笔失败，历史与审计同步回滚。

验证独立信封向量、跨人与跨行替换、标签损坏、缺键、保留旧键及注销后的历史；运行身份不能修改或删除取值。停机更正覆盖本人或另一正常非管理员操作者、非管理员目标、无值、同值、操作者暂停/注销/绑定变化、目标暂停、目标账户/实名/最新取值变化、dry-run 零业务和审计写入及脱敏输出。输出失败后旧确认不能再次追加。非目标业务事实保持不变。事务交错使用显式同步。

管理验收覆盖首值、同值追加、过期确认拒绝、准确权限、严格等级、双权限及并发更正顺序。候选在未填、已填、取值损坏或取值查询被拒时保持相同披露；仅更正权始终不能读取取值。审计失败使业务事实回滚。提交回包丢失返回未知，应用不独立恢复、不再次写入；后续只按当前资格查状态。调用取消和超时不让状态未知的连接回池。

读取验收覆盖本人读取、实名更正、注销及同号新人员、按生效时间而非 UUID 选当前值、分页上限与越界总数。每页保持同一快照；旧身份或权限锚重试时，全部资格都重新判断。身份失效先于敏感解密；等待连接后重查会话到期。缺键、坏标签、未来时间或原办理人损坏使读取失败并关闭接纳；普通查询拒绝保持接纳。查询取消、超时和只读 COMMIT 未确认均不交付结果。HTTP 核对 GET/HEAD、目标形状、强类型手机号、最小投影、Origin、输入拒绝、限流、安全错误、会话期限及 OpenAPI；日志不含资料、凭据或 SQL 原文。
