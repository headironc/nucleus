# 网站与小程序页面

网站提供匿名介绍、本人服务和管理服务；小程序提供匿名介绍与本人服务，网站先交付。具体交付范围见[能力状态](../README.md#能力状态)。两端消费相同的服务端事实与权限，不各建一套人员、授权或工牌业务状态。网站按[独立托管边界](../http/site.md#托管与路由归属)构建和发布，技术栈见[网站工程](website.md)；小程序使用原生页面。传输与响应见[客户端协议](protocol.md)，会话与原操作见[小程序会话](session.md)、[网站持久会话](../identity/website.md)和[客户端原操作恢复](recovery.md)。

## 页面范围

首版包含内部网站工牌流程，以及网站管理与发布内容、网站和小程序共用已发布内容展示；工牌优先交付。公开读取不扩大小程序认证、微信扩展或工牌办理的范围，具体状态见[能力状态](../README.md#能力状态)。小程序本片限于主动手机号验证、正式注册、本人账户与两种退出入口，不增加头像更换、微信身份绑定、政治面貌、员工服务、工号或工牌入口。下文旧设计稿只保留作为可视材料，不证明符合简化后的业务规则。既有短信与登录的安全、存储及恢复合同继续有效。

| 页面组         | 网站                                                                                                           | 小程序                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 介绍与进入     | 公开简介、登录与注册入口                                                                                       | 公开简介、本人登录入口                                                       |
| 公开内容       | 首页、栏目页与文章页，匿名浏览、服务端渲染；管理者的栏目、文章、首页编排及图片编辑页                           | 匿名读取同一套已发布内容并展示，不提供管理与发布入口                         |
| 账户与认证     | 短信及网站微信登录、正式注册、本人账户、头像、登录方式、退出、换号、注销及更正历史                             | 小程序手机号和微信身份、正式注册、本人账户、头像、登录方式及退出；不提供换号 |
| 人员档案       | 本人政治面貌及有权管理者的独立档案页面                                                                         | 本人政治面貌页面                                                             |
| 员工服务与工号 | 本人员工服务状态、结束员工服务、首次申请工号和通过邀请码加入；管理者的角色、加入办理、服务资格管理、工号及邀请 | 本人员工服务状态、结束员工服务、申请工号和通过邀请码加入                     |
| 工牌           | 本人提交快照、查看、取消及新申请；管理审批、生成或重试、成品下载与发放                                         | 暂缓                                                                         |

介绍页只展示公开内容：[网站公开内容](../content/publication.md)交付前随网站发布固定，之后按[渲染与网站服务](../http/site.md#渲染与网站服务)由服务端读取；不请求人员、授权或工牌列表。管理页使用所属能力的精确候选和分页入口，不增设无权人员搜索或在客户端拉全库筛选。只装配已交付的能力入口；页面缺失不能被解释为已有授权，菜单显示也不能替代服务端当前权限检查。登录后分别读取当前账户、机构角色、Workforce 授权及领域角色；普通注册不自动显示为已经加入 Workforce。账户暂停停止本人服务；仅领域暂停仍保留合法的本人退出和取消未发放申请入口。

网站工牌链使用真实注册、有效参与资格及工号，提供照片和固定牌面预览、领取地点、申请、审批、生成 PDF、下载及发放。三种类型只作为选择字段。普通工牌响应丢失后刷新列表或详情，不保存原请求重放材料，不自动批准、生成或发放。短信和未迁移接口仍按所属原操作合同处理。实体打印与登记发放分别呈现，恢复备份后的补记由维护者按[恢复规则](../operations/backup.md#恢复与限制)办理。

网站发码页面按 [Turnstile 生命周期](../platform/turnstile.md#网站-widget-与-token-生命周期)管理组件和候选证明，按 [C1 证明恢复](recovery.md#c1-证明与-widget-恢复)保留已提交操作。前端显示挑战成功不代表已取得短信发送许可。

C1 独立页面为 `/authentication/codes`，验证码填写与登录恢复使用 `/authentication/login`。发码结果允许继续验证时，页面提供验证码输入入口；登录取得会话后进入 `/account` 独立检查当前本人。供应商受理显示“短信已提交发送”，并说明受理不代表送达。恢复材料缺失、过期或原证明无效时，页面说明发送情况尚不能确认，不默认附上重新发码动作。

## 页面名称与状态

页面、表单及工牌统一使用“工号”。本人动作称“申请工号”，管理动作称“分配工号”“补录工号”“更正工号”及“恢复工号”。本人选择人员类别并明确确认后自动分配，不新增审批环节。工号的规则由 [Workforce](../workforce/numbers.md) 拥有，不把人员 ID、实名版本 ID 或业务顺序号显示成工号。

Workforce Grant 的用户提示围绕“员工服务”表达，不显示内部的领域或授权类型名。按[授权生命周期](../access/grants.md)已确认的 active 开放员工服务入口；suspended 显示“员工服务已暂停”，terminated 显示“员工服务已结束”。可信的 `grant_absent` 引导使用邀请码加入；已结束者可重新加入；新工牌按当前资格与申请状态办理，终态不重开，不追溯增办来源。本人动作称“使用邀请码”“结束员工服务”；管理动作称“暂停员工服务”“恢复员工服务”“结束员工服务”。账户状态、管理权限和微信绑定分别展示；服务可用也不代表每项业务的前提均已满足。

申请类型为“新办”“增办”“换证”，由本人选择。submitted 显示“待审核”，rejected 显示“审核未通过”及理由，可新建申请；approved 显示“审核通过”，没有成品时提供有权管理者的生成或重试动作；ready 显示“工牌已生成”；issued 显示“已发放”和固定领取地点，不称“已领取”；cancelled 显示“已取消”。原快照不编辑，更改内容新建申请。同人同类型允许同时多份申请。

公开内容与受限办理区分开展示：受限办理区在用户界面称“员工服务”，公开首页可匿名浏览，进入员工服务才要求登录。使用邀请码只表示加入员工服务，不称员工身份认证，也不表示人事入职或完整人事关系。

正常账户的“我的”入口独立于员工服务资格。服务暂停、结束或尚未加入时，仍可管理本人账户、头像、登录方式、政治面貌及退出登录。结束员工服务在正常或暂停的服务页办理；结束态与邀请码页保留账户入口，返回办理页仍按当前可信状态分流。已有工号页只展示当前读取提供的内容，不显示未提供的办理日期。

## 用户可见文案

本节规定设计稿和正式客户端的用户文案。以普通、非程序员用户能否理解为准。围绕用户要完成的事情表达，让用户知道发生了什么、现在能做什么。不要把内部处理过程翻译成用户任务。

标题直接说明相关事项，如登录、注册或更换头像。正文只保留已知事实、必要后果和下一步。省去不影响用户决定的技术原因。不要用更长的机制解释弥补难懂的提示。“查询所需信息暂不可用”“核对未获接纳”“恢复定位”等内部表述不直接作为用户提示。

按钮写实际动作或目标页面。进入个人账户可用“打开个人账户”或“返回个人账户”。触发网站自动检查时，可用“检查登录状态”，并显示明确的结果与下一步。不只要求用户自行“查看登录状态”或“确认当前身份”。身份、权限和结果的检查由系统完成。只有确实要求用户同意或检查具体内容时，才使用“确认”，并说清楚确认对象。不要用“核实办理情况”代替具体指引。

只陈述已有依据的结果。结果未知时不写成功或失败，不引导重复提交。取得确定结果时，按实际情况说明完成或拒绝。有依据确认相关处理仍在进行，才显示对应的进行中提示。等待用户点击后才会执行的动作，不写成正在执行。简化文案不改变所属协议的恢复、权限和保密规则。

提示与实际能力一致。要求重试时提供可用动作；无法继续时说明限制，并给出当前可用的去向。用户在手机查看短信等页面外动作也写明具体对象。不要假设原标签页仍在、编造故障原因或承诺尚未提供的查询能力。

用语简短、自然、克制。确需指代本次操作时使用“本次”，不使用“这次”或“此次”。能直接说出事项时，省去多余指代。区分“本次修改”“当前账户”和“此前操作”，不机械替换。

| 实际情形               | 用户可见表达                                     | 使用条件                                           |
| ---------------------- | ------------------------------------------------ | -------------------------------------------------- |
| 前往个人账户           | 打开个人账户                                     | 系统随后检查能否进入，分别处理未登录和资料读取失败 |
| 网站检查当前登录       | 检查登录状态                                     | 点击后自动检查；当前账户不证明此前登录或注册完成   |
| 账户已创建             | 账户已创建                                       | 已取得可信的创建成功结果；仅收到请求不适用         |
| 本次修改已完成         | 本次修改已完成                                   | 已确认这一次修改完成；结果未知不适用               |
| 无法确定短信是否已发送 | 暂时无法确认验证码是否已发送。请先查看手机短信。 | 不推断短信未发送，不自动再次发送                   |

结合页面和触发情形审查文案。读完后，应能用日常语言说出发生了什么，以及每个动作会做什么。仍要解释“这个状态是什么意思”“在哪里核实”或“怎样确认”时，继续修改文字和对应指引。开发者能读懂、句子更短或词语替换完成，都不能代替这项判断。

## 路由命名

网站与小程序页面路径按资源和用例命名，与后端资源同词汇。网站使用根路径下的普通路径，例如 `/authentication/login`、`/applications/{id}`、`/submissions/preview`；小程序按原生约定把同名页面放在 `pages/` 下，例如 `pages/authentication/login`。不使用 `auth`、`badge`、`me` 这类客户端自创分组名，也不把内部 crate 名加入路径，与 [HTTP 路由与请求边界](../http/api.md#路由与请求边界)同源。页面与工具文件使用完整业务名词（`session.ts`、`recovery.ts`），不发明缩写。

## 网站 UI 设计

网站工程代号为 `halo`，见[客户端命名](../../README.md)。用户界面仍称“司籍处”。

网站已有[公开首页](../../design/halo-home.html)、[公开阅读](../../design/halo-reading.html)、[登录注册](../../design/halo-authentication.html)、[员工服务主页](../../design/halo-services.html)、[本人账户](../../design/halo-account.html)、[本人政治面貌](../../design/halo-affiliation.html)与[栏目维护](../../design/halo-columns.html)设计稿，包含桌面与窄屏布局。账户稿只覆盖本人资料与实名更正记录；其他维护流程、工号、工牌及管理内页后续逐项设计。下文的小程序稿只覆盖小程序的布局与交互。网站沿用克制的中式风格；技术栈与组件见[网站工程](website.md)。

公开首页与公开阅读的 Figma 画布保留可编辑布局、文字和组件，HTML 稿承担交互演示。Design 中的嵌套画面没有原型连线。画布将系统宋体、苹方分别映射为 Noto Serif SC、Noto Sans SC；字形度量及深色素材滤镜与 HTML 存在已知近似。

网站按三类使用场景组织页面：

| 场景     | 页面与主要任务                       | 布局重点                                       |
| -------- | ------------------------------------ | ---------------------------------------------- |
| 公开浏览 | 公开介绍、内容浏览和员工服务入口     | 内容层次、阅读宽度、公开导航与登录入口         |
| 本人办理 | 登录注册、账户、员工服务、工号与工牌 | 明确下一步、表单与预览、进度和结果；兼顾窄屏   |
| 管理办理 | 角色与人员管理、模板目录、审批和发放 | 桌面导航、查找与列表、详情和确认；控制信息密度 |

公开首页连接登录注册。首批登录与注册在可信本人读取后进入只读当前账户。完整目标稿的已有账户示例仍连接员工服务主页。后续补齐具体办理及管理页面。每个功能开始实现前，先补齐对应的页面与状态设计。各流程逐项交付，不把整站 UI 完成作为首个功能的统一前置条件。

### 网站本人固定工牌申请

本人从员工服务进入 `/workforce/applications`，查看申请列表。`/workforce/applications/new` 准备新申请，`/workforce/applications/{id}` 查看已保存详情。页面按[申请](../workforce/applications.md)读取本人投影，不以当前工号是否存在决定历史可见性。服务暂停或结束时，只显示允许读取的未发放摘要，不展示工牌内容、照片或模板资源。

新申请先核对正常账户、活跃员工服务和当前工号，再读取可选目录、固定模板与领取地点。默认科室仅供预选，本人明确确认实际科室。照片裁剪独立于账户头像；调整裁剪后重新确认。领取地点在画布之外展示。

完整预览使用服务端返回的实际文字行、固定字体和资源，按[媒体规则](../workforce/media.md)保持照片比例、透明度及居中留白。加载失败、字体不可用或文字无法完整显示时，停止确认提交。确认对话提供完整牌面、文字与领取地点；窄屏内容区独立滚动，操作按钮保持可见。

本人确认后仅提交当次快照。内容变化时撤销旧预览，提示刷新内容后重新确认。可信创建回执才显示“工牌申请已提交”；结果未知时只提供申请列表刷新入口，不自动重发，也不保存原请求重放材料。列表故障与“暂无申请”分开。页面离开、隐藏、账户切换或失权时清除受限资料及图片，隔离迟到响应。

本人列表与详情展示实际审核状态。完整详情展示服务端允许读取的审核人脱敏姓名、审核时间和完整驳回理由，保留换行，不用标识符代替姓名。牌面或照片加载失败时显示真实占位，已取得的固定资料和审核结果仍可阅读。受限读取只显示可取消申请的编号、类型、状态和提交时间，不展示审核事实、姓名或照片。

### 网站工牌审核

管理者从员工服务进入 `/workforce/reviews`，按[申请合同](../workforce/applications.md#存储与-http)检查当前审核权与全单位对象范围。默认查看待审核申请，可切换审核通过或审核未通过。筛选、总数和记录均来自同一服务端分页响应；切换筛选或刷新回到第一页。空集合、越界页、加载失败和无权访问分别呈现。

`/workforce/reviews/{id}` 并排展示提交时保存的完整资料与当前变化。当前姓名、工号或目录变化不改写原牌面，也不单独阻止批准。申请人账户或参与资格失效时禁止批准，有权管理者仍可查看固定资料并附理由驳回。完整牌面不可查看时显示占位并禁止批准，不用替图表示加载成功。

批准和驳回均须明确确认。驳回理由必填，保留完整输入并提示过长或无法使用的字符；理由对申请人可见。提交中禁止重复操作。结果未知时先清除旧申请内容，仅提供详情刷新，不自动重发；状态竞争后读取当前决定，不覆盖他人结果。失权、隐藏、离页或切换账户时遮蔽旧资料并释放图片，迟到响应不得恢复旧内容。窄屏对话的内容区独立滚动，错误提示与底部操作保持可见。

### 网站机构入口开通员工服务

网站 `/workforce/grants/new` 从个人账户中的机构管理入口进入，标题为“开通员工服务”。入口独立读取当前机构角色，仅准确的 `institution.workforce` 开放；不要求办理人先开通员工服务。实际接纳仍由服务端按[准入合同](../access/grants.md#http-入口)复核。页面固定使用机构来源，不切换为领域来源。本片不提供邀请码、工号、角色维护或工牌办理。

页面沿用网站外壳、纸色和朱砂操作色。桌面以限宽表单呈现，窄屏顺序堆叠。先输入完整手机号查找已注册同事，再确认脱敏姓名、身份证尾号、账户与员工服务状态，并选择角色。角色使用服务端分页，按总数定位末页取得 `kind: default` 并预选普通成员，不预选排序首行，不自动拉取全部角色。每次换页重新核对同一目标和总数。其他角色由人明确选择，确认弹窗醒目展示实际角色名称。页面不展示完整证件、内部标识、版本或权限代码。

| 状态           | 可见内容与动作                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| 本人与权限检查 | 加载时遮蔽资料；登录失效提供登录；无权只显示无法办理；读取失败提供重查，不显示空候选                         |
| 查找与确认     | 完整手机号查找；目标不可用说明无法为该账户办理；账户暂停或已有未结束服务只读提示，不开放提交                 |
| 角色读取       | 分页读取中隐藏旧确认；依赖失败显示重新查找；目标确认或总数漂移要求重新查找，不拼接不同快照                   |
| 开通确认       | 显示脱敏同事、角色与开通后果；取消默认聚焦，Escape 取消并回到触发按钮；当前资料变化时关闭弹窗                |
| 提交与待确认   | 提交前保存最小原操作材料；保存失败说明尚未提交；提交中关闭重复动作，离开只结束等待                           |
| 原结果查询     | 未知结果显示“检查开通结果”，只以原标识和完整原输入重放；查询失败仍待确认，不开放换键重办                     |
| 确定拒绝       | 目标或角色变化要求重新查找并确认；账户暂停、已有服务及不可管理目标分别说明，不绕过限制                       |
| 完成           | 显示本次员工服务已开通、所选角色和时间；说明同事刷新员工服务页查看当前状态，不称已取得工号；可继续办理另一人 |

原操作材料按当前办理账户隔离，只保存原操作者、操作标识和重放所需的目标及角色确认，不保存整份候选或脱敏展示资料。准入原事实永久保留，未确定的原操作不套用短信短期截止；取得确定结论后清除原输入。会话失效或失权保留待确认责任，待同一操作者恢复有权身份后明确检查。原完成只证明当次开通，不推断同事此刻仍为正常服务状态。恢复细则见[客户端恢复](recovery.md#恢复材料)。

离页、后台、账户或会话选择变化时同步遮蔽同事资料、表单与弹窗，晚到请求按原会话选择和代次丢弃。键盘、桌面与窄屏、明暗主题、脱敏和真实页面画面随实现验收。受控浏览器证明页面状态与请求行为，真实后端另验证建立资格、首条指派及同事刷新后的 active。

注册首次提交前保存失败时，保留可编辑资料并明确“本次尚未提交注册”。重新检查只回到填写，仍须本人再次明确提交。已提交而结果未知时，恢复信息暂时读取失败与更新失败分别展示。两者保留原资料、锁定与结果核对责任。更新失败时提示留在本页继续查看结果，避免重复提交或刷新页面。读取失败不称信息未保存。重新取得原材料后回到原待确认。材料确实缺失或到期时，不推断失败或重新注册。页面说明暂时无法确认结果，提供“检查登录状态”和公开首页入口。

本地已知字段错误可就近提示。服务端仅含应用码的通用输入拒绝只显示表单级提示，不同时标错姓名和身份证号。身份证号被占用时只提示核对填写内容或联系管理员，不假定占用者是本人。重新验证手机号后按页面提示继续，不预先承诺登录已有账户。首次请求拒绝与此前结果未知时的确认拒绝分别展示。确认请求的输入或权限拒绝只说明本次请求未受理。此前注册结果与原输入保持不变。来源、恢复及确定结果仍以[正式注册](../identity/registration.md)、[身份 HTTP](../http/identity.md) 和[客户端恢复](recovery.md)为准。

发码、登录和注册的受限画面区分首次请求拒绝与此前结果未定。已有待确认办理时，等待说明与按钮明确继续查询本次结果，等待后仍回原待确认，不因验证码或凭据期限到就重新认证。首次请求受限时，发码返回获取验证码、登录继续验证；注册按凭据是否仍有效返回填写或重新验证手机号。上述三类沿用既有状态，按进入上下文呈现文案，不新增场景。

非忙碌的结果未定画面明确等待用户操作。按钮分别为“查看发送结果”“查看登录结果”“查看注册结果”。主动加载或查询仍使用“正在”。登录或注册结果无法确认时，提供“检查登录状态”，点击前不假定已登录。该入口独立检查当前选择及当前本人。检查后区分可信当前账户、需手机号登录和检查未完成；成功不表明历史登录或注册完成。预览工具覆盖无登录选择、普通读取失败和登录存储不可用。当前登录失效、检查被拒绝、技术失败、受限和选择变化也有对应示例。检查未成功前隐藏旧资料。没有可信选择时提供手机号登录。普通读取失败的恢复操作仅提供重新检查；返回公开首页不受此限制。已确认登录选择存储不可用或损坏时，遮蔽资料并提供重新检查与显式手机号登录。检查被拒绝时可返回首页。发码恢复信息缺失时只提示查看手机短信，暂时不要重复获取验证码。本片 R2 页面在原证明无效或资料不一致时，保留原材料至原期限并停止提供原请求恢复入口，改为检查当前登录状态。两类拒绝不证明原注册失败，也不引导重新填写或提交。原会话无法交接的 `verification_required` 仍提供手机号重新认证，不与这两类拒绝混用。填表说明姓名与身份证号用于账户登记，员工服务另行开通。尚未提交的实名输入不会自动保存。提交后的有限恢复材料仍按恢复契约处理。

收到可信注册 Session 后，浏览器选择保存失败仍保留“账户已创建”。页面同时说明浏览器未能保留登录信息，检查浏览器后重新登录。临时验证信息清理失败也保留已创建事实。重新检查只演示本地清理，再读取当前账户，不重提注册。本人读取成功且当前选择仍匹配后，才展示姓名、证件尾四位与头像。读取失败、受限、401、403 和选择变化时隐藏旧资料；头像图片失败单独处理。存储与会话机制仍由客户端实施片验证。

独立登录状态检查没有可信登录选择、发现当前登录失效，或已确认选择存储不可用、损坏时，“手机号登录”在新标签页打开同一预览范围的手机号起点。前两类以登录为主操作；存储不可用时仍以重新检查为主，另提供手机号登录。用户重新填写手机号并验证，原页不清理办理材料、不自动发码，也不因打开登录而改变原结果未知的事实。该导航不实现生产会话存储或跨标签页协调。

验证码使用 6 格展示同一个连续字符串，对应网站实现的 Base UI OTP Field。各格只接受 ASCII 数字，并开启 `autocomplete="one-time-code"`。输入一位后焦点前移。Delete 或 Backspace 删除已有位时，后续数字左移，不留下中间空槽；空尾格的 Backspace 删除前一位。聚焦超过首个未填位的格时，回到首个未填位。方向键、Home 和 End 只在已有位及首个未填位之间移动。

整段粘贴或系统填充的内容须全部是 ASCII 数字：6 位时从首格替换，较短时从当前可编辑位覆盖。含非数字字符或超出剩余格数时整段拒绝并提示，不过滤或截断。IME 组合结束前不接纳或提交，结束后对组合结果整段校验。第一格关联“短信验证码”标签，其余格标注“第 N 位，共 6 位”。提示文字和错误提示通过 `aria-describedby` 关联到各格；错码时各格同时标为无效，验证中和待确认时整组锁定。虚构示例 `012345` 保留前导零，旧八位码作为超长输入整段拒绝；缺位不能提交。

短信与注册状态对应[短信认证](../identity/authentication.md)、[正式注册](../identity/registration.md)和[网站会话](../identity/website.md)。通用 `permission_denied` 不足以区分账户暂停与来源拒绝，界面仅提示暂时无法登录。注册页只显示手机号已验证，不从凭据推导号码。微信状态按[微信身份](../identity/wechat.md)设计，正式入口随网站授权能力交付。

登录流程只占一个浏览器历史条目，前进与后退离开或回到整个登录页，不在步骤间切换；从缓存返回时，提交中的办理进入对应待确认状态；刷新会丢失演示页内存，待确认改为恢复材料缺失的结果；其余从手机号重新开始。直接打开带状态的链接只用于设计查看。状态选择器切换到其他分组时清除上一办理的资料与待确认标记，同组切换保留，用于演示同一办理的异常，且不延长原期限。确认原操作期间暂时受限，等待后回到原待确认状态。登录资料不一致仍按原登录结果路径处理。姓名、身份证号只留在演示页内存中。离开未填完的注册页先经浏览器确认，离页或完成演示时清除；已提交待确认的资料在确认结束前保留。表单只演示格式提示，不承担服务端的完整实名校验。安全验证和二维码均为展示占位。倒计时使用示例时长；正式接入须消费实际截止及 `Retry-After`。

默认、R1 与 R2 入口共用 C1 发码状态。发码核对返回 `request_mismatch` 后，原资料与证明保留至原截止，停止继续核对。页面提示先查看短信、暂时不要重复获取，只提供返回公开首页。返回与重进均不发起新办理。演示页刷新后，因内存材料缺失而显示相应提示，不回到发码表单；实际恢复材料规则见[原操作恢复](recovery.md)。

[Figma C1 资料不一致补充稿](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=206-1667)保留可编辑文字、组件和层级，包含 320、390 px 的资料不一致整屏，以及 320 px 的重进材料缺失整屏。原有发码状态卡同步此处文案与公开返回去向。画布只展示静态状态，点击和重进以仓库原型核对；Make 未同步本片。

填写超时只适用于尚未提交的注册资料。提交后锁定表单并隐藏填表倒计时，按[原操作恢复](recovery.md)确认结果。结果未明时不引导重新发码或注册；确认原操作时暂时受限，等待后回到原待确认状态，不开放编辑。返回登录前确认清除未提交资料；已提交时保留继续确认入口。登录后须读取本人成功，再按可信服务资格进入后续页面。

样式与脚本位于 `design/assets/halo-authentication.css`、`halo-authentication.js`，共用首页的颜色、字体和品牌素材。用上文的本机预览服务打开 `/halo-authentication.html`。浏览器核对正常两条分支、状态切换、字段错误、焦点、返回确认和窄屏布局。验证码在桌面、中间宽度和窄屏下逐项核对 6 格排列、逐位输入与焦点前移、删除回退、整段粘贴、非数字拒绝和错码状态。设计稿不实现真实短信、注册、持久登录或跨标签页恢复。

### 网站员工服务主页设计稿

本节记录现有稿覆盖，不表示稿件已完成简化设计验收。关于旧申请、原 Grant 和增办来源的旧场景不作为新工牌要求；实现前按[申请](../workforce/applications.md)核对页面状态。

[员工服务主页](../../design/halo-services.html)承接登录后的本人入口，覆盖正常、未开通、暂停和结束四类状态。页头保留公开首页与个人账户导航。桌面将办理入口和最近申请放在主栏，账户与帮助放在侧栏；窄屏按办理优先的顺序排列。

| 已确认的情况 | 主页展示与可用入口                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 未开通       | 说明工号与工牌用途，提供使用邀请码入口；个人账户仍可使用                                             |

| 暂停         | 说明恢复方式，只展示取消所需的未发放申请摘要；保留结束员工服务和个人账户                             |
| 结束         | 说明原申请无法继续，仍可取消未发放的原申请；提供邀请码重新开通入口，不恢复旧申请或旧工牌的增办资格   |

正常态另有尚无工号、暂无申请及读取失败示例；尚无工号示例仍列出历史申请，申请区只按申请读取结果判断是否为空。暂停态与结束态各有暂无可取消申请和读取失败示例。状态选择器共提供 17 种场景。工号未确认时不开放工牌申请；已有申请不阻止新申请。申请状态按原事实呈现，不从审核结果推断制作或领取情况。

结束员工服务连接[本人结束服务稿](../../design/halo-service-termination.html)，演示确认、办理结果与继续核对，不执行真实办理。取消申请只展示具体后果及确认位置。个人账户与个人资料入口连接本人账户稿；邀请码、工号、照片与申请详情按钮打开独立的设计旁注，后续逐片补齐目标页面。暂停时不展示完整工牌资料；结束时不提供继续旧申请入口。

当前登录注册稿的首批 R1、R2 入口在本人读取成功后只展示当前账户；默认完整目标稿的注册完成也采用此落点，不跳转员工服务示例。员工服务主页仍可独立查看正常、未开通、暂停和结束的虚构状态。正式页面目标保留登录后进入员工服务，并按当前可信服务读取分流，不能从登录或注册成功推断资格。本稿不发起请求，也不保留账户资料。页面每次进入（直接打开、刷新或缓存返回）都先遮蔽姓名与账户入口，复查完成后再显示；页内锚点只移动焦点，不改写状态地址。

样式与脚本位于 `design/assets/halo-services.css`、`halo-services.js`。用本机预览服务打开 `/halo-services.html`。验收覆盖四类主状态、读取与空态区别、入口和确认、键盘焦点。桌面、中间宽度与窄屏均核对字号、留白和内容顺序。本稿的浏览器检查不代替真实服务资格及写入恢复验收。

### 网站本人首次领取工号

`/workforce/number` 从员工服务的“首次领取工号”进入。页面先检查当前账户、有效员工服务及当前工号。可信的当前空值只开放首次申请入口，不证明此前从未领取；服务端仍按[工号规则](../workforce/numbers.md#首次分配工号与补录)判断。

人员类别不预选。本人明确选择后，确认弹窗展示所选名称和领取后不能自行改选的后果，初始焦点落在“暂不领取”。确认后由系统分配本年度工号，页面显示原成功的固定工号与细分类名称。号码池耗尽时说明本年度该类别已用完；只有原类别选错时才提供重新选择，不引导改选其他类别获取号码。

结果未知时显示“领取结果待确认”，提供“查看本次领取结果”。刷新只恢复显示，不重复申请。当前工号与本次领取结果分别解释；已领取过但当前没有工号者联系医院管理员。账户变化或页面隐藏时遮蔽原资料，登录原账户后才能继续查看。恢复合同见[本人首次工号恢复](recovery.md#本人首次工号恢复)。

### 网站本人结束员工服务设计稿

[结束员工服务稿](../../design/halo-service-termination.html)承接主页正常与暂停状态的本人入口。确认页说明停止办理及保留内容，确认弹窗初始焦点落在“暂不结束”。取消确认后回到原入口。服务资格、结束后果及原请求契约由[授权生命周期](../access/grants.md)拥有。

正式路由为 `/workforce/termination`。页面只消费当前可信账户、本人员工服务状态和保存的本人原请求定位；登录返回使用固定站内意图 `service-termination`，不接受任意地址。

可编辑画布见 [Figma「网站 · 结束员工服务」](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=217-983)。画布包含 11 张响应式代表屏、37 张状态卡，以及结束确认和待确认离开两类弹窗规格。代表屏覆盖 320、390、768、1440 像素与浅深主题。Figma 展示静态可编辑状态，实际点击与固定登录返回以 HTML 原型核对。字体沿上文的系统字体映射，不声明像素一致。Make 未同步本片。

两份稿件的原成功标题和主次操作已对齐。入口侧栏组合、状态徽标及导航选中样式仍有差异，留待后续视觉统一。

首次发送前保存失败显示“尚未提交结束申请”。提交中与结果未确定分别展示。首次提交收到可信的入口限流拒绝时，显示“本次申请尚未受理”，等待后返回确认页面，由用户再次确认。该拒绝发生在[业务执行前](../http/admission.md#逐级扣额与回收)，不显示结果待确认的离开警告。

此前结果未知时，继续核对沿[客户端恢复](recovery.md)使用准确的原人员、服务及办理材料；不能换成当前新开通的服务。核对暂时受限只说明本次核对未被接纳，等待后仍核对原办理，不推断此前申请未受理。请求信息不一致时停止继续提交，并提供当前服务读取。读取当前状态不能证明此前申请的结果。

已确认的原成功始终保留，当前服务读取另列进行中、失败、已结束及重新开通的画面。重新开通画面明确说明当前服务不受此前核对影响。原成功不会因当前读取失败变成待确认。材料不可用或不再适合恢复时，只提供当前有权使用的服务、账户或公开入口，不默认提供重新结束。Grant 完成记录永久保留，本稿不设服务端结果过期时间，也不套用匿名认证的秘密保留期限。

原成功画面以“此前的员工服务已结束”为主标题。当前服务已读取时，“查看当前员工服务”为主操作，个人账户为次操作。当前读取失败时，“重新读取当前状态”仍为主操作。

键盘重读后的焦点回到主标题，以文字下划线标明位置。操作控件仍使用轮廓焦点提示。等待按钮使用中性底色和实色文字，保持等待时间清楚可读；等待结束前禁用，不提前提交。

身份复查与选择变化沿[网站会话](../identity/website.md)遮蔽旧资料与办理提示。重新登录使用固定站内返回意图，不接收任意地址。完整登录稿的已有账户路径展示同账户继续核对、其他账户遮蔽及材料不可用三种返回。登录成功与当前服务读取均不代替原办理结果。结果待确认时离开须明确提示，返回账户或公开首页不会取消已发出的申请。

画面与状态工具使用虚构资料，只演示导航、焦点与信息层次。脚本不保存业务材料，不发送结束请求，也不证明浏览器持久恢复、后端办理或真实登录完成。正式网站仍须验收发送前保存失败零请求、准确 Grant 绑定、原请求恢复、同账户新会话、另一账户隔离及重新加入后的旧响应。原型的状态选择和演示计时遵守[设计稿审查边界](../engineering/verification.md#设计稿审查)。

### 网站本人账户设计稿

[本人账户稿](../../design/halo-account.html)用于核对当前账户资料与本人实名更正记录，沿用网站外壳与纸墨配色。员工服务主页的账户与个人资料入口均连接本稿；员工服务未开通、暂停或结束时，正常账户仍可进入。

可编辑画布见 [Figma「网站 · 本人账户」](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=39-2)。画布包含 8 张完整代表屏。宽度覆盖 1440、768、390、320 像素。其中含 390 像素的深色长姓名示例。另有 20 种状态卡和 5 个维护说明弹窗。资料行有 6 个变体，历史卡有 2 个变体。画布复用既有 75 个变量，全部文字关联文字样式。页面保留可编辑文字、组件和自动布局。品牌标志与正常虚构头像使用离散图片，头像失败占位沿用源稿 SVG。

Figma 画布展示静态状态。状态切换、跨页导航和弹窗交互以 HTML 演示稿核对。资料重读、头像重试和历史分页也在 HTML 中演示。工具折叠、每页条数、键盘焦点与返回均在浏览器中检查。画布中的受限按钮固定展示初始等待时间，不执行倒计时。

设备系统无衬线字体在画布中映射为 Noto Sans SC。品牌宋体映射为 Noto Serif SC。替代字体的字形、字重及换行度量可能与浏览器不同。本稿不声称像素一致，字号与间距按源稿核对。客户端落地时，按实际字体复验窄屏长姓名、分页和深色状态的换行与布局。

当前资料按[本人账户投影](../identity/current.md#本人账户投影)展示完整姓名、身份证尾四位、头像与可信的微信绑定事实。姓名、证件号和微信绑定状态只读，本页不提供绑定、解绑或扫码登录动作。页面不补造手机号、注册日期、登录方法、设备或微信昵称。头像图片单独失败时保留其他已可信读取的资料，显示图片占位及有界重读位置；不从图片失败推断登录失效。

实名更正记录按[本人历史](../identity/correction.md#历史读取)展示更正前后完整姓名、证件尾四位及更正时间，不显示办理人。记录倒序分页，区分真实空历史、读取失败与越界页。示例显式选择每页 2 条以展示跨页；可切换每页条数，刷新从第一页读取。虚构材料含长姓名与前导零尾号，不使用真实人员资料。

状态工具提供 20 种场景，涵盖正常、未绑定、整页读取中与失败、暂时受限、登录失效、读取被拒绝、账户选择变化、实名版本变化、头像图片失败，以及历史加载、分页、空态、失败和越界。整页读取未可靠完成或账户变化时遮蔽资料与历史；一般读取故障不解释为退出，通用失效不猜测暂停或注销原因。

头像更换、更换手机号、退出本次登录、退出全部设备和本人注销连接各自的独立设计稿。政治面貌进入[本人政治面貌稿](../../design/halo-affiliation.html)；微信及登录安全只打开设计说明。样式与脚本位于 `design/assets/halo-account.css`、`halo-account.js`。本稿不实现生产会话、持久存储或浏览器恢复机制。用本机预览服务打开 `/halo-account.html`，在桌面、中间宽度与窄屏检查资料、历史、翻页、焦点、返回与遮蔽；本稿不代替客户端或业务验收。

### 网站本人注销设计稿

[本人注销](../../design/halo-cancellation.html)从[个人账户](../../design/halo-account.html)的“注销账户”进入。入口保留长姓名、资料更新与另一账户示例。`?example=primary|long-name|updated|other` 只选择虚构资料，不携带原注销状态、任意回跳地址或操作标识。页面只处理当前正常本人账户的一次注销，不扩展历史查询、管理注销或客服入口。范围沿[本人注销](../identity/cancellation.md)，可信资料沿[当前账户](../identity/current.md)，选择与失权沿[网站会话](../identity/website.md)，未知结果沿[客户端恢复](recovery.md)。

页面先读取当前账户，只展示完整姓名与身份证尾四位，不补造手机号。本人核对后果后明确确认。发送前保存失败明确尚未提交，提交中不提供第二次提交。成功只依据可信 `ok`、注销编号与 `cancelledAt`，显示一个完整结果。首次受限、输入拒绝、首次 401/403 和已知回滚分别展示，不标为结果未知。`target_changed` 重新读取后仍须本人再次确认；`request_mismatch` 保持结果待确认。

未知结果停止自动重发，不提供注销结果查询。检查登录状态只读取当前账户。同一账户仍有效，也不能单独证明注销已完成或未完成。读取失败、受限、失权、禁止访问、选择变化与另一账户分别展示。没有当前登录、登录失效或已确认选择存储不可用时，提供现有[手机号登录稿](../../design/halo-authentication.html)入口。普通读取失败只重新检查，新注册或另一账户不承接本次注销。

选择变化及另一账户先遮蔽旧姓名、尾号和原办理提示。随后检查失败或失权仍保持遮蔽，不再带出原注销上下文。结果页收起私人导航，只保留当前状态允许的动作。未提交离开与提交后结果未明离开分别提示，取消、关闭和 Escape 返回原焦点。

有未提交选择时，离页提示放弃当前选择。提交等待中离页时，提示离开不取消已发送填写。其余状态直接离页。关闭、Escape 与留在此页返回触发控件焦点。401、403、后台、离页或账户变化时，页面立即遮蔽姓名、政治面貌和选择。晚到响应不恢复旧资料。

原登录仍有效的只读查询页以“此前退出结果”为标题，说明只查询、不再次退出，不称已有新登录。已提交后的原退出页头按提交中、结果未知与确定完成分别说明，不再提示开始新的退出。查询结果的侧栏说明只在已提交且结果未知、查询信息仍在且本次查询未被拒绝时展示。查询被拒绝或输入无效时，离开提示只保留结果未知、离开不取消与不重提，不承诺继续查询。固定登录返回遇到其他账户时，按钮说明下一步读取当前账户资料，不承诺员工服务或显示旧退出信息；查询信息缺失时，只提示返回登录前页面，不承诺继续查询。

实际客户端将尚未取得证明与已知不匹配分开保存。分类前离页或分类保存失败后重进，先显示中性的“退出结果”；同账户明确查询取得匹配的原范围和发起者后，可确认本次全部退出完成。已保存的不匹配不会被后续通知抹去。分类结果未能保存时，不凭旧本地判断宣称匹配，仍须核对服务端原证明；证明不匹配只展示此前记录。

原退出完成仅描述当次撤销的集合。恢复成功及迟到成功另行说明当前的新登录继续保留，不宣称后来登录也已退出。另一账户画面隐藏旧操作类型、状态和离开提示。确认与结果未定时离开分别提示；取消、关闭和 Escape 返回触发位置。长姓名、头像图片失败、浅深色及 1440、768、390、320 像素宽度由本片验收。

提交中、结果未知和完成后的页头分别说明本次退出的进展或结果，不再提示发起新退出。已明确未受理的提交受限不进入结果未定状态。当前身份未读完、读取失败、受限或被拒绝时，只显示中性账户页头，也不弹旧操作的离开提示。账户链接沿当前已知登录状态返回，失效、禁止访问及尚未确认时不直接展示旧资料；普通查询技术失败不抹去已可信读取的当前账户。待确认离开提示不要求仍有效的当前登录重复登录。品牌和其他同目标链接使用相同离开提示。查询被拒绝时的离开提示不承诺继续查询；查询信息缺失时直接返回，不弹恢复承诺。长姓名、资料更新、另一示例账户及图片失败入口分别保持原资料场景。取消后返回相同账户画面。

结果未知时，手机号登录使用固定的 `?return=all-logout-result`。完整目标预览的已有账户登录且本人读取完成后，可返回原退出页面。返回后重新读取当前账户，同账户才提供只读查询。另一账户只提供当前账户入口；查询信息缺失时停止查询。注册完成、普通登录、R1 与 R2 的去向保持原范围。注册新账户不能取得旧退出的恢复资格。认证页只接受本次退出与全部退出各自固定的站内意图，不接收任意返回地址或操作标识。

样式与脚本位于 `design/assets/halo-all-logout.css`、`halo-all-logout.js`。预览工具可选择提交、登录检查和原查询的示例结果；页面按钮依次走对应路径。虚构完成示例的 `count` 为 3 条会话，时间和资料均为虚构。原型不执行 HTTP、生产存储、真实登录或跨标签页恢复。静态画布、浏览器交互与客户端实施分别验收。

### 网站本人头像更换设计稿

[更换头像](../../design/halo-avatar.html)从[个人账户](../../design/halo-account.html)的头像入口进入。页面先核对当前本人，再提供本地选图、候选预览和明确确认。头像维护不依赖员工服务资格，也不更换工牌照片。输入与结果沿[账户头像](../identity/avatar.md)，恢复边界沿[客户端恢复](recovery.md)。

可编辑画布见 [Figma「网站 · 本人头像」](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=63-2)。画布包含 10 张完整代表屏、42 张状态卡，含[更换结果查询被拒绝](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=94-107)。另有 2 种离开确认，含桌面和窄屏示例。画布展示静态可编辑状态，选图、确认、返回和导航交互以 HTML 原型核对。

当前读取覆盖加载、失败、受限、登录失效、同源拒绝与账户变化。未取得可信资料时遮蔽旧头像和候选。图片单独失败时保留可信读取，提供一次重新加载。选图展示空态、读取中、预览，以及格式、大小、原始尺寸、损坏和动画错误。

提交前由本人预览并确认更换。请求发出后区分进行中与结果未确定，通过查询更换结果继续办理。查询过程提供失败、受限、同源拒绝、暂无可读结果和恢复定位缺失画面。同源拒绝只表示本次查询未完成，遮蔽图片并保留查询原完成的入口，不称退出或更换失败，不开放选图。暂无可读结果和恢复定位缺失也不表示更换失败，不直接开放重传。

结果未确定时登录失效则隐藏旧图片，保留原更换责任；预览工具可模拟登录更换头像时使用的账户，再由明确操作查询结果。账户读取期间及另一账户的页面不显示旧操作类型、状态、图片或离开提示；读取当前账户后可选择该账户的新头像。设计工具仅私下保留旧记录标志，重新读到原账户后才恢复其结果查询。

当前头像变化后先重读，再由本人重新确认新头像。原更换完成、本次无需更换及这两类完成后当前头像后来变化分别展示。当前图片不替代原完成。

样式与脚本位于 `design/assets/halo-avatar.css`、`halo-avatar.js`。顶部状态工具提供虚构示例、确定结果和等待结束演示。真实文件选择只在本地检查与预览；普通确认路径模拟完成，不读取账户或上传图片。账户正常态与头像页复用同一虚构猫头像。离开未提交的新头像与离开结果未确定的更换分别提示后果。关闭、Escape 和留在此页只关闭提示并返回触发位置；查询结果由页面上的明确操作触发。生产持久恢复、会话选择与真实上传留待客户端实施。

本设计工具检测到 EXIF 元数据时，不展示或确认该候选，并说明无法准确展示原始方向，可用示例演示。该限制不表示文件不合规，不成为产品接纳规则。无 EXIF 的文件使用浏览器默认解码，原始字节不变；正式客户端仍遵守不按 EXIF 旋转的原始方向契约。

本轮原生文件选择验证被 Chrome 扩展的本地文件访问权限阻止。状态演示与布局检查不证明真实图片解码或 EXIF 方向已验证。

页面沿用网站外壳与颜色令牌，提供桌面、中间宽度和窄屏布局。客户端落地时，按实际字体复验文案换行、按钮与图片比例。

### 公开内容页面

栏目页、文章页由站点服务端读取[内容公开接口](../content/http.md#公开读取)并渲染，文章正文由客户端组件按结构化节点输出，不注入 HTML。全部文章入口的正式网站地址由[公开内容页面](../http/site.md#公开内容页面)规定。首页在首次发布编排后改为服务端读取，区块沿[首页编排](../content/home.md)。

公开阅读稿位于 [halo-reading.html](../../design/halo-reading.html)，样式与演示脚本分别为 `design/assets/halo-reading.css`、`halo-reading.js`。稿子复用首页视觉、令牌与插画，提供一层栏目列表、三篇虚构文章及返回栏目或首页的路径。首批不做站内搜索。全部内容匿名可读，不读取或展示本人资料。

[公开阅读 Figma 画布](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=21-2)包含 24 张画面，展示列表、状态与正文代表。正文画布以 `seasons` 为代表；另外两篇完整正文从 HTML 稿的 `?article=table`、`?article=courtyard` 入口查看。

| 画面 | 状态与查看入口                                                                                                                                                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 列表 | 默认展示全部文章；`?column=culture` 和 `?column=life` 进入具体栏目。正常、分页、页码越界、空、加载、读失败、栏目不可用分别为 `list-normal`、`list-pagination`、`list-page-out-of-range`、`list-empty`、`list-loading`、`list-error`、`list-unavailable` |
| 文章 | `?article=seasons`、`?article=table`、`?article=courtyard` 打开对应正文。正常、加载、读失败、不可用、所属栏目停用分别为 `article-normal`、`article-loading`、`article-error`、`article-not-found`、`article-column-disabled`                            |

顶部演示工具通过 `state` 查询参数选择状态，手机默认折叠。状态参数仅供设计查看，不定义正式路由。读取失败隐藏列表或正文，保留重新加载和返回路径；空态只表示成功读取后暂无已发布文章。不可用状态显示 404 和返回路径，不猜测撤回、未发布或地址错误的原因。所属栏目停用时正文仍可读，栏目名为普通文字，返回入口改为全部文章。

分页示例为 `?state=list-pagination&page=1`，每页 2 篇，上一页与下一页保留栏目。页脚显示当前页、总页数与总篇数，首末页分别关闭越界方向。`?state=list-page-out-of-range`、超过末页或无效的 `page` 展示 404、“本页暂无文章”与返回第一页，说明中保留总篇数，与成功读取的栏目空态分开。全站空态只提供返回首页；具体栏目空态仍可浏览全部文章。

正式站点的越界页按[公开内容页面](../http/site.md#公开内容页面)返回真正的 404 和 `noindex`；内容接口仍按[列表契约](../http/lists.md)返回总数与空数组，两者各自负责接口数据和网站响应。静态设计稿标记 `noindex`，只演示可见错误页，不证明 HTTP 状态已实现。带目标页的加载或读取失败隐藏整页结果，重新加载保留该页。正式列表刷新从第一页开始，演示稿不承担浏览器恢复。

文章展示署名、首次发布时间及有变化时的更新日期，不展示草稿版本号或办理人。正文覆盖段落、二至四级标题、有序与无序列表、引用、分隔线、带替代文字的图片、粗斜体与站内链接。列表封面同样保留替代文字。示例只讲文化与生活，不提供医疗建议，不设评论、点赞、收藏或作者账户。首页与正文首批只允许站内链接，失效引用的公开隐藏及管理提示按[首页规则](../content/home.md#上线与回退)执行。

本稿只供视觉与路径评审，不证明服务端渲染或内容接口已经实施。以 1440、768、390 和 320 像素宽度核对排版、阅读限宽、折叠工具、键盘焦点和主要导航；正式缓存、会话与浏览器恢复留在客户端实施切片验收。

管理端的文章、首页编排和图片编辑页仍待设计，实现前须先补齐列表、编辑、预览、发布、撤回、恢复、版本历史及冲突与待确认状态的设计。正文格式见[文章正文结构](../content/articles.md#正文结构)，编辑器约束见[网站组件](website.md#组件)。

### 网站栏目维护设计稿

[栏目维护 Figma 画布](https://www.figma.com/design/p05BAl3mRubRl8XTuiUvv5?node-id=98-2)包含 13 张代表画面、41 张紧凑状态卡和 4 个弹窗。文字、自动布局和组件实例可编辑，使用 23 个首用组件变体与现有 75 个共享变量，未新增整套组件库。画布没有交互连线，HTML 稿负责导航、保存确认、结果查询和离开弹窗的交互演示。

画布用 Noto Sans SC、Noto Serif SC 和 Roboto Mono 映射设备字体，字体度量与 HTML 存在近似。代表画面覆盖 1440、768、390、320 像素宽度及深色；状态卡补齐适用分支，不代表每个状态均有四种宽度的完整画面。原型只供设计评审，不证明客户端或内容管理接口已经实施。

[栏目维护稿](../../design/halo-columns.html)供持有 `institution.articles` 的正常网站账户查看全部栏目、创建及修改名称、说明和启停状态。资格不依赖员工服务，首页编排权限不包含栏目维护。两项内容权限及默认授予由[权限目录](../access/capabilities.md#网站公开内容权限)拥有。

[员工服务主页的栏目维护者示例](../../design/halo-services.html#content-manager)在正常账户与准确权限已确认时显示栏目管理入口，同时展示员工服务尚未开通，避免把员工服务资格作为内容维护前提。其他既有状态不推定具备这项权限。

栏目规则由[栏目](../content/columns.md)拥有。稿子只覆盖一层栏目，保存前核对完整内容及直接生效的后果；创建时明确选择启用状态，修改时公开地址名只读，说明其永久保留。停用从公开导航隐藏栏目并使栏目页不可访问，已经上线的文章仍可访问。完整列表包含停用栏目，不提供分页、排序或删除操作。文章、首页编排、图片维护及完整变更历史不在本稿范围。

用 `?state=状态名` 查看以下画面；`?state=edit&id=culture` 与 `id=life`、`id=archive` 查看对应编辑页。参数只用于设计预览，不规定正式管理页面地址。

| 画面           | 状态名                                                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 列表与读取     | `list`、`loading`、`empty`、`at-limit`、`read-error`、`limited`、`target-unavailable`                                                                                                   |
| 资格与遮蔽     | `session-invalid`、`denied`、`homepage-only`、`permission-changed`、`account-changed`、`other-account`                                                                                  |
| 表单与冲突     | `create`、`edit`、`recovery-save-failed`、`submit-limited`、`field-errors`、`key-in-use`、`name-in-use`、`unchanged`、`column-changed`、`refresh-loading`、`refresh-error`、`refreshed` |
| 提交与继续确认 | `submitting`、`pending`、`create-pending`、`checking`、`check-error`、`check-limited`、`result-unavailable`、`request-mismatch`、`recovery-missing`、`current-loading`、`current-only`  |
| 完成与当前内容 | `complete`、`completed-current-loading`、`completed-current-error`、`later-changed`、`later-unavailable`                                                                                |

读取失败隐藏整份列表，错误不表示没有栏目。名称冲突与永久占用的地址名分别提示。当前变更前提失效时先重新读取，旧输入只供对照，不静默覆盖或自动保存。未提交输入离开前确认放弃；提交中的离开不取消保存。

首次发送前未能保存继续确认所需的材料时，尚未提交，保留可编辑输入。首次保存被可信限流明确拒绝时，同样不进入待确认；按等待提示结束后，由人重新核对并明确确认，不自动发送。可信完整列表已有 100 个栏目时，创建入口不可用并说明上限，已有栏目仍可修改。

结果未知时，界面使用“查询保存结果”，只以这次保存的原标识和同一输入核对所属变更，不用列表当前值证明原完成。暂未查到结果不表示保存失败，不开放重复创建或保存；离开不取消已发出的请求。恢复材料缺失时，只能查看当前有权读取的栏目，不开放猜测性的重复创建或修改。原完成与另行读取的当前栏目分别展示；后来的修改或栏目不再存在，不否认这次保存已完成。恢复职责见[客户端原操作恢复](recovery.md)，本稿不实现真实接口、生产会话或材料持久保存。

原完成已知后，当前栏目另行读取中或读取失败时继续保留这次完成与保存内容，隐藏尚未核对的当前值。普通读取失败不表示栏目已删除，只重读当前栏目，不重新保存。账户或权限变化会清除旧表单、办理摘要及核对弹窗；重新核对后不重新带出旧输入。

稿子复用现有视觉令牌与网站外壳，顶部工具在手机折叠。以 1440、768、390、320 像素宽度核对列表、表单、弹窗、文本换行、主要动作、键盘焦点及遮蔽。HTML 为交互设计材料，不证明内容管理能力已经实施。

## 工牌预览与管理交互

头像和工牌照片分别办理。本人明确确认照片裁剪效果，不静默改变输入。科室、职务、职称沿现有目录选择；默认科室仅供初次预选，提交仍要求本人确认。目录不是人员任职或权限归属。目录管理不改写旧快照。

首版使用固定模板与确定字体，预览展示完整姓名、工号、科室、职称、照片和牌面。字体缺失、文字溢出或资源不可用时明确提示，不靠截断、省略或压缩制造成功。领取地点在画布外选择，提交保存原文字。

服务端根据可信资料及本人选择保存快照，预览内容变化时重新展示供确认，不要求提交实名版本或模板摘要。审批和正式 PDF 始终使用原快照。管理页将“提交时资料”和“当前资料”分开展示；差异只提示，不自动改内容或否决审批。

生成中的提示只表示当前请求正在执行，不是持久 Render 状态。失败、断连或刷新后 approved 且无成品时，可由有权人员明确生成或重试。ready 才提供发放。取消与重复点击按服务端状态解释，不自动重交。

照片、模板资源和成品由当前会话及对象权限控制读取，不签工牌短期 URL。离页、切换账户或失权时清除受限页面资料。已有默认头像签名规则保持。表单提供标签、键盘操作、焦点与字段错误，窄屏本人页面和桌面管理页面均实际验收。

裁剪前从[固定模板入口](../workforce/media.md#模板与固定资源)取得照片区域和领取选项。确认后实际编码图片按完整比例居中放入区域，显示透明度与留白；不以像素和微米精确同比分辨率作为前提。文字按服务端给出的原文字节范围及行定位展示。正常账户及活跃资格可读完整本人历史，当前无工号不隐藏历史；资格暂停或结束后仅显示[可取消摘要](../workforce/applications.md#存储与-http)，清除快照和媒体，不继续沿用已加载的完整内容。

## 验收

当前网站验证认证、真实账户准备、本人隔离、管理权限与范围、账号切换及迟到响应。完整证件号只在所属有权管理投影中展示，不因审批开放。已有短信和登录恢复单独沿原合同验证。

工牌验证三种类型、同人同类型多份申请、固定快照与资源、资料差异提示、一次审批、驳回后新申请、取消、人工生成重试及发放。响应丢失只刷新状态，失败不显示空申请。下载逐次鉴权，缺文件明确报错。区分驳回、生成失败、已生成与已发放，不能显示“已领取”冒充物理领取事实。

小程序、微信扩展及公开内容管理暂缓，不作为本次页面验收项。设计稿和文档不证明实际浏览器、打印或生产验收通过。网站发布及后端入口分别遵守[网站交付](../http/site.md)与 [HTTP 合同](../http/api.md)。
