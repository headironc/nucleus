# 客户端协议

本文规定客户端消费 HTTP 契约、校验响应及传输的规则。交付状态见[能力状态](../README.md#能力状态)。服务端路由、请求和响应的权威来源是 [HTTP 入口与响应](../http/api.md)及所属用例；按业务区分的失败处理见[客户端恢复](recovery.md)。

## 同一份接口描述

两端从 nucleus 实际导出的 OpenAPI 3.1 文档构建共享的 TypeScript 请求和响应类型，以及运行时响应校验函数。构建输入是从本机 `/openapi/v1.json` 导出的固定快照，见[路径前缀与版本](../http/api.md#路径前缀与版本)；构建和启动客户端不依赖生产 API。类型由 openapi-typescript 生成，响应校验由 Ajv 预编译。生成物不手工维护，不另写一份必填字段或应用码清单。服务端尚未装配的入口不能凭客户端类型宣称可用。

类型检查只约束客户端源码，收到的网络字节仍须独立校验。构建过程解析本地引用，按所用 OpenAPI 与 JSON Schema 语义处理注解、组合、缺失字段和 `null`；无法支持的校验关键字或格式使构建失败，不能静默丢弃约束。校验代码在构建时生成，运行时不使用 `eval` 或 `Function` 编译 schema。生成工具、实际 Rust 导出文档和构建器的组合须用真实接口样本验证，不能从工具宣称支持 OpenAPI 3.1 推定组合可用。

Halo 选择已接入用例的路径和可达 schema，清单见 [Halo 使用说明](../../halo/README.md#协议快照)。Session 协议适配器只组装请求和验证结果，不自动重试或选择会话。登录页面拥有原操作恢复，会话选择遵守[网站持久会话](../identity/website.md)。错误码从对应状态的导出描述生成；描述无法明确列出应用码时，生成失败。`200` 还须具有普通业务协议的 `code: "ok"`，不从描述或提示推断成功。

工牌照片上传和资源读取的二进制媒体清单同样由实际 OpenAPI 生成。字节成功与 JSON 失败分别处理，不把错误正文当作照片或字体。生成器只接纳明确支持的二进制 schema；额外且未支持的约束使生成失败。提交适配器只接纳 `201`，并核对回执与本人确认的实际快照一致。

共享模块分别构建成网站可用的模块和小程序包内的代码与类型声明。小程序运行时只加载随包交付的文件，不引用项目根目录之外的源码。两端由同一份协议实现生成产物，不手工复制实现。

共享 JSON 契约判断由 `client/protocol/response.ts` 拥有，平台传输继续由各客户端实现。网站构建身份包含该共享输入。Halo 与 Orbit 直接消费同一份实际导出的 `halo/protocol/openapi.json`，不另存小程序副本。Orbit 使用相同的 OpenAPI 选择与 Ajv 编译实现，单独选择本片消费的入口及保留标识。共同描述保留已装配的 Message/Mobile 与 Cookie/Bearer 联合；Halo 只消费 Message 与 Cookie，Orbit 只消费 Mobile 与 Bearer，类型和运行时均保持该边界。生成及构建绑定原快照摘要，不以通过构建代替真实平台或端到端验收。命令与证据边界见 [Orbit 说明](../../orbit/README.md)。

## 请求与传输

共享协议层根据 method、路径和用例输入组装请求，不持有 DOM、`wx` 或业务事实。Operation-Id 的生成和写入重试规则由[客户端原操作恢复](recovery.md)拥有；服务端对请求头的校验由 [HTTP 入口](../http/api.md)拥有。创建 Session 和正式注册的传递方式由服务端按可信认证来源确定，客户端不额外声明；来源和结果形状见[匿名身份入口](../http/identity.md)。

网站传输按[网站持久会话](../identity/website.md)携带当前浏览器选择，并按[当前身份](../identity/current.md)解释会话失效。小程序传输使用 `wx.request` 和 Bearer 会话，明确适配请求取消、HTTP 状态、响应头及 `ArrayBuffer`。传输取消只中止本地等待；涉及写入时，普通工牌刷新当前状态，短信及未迁移消费者按所属原操作合同处理。两端共享响应判断，平台接口和存储由各端适配。

## 响应可信性

解析成功不等于响应可信。客户端先按实际 method、路径、HTTP 状态和媒体类型选择契约。再验证正文结构、必填字段、合法结果分支及 JSON 错误封装。响应不回显请求标识；客户端用本次调用持有的原操作、目标及会话选择修订关联响应，迟到响应不能覆盖后来选择。原结果中的业务 ID 仍按所属契约验证。豁免入口不增加另一种请求标识传递方式。未知应用码及状态与应用码矛盾时，不从提示文字推断业务结论。写入响应验证失败时，不自动重做；普通工牌刷新状态，短信及未迁移消费者保留原定位，见[客户端失败处理](recovery.md)。普通读取显示“暂时无法加载，请刷新后重试”，并提供明确刷新动作。

本人账户响应只接纳已交付的准确投影。姓名须为规范 NFC 输出；客户端拒绝错误值，不改写响应。头像使用独立 HTTPS origin，按已交付的 WebP 尺寸、签名链接形状和期限字段一致性核对。客户端不验签或访问链接，也不按本机时钟拒绝已过期的合法元数据；真实 HMAC 和到期判断仍归图片服务。

本人更正记录只消费[本人历史投影](../identity/correction.md#历史读取)。客户端按服务端顺序展示完整姓名、证件尾四位与北京时间，区分真实空集合和越界页。分页与总数来自同一响应；刷新回到第一页。计数超出 JavaScript 安全整数范围时拒绝响应，不增设服务端业务上限。

记录仅存在于当前可见账户页内存，绑定会话选择修订与一次可信本人检查。本人检查失效、离页或恢复前台时先清除记录和总数，再重新确认身份；旧代次响应不能写回。普通失败与限流保留独立可信的账户摘要，遵守重试等待。有效历史请求的 401 或 403 先遮蔽私有资料；401 仅比较清理原选择。记录读取不保存原操作材料，也不触发更正、登录或退出。

字节接口按所属媒体类型处理成功正文。程序化请求签名图片时，成功交付图片字节，失败解析并验证 JSON 错误，不把错误正文当作图片。浏览器原生图片元素不要求添加 Operation-Id，也无法从加载失败事件读取状态码或 JSON 原因。此时显示“图片暂时无法加载”及占位，不据此认定链接已过期、会话已退出或写入失败。重新取得链接及重试上限仍按[头像链接](../identity/avatar.md#链接与缓存)等所属资源契约，不形成无限刷新。HEAD 没有正文，客户端不得要求从中取得 JSON 错误。

## 用户提示

本人员工服务页先确认当前账户，再读取同一会话选择下的最近一份 Grant。只将可信 `grant_absent` 显示为“员工服务未开通”；成功响应的 active、suspended、terminated 分别显示“员工服务已开通”“员工服务已暂停”“员工服务已结束”。页面只保留状态，不展示固定办理人、业务标识或顺序。Grant 中的旧实名版本合法，不要求等于当前实名版本。

服务状态只存在于当前可见页内存，沿用本人记录的身份绑定、离页遮蔽、迟到响应与限流等待规则。普通读取失败保留独立可信的账户摘要；401 或 403 遮蔽受限内容。读取不保存写入恢复材料，也不触发加入、暂停或结束办理。

员工服务的 active 态独立读取[本人当前工号](../workforce/numbers.md#http-入口)。页面按工号所有者的细分类、年份与顺序号规则校验，再显示工号文本与准确细分类名称。历史年份不按今天重判。只展示当前投影，不显示版本标识或补造办理日期。可信的 `null` 只说明当前没有工号，不猜测从未取得或撤销原因。

工号只存在于可见页内存，同时绑定可信本人检查与当次 active 服务读取。服务重新检查、身份或选择修订变化、隐藏及离页先清除工号。旧响应即使迟到或忽略取消，也不能重新显示。工号独立刷新，普通失败和限流保留分别可信的账户与服务状态，遵守 `Retry-After`；401 仅比较清除原选择，403 保留选择并遮蔽受限内容。active 只是本页的展示门槛，不改变后端本人读取资格或退出后保留工号的规则。

页面按已验证的用例结果生成提示。标题、字段、按钮、状态、空态及打印内容使用所属业务名称；工号和员工服务状态的展示见[页面](pages.md)。提示说明已经确认的情况，并给出当前允许的下一步。不直接显示应用码、内部类型名、数据库错误、供应商原文或 OpenAPI 描述，也不以 UUID 或版本号代替业务说明。

输入不符合要求时，提示“请检查填写内容”，并在能够确定的字段旁说明要求。缺少办理权限时提示“你无权进行此操作”；目标不存在或不可访问时提示“无法查看这项内容”，不猜测隐藏原因。资源预算受限的 `rate_limited` 提示“暂时无法处理，请稍后再试”，等待仍遵守 `Retry-After`。该结果不单独证明用户操作频繁，也可能是共享处理名额已满。当前会话无效按[网站会话](../identity/website.md)或[小程序会话](session.md)进入重新登录；写入结局未知按[失败处理](recovery.md)进入适用的状态刷新或原结果核对，不提示用户直接重发。

只有可信的成功响应确实返回空集合，才显示“暂无申请”“暂无更正记录”等对应空态。加载失败不显示为空列表。读取原结果成功不等于原办理成功；页面继续解释具名结果中的完成、拒绝或进度。确定拒绝只显示所属契约允许公开的原因，不从一个通用错误推断账户暂停、人员不存在或邀请码失效原因。

## 验收

构建验证覆盖真实导出文档中的本地引用、组合、格式、注解、`null` 与缺失字段；不支持的约束必须使构建失败。运行验证覆盖正确响应、缺失必填字段、错误媒体类型、未知应用码及状态与码冲突。另验证无请求标识回显时的原调用关联和迟到响应。分别验证程序化图片请求的成功字节与 JSON 错误、原生图片加载失败和 HEAD 无正文。网站与小程序分别验证传输适配。逐项检查用户提示及可用动作与已确认事实一致，空态与读取失败分开，原拒绝不显示为办理成功；写入响应不可信时按所属业务刷新状态或核对原操作，不得自动重做。
