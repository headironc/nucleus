# 客户端协议目标设计

状态：目标设计，尚未实施。本文规定网站与小程序如何消费业务 HTTP 契约、校验响应及适配各自传输。服务端路由、请求和响应的权威来源是 [HTTP 入口与响应](../http/api.md)及所属用例；原写入的保存和结果判断见[客户端原操作恢复](recovery.md)。

## 同一份接口描述

两端从 nucleus 实际导出的 OpenAPI 3.1 文档构建共享的 TypeScript 请求和响应类型，以及运行时响应校验函数。构建输入是一份已固定的本地文档；构建和启动客户端不依赖生产 API。生成物不手工维护，不另写一份必填字段或应用码清单。服务端尚未装配的入口不能凭客户端类型宣称可用。

类型检查只约束客户端源码，收到的网络字节仍须独立校验。构建过程解析本地引用，按所用 OpenAPI 与 JSON Schema 语义处理注解、组合、缺失字段和 `null`；无法支持的校验关键字或格式使构建失败，不能静默丢弃约束。校验代码在构建时生成，运行时不使用 `eval` 或 `Function` 编译 schema。生成工具、实际 Rust 导出文档和构建器的组合须用真实接口样本验证，不能从工具宣称支持 OpenAPI 3.1 推定组合可用。

共享模块分别构建成网站可用的模块和小程序包内的代码与类型声明。小程序运行时只加载随包交付的文件，不引用项目根目录之外的源码。两端由同一份协议实现生成产物，不手工复制实现。

## 请求与传输

共享协议层根据 method、路径和用例输入组装请求，不持有 DOM、`wx` 或业务事实。Operation-Id 的生成和写入重试规则由[客户端原操作恢复](recovery.md)拥有；服务端对请求头的校验由 [HTTP 入口](../http/api.md)拥有。

网站传输按[网站持久会话](../identity/website.md)携带当前浏览器选择，并按[当前身份](../identity/current.md)解释会话失效。小程序传输使用 `wx.request` 和 Bearer 会话，明确适配请求取消、HTTP 状态、响应头及 `ArrayBuffer`。传输取消只中止本地等待；涉及写入时，页面仍按原操作恢复规则判断结局。两端共享响应判断，平台接口和存储由各端适配。

## 响应可信性

解析成功不等于响应可信。客户端先按实际 method、路径、HTTP 状态和媒体类型选择契约。再验证正文结构、必填字段、合法结果分支及 JSON 错误封装。响应不回显请求标识；客户端用本次调用持有的原操作、目标及会话选择修订关联响应，迟到响应不能覆盖后来选择。原结果中的业务 ID 仍按所属契约验证。豁免入口不增加另一种请求标识传递方式。未知应用码及状态与应用码矛盾时，不从提示文字推断业务结论。响应验证失败的写入继续保留原操作定位，由[客户端原操作恢复](recovery.md)处理待核对状态；普通读取显示协议错误并允许用户明确刷新。

字节接口按所属媒体类型处理成功正文。程序化请求签名图片时，成功交付图片字节，失败解析并验证 JSON 错误，不把错误正文当作图片。浏览器原生图片元素不要求添加 Operation-Id，也无法从加载失败事件读取状态码或 JSON 原因。此时显示受控失败或占位，不据此认定链接已过期、会话已退出或写入失败。重新取得链接及重试上限仍按[头像链接](../identity/avatar.md#链接与缓存)等所属资源契约，不形成无限刷新。HEAD 没有正文，客户端不得要求从中取得 JSON 错误。

## 验收

构建验证覆盖真实导出文档中的本地引用、组合、格式、注解、`null` 与缺失字段；不支持的约束必须使构建失败。运行验证覆盖正确响应、缺失必填字段、错误媒体类型、未知应用码及状态与码冲突。另验证无请求标识回显时的原调用关联和迟到响应。分别验证程序化图片请求的成功字节与 JSON 错误、原生图片加载失败和 HEAD 无正文。网站与小程序分别验证传输适配；写入不可信时须保持原操作待核对，不得自动换标识重做。
