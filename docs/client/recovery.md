# 客户端原操作恢复目标设计

状态：目标设计，尚未实施。本文规定网站与小程序在写入响应丢失、断连和结果未知时保存原操作并继续核对的行为。服务端原事实、证明、结果期限与业务拒绝由各用例拥有；共同响应码见 [HTTP 入口](../http/api.md)。网站会话选择见[网站持久会话](../identity/website.md)。

## 页面状态与原操作

页面区分编辑、提交中、待核对、已完成和已拒绝。网络断连、超时、`outcome_unknown` 或无法信任的写入响应进入待核对。只有所属协议返回确定结论，页面才显示完成或拒绝；请求取消只结束本地等待，不证明服务端回滚。

首次发送前固定 Operation-Id、目标、原修订、确认内容及用例要求的最小恢复材料。客户端先确认材料已保存，再发送依赖这些材料的写入。用户改变目标或内容时开始新办理，保留旧操作的待核对定位；新输入不得覆盖原证明。在所属恢复期内，一个原操作重试使用原标识、原规范输入和原证明，不因页面重开重新交换微信 code、发送短信或执行其他外部动作。短期服务端记录清理后，同一 UUID 可能进入新办理判断；客户端不把旧请求无限重试。

## 标识生成

客户端按[项目标识](../identifiers.md)生成随机 UUIDv4 Operation-Id，使用平台提供的安全随机源。取随机值失败时停止发起，不回退到可预测的伪随机数。标识生成不依赖设备时间、HTTP `Date` 头或客户端校时。

请求层不自动重试写入、短信发送或微信 code 交换。断连、未知响应和普通 `503` 都不授权换键重发；继续核对原操作使用已保存的原标识与材料。结果判别依赖应用码，不解析提示文字。

## C1 证明与 widget 恢复

网站 widget 实例与候选 token 的管理见 [Turnstile 生命周期](../platform/turnstile.md#网站-widget-与-token-生命周期)。首次 C1 提交后，原 token 同时是原办理的恢复证明。供应商验证有效期结束，不等于服务端原结果的恢复期结束。在所属恢复期内，原请求仍携带原标识、原规范输入和原 token，由服务端先核对已有事实。widget 重置、页面重进和新 token 回调不得替换这份材料。

原 C1 处于提交中或待核对时，恢复动作不重新挑战、不换键，也不要求 widget 再次成功。`progress`、网络失败、请求取消、普通 `503` 和 `outcome_unknown` 均不触发新发码。原 token 或其他恢复材料缺失时，停止自动恢复并说明原结果无法核对，不推断短信未发送。

可信的 `verification_invalid` 或 `verification_required` 结束相应原操作的自动办理。用户明确再次发码时，以新操作标识和新 `cData` 取得新 token，再保存新材料并提交。已知 `message` 结果按短信进度展示，不因 widget 已过期而再次发码。用户改变手机号或用途时，沿用本页的新办理规则，独立保留旧操作的待核对定位。

## 恢复材料

恢复记录按用例区分，只保存该用例取回原结果所需的证明、输入和截止，不持久保存任意请求正文。网站用 `sessionStorage` 保存短期原操作材料；小程序用原生私有 storage。网站微信授权的原证明只留在发起它的标签页。客户端按账户身份隔离记录；切换账户后不展示或使用另一账户的受限记录。

| 用例                                | 客户端保留的定位与证明                                                               | 恢复入口                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 短信发码、认证与正式注册            | 各阶段原 Operation-Id、原输入和证明及短期截止；R2 的姓名与身份证号仅在原恢复期内保留 | 按[匿名身份办理 HTTP](../http/identity.md)向所属原 POST 重提原输入，服务端先匹配原结果     |
| 网站微信授权                        | 原标识、secret、授权 ID、期限及发起时的登录尝试或本人会话选择                        | 按[微信身份](../identity/wechat.md)读取原授权结果，不发起第二次 code 交换                  |
| 绑定与解绑                          | 原动作、证明、修订、目标与期限                                                       | 按[微信身份](../identity/wechat.md)的独立结果入口读取；原本人会话失效时不访问本人资料      |
| 会话退出、头像更换                  | 所属用例规定的最小证明与定位                                                         | 按[会话撤销与退出](../identity/revocation.md)或[账户头像](../identity/avatar.md)读取原结果 |
| Access、Workforce、Badge 与中心档案 | 原操作者、目标、操作定位及适用确认引用；政治面貌值不存入恢复记录                     | 有权身份读取所属原完成；当前资料另行鉴权读取                                               |

匿名认证与注册材料在首次发送前保存。客户端的本地秘密保留上限为创建后 30 分钟；服务端给出更早截止时收窄。取得确定结果或下一阶段材料已保存后，移除上一阶段的秘密。取得会话后清除发码、认证和注册的原凭据及实名输入。未完成的实名输入不得进入表单自动保存、分析事件或普通日志。本地材料到期只表示客户端不能继续证明原结果，不能推断原业务失败。

退出时清除普通会话及受限页面资料；仍可合法读取原最小结果的证明按所属期限保留。需要当前操作者的记录须待同一账户重新登录并鉴权。材料缺失或恢复期结束时，页面说明原结果无法继续取回；用户可按当前权限另查业务事实。新业务动作须重新确认，客户端不得猜测旧操作未执行而自动换键重办。

## 读取与响应处理

待核对状态只调用所属协议允许的原结果入口。轮询使用有界退避并遵守 `Retry-After`；离页或进入后台停止，返回后凭原定位继续。确定拒绝、证明失效、恢复到期或失权结束本次自动读取。普通当前资料和原完成分别鉴权；一份旧完成不代表当前状态或当前权限。

恢复请求中的 `authentication_invalid` 只说明本次原证明不成立；`request_mismatch` 不改变已保存的原输入。`result_unavailable` 不证明原命令失败。原会话无法交接的 `verification_required` 结束该次自动恢复，并提供重新认证入口；不能清除后来选定的另一有效会话。已知业务拒绝按所属应用码显示；[客户端协议](protocol.md)判为不可信的写入响应保持待核对，不自动重做业务。各码的服务端条件仍以 [HTTP 入口](../http/api.md)和所属用例为准。

## 验收

用真实客户端和可控响应顺序验证：首次发送前保存失败、响应丢失、迟到成功、同键异输入、页面重进、切换账户、恢复材料过期与服务端晚提交。验收覆盖无 `Date` 和设备时钟偏差不影响标识生成，以及断连不换键重发。旧操作的结果不能覆盖新目标、新账户或新会话；本地过期不能触发猜测性重做。检查秘密未进入日志、分析事件、自动表单存储或其他账户的页面。网站多标签页选择另按[网站持久会话](../identity/website.md)验证。
