# 客户端失败处理与原操作恢复

本文区分普通工牌的状态刷新与现有认证的原操作恢复。交付状态见[能力状态](../README.md#能力状态)。服务端原事实、证明、结果期限与业务拒绝由各用例拥有；共同响应码见 [HTTP 入口](../http/api.md)。网站会话选择见[网站持久会话](../identity/website.md)，小程序本地隔离见[小程序会话](session.md)。

## 普通业务状态刷新

新增工牌请求断连、超时或响应不可信时，提示“未能确认，请刷新查看”，提供申请列表或详情刷新入口。不持久保存原请求材料，不自动重交申请、审批、生成或发放，不以请求 ID 推导去重。

刷新只说明当前状态，不证明某次请求的精确结局。申请允许重复，误申请可取消；审批和发放由状态条件保护。approved 且没有成品时允许人工生成或重试，不建立后台恢复。失权或账户切换时隐藏受限资料。

以下原操作章节仅适用于短信、已接入的手机号登录注册，以及尚未迁移且明确提供原结果合同的消费者。其他微信扩展设计不成为新工牌要求。

## 页面状态与原操作

页面区分编辑、提交中、待核对、已完成和已拒绝。网络断连、超时、`outcome_unknown` 或无法信任的写入响应进入待核对。只有所属协议返回确定结论，页面才按具体办理显示完成或拒绝；请求取消只结束本地等待，不证明服务端回滚。可见提示与动作按[用户可见文案](pages.md#用户可见文案)表达，不把内部状态名称直接作为用户提示。

首次发送前固定 Operation-Id、目标、原修订、确认内容及用例要求的最小恢复材料。客户端先确认材料已保存，再发送依赖这些材料的写入。用户改变目标或内容时开始新办理，保留旧操作的待核对定位；新输入不得覆盖原证明。在所属恢复期内，一个原操作重试使用原标识、原规范输入和原证明，不因页面重开重新交换微信 code、发送短信或执行其他外部动作。短期服务端记录清理后，同一 UUID 可能进入新办理判断；客户端不把旧请求无限重试。

## 本人首次工号恢复

首次领取沿用[工号原结果合同](../workforce/numbers.md#存储与原结果)，不迁入普通工牌的状态刷新。首次发送前，将原 Operation-Id、账户、人员与完整 `{subtype}` 输入保存并回读；本标签页历史另保存原操作标记。材料不含姓名、证件号或会话秘密。

刷新、页面重进和重新登录只恢复显示。本人明确查看结果时，系统先检查当前可信账户与人员，再以同一原操作和原输入重放 POST。新会话可核对同一账户的原领取；资格后来暂停不抹去原成功。另一账户不显示原类别、工号或继续提交入口。会话失效仅比较清除发起请求时的原选择，保留后来的选择。

断连、取消、服务失败和限流保留原材料及等待截止。每次继续至少等待 5 秒，并保留更长的 `Retry-After`。响应不可信时停止本页写入，要求重新加载；原输入不一致时永久关闭该原操作的继续入口。材料缺失或损坏时，历史标记保持关闭，不能据此开始新申请。当前工号读取只说明当前值，不证明原请求的结果。

原成功保存完整固定工号版本。保存失败时保留本页已确认结果，不用旧待确认材料覆盖。只有确定的号码池耗尽允许本人明确重新选择类别；清除原拒绝材料及历史标记并回读后，重新核对当前资格和工号。成功、已有或曾有分配、输入不一致及未知结果均不开放重新领取。

## 标识生成

客户端按[项目标识](../identifiers.md)生成随机 UUIDv4 Operation-Id，使用平台提供的安全随机源。取随机值失败时停止发起，不回退到可预测的伪随机数。标识生成不依赖设备时间、HTTP `Date` 头或客户端校时。

请求层不自动重试写入、短信发送或微信 code 交换。断连、未知响应和普通 `503` 都不授权换键重发；继续核对原操作使用已保存的原标识与材料。结果判别依赖应用码，不解析提示文字。

## C1 证明与 widget 恢复

网站 widget 实例与候选 token 的管理见 [Turnstile 生命周期](../platform/turnstile.md#网站-widget-与-token-生命周期)。首次 C1 提交后，原 token 同时是原办理的恢复证明。供应商验证有效期结束，不等于服务端原结果的恢复期结束。在所属恢复期内，原请求仍携带原标识、原规范输入和原 token，由服务端先核对已有事实。widget 重置、页面重进和新 token 回调不得替换这份材料。

原 C1 处于提交中或待核对时，恢复动作不重新挑战、不换键，也不要求 widget 再次成功。`progress`、网络失败、请求取消、普通 `503` 和 `outcome_unknown` 均不触发新发码。原 token 或其他恢复材料缺失时，停止自动恢复。页面显示“暂时无法查看本次发送结果”，说明“不表示短信没有发送”，并请用户先查看短信。材料缺失或到期的原因放在次要说明中，不提供自动重新发送动作。

C1 页面在待确认期间锁定原手机号，不提供修改目标入口。继续确认由用户明确触发，刷新和页面重进只恢复显示。每次核对等待最多 35 秒。断连、取消、版本核对失败、服务失败或仍在发送时，下次核对至少等待 5 秒，并遵守更长的 `Retry-After`。退避截止随原材料保存，刷新后继续遵守。页面进入后台或离开时结束本地等待，原材料仍保留。材料到期后，迟到的成功、失败或版本检查结果均不能恢复待确认动作。当前实际接口的 `message.sending` 显示“短信仍在发送”；其他具名短信结果分别解释供应商受理、确认失败与供应商结果未知。`progress` 的目标分支不作为当前响应接纳依据。

已发起且结果未明时，按钮显示“查看发送结果”。暂时受限时显示“重试本次申请”。两者都说明只处理本次申请，不会另外发送短信，仍以原标识和材料请求原 C1。首次明确未受理或安全验证未通过的页面保留重新填写、重新验证动作，不统一改成查看结果。

可信的 `verification_invalid` 或 `verification_required` 结束相应原操作的自动办理。用户明确再次发码时，以新操作标识和新 `cData` 取得新 token，再保存新材料并提交。已知 `message` 结果按短信进度展示，不因 widget 已过期而再次发码。用户改变手机号或用途时，沿用本页的新办理规则，独立保留旧操作的待核对定位。

首次请求收到可信的 `invalid_input` 或 `permission_denied` 时，当前实际入口尚未受理 C1。页面允许用户明确选择“重新填写并验证”，再开始新办理。若此前请求结果未知，恢复时收到这两种拒绝只说明本次核对未被接纳；页面保留原材料至截止，说明先前结果仍无法确认，并停止继续核对和重新发码。刷新不把这类拒绝转换为确定未发送。

材料同时保存是否已尝试 POST，每次 POST 前先保存“已尝试”标志。版本核对中断而尚未发出请求时，刷新后保留这一事实。页面说明“本次申请尚未发出”，按钮显示“继续申请”。缺少标志的旧材料按可能已发送处理；标志保存失败时不发出请求。

## 恢复材料

恢复记录按用例区分，只保存该用例取回原结果所需的证明、输入和截止，不持久保存任意请求正文。网站用 `sessionStorage` 保存短期原操作材料；小程序用原生私有 storage。网站微信授权的原证明只留在发起它的标签页。客户端按账户身份隔离记录；切换账户后不展示或使用另一账户的受限记录。

C1 页面重进时，为读回的办理恢复当前历史条目的非秘密标记。损坏材料清除后保留不含证明的占位记录，刷新仍显示结果无法确认。历史标记无法保存时停止办理，已读到的有效原材料仍保留至截止。

匿名认证与注册材料在首次发送前保存。客户端的本地秘密保留上限为创建后 30 分钟；服务端给出更早截止时收窄。取得确定结果或下一阶段材料已保存后，移除上一阶段的秘密。取得会话后清除发码、认证和注册的原凭据及实名输入。未完成的实名输入不得进入表单自动保存、分析事件或普通日志。本地材料到期只表示客户端不能继续证明原结果，不能推断原业务失败。

机构入口准入沿永久原完成合同，未确定材料不套用认证秘密的短期截止；确定完成或拒绝后清除原输入。`request_mismatch` 保留停止核对状态，刷新或同账户重新登录不解除。会话失效及失权只停止本次核对，原材料仍由原操作者恢复合法身份后使用，不展示给另一账户。

C1 离开办理页后仍按原截止清理秘密。首页及其他网站页面在加载和恢复执行时检查材料，并在页面运行期间继续检查。浏览器暂停期间无法执行物理清理；恢复后先检查截止，再允许使用证明。设备时钟回拨至材料创建之前时，也停止使用并关闭材料。到期或损坏材料清理后保留非秘密占位，返回或刷新不会自动开始新申请。已知结果与其他办理材料保持原样。存储暂时不可用时停止使用到期证明，后续检查继续尝试清理；失败不代表秘密已经删除。清理不请求原结果，也不重新发送短信。

退出时清除普通会话及受限页面资料；仍可合法读取原最小结果的证明按所属期限保留。需要当前操作者的记录须待同一账户重新登录并鉴权。材料缺失或恢复期结束不改变已知结果。结果仍未知时，说明当前业务结果无法确认，并提供实际可用的下一步。不以“核实办理情况”代替入口。网站登录显示“登录状态待确认”。说明为“请先检查当前登录状态，暂时不用再次获取验证码”。注册显示“暂时无法确认注册结果”。说明为“请先检查当前登录状态，暂时不要再次提交注册”。主动作均为“检查登录状态”，另可返回公开首页。页面只提供当前有权使用的记录或资料入口，不默认附上重新提交动作。当前资料不能证明此前操作的结果。不能判断所属业务时使用办理结果，不编造过期原因。新业务动作须重新确认，客户端不得猜测旧操作未执行而自动换键重办。

检查登录状态时，不预先假定已登录。页面独立读取浏览器当前选择，再按[当前本人读取](../identity/current.md)核对当前登录。检查后区分可信当前账户、需登录和检查未完成。没有可信选择时明确提供手机号登录。本地选择或当前资料发生普通技术读取失败时，恢复操作仅提供重新检查，不自动重新登录。返回公开首页不属于恢复操作，不受此限制。已确认浏览器选择存储不可用或记录损坏时，遮蔽资料，提供重新检查与显式手机号登录。当前读取的 401 仅说明该次选择已不可用，提供手机号登录。403 隐藏资料并可返回首页。受限时等待后重新检查。成功只展示当前登录的账户，不代表此前登录或注册完成。后来选中的账户不能视作原注册创建的账户。已知账户创建事实仍保留，未提交资料仍按原表单规则处理。

本片独立登录状态检查预览在没有可信选择、当前登录失效或已确认选择存储不可用、损坏时，以原生链接在新标签页打开手机号登录起点。存储不可用时保留重新检查为主操作，登录为次操作。新页须由用户填写手机号并验证，不清理原页材料，也不改变原办理的未知事实；不以此预览实现生产会话存储或跨标签页协调。

## 读取与响应处理

### 小程序手机号与正式注册

手机号授权 code 只来自用户主动授权事件。新 code 使用新 Operation-Id。首次发送前保存完整 code、secret、原标识及截止，恢复只重提原材料。每次首次或恢复 POST 前，都持久保存可能已尝试的事实和保守退避。退避覆盖本次有界等待及其后至少 5 秒；取得可信响应后再按结果和 `Retry-After` 调整。进程中断或本地等待取消后按未知处理，不因页面重开认定尚未发送。取消保存失败时继续保留原材料，不用旧记录撤回已经建立的保守未知状态。技术失败、不可信响应及 `outcome_unknown` 都保留原材料，等待后由用户明确核对。退避遵守至少 5 秒及更长的 `Retry-After`，到时只开放动作，不自动请求。

首次取得可信的 `authentication_invalid`、`permission_denied` 或 `invalid_input`，且此前没有未知尝试时，结束相应输入流程。手机号可由用户明确重新授权，新 code 使用新标识。此前已未知后，再取得这些拒绝只说明本次核对未获接纳，不证明原登录或注册未成立。此时保留原材料至截止并停止原恢复。页面提供独立检查当前登录或返回公开首页，不自动换键重办。`request_mismatch` 同样保留原输入并停止恢复。只说明允许公开的拒绝，不由这些码推断账户暂停或不存在。

R2 使用独立标识，固定原凭据 ID、token、规范姓名及身份证号。尚未提交的填表受待注册凭据截止约束；已发出 R2 的原成功恢复使用自己的 10 分钟窗口，不因原凭据填表截止先到而丢弃材料。`mobile_taken`、`id_number_taken` 按注册原结果解释；明确手机号占用时提供可到达的重新验证入口。取得会话后清除认证、注册证明与实名输入，当前本人读取另行验证。

两种退出先保存原账户、发起会话、范围及标识，再发无正文 DELETE。401 不构成原退出证明；后来同账户会话只发 GET 查询原撤销结果，并核对原范围及发起会话，不重放旧 DELETE。待确认定位按账户独立保存，不阻止另一账户退出。恢复截止结束清理旧定位并保留非秘密未知标记，不宣布退出失败；仍有有效会话时提供当前登录检查，不能伪装成匿名起点。

### 共同响应处理

原结果核对只调用所属协议允许的原结果入口。轮询使用有界退避并遵守 `Retry-After`；离页或进入后台停止，返回后凭原定位继续。确定拒绝、证明失效、恢复到期或失权结束本次自动读取。独立检查当前登录不重提原业务。普通当前资料和原完成分别鉴权。一份旧完成不代表当前状态或当前权限。当前本人读取也不证明历史办理完成。

恢复请求中的 `authentication_invalid` 只说明本次原证明不成立；`request_mismatch` 不改变已保存的原输入。C1 收到后保留原材料至截止，显示资料不一致并停止继续核对，页面重进也不开始新办理。`result_unavailable` 不证明原命令失败。原会话无法交接的 `verification_required` 结束该次自动恢复，并提供重新认证入口；不能清除后来选定的另一有效会话。已知业务拒绝按所属应用码显示；[客户端协议](protocol.md)判为不可信的写入响应保持待核对，不自动重做业务。各码的服务端条件仍以 [HTTP 入口](../http/api.md)和所属用例为准。

本片 R2 页面收到 `authentication_invalid` 或 `request_mismatch` 时，保留原材料至原期限，停止提供该原请求恢复入口，并提供独立登录状态检查。这是页面的消费者选择，不改变所属协议的原结果规则，也不表示协议一概禁止所有手动恢复。当前账户读取不证明原注册完成。

## 验收

普通工牌验证响应丢失后只刷新状态、没有自动重做、同类型多份申请可查看、人工重试与权限遮蔽。以下原材料场景只验收仍使用原操作协议的消费者。

用真实客户端和可控响应顺序验证：首次发送前保存失败、响应丢失、迟到成功、同键异输入、页面重进、切换账户、恢复材料过期与服务端晚提交。验收覆盖无 `Date` 和设备时钟偏差不影响标识生成，以及断连不换键重发。旧操作的结果不能覆盖新目标、新账户或新会话；本地过期不能触发猜测性重做。检查秘密未进入日志、分析事件、自动表单存储或其他账户的页面。网站多标签页选择另按[网站持久会话](../identity/website.md)验证。
