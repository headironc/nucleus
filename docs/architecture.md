# Nucleus 架构

本文拥有简化后的目标架构、事务、失败处理、安全边界和审计。Nucleus 面向约 1500 名内部人员，使用单实例、单进程、Rust、PostgreSQL 和本地文件。复杂度按故障代价选择，工牌办理接受人工补救。

目标设计不等于已交付行为。[能力状态](README.md#能力状态)仍按代码记录。标为“迁移前”的机制只约束仍依赖它的现有消费者，不要求新增功能接入或继续扩展。简化时同步调整调用链、数据库保护、测试与公开契约，不能只跳过核验。

## 业务范围与事实所有权

当前方向是内部身份、权限、工号与工牌。公开网站内容管理、小程序和 Schedule 暂不实施。已有网站首页和登录继续使用。备份属于真实业务上线前的必要工作，见[备份与恢复](operations/backup.md)。

| 模块            | 负责的业务                                           |
| --------------- | ---------------------------------------------------- |
| Identity        | 人员资料、短信认证、账户、会话及账户生命周期         |
| Access          | 角色、权限、作用范围、参与资格和邀请                 |
| Center          | 已有政治面貌资料                                     |
| Workforce       | 工号、目录、工牌申请、成品与发放                     |
| Platform 与入口 | 数据库连接、密码工具、文件操作、HTTP、配置和进程运行 |

这些是同一程序内的模块，不是服务边界。用例可直接调用其他模块，也可在同一事务联表查询。复用相同值规则，不为跨模块调用增加防腐层或逐层 DTO。

Person 保留稳定人员 ID，Account 表达登录身份。注销保留必要历史，同号码重新注册不自动继承旧人的权限与申请。工号不随注销自动释放。账户可登录、人员可参与和管理者可办理分别判断。

角色决定能执行的动作，作用范围决定可操作的对象。取消机构与 Workforce 两套数字等级。首版范围为本人和全单位；科室分管须先有可信人员归属，不能从自选打印科室推导。权限迁移由[角色设计](access/roles.md#简化目标)拥有。

申请保存提交时内容；当前资料变化只影响新申请和管理页面的差异提示。工牌是展示物，不是门禁凭证。不逐张登记失效、收回、销毁或打印次数。已有历史与引用文件不因简化设计自动删除。

## 复杂机制取舍

| 机制                                | 目标   | 原因与放弃的保证                         |
| ----------------------------------- | ------ | ---------------------------------------- |
| 短信去重、限频和验证码安全          | 保留   | 有外部费用和认证风险，同请求不能重复发送 |
| 注册事务、数据库约束和状态条件      | 保留   | 低成本保护共同结果和一次审批             |
| 快照、访问控制和安全日志            | 保留   | 防止牌面漂移与敏感资料泄露               |
| 普通写入完成证明与独立恢复          | 删除   | 刷新看状态，放弃原请求精确结果重放       |
| 工作登记、全局锁序和执行围栏        | 简化   | 普通请求与短事务，接受偶然重复计算       |
| 封印、锚定和全量历史扫描            | 删除   | 权限、审计与备份；放弃篡改及部分回退检测 |
| 两套角色等级                        | 简化   | 角色加作用范围，不靠等级判断对象         |
| 实名与工号历史版本链                | 简化   | 当前值加审计；工牌直接保存当时内容       |
| Submission、Render、Delivery 事实链 | 删除   | 申请与成品记录足以表达审批和发放         |
| 自动分类、增办来源及固定 Layout     | 删除   | 类型字段与本次快照，不承诺来源追溯       |
| 模板编辑器、通用文件工作流          | 暂不做 | 固定模板、私有文件与人工重试             |
| 统一审计、每日完整备份              | 增加   | 用简单方式支持追溯和人工恢复             |
| 公开内容管理、小程序                | 暂缓   | 先完成内部流程                           |

## 用例与事务边界

用例直接负责授权、短事务和结果处理。共同成功或失败的事实使用同一数据库事务，不按模块分别提交。外部网络、文件生成和人工等待放在事务外。

| 动作             | 同一事务内的结果                                   |
| ---------------- | -------------------------------------------------- |
| 注册             | 人员、账户、默认指派，以及必要的凭据消费与会话结果 |
| 邀请接纳         | 使用限制更新、参与资格与默认指派                   |
| 暂停、注销、换号 | 账户变化及对应会话失效等必要后果                   |
| 工号变更         | 当前工号与号码池占用变化                           |
| 提交申请         | 固定快照、申请与审计                               |
| 审批             | 状态、审批人与时间、驳回理由及审计                 |
| 保存成品         | 成品记录、申请变为 ready 及审计；文件先写完整      |
| 发放             | 申请变为 issued、发放人与时间及审计                |

### C1 与 R1

短信是付费外部调用，保留请求 ID 去重和限频。发送许可与占用先持久保存，再调用供应商。同一请求结果未知时不自动再发，也不返还额度。重复请求读取已有状态，不能只靠供应商关联 ID 防重。

保留验证码有效期、错误次数、消费规则、会话安全和日志脱敏。现有阶段与原材料合同见[短信认证](identity/authentication.md)。普通业务简化不连带删除短信仍需的协调。短信自身若简化，单独验证实际外呼次数与额度。

### 注册

从有效注册凭据取得已验证手机号。人员、账户和默认指派共同建立，任何必要步骤失败则整笔回滚。手机号及证件占用由唯一约束兜底。权限迁移前沿用机构普通账户指派，迁移后使用新普通角色，不能省略默认指派。

### 注销与晚到结果

保留暂停、注销、换号的账户和会话安全后果。注销不删除审计和历史申请。后续办理重查当前资格；工牌按当前资格拒绝后续动作，必要时由管理者取消，不建立跨模块后台恢复。

## 并发协调

### 锁与决定性读取

普通业务使用唯一约束、外键、行内 CHECK 和状态条件更新。审批以 WHERE status = 'submitted' 限定一次决定。影响行数为零时查询当前状态或报告冲突，不宣称本次成功。

不增加全局锁序、原操作锁、执行围栏或分布式锁。数据库正常事务及 UPDATE 自身取得的行锁继续存在。共同后果一起提交，短信防重与限频保留实际需要的协调。旧锁函数随消费者迁出，不直接删除仍被触发器依赖的函数。

### 进程内工作与容量

普通请求直接执行，不统一移交独立工作登记，不承诺断开后完成。保留连接池、超时、请求体及图像大小等资源上限，不建设许可跟随业务工作寿命的框架。

工牌生成中断后人工重试，不建队列或自动接管。图像库若在取消等待后仍执行，按真实行为管理资源；取消等待不代表计算已终止，也不因此增加业务状态机。

## 原操作与恢复

### 原操作识别与保留

普通业务不要求规范输入证明、完成记录和永久原结果重放。请求 ID 可用于诊断，不自动具有去重语义。允许同人同类型有多份进行中申请，误申请通过审批或取消处理。

短信请求 ID 仍承担持久去重。既有认证和其他公开 API 的原操作合同在实际迁移前继续有效，不能只修改客户端便假设服务端已改变。

### 未知提交

普通写入未收到提交确认时，返回“未能确认，请刷新查看”。不通过独立连接取得原锁核对，不自动重复写入。刷新使用正常有权查询，显示当前业务状态，不证明某次请求的精确结局。

连接异常不等于回滚。应用不虚报确定失败，也不将状态未知的连接交回池中使用。正常回滚、连接淘汰和资源释放沿数据库库的约定执行。短信未知结果另按防重规则处理。

### 清理

会话、验证码等沿实际安全保留期清理。新工牌文件默认保留。失败残留在停止相关写入的维护窗口按数据库引用人工清理，不按年龄直接删文件，不建立通用过期记录框架。

## 应用内核

目标是明确用例函数、普通事务和共用安全错误处理。新增工牌不要求 Command、Query、完成模板或封印种类。通用工具只服务真实重复逻辑。

### 内核组成

迁移前 domain::kernel、domain::history、Work 和 Registry 已被账户、会话、角色、目录、Center 等调用。旧消费者继续遵守实际合同，停止把其他能力迁入这套机制。

### 用例执行器

按完整业务消费者迁出旧执行器，查询、写入、HTTP、数据库权限与测试成套调整。最后一个消费者退出后删除无用设施。顺序见[旧机制退出](engineering/delivery.md#架构内核与状态封印)。

### 完成记录

普通新功能使用当前状态与审计，不新增完成表。旧完成表退出时处理客户端与保留义务。审计不是原结果重放数据库。

### 错误模型

区分输入错误、未认证、无权限、状态冲突和技术故障。只按已知 SQLSTATE 与约束身份映射业务冲突。技术错误不伪装成空列表或无申请。

在最终处理处记录一次技术失败，保留安全的操作、阶段和原因。日志不输出手机号、证件号、验证码、会话凭据、原始请求或数据库 detail。安全日志与业务审计分别承担诊断和追溯。

## 文件与数据库后果

本节简化目标用于新增工牌。已交付头像的发布意图、原工作恢复、签名读取及删除协议仍按[头像合同](identity/avatar.md#工作事务与故障恢复)执行，随该消费者整体迁移后再退出。

### 发布与接纳

以服务端唯一标识在私有目录写文件，完成后再保存数据库引用。文件失败不创建成品记录。数据库保存失败允许留下无引用文件；不覆盖既有文件，不立即删除可能已提交的候选。

偶然并行生成允许重复计算。保存成品以申请状态和每申请一个成品的唯一约束兜底。未采用文件在维护时清理，不采用发布意图、Render 代次或自动恢复。

现有头像先确认 SQL 发布意图提交，再创建私人候选；同步文件及目录后才能接纳。发布调用失败不证明没有文件，由原工作按意图核对和恢复。其事务、工作监督及持久写入合同继续有效，不套用工牌的人工重试。

### 删除与读取

文件按当前会话及对象权限读取，私有目录不直接公开。路径由服务端根据资源 ID 生成。照片、背景与字体不可原地覆盖，快照引用的字节继续保留。缺文件明确报错，由管理员从备份恢复，不返回假的成品成功。

现有头像在移除引用及删除意图共同提交后删除文件，未知结果及启动恢复仍检查原意图。读取在资源协调内取得句柄，保留句柄直到读取完成。头像既有签名链接按自身有效期和清理规则处理，不改成工牌会话鉴权。

### 文件换钥

首版工牌不引入逐文件应用加密、换钥意图或签名链接系统，采用私有存储、访问控制和加密备份。已有敏感字段加密继续有效，旧密钥在真实数据不再依赖前保留。

## 类型、构造与查询

保留输入形状、业务值校验、参数化 SQL 和当前权限检查。认证主体与短信许可只能通过对应检查产生；删除封印不允许伪造认证结果。

普通行经字段和关系校验后供用例使用，不要求通用 Verified 类型或历史核验。迁移前受保护类型仍通过原加载器，直到消费者完整迁移。列表直接查询实际投影，不增加跨模块适配层。

## Crate 与模块组织

保留 nucleus、domain、platform、deployment、fixture，分别承担入口、业务、技术工具、部署、测试。简化不以移动目录或合并 crate 为目标。SQL 随实际用例维护，同一规则保留一个实现。

### 根包入口目标

现有入口继续使用，新增路由调用明确业务函数。公开 URL 不由内部目录决定。API 变化与客户端同步交付，实际 OpenAPI 不因设计改变而自动变化。

### 装配、状态与监听

单进程装配数据库、供应商、业务和 HTTP。保留来源校验、可信代理和就绪检查。网站继续独立构建托管，见[网站交付](http/site.md)。

### 业务执行与后台消费者

工牌没有自动渲染或恢复消费者。备份归系统定时任务；现有认证清理等运行任务在各自简化前继续使用，不建立通用任务平台。

## PostgreSQL 组织

### 事实与结构

沿用现有 schema，不把 schema 当服务边界。工牌新增 workforce.applications 与 workforce.badges；全系统共用 audit.events。字段由[申请](workforce/applications.md#数据结构)、[成品](workforce/fulfillment.md#数据结构)及下节审计拥有。

### 类型与约束

使用主键、必要外键、唯一、非空和行内 CHECK。申请数量不加唯一约束；每份申请正式成品唯一。时间使用 timestamptz，ID 沿用[标识规则](identifiers.md)。

### 数据库与 Rust 的职责

数据库兜底结构与状态条件，Rust 用例负责授权和办理规则。不为每种状态重建历史触发器。旧触发器随消费者迁出，运行身份与 DDL 身份分离，保持最小权限。

### 时间与个人顺序

新普通业务使用数据库时间，不增加全局、个人或发放连续序号。审计 ID 只定位记录，不证明严格因果顺序。短信期限与时钟安全按现有认证消费者保留，不向工牌扩展高水位协议。

## 状态、历史与完整性

保存当前状态和必要审计。快照及已保存审批结果不通过普通编辑覆盖。不新增封印、历史版本链、回退检测或通用投影。移除旧引用不自动授权删除历史。

### 状态模型

状态决定允许动作；条件更新、成品唯一约束与共同事务保证流程。历史用于追溯，不重建当前权限。

### 状态对象

账户、会话、角色、参与资格和工号各保留实际需要的状态。不统一增加序号、版本和封印列。工牌状态由[申请专题](workforce/applications.md#阶段审批与结束)拥有。

### 状态历史模块

迁移前 history 继续服务现有消费者，不扩展种类或投影。退出时同步调整受保护 SQL 守卫与夹具，不单独关闭检查。

### 锚定

进程内锚定不是目标要求。旧消费者的待定提交仍依赖它，不能清空锚定绕过原合同。整套依赖退出后删除。

### 威胁模型

保留访问控制、会话安全、参数化查询和日志脱敏。数据库权限减少误改，审计用于追溯，备份用于恢复。

不承诺发现有数据库写权限者对合法数据的篡改、历史删除或部分回退。审计不是防篡改证明。错误数据可能需要人工纠正，数据损失窗口见[备份限制](operations/backup.md#恢复与限制)。

### 核验职责

用例检查授权与输入，数据库约束兜底结构。启动检查配置、数据库、迁移兼容与必要文件，不对新业务全量核验永久历史。已有扫描随消费者退出。

### 事实封印

普通业务不新增 HMAC 事实封印或封印版本。短信证明、会话摘要和敏感字段加密用途不同，继续保留。

### 个人事件索引

不向 identity.events、identity.event_facts 增加工牌来源，也不用另一套对象序号替代。旧来源迁出后移除索引及相关锁，统一审计采用普通事件表。

### 审计

一张 audit.events 记录实际操作者、时间、动作与对象。成功变更和审计同事务提交；事务失败不留假的成功审计。技术失败记安全日志。旧能力按消费者接入，不伪造缺失历史。

| 字段                   | 类型与含义                               |
| ---------------------- | ---------------------------------------- |
| id                     | bigint，主键                             |
| actor_id               | uuid，引用稳定 Person ID，不引用实名版本 |
| occurred_at            | timestamptz，数据库记录时间              |
| action                 | text，明确业务动作                       |
| target_type、target_id | text 与 uuid，目标种类和 ID              |
| details                | jsonb，必要前后状态与安全说明            |

运行身份只可追加和按权限读取审计，不可改删。details 不保存完整请求、手机号、证件号或凭据。审计只对有权管理者开放，不因申请属于本人而开放管理审计。文件动作先完成文件，再与对应成功业务状态共同记录。

## 设置、凭据与部署

沿用[设置](settings.md)和[凭据](platform/credentials.md)的读取及脱敏规则。配置只随实际消费者增加。对应程序版本、配置和解密密钥进入恢复材料，秘密不写仓库。

## 启动、后台与停止

### 实例锁

保持单实例单进程。现有实例锁在迁移前有效，不新增租约、集群协调或渲染围栏。备份停写期间不能另起业务写入进程。

### 启动顺序

读取配置和凭据，检查数据库、迁移兼容及文件目录，装配实际能力后开放请求。旧鉴别与扫描仍由实际消费者决定，文档不表示代码已改变。

### 就绪与观测

保留存活、数据库和必要资源检查。记录技术故障及备份失败，不用永久处理中掩盖人工待办。

### 正常停止

停止接收新请求，按进程管理方式结束服务。新普通业务不承诺独立工作排空。备份先确认写入者停止，再生成数据库和文件副本，见[备份执行](operations/backup.md#执行与保存)。

## HTTP 与客户端恢复

普通业务没有响应时引导刷新列表或详情。工牌不持久保存原请求重放材料，不自动补交申请、审批、生成或发放。按钮防重复点击只改善交互，最终状态由数据库保护。

短信和已实现登录的恢复按[客户端恢复](client/recovery.md)执行。既有 API 的 Operation-Id 与应用码在迁移前保留，新工牌按所属专题实现。

## 隔离验收

使用虚构资料、隔离数据库及供应商替身。不用旧强恢复矩阵要求新工牌重建已取消的机制。

| 范围     | 必需结果                                                           |
| -------- | ------------------------------------------------------------------ |
| 短信认证 | 同请求不重复外呼；限频、验证码期限、计错和会话安全有效             |
| 注册     | 人员、账户、默认指派共同成功或全部回滚                             |
| 授权     | 本人不能读他人资料；权限与范围有效；失权后不能继续办理             |
| 申请     | 同人同类型允许多份；快照不随资料改变；固定资源保留                 |
| 审批     | 条件更新只决定一次；理由、操作者、时间和审计一致                   |
| 生成     | 使用快照；失败中断可人工重试；未完成文件不保存成功；并行结果不覆盖 |
| 发放     | 只有已有成品可发放；重复点击不改写第一次记录                       |
| 失败     | 连接故障不虚报确定失败或成功；刷新显示状态；不自动重做             |
| 数据保障 | 约束有效；日志脱敏；备份恢复后能打开照片和成品                     |

旧消费者按实际合同验收，迁移时替换相应预期。文档修改不证明业务实现、备份或恢复演练已完成。
