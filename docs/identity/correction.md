# 实名更正

本文拥有实名更正的办理资格、永久事实、历史读取及运维更正。写入屏障和未知提交核对见 [架构恢复协议](../architecture.md#原操作与恢复)；姓名与身份证号的规范值沿用[正式注册](registration.md)。

## 用例与不变量

办理人必须有当前正常账户及 `institution.corrections` 权限。管理入口只允许更正他人，办理人的当前机构等级必须严格高于目标。办理资格不依赖双方的 Workforce 状态。目标没有当前账户时不比较等级，具备更正权的管理者可以按人员 ID 更正。目标人员身份不变，也不因此建立账户或转移其他领域事实。

姓名和身份证号都作为完整的新值提交，只变一项也必须提交另一项。姓名去除首尾空白并作 NFC 规范化，限 1 至 64 个 Unicode 标量且无控制字符。身份证号必须为 18 位居民身份证号码。出生日期真实、MOD 11-2 校验位有效，末位小写 `x` 规范为 `X`。更正使用稳定值规则，不因本次办理日期重新判断出生日期。更正后的两项共同生效或共同拒绝。与当前两项均相同的新办理返回 409 `state_conflict`。新身份证号被其他未注销账户占用时返回 409 `id_number_taken`。不要求人工理由或审批。

更正不改变手机号、政治面貌、账户状态、会话、角色、授权及已保存的业务历史。新姓名供工牌管理页与原申请的固定姓名比较并显示差异；更正不自动转换或结束申请，也不改写已经确认的打印内容。只改身份证号不产生新的工牌内容后果。原注册结果仍以注册时实名版本核对和恢复。

## HTTP 入口与目标确认

| 入口                                  | 输入及读取或写入结果                                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/corrections/candidates` | 以正文中的规范手机号精确定位有当前账户的目标；返回完整姓名和身份证号及固定目标。                                                                   |
| `GET /api/v1/corrections/{person_id}` | 按已知人员 ID 定位目标，包括没有当前账户的人员；返回同一候选结构。                                                                                 |
| `POST /api/v1/corrections`            | 正文必填 `target: { personId, revisionId }`、`name`、`idNumber`，另携客户端 Operation-Id；新成功返回 201 及更正 ID、生效时刻，原成功重放返回 200。 |

两个候选入口先验证当前会话及 `institution.corrections`，再按当前等级及非本人条件过滤。无职责返回 403，目标不存在或不在范围内返回 404。数据库或解密失败不能伪装为 404。候选返回 `{ code, candidate: { target, name, idNumber } }`。`target` 只含 `personId` 和读取时的 `revisionId`，不含账户 ID 或手机号。完整姓名、身份证号和目标版本来自同一读取快照。候选只供人工核实，提交时必须重查权限、目标人员、当前版本和占用。旧版本确认返回 409 `target_changed`，不能覆盖其间发生的更正。

三个入口复用网站会话和 Operation-Id。两个 POST 使用必填准确 Origin、已认证写入预算及 8 KiB 正文上限。GET/HEAD 使用元数据预算和[当前身份的读取同源规则](current.md#凭据选择与来源)。路径直接解析为 Person ID，非法值在认证前返回 400。两种候选都是普通读取，沿[同页快照](../http/lists.md)确认授权与完整资料。响应禁止缓存，不设置 cookie。成功更正返回 `{ code, correction: { id, correctedAt } }`，不重复返回完整实名资料。共同执行名额耗尽时返回 429 `rate_limited`，并携带 `Retry-After`。HTTP 等待最多 30 秒；取消或超时不释放尚未结束的工作。

写入正文与 `target` 都拒绝未知字段。会话认证在正文之前，非法值在权限及原结果判断之前返回 422。合法输入再按[管理判定顺序](../access/http.md)复查当前会话及准确更正权。原操作已有完成时，核对办理人所属人员、目标人员及原版本，再核对新版本的规范姓名和身份证号，全部匹配才返回原完成。当前版本、目标等级或号码占用后来变化，不改写原成功，也不把它当新办理。标识相同而输入不同返回 409 `request_mismatch`。原标识不单独授予已失权办理人读取资格。

## 永久事实与共同事务

每次更正建立新的实名版本及只追加的更正事实，两者共享 ID。更正事实记录目标人员、办理人当时的实名版本、更正时刻、目标人员的历史顺序号及唯一非空原 Operation-Id。在线更正在同一事务写入与更正事实共享原 Operation-Id 的永久个人完成；完成固定办理人人员及其当时的实名版本、目标人员、更正时刻和规范输入，并与更正事实互为唯一来源。每次更正的原版本是该人员上一次更正后的版本；首次更正的原版本是注册或初始化建立的首版。两次更正之间可以有该人员的其他历史事实。原版本、新版本和办理人版本永久保留，注销不删除。

目标有当前账户时，更正事实固定本次核验的机构指派 ID。目标无当前账户时，该引用为空。原结果、历史及启动鉴别固定指派及所选角色变更，以确认运维或在线来源。不按更正时间重新寻找最后指派，也不依赖目标今天的角色或账户。更正推进 Person 状态的对象内顺序，机构指派使用独立的 Holder 顺序。

业务事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、办理人与目标人员、当前账户及新身份证号占用。取得原操作协调后先复查当前认证和基本更正权，再查原完成。新办理才判断目标范围、当前版本和号码占用。新实名版本、更正事实、在线完成与 Person 当前版本共同提交。有当前 Account 时，当前身份证号占用也属于同一办理；只改姓名时保留账户的原身份证号占用，但仍写入更正完成。目标已无当前账户时仍检查新号码占用，但不创建或更新 Account。在线完成永不过期，同一 Operation-Id 不能同时具有在线与系统完成，普通运行身份不能更新或删除。号码唯一性最终裁决当前身份证号占用，其他数据库或解密错误不映射成业务冲突。

已有人员的新实名版本只能由更正建立，Person 当前版本只能随本次更正改变，当前账户的证件号占用只能随相应更正变化。办理者在等待并发角色办理后，仍须具备正常账户、准确更正权及当前等级。更正时刻不得早于 Person 当前状态的变更时刻。永久历史不可修改或普通删除。更正失败不留下孤立版本、变化的当前版本或部分身份资料。

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原更正及其共同提交的实名版本、谱系和完成。后续合法更正可以改变当前版本，回读不要求旧成功仍是当前版本。原结果鉴别必要的前后版本并比较规范输入；这些依据不依赖当前 Account 或注册结果保留。两类完成与永久事实必须一一配对：缺失、错源、双方并存或孤立完成按损坏处理，读取、启动扫描和恢复都拒绝。确认未提交时，本次工作报告依赖失败。客户端以原标识和材料重试，再按当前资格判断能否办理。结局仍未知时返回 `outcome_unknown`。更正是永久结果，不能删除原更正来释放 Operation-Id。

内部恢复保留首次办理时核验的办理人员及本次更正 ID，不因后来会话撤销或更正权丧失而丢失原完成。在线重放比较原办理人所属人员及原目标版本，不要求办理人今天的实名版本，因此办理人后来更名仍返回原完成；新请求仍执行当前身份和权限检查。

## 历史读取

`GET/HEAD /api/v1/accounts/current/corrections` 供本人读取自己的历史。`GET/HEAD /api/v1/persons/{id}/corrections` 按永久人员 ID 提供管理历史。更正办理的原结果不替代列表读取。

两个列表入口使用 `page` 和 `size`；省略时分别为 1 和 20，`page` 从 1 开始，`size` 为 1 至 100，显式无效值返回 400 `invalid_input`。每页在同一快照中核对当前权限、计算 `count` 并读取本页记录；按同一人员实际更正成功顺序倒序，不按 UUID 推断先后。每条含更正 ID、`before`、`after`、`correctedAt`。无记录返回 200、`count: 0` 和空数组；越界页返回 200、原总数和空数组。跨页不保证同一快照。

管理入口要求办理人当前有 `institution.corrections` 且机构等级严格高于对象；目标为本人或等级不低于办理人时按 404 处理，无职责为 403。目标没有当前账户时不比较等级，因此任一具备更正权的管理者均可读取其完整历史。这使“系统管理员”等目标注销后的历史可读范围大于在职时，是本用例的既定规则。曾经经办、持有相同证件号码或注销后再注册都不产生读取权。

管理投影中的前后姓名、身份证号均为完整值，另返回 `operator: { personId, name }`。办理人姓名是更正当时的完整值，来自原事实固定的实名版本。办理人后来更名或失去当前账户不改写历史投影。本人入口只要求当前账户代表该人员，不比较等级。前后姓名完整，身份证号仅为 `idNumber: { suffix }`，不返回办理人。本人没有读取完整历史身份证号的入口。运维更正沿用本人与管理投影。人员不存在或不在管理范围返回 404；依赖失败不能伪装成空列表。响应与错误禁止缓存，日志不记录完整实名资料。

两个入口沿网站元数据预算和读取同源规则。它们复用 Operation-Id、Session-Id 及原会话 cookie。本人入口不接受目标人员或账户参数。管理路径直接解析为 Person ID，非法值在认证前返回 400。认证先于分页参数解析。响应为 `{ code, count, corrections }`，不设置 cookie。分页值、重复及未知参数、偏移溢出沿[共同分页协议](../http/lists.md)拒绝。

管理读取与候选共用目标范围判断，无当前账户时另核对永久人员存在；它不读取目标当前资料，也不以当前版本替代原事实。计数核对完整历史，空页不隐藏已丢失的历史事实。查询、鉴别或可信时间确认失败使整页失败；管理读取另鉴别办理人固定版本，仅披露其姓名和人员标识。

## “系统管理员”的运维更正

在职“系统管理员”的机构等级为 1000，没有等级更高的管理者，HTTP 管理入口对其返回 404。其实名资料由停机命令 `deployment admin correct` 更正，只接受当前机构角色仍为“系统管理员”的目标；操作者可以是目标本人，也不需要自己是系统管理员。它不成为普通人员的备用更正入口。共同停机和未知结局协议见[停机运维协议](../operations/maintenance.md)。

命令为 `deployment admin correct --input FILE --operation UUID [--dry-run]`。输入 JSON 固定为 `operator: { "mobile": "…" }`、`target: { "personId": "…", "revisionId": "…" }`、`name` 和 `idNumber`，各层拒绝未知字段。操作者按唯一手机号定位，并复核当前正常账户。账户暂停、注销或手机号不再精确匹配时，拒绝新办理。目标须有当前账户，当前实名版本与确认版本相同，当前机构角色为系统管理员。目标账户暂停本身不取消其角色资格。动作沿用稳定值规则，检查规范输入、实际变化和当前号码占用。

命令使用运行身份、真实网站 AppId、完整启动核验、实例锁和共同栅栏，并复用在线应用执行器。业务事务先取运行屏障和原操作锁。系统更正与在线更正对同一 Operation-Id 串行。锁后重新读取操作者、目标、当前实名与机构角色，并取得决定性的可信时间。新实名版本、更正事实、Person 当前版本、适用的 Account 号码投影及系统完成共同提交。只改姓名时不更新 Account 投影。系统完成永不过期，普通运行身份不能删除它。

原操作已有系统完成时，执行器核对其固定的人员、目标、Operation-Id、办理人实名版本、时刻及规范输入。完整匹配才返回原结果，不重新要求当前操作者或目标角色有效。操作者后来改名、换手机号、失去账户或注销，以及目标后来换角或注销，都不改写原成功。保留系统更正却缺失完成时，按损坏处理。原操作已有完整且来源有效的在线更正时，返回 `request_mismatch`；保留来源损坏时仍按损坏处理。没有原更正事实时，才判断新办理资格。其他业务族使用相同 UUID 不占用本更正的原操作。

每次系统更正永久固定本次核验的机构指派 ID，该指派所选的固定角色变更必须为系统管理员。原结果与两类历史按固定指派及其角色变更确认系统来源，不依赖目标今天的角色或账户。缺少同一事务系统完成的系统更正不能成立；普通人员的本人更正不能借系统来源成立。普通在线更正继续要求非本人、准确权限及严格等级；管理员注销后的在线更正沿无账户规则办理。

运维更正不改变手机号、政治面貌、会话、角色、授权或已确认工牌内容。`--dry-run` 在相同锁与判断后回滚，保留零业务写入；命中原完成时报告 `completed`。未知提交、原输入重试及输出失败由[停机运维协议](../operations/maintenance.md)规定。

## 验收边界

网站办理验收覆盖原操作并发重试、输入不匹配、权限及目标版本变化，同证件号码竞争（含真实 R2）、只改姓名和无账户人员。新版本、当前版本、当前占用、更正事实与在线完成共同提交，旧注册、会话和业务历史保持原绑定。旧号码被其他账户占用后，只改姓名仍被拒绝；此前的永久原成功仍可核对。在线完成缺失、错目标、错输入、错时刻、封印损坏、错源或与系统完成并存使读取、重放及启动核验失败；办理人后来更名仍可重放原成功，失权或退出后的新请求被拒绝。恢复验收覆盖提交确认丢失、确定回滚、晚提交、回读失败和取消等待；办理人在内部恢复前退出不改变原结果，新请求被拒绝。

完整性负例覆盖孤立版本、孤立更正、单边改变当前版本、无更正来源的证件号占用变化、本人和高等级目标、失去准确权限的更正；撤权先提交时更正拒绝且身份事实不变。持久谱系、实名材料或规范值损坏关闭共同接纳；普通查询失败保留技术错误分类，不能解释为查无记录。同一办理中两次完整更正可以依次成立。

历史读取验证满页、末页、越界页、其他人员的空历史，两次更正间插入其他历史事实，并发更正、暂停、撤权不改变已建立快照，后续请求按新权限判断。管理历史验证完整前后值及当时办理人姓名，办理人后来更名不改写历史；本人、同级、高等级及不存在的目标被拒绝，移除当前账户后保留永久历史，同号新注册不继承旧人员或管理权限。必要版本或办理人材料损坏使整页失败，失败不交付部分页；HTTP 另核对分页拒绝、认证与同源规则、共享限流、GET/HEAD 和方法拒绝。

运维更正验收覆盖初始化管理员自我更正、另一正常操作者更正、非管理员目标、缺失目标、操作者不可用、同值、号码占用、未知或畸形输入及 dry-run 零业务写入；提交回执丢失与确认回滚后用原输入恢复且只保留一次更正。操作者后来改名、换手机号或注销，原结果仍可重放；异输入、异手机号或异值返回 `request_mismatch`。缺少系统完成、固定指派缺失或角色变更错配的运维更正被拒绝。真实注销后的在线更正仍成功，历史保留两种来源；后来换角或注销不改写原系统来源。实例互斥和文件边界复用[共同验收](../operations/maintenance.md#验收)。
