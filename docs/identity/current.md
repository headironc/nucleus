# 当前身份与本人账户读取目标设计

状态：目标设计，尚未实施。本文拥有普通业务入口的会话证明、可信操作者、当前账户资格复查，以及 `GET /accounts/current` 的一致投影。会话创建与原登录结果归各认证入口；逐会话撤销见[会话撤销与退出](revocation.md)，账户暂停见[账户暂停与恢复](suspension.md)，微信关联依赖见[微信身份登录](wechat.md)。

## 身份边界

正式账户固定关联一名人员。登录只证明本次请求可使用该账户，不授予领域参与或管理权限。各业务所有者仍按当前领域授权、角色、目标和动作独立判断。原注册回执、待注册凭据、登录结果交接和已清理的协议记录均不是长期会话证明。

根 HTTP 对要求登录的普通路由先解析明确选中的会话凭据，并检查适用同源条件。Identity 核对原会话、账户和来源后，才产生本次请求的受控 Actor。Actor 只固定原账户 ID、Session ID 和可信应用来源；不携带 token、实名、领域权限或可跨请求复用的有效状态。客户端不能提交 Actor、账户 ID、应用身份或认证方法来改变操作者。普通业务写入仍在适用对象协调之后，以 Actor 固定的原会话和账户重新读取当前资格。

同一个业务路由通过共同认证中间件支持网站 cookie 和小程序 Bearer。中间件分别读取两种传递方式，再调用同一会话验证能力，不增加两套路由前缀或监听地址。验证成功后将 Actor 放入请求 extensions；下游不重复读取凭据。该设计尚未实施，不能由现有 C1 的匿名 HTTP 验证推定已交付。

## 凭据选择与来源

网站会话以 `Session-Id` 头选定会话 ID，按[项目标识](../identifiers.md)解析 UUID 值，不强制输入规范文本。服务端用该值的小写、带连字符形式定位对应名称的受保护 cookie。同值的不同 UUID 文本选择同一 cookie；不直接拼接原始头值。cookie 保存服务端随机会话 token；ID 本身不构成登录证明。目标 cookie 缺失时不搜索其他有效 cookie，也不选择最近登录。重复目标 cookie 拒绝；其他会话 cookie 与微信授权流程 cookie 不参与本次选择。小程序只以 `Authorization: Bearer` 提供原 token，不携 `Session-Id`。两种证明不能混用，网站 token 不能改用 Bearer 取得同一账户。

`Session-Id` 和 `Authorization` 同时出现时返回 400 `invalid_input`，不设优先级，也不在一种验证失败后尝试另一种。重复、空值、多值或格式错误同样拒绝。两种选择均缺失，或已选网站会话的目标 cookie 缺失时，返回 401 `authentication_invalid`。浏览器附带的其他 cookie 不算第二种选择。匿名入口不会因附带凭据而自动进入当前会话认证；其同源和原证明要求仍由所属路由决定。

会话保存创建时固定的实际 AppID 和认证方法。网站短信、网站微信身份属于网站 cookie 来源；小程序手机号、小程序微信身份属于小程序 Bearer 来源。验证同时核对 token 的 SHA-256 摘要、网站指定的 Session ID、存储来源与本次传递方式。未知 AppID 或非法方法组合是持久事实错误，不能默认采用另一来源；合法来源与本次传递方式不符则拒绝本次认证。启动时核对全部保留会话的固定应用身份及方法，包含过期和已撤销行；矛盾时拒绝开放相关入口，不改写旧来源。短期请求和交接记录合法清理后，仍依据会话自身来源验证有效会话。

网站 cookie 模式的非安全方法要求唯一、准确匹配固定 HTTPS origin 的 `Origin`。GET 没有 `Origin` 时仅接受 `Sec-Fetch-Site: same-origin`；有 `Origin` 时它必须准确匹配，若同时有 `Sec-Fetch-Site`，其值也必须为 `same-origin`。`null`、重复、多值、同站子域和跨来源均拒绝，不用 `Referer`、`Host` 或转发头补足。小程序 Bearer 入口不要求浏览器 `Origin`，但须通过存储来源与传递方式核验；不能把网站 token 放进 Bearer 来绕过同源条件。普通请求的 Operation-Id 不作为会话证明，也不创建读操作的原请求记录；响应关联使用[客户端保存的请求上下文](../client/protocol.md#响应可信性)。

Origin 限制用于阻止浏览器自动携带 cookie 发起跨来源用权，不代替 token 或业务授权。Bearer 由客户端显式放入 Authorization。两种传递均使用[不透明会话 token](session.md#来源与秘密)，不因名称为 Bearer 而改用 JWT。网站 cookie 的 HttpOnly、Secure、SameSite 和范围见[网站持久会话](website.md)。

网站凭据不开放跨 origin CORS。网站使用专属受信主机；同一主机的其他端口也不得承载互不信任的服务，因为 cookie 不按端口隔离。静态资源、签名图片、健康、OpenAPI、微信回调和匿名结果读取各守原入口证明，不因浏览器附带登录 cookie 而取得本人身份。

## 当前会话资格

一次会话验证在同一数据库语句快照内读取原 Session、Account、数据库时间、撤销事实及适用的当前微信关联。须同时满足：原 token 匹配；会话的账户与来源关系有效；尚无 Revocation；数据库时间严格早于原 `expires_at`；账户存在且未暂停。微信身份会话还须引用同账户当前绑定的原修订。手机号会话不依赖微信绑定。解绑后重绑即使身份相同，也不能使旧微信会话复活。

Session 的账户、token 摘要、应用来源和方法建立后不可改。普通写入不得改挂原绑定引用；删除原绑定时，已撤销会话的引用可按合法外键清空。已撤销的微信会话无论保留原引用还是引用已清空，都不能通过当前认证。未撤销的微信会话必须保持原绑定引用，其他方法不应拥有绑定引用。数据库行的存在或解码成功不能单独构造 Actor。

中间件产生 Actor 后，具体用例须按自己的决定性时点复查。本人读取重新验证原会话；写入用例在对象锁后重新检查原会话、账户及适用业务条件。不得换成同账户另一会话、后来浏览器选择或新绑定。原证明通过不冻结期限、撤销、暂停或绑定状态。单笔提交未知不暂停无关办理；当前身份验证与本人资料读取在可靠快照中继续，读取失败不代替原写入结局核对。

## 本人账户投影

`GET /accounts/current` 只读取本次 Actor 固定的本人账户，不接受目标账户参数。决定性语句共同读取并复查 Session、Account、Person、当前实名 Revision、当前头像及其文件元数据、当前微信绑定和数据库时间。必要实名版本必须属于该人员；头像须是同一账户的当前行。SQL 结果区分真实未绑定、失效会话与必要资料损坏，不把任一查询失败填成空绑定或默认资料。

通过当前认证与关系检查后，服务端解密当前姓名和身份证号，只投影完整姓名及身份证号最后四个字符。`idNumber` 为 `{ suffix: string }`，保留前导零，不返回完整号码。响应的 `account` 包含 `id`、`personId`、`revisionId`、`name`、`idNumber`、当前 `avatar` 和必有的 `binding`。真实未绑定时 `binding` 为 `null`；已绑定时仅含当前 `revision`，不输出 UnionID、OpenID 或供应商材料。头像链接在取得完整有权快照后按其所属签名协议生成，不从另一语句拼接旧实名或新头像，也不读取图片正文。

成功返回 HTTP 200、`code: ok` 与完整 `account`，并设置 `no-store`，不回显请求标识。该 GET 不写 Identity 事实、不签发或刷新会话 cookie、不延长期限，也不按 Operation-Id 返回旧资料。重复读取反映各次可靠快照；资料在决定性语句之后变化时，已完成的响应可代表读取时点，后续用权仍复查。客户端仅在原 Session ID 与本地选择修订仍匹配时接纳迟到响应，不能把旧账户资料写入后来选择的账户页面。

## 拒绝与验收

| 情形                                                                                  | HTTP 与 code                 | 边界                                                 |
| ------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------- |
| 头、cookie 或 token 结构错误，重复目标 cookie，证明方式混用                           | 400 `invalid_input`          | 拒绝本次请求，不改会话或回退到其他凭据。             |
| 网站同源条件不成立                                                                    | 403 `permission_denied`      | 不读取本人资料或执行业务。                           |
| 缺少认证选择或目标 cookie、秘密错误、来源不符、到期、撤销、账户不可用、原微信关联失效 | 401 `authentication_invalid` | 不泄露是哪项失败，也不判断此前写入是否成功。         |
| 数据库或可信时钟不可用、存储来源异常、必要关系损坏、解密或头像签名失败                | 503 `dependency_unavailable` | 不返回部分资料，不伪造成退出、正常未绑定或默认头像。 |

网络错误或 503 不证明会话已失效；客户端保留原会话选择，重试时重新核验。普通当前读取不返回 `outcome_unknown`、进度或原写入完成。

验收以可控事务交错覆盖中间件通过后的到期、撤销、暂停、解绑和注销，以及实名、头像、绑定变动前后的整份快照。另须验证两端来源错配、重复 cookie、同源负例和持久来源损坏。短期认证记录清理后，有效会话仍能使用。当前读取不产生业务写入，错误不伪装成空资料，迟到响应不能覆盖新会话选择。

同一路由分别验证 cookie 和 Bearer。覆盖两种选择同时出现、错误凭据不回退、无关 cookie 不改变选择。网站 token 改放 Bearer 仍须被拒绝。匿名入口的行为不得被附带 cookie 或 Authorization 改变。当前认证中间件、Actor 提取和上述验收均为后续实施内容。
