# 微信身份持久事实目标设计

本文规定[微信身份用例](wechat.md)的关联、授权、code 占用及变更结果之间的业务关系。业务资格、外部调用和恢复期限由所属用例决定。

## 事实与真实引用

当前微信关联归唯一 Account，保存受保护 UnionID 及当前绑定修订；解绑或注销移除关联，原变更结果仍保存办理时的账户、会话、期望和结果。变更结果的账户必须真实存在，原本人会话必须属于同一账户。新微信 Session 关联建立时的当前绑定，且与账户、当前绑定修订一致。解绑先撤销所有依赖原关联的两端微信会话并关闭交接，再移除关联；只有已经撤销的旧会话才可失去关联。普通退出不移除微信关联。

每份变更结果、网站授权和微信 code 交换各独占一份原请求；网站回调独占其原授权。原请求的用途、认证方法、实际 AppID 和协议种类须与所属结果相容。小程序登录、网站登录、小程序绑定、网站绑定及解绑各只有所属的业务结果和必要协议配套；解绑没有供应商 code 占用。网站回调必须沿原授权归属网站请求，不能借另一流程的 state、cookie 或 code 改挂。来源角色、秘密、供应商结果和当前本人资格仍由用例核对。

同一应用的同一微信 code 只能被占用一次，跨查找键版本仍然有效；网站授权的 state 也唯一。小程序微信登录与绑定共用 code 交换占用，网站登录与绑定共用回调占用；各协议之间的 code 不互认。

## 提交与状态保护

新请求接纳时，业务结果和该入口必需的协议或授权事实一起完整成立；缺少、双挂或跨协议混挂均拒绝。登录只对应认证结果，绑定和解绑只对应变更结果。业务事实和协议事实的归属、来源、占用身份及原输入不可在线改写。协议执行只从执行中转至一份终态并固定结束时间；授权创建后不在线改写 state 或 cookie；变更结果只按绑定或解绑的所属结果推进，不把已完成业务重开。具体状态及对外结果见[微信身份用例](wechat.md)。

清理时，协议记录可早于其已关闭业务结果删除；变更结果只与其原请求按同一条件删除。注销可提前关闭账户所属结果读取并删除变更结果，但仍保留阻止 code 二次交换的必要协议占用与原请求。删除前检查原事实的终态、执行结束、恢复窗口和所有引用；清理不能把旧请求重新变成可办理。

微信绑定推进账户的微信修订并保留头像修订，头像更换反之。移除关联时，已撤销会话只失去关联，不替会话写撤销，也不允许改挂。已完成授权、原 code 占用和永久身份历史不可改写。

## 验收

验证孤立请求、缺少配套、错用途、双挂、跨应用归属、同 code 跨登录与绑定、跨查找键版本占用、合法办理的最终组合、协议终态不可重开、未撤销会话不能失去关联、已撤销会话的合法清空、正常清理及注销保留技术占用。验证权限负例和数据库约束错误不会伪装成确定业务拒绝。
