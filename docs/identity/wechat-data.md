# 微信身份持久事实目标设计

状态：目标设计，尚未实施。本文规定[微信身份用例](wechat.md)的关联、授权、code 占用及变更结果的持久关系。业务资格、外部调用和恢复期限由所属用例决定；真实表、迁移和运行权限交付时须按[数据库](../database.md)与[模型与存取](../architecture.md#类型构造与查询)验证。

## 事实与真实引用

当前 Connection 归唯一 Account，保存受保护 UnionID、用途隔离的查找摘要及当前绑定修订；解绑或注销删除关联，原 Change 仍保存办理时的账户、会话、期望和结果。Change 的非空账户引用真实 Account；原本人会话与账户须由组合关系证明属于同一账户，不能分别引用两个无关行。新微信 Session 引用建立时的 Connection，且与账户、当前绑定修订一致。解绑先撤销所有依赖原关联的两端微信会话并关闭交接，再删除关联；只有已经撤销的旧会话才可随受保护外键清空关联引用。普通退出不删除 Connection。

每份 Change、网站 Authorization 和微信 Exchange 各独占一份原 Request；网站 Callback 独占其原 Authorization。父用途、认证方法、实际 AppID 和协议种类须与子事实相容。小程序登录、网站登录、小程序绑定、网站绑定及解绑各只有所属的业务结果和必要协议配套；解绑没有供应商 code 占用。网站 Callback 必须沿原 Authorization 归属网站请求，不能借另一流程的 state、cookie 或 code 改挂。协议父链只用真实非空引用和唯一性表达；来源角色、秘密、供应商结果和当前本人资格仍由用例核对。

Exchange 和 Callback 分别按实际应用、摘要密钥版本和 code 摘要唯一占用；网站 Authorization 的 state 摘要也唯一。同协议新 code 须在对象协调内查询全部仍保留的密钥版本，再由版本内唯一约束裁决。小程序微信登录与绑定共用 Exchange 占用，网站登录与绑定共用 Callback 占用；各协议之间的 code 不互认。密钥版本有真实元数据引用与用途检查，密文封装头仍须由密码入口核验。单有外键不证明密钥材料存在或外部 code 可信。

## 提交与状态保护

新 Request 接纳时，业务事实和该入口必需的协议或授权事实在同一提交中完整成立；缺少、双挂或跨协议混挂均拒绝。登录只对应 Authentication，绑定和解绑只对应 Change。业务行和协议行的父引用、来源、占用身份及原输入不可在线改写。协议执行只从 running 转至一份终态并固定结束时间；Authorization 创建后不在线改写 state 或 cookie；Change 只按绑定或解绑的所属结果推进，不把已完成业务重开。具体状态及对外结果见[微信身份用例](wechat.md)。

行内约束负责非空、摘要长度和单行状态组合；真实引用负责父子存在与唯一归属。跨表提交完整性用必要的可延迟约束在最终事务状态检查，不在每次更新时重新要求新建配套。清理时，协议记录可早于其已关闭业务父行删除；正常删除 Change 须与原 Request 的删除条件一致。注销可提前关闭账户所属结果读取并删除 Change，但仍保留阻止 code 二次交换的必要协议占用与技术父记录。删除守卫检查原事实的终态、执行结束、恢复窗口和所有引用；清理不能把旧请求重新变成可办理。

运行身份只获得实际读写所需的列权限和受保护删除权。微信绑定写者推进账户的微信修订并保留头像修订，头像写者反之；复合列授权不能隔离子字段，须由受控写者和真实约束验证。受保护 Connection 删除引起的已撤销 Session 引用清空只改该引用，不替会话写撤销，也不允许改挂。普通业务不得 UPDATE 已完成授权、原 code 占用或永久身份历史。

## 验收

用真实运行身份和事务分别验证孤立 Request、缺少配套、错用途、双挂、跨应用父子、同 code 跨登录与绑定、跨密钥版本占用、合法事务的最终组合、协议终态不可重开、未撤销会话拒绝失去关联、已撤销会话的合法清空、正常清理及注销保留技术占用。验证权限负例和数据库约束错误不会伪装成确定业务拒绝；文档约束不表示迁移已经交付。
