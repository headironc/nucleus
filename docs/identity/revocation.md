# 会话撤销与退出

本文拥有本人有效会话列表、逐会话撤销事实，以及退出当前会话、指定其他会话、全部设备和原退出结果读取。[账户暂停](suspension.md)、[本人换号](mobile.md)与微信解绑另行产生撤销，并拥有各自的办理资格与共同后果。共用写入屏障与提交未知核对见 [架构恢复协议](../architecture.md#原操作与恢复)。

## 本人会话管理

`GET /api/v1/sessions` 在同一决定性快照内鉴别当前本人资格，并读取本账户的有效会话。响应为 `{ code: "ok", sessions: [...] }`，按会话 ID 排序，不分页。每项只包含 `id`、`source: website | mini`、`createdAt` 和 `current`。有效表示尚未撤销且未到期；不返回其他账户、过期或已撤销会话。来源取自已核验的签发事实，不推断设备、操作系统、位置或可信设备。响应使用 `Cache-Control: no-store`。

`DELETE /api/v1/sessions/{id}` 只撤销本人指定的其他有效会话。当前目标返回 409 `current_session`；跨账户、不存在、过期及已撤销目标统一返回 404 `resource_not_found`。入口不接受正文，沿用原 Operation-Id、Cookie/Bearer 严格互斥及写入同源规则。成功返回既有 `completion: { id, count, revokedAt }`，`count` 恰为 1，不清理发起会话的 cookie。

列表与定向撤销均接纳网站 Cookie 或小程序 Bearer。列表采用读取同源规则，网站定向撤销要求准确 Origin；混合证明拒绝。账户页的本次退出与独立会话管理页的底部全部退出仍由各客户端切片交付；本切片不实现页面。

定向撤销沿用 Logout，新增 `other` 范围。共同完成的规范输入额外绑定目标会话 ID；`current/all` 的原编码不变。永久 Logout 的固定集合恰为目标一项，且不含发起会话。原结果的 `original.scope` 为 `other`，`initiatorId` 为原发起会话，目标取自唯一 `revocations` 项。数据库约束与受控构造共同保护此形状；读取及重放不从当前会话状态重建目标。

事务持有 Account 与本账户 Session 锁后，再复查发起者资格及目标的账户、期限和撤销状态。Account 推进、永久 Logout、目标撤销、目标 Handoff 删除与共同完成一并提交。竞争撤销同一目标时只有一个新操作成功，后来操作返回 404。与全部退出交错时按同一账户锁串行决定；全部退出先提交使旧发起会话失效。定向退出先提交后，全部退出只选择剩余未撤销会话。

发起会话仍有效时，同一 Operation-Id 与相同目标可以核对原完成；更换目标、范围或发起者返回 `request_mismatch`。新 Operation-Id 不会重复撤销原目标。提交未知、等待者取消、原结果读取和短期会话清理继续使用现有 Logout 恢复协议；成功原集合不会因后来登录而扩大。

## 用例、范围与结果

退出只能由当前有效会话的本人发起。`DELETE /api/v1/sessions/current` 选中本次认证的会话；`DELETE /api/v1/sessions` 选中该账户在退出事务内尚未撤销的全部会话，包含网站和小程序会话，以及已到期但仍保留的会话。两个入口使用各自的客户端 Operation-Id，无正文，客户端不能指定目标账户。退出保留账户、实名、当前微信绑定和领域授权。已签发的头像图片链接依自身期限继续有效。

退出范围由事务取得对象协调后的会话集合固定。新登录先提交、全部退出后提交时，新会话属于撤销范围；退出先提交、新登录后提交时，新会话有效。退出不安排后台扫描后来会话。原退出完成只描述当次撤销的集合，不因后来登录、清理或绑定变化重选范围。

| 入口                                        | 当前身份与结果                                                                                                                                                                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DELETE /api/v1/sessions/current`           | 当前会话有效时执行；成功返回 200 和 `completion: { id, count, revokedAt }`，`id` 为原 Operation-Id。                                                                                                                                      |
| `DELETE /api/v1/sessions`                   | 当前会话有效时执行；成功返回 200 和同形完成，`count` 为本次撤销的会话数。                                                                                                                                                                 |
| `GET /api/v1/revocations?operation_id={id}` | 由同账户的当前有效会话读取原退出；返回 200、`original: { scope, initiatorId }`、`count` 及按会话 ID 排序的完整 `revocations: [{ id, revokedAt }]`，不分页。没有本账户可读的原退出时，`original` 为 `null`，集合为空。只读查询不执行退出。 |

网站使用 Session-Id 选中原 cookie 认证并遵守同源条件。两条 DELETE 采用本次请求实际认证的会话；原会话被撤销后，以它重发 DELETE 返回 `authentication_invalid`，不能从这个 401 推断原退出是否提交。用户取得同账户的新会话后只能使用 GET 核对原操作；以新会话和旧 Operation-Id 重发 DELETE 不构成新退出，也不返回原完成。新的退出动作须用新 Operation-Id。GET 不要求原会话仍存在。GET 请求头中的 Operation-Id 只标识本次查询，查询参数才是原退出标识；响应不回显本次请求标识。

DELETE 无正文，非空正文返回 400，超过共同上限返回 413；GET 原结果的必填原操作查询参数重复、缺失或非法时返回 400。网站 DELETE 使用必填准确 Origin，网站 GET 沿读取同源规则；小程序使用 Bearer，不要求网站 Origin。网站当前或全部退出成功只清理所选 cookie；指定其他会话退出、小程序退出、全部失败及原结果读取均不设置 cookie。

## 撤销事实与约束

Session 撤销记录证明一条会话已经撤销，同时保存真实来源。退出、账户暂停及换号分别使用 `logout`、`suspension`、`transfer`，绑定各自原请求的非空 Operation-Id 和原因标识。微信解绑的撤销仍归相应目标设计。账户注销清理完整短期会话组，并保留 Account 墓碑，不再逐会话追加撤销。当前资格鉴别 Session 和 Account 状态，再判断期限、撤销和账户资格，不从历史聚合推导。

| 事实            | 含义与约束                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------- |
| Session 撤销    | 一条会话至多撤销一次，固定原账户、原操作、撤销时间及真实原因。                               |
| 退出原因        | 指向 Account 的永久 Logout，原因标识就是原退出 Operation-Id。                                |
| 暂停或换号原因  | 指向同账户的真实暂停或换号完成，各自保留原请求与生效时间。                                   |
| 永久 Logout     | 固定原账户与人员、原 Operation-Id、发起会话、范围、完整会话 ID 集合及时间。                  |
| Logout 退出范围 | `current` 只含发起会话；`all` 包含当次全部尚未撤销的保留会话；`other` 只含指定其他有效会话。 |

永久 Logout 属于 Account 自有历史，整体封印原退出集合。集合成员属于同一账户，由同一次办理形成，后续办理不能追加或重选。`current/all` 的原发起会话在集合中；`other` 只包含指定的其他会话。相同原操作在其他账户已有退出时，不得接纳为新退出。Logout 与共同完成记录承担原结果依据，短期逐会话撤销不替代永久原组。

暂停撤销与所属暂停的账户、原操作和时间一致。既有退出撤销保持原来源；目标零会话也可以成功，完成依据是所属暂停。完整暂停结果和原集合核对归[账户暂停](suspension.md#事实约束与权限)。

保留的撤销事实不可修改。Session 失效后默认保留 24 小时，且无短期引用时方可清理。失效时刻取到期时刻或撤销时刻。Handoff 在撤销时删除；到期清理共同删除 Session、签发记录、撤销记录及剩余交接，注销也按完整组清理。永久 Logout 与 Account 墓碑继续保留，原 Operation-Id 不因短期组消失而成为新操作。会话组保留期间不能用已撤销的 Session ID 新建会话或交接。

## 事务与并发

当前退出与全部退出由所选用例区分，共用同一原操作协调，范围不参与区分。业务事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、Account 和 Session，再重查本次认证的会话、来源、Account 当前资格、可信时间和原退出集合。第一次查到的候选不能直接决定撤销范围；新增竞争对象使事务回滚后按完整集合有界重试。

原 Operation-Id 命中退出完成时，核对所属账户、原发起会话及退出范围。DELETE 先复查当前资格；原会话已撤销时仍返回 401。其他有效会话不能借旧操作读取或扩展原完成，返回 409 `request_mismatch`；同账户用户以 GET 读取。命中其他账户也不返回对方内容。新办理先鉴别持锁后的完整保留会话集合，再按范围选择尚未撤销的成员。Account 的永久 Logout、状态推进、各 Session 撤销、对应 Handoff 删除及共同完成记录一并提交。当前认证会话有效，因此新办理至少撤销一条会话。任何一项失败都使本次办理整体回滚。

提交前按本次退出用例核对范围：当前退出恰好撤销原认证会话；全部退出提交时，该账户没有尚未撤销的会话。发起会话当时须有效且账户未暂停；其他成员可已过期。全部退出后，同一办理不能再建会话。会话建立、解绑、暂停、换号、注销及 Handoff 清理只要改变上述判断，都须遵守相同账户与会话对象协调。已经撤销的会话不重复撤销。退出与绑定的供应商外呼可交错，但绑定最终接纳时须重新核对原本人会话；退出先提交后，旧绑定不能借后来新会话成功。成功退出的响应在撤销本次认证会话后直接形成，不重新认证而误报 401。

## 响应丢失与读取

退出没有事务外供应商调用。等待者取消不会取消已接纳工作；HTTP 等待超时返回 `outcome_unknown`。提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对共同完成记录和永久 Logout，匹配原账户、人员、发起会话、范围及原集合；普通组成员不能冒充原发起会话。撤销范围不按后来变化的会话集合重算，也不要求已合法清理的短期会话仍存在。可靠确认未提交后，新的办理仍须具有有效的原会话。注销保留永久原结果，查无短期撤销不证明回滚。完整匹配原结果后成功即已确定，后续收尾失败不改变结论。

GET 先等待相关在途工作，不登记新写工作。它在一个决定性快照内鉴别当前会话、可信来源和 Account 资格，再鉴别本账户的永久 Logout。响应直接使用封印的原会话 ID 集合及退出时间，不重扫短期会话后果，也不交付被过滤后的部分结果。其他账户的同 Operation-Id 与不存在的集合都返回空列表，不泄露归属，也不声称旧事务已回滚。无法可靠读取时返回技术错误，不伪造空列表；持久事实矛盾关闭接纳。原集合及读取资格完整确认后结果已知，后续只读收尾失败不丢弃结果。GET 不删除 cookie、Handoff 或 Session。

`original` 始终存在于响应中。非空集合的 `scope` 为 `current`、`all` 或 `other`，`initiatorId` 为原发起会话。`current` 恰好只有该会话；`all` 包含它；`other` 恰好只有指定的其他会话。绑定与集合来自同一已核验永久 Logout，短期会话清理后仍保留。不存在及跨账户读取均返回 `original: null`、`count: 0` 和空集合，不交付对方绑定。客户端将原范围、发起者及定向退出的目标与首发前保存的材料比较，不从集合数量或当前资料推断原范围。缺失、非法或与集合矛盾的证明不能构成成功。

网站当前或全部退出首次成功响应只清理由本次认证指向的准确 cookie，使用空值与过去的 Expires，不设置 Domain 或 Max-Age。浏览器也只在本地仍选中相同 Session ID 与修订时清空选择，迟到响应不得清除后来登录的会话或新登录尝试。退出其他会话及原完成查询不清理当前 cookie。服务器上的撤销在提交时生效，不依赖其他设备收到响应。

## 验收

本人会话管理覆盖跨账户隔离、过期及撤销过滤、网站和小程序来源、当前标识与最小字段。定向撤销覆盖当前目标拒绝、无效目标统一 404、固定目标绑定、发起者保留、并发同目标及全部退出交错、提交未知、原结果读取和重启核验。SQL 负例拒绝 `other` 包含发起者或具有多个成员；既有 `current/all` 结构保护与原输入编码继续验收。

用真实事务控制以下交错：当前退出与全部退出的准确范围，全部退出包含保留的过期会话并排除已撤销会话；同账户新登录先于或晚于全部退出提交；同一会话的两笔撤销竞争；退出与绑定结果竞争；任一撤销或 Handoff 删除失败的整体回滚；提交回包丢失、晚提交及普通重启后的按需核对；原会话已撤销时 DELETE 的 401 与同账户新会话 GET 的原集合；跨账户和不存在操作的空列表及零写入；迟到网站响应只清理原 cookie，不清除后来选中的会话。

完整性负例覆盖永久 Logout 的集合、身份、原操作、范围、时间或封印损坏，GET 拒绝结果并关闭接纳。保留的 Session 历史另覆盖缺少签发或撤销、错误账户和未删 Handoff，按所属读取及启动核验拒绝损坏。合法清理发起会话及其他完整会话组后，新会话仍可读取永久原组；保留的已撤销 Session ID 不能用于新建会话。HTTP 另覆盖严格 Origin、混合证明、非空正文、非法查询和失败不清 cookie。真实浏览器选择修订属于客户端验收。
