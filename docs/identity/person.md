# 人员与实名版本

Person 固定人员归属，实名版本保存一次完整姓名与居民身份证号。首次版本由[系统初始化](../operations/access.md#初始化)或网站 [R2 注册](registration.md)建立；后续版本由[实名更正](correction.md)追加。Person 指向当前版本。

## 构造与关系

证件尾号为身份证号的最后四个字符。更正候选及管理历史按所属权限披露完整姓名与身份证号；本人及其他脱敏响应只投影所属字段，不因值可以序列化而取得完整读取权。HTTP 的脱敏字段形状与读取权限由[当前身份](current.md#本人账户投影)及所属用例规定。

首份实名版本、Person 当前版本、Account 及注册结果在一次成功办理中共同成立，真实同人关系不由事后补写或约定替代。后续更正追加新版本并共同改变当前版本与当前身份证号占用，既有版本不可修改或删除。注销保留 Person、实名版本和必要历史，注销后重新注册建立新的 Person。

Person 的当前状态固定人员归属、当前实名版本与最后变更时刻。首次建立占自身顺序的首位，更正与注销各自推进一次。更正事实固定变更前后版本；注销保留当前版本，后续更正仍沿既有资格办理。同刻变更合法，早于当前状态时刻则拒绝。

首次记录固定原 Account、实名版本、Operation-Id 与建立时刻。它与 Account 建立事实及实名取值共同成立。更正和注销分别保留原业务事实，与首次记录组成该人员的完整历史。记录不可改删，所有字段均受封印保护。

姓名和身份证号先按[正式注册的稳定值规则](registration.md#业务边界与不变量)规范化。首次新建人员另检查可信办理日。历史版本、原输入匹配和更正使用同一稳定值规则，不用今天的日期重新判断原值。完整明文只存在于受控输入和必要的短期解密；普通响应按所属读取权限投影，不能因为持有版本 ID 就读取完整资料。

## 封装与读取

实名版本的姓名与身份证号分别受[密钥材料](../keys.md)规定的封装保护。完整版本还鉴别版本 ID、人员归属及两项规范实名值；任何一项失败都不得产生部分版本。读取的明文必须已经是稳定规范形式；若重新构造所得值不同，报告该字段的完整性故障，不修剪或改写历史。技术重新加密保持业务明文、版本 ID 和人员归属，不形成新的实名版本，也不改变版本封印。

按人员和版本读取历史版本时，两者必须同时匹配；查询真正无结果与数据库或解码失败分开。注册原结果使用注册时的版本，当前本人读取使用决定性快照中的当前版本；后来的更正不能改变旧回执或业务记录所引用的版本。持有版本不等于当前本人有权读取。当前读取的权限与投影见[当前身份](current.md)，历史读取见[实名更正](correction.md)。

实名更正按永久人员定位当前实名资料；仍有账户时另核对当前身份证号占用。注销后的账户缺席是合法状态，必要版本或占用损坏不是缺席。Center 的人员候选只取得脱敏身份。

当前读取鉴别 Person 状态，再按其固定版本读取实名取值。原回执和历史只使用原事实固定的版本，不要求今日状态仍相同。更正历史核对完整顺序及固定来源，空页不隐藏缺失事实。封印、锚定与启动核验沿[状态历史模块](../architecture.md#状态历史模块)。

机构角色变更历史使用原办理人当时的版本，指派和账户状态历史使用当次双方的版本。这些历史只按业务历史固定的版本读取，交付 `{ personId, revisionId, name }`，姓名脱敏规则见[角色历史](../access/roles.md#原请求与读取)。本页任何必要版本缺失或鉴别失败都使整页失败，不返回部分版本，也不按当前办理日重判历史生日。管理更正历史沿[所属披露规则](correction.md#历史读取)读取完整资料，办理人仍只交付当时姓名。

## 验收

验证首版与 Person 当前版本共同成立、版本必须属于原人员、单字段失败回滚、旧键读取、错版本或错字段材料拒绝、非规范历史明文拒绝，以及原版本和当前版本分别读取。验证注销保留历史、更正不修改旧版本，且查询失败不伪装成查无结果。注册原成功始终引用首版，当前版本改变后仍按原资料交接。更正的版本来源与原结果依据见[实名更正](correction.md#永久事实与共同事务)。
