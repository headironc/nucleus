# Identity 号码查找摘要目标设计

状态：手机号摘要计算、密钥装载和 C1 原请求的持久摘要核对已交付。按号码查找账户、号码占用、换钥和身份证号摘要尚未实施。本文规定当前手机号和居民身份证号的确定性查找摘要。号码的输入规范由[匿名身份办理 HTTP](../http/identity.md#请求字段) 和[正式注册](registration.md#业务边界与不变量)拥有。密钥用途和长度前缀编码见[密钥材料](../keys.md)。账户占用和注销后重新注册的业务后果由[正式注册](registration.md)拥有。

## 编码与用途

手机号使用活动 `mobile` 密钥，身份证号使用活动 `id_number_lookup` 密钥。两个密钥都须与已核验的数据库活动元数据一致。把受控规范字符串编码为 UTF-8 字节后，按[长度前缀编码](../keys.md#51-长度前缀编码)计算：

```text
mobile_hash = HMAC-SHA-256(
    K_mobile,
    E("nucleus/identity/mobile/v1", mobile)
)

id_number_hash = HMAC-SHA-256(
    K_id_number_lookup,
    E("nucleus/identity/id_number/v1", id_number)
)
```

两个结果均保留完整 32 字节。输入不加入账户、人员、版本、原操作或随机 nonce；同一用途及密钥下，相同规范号码形成相同摘要。域标签和密钥用途共同隔离两类号码。查找摘要不使用请求输入或随机凭据证明的编码，也不用于还原原号码。

当前账户、待注册凭据、认证挑战与注册尝试中保留的手机号采用同一规则；消息及校验沿原挑战读取，不另存手机号占用值。账户的身份证号摘要只代表同一人员当前实名版本的占用，历史版本不单独占用号码。查询消费已计算的摘要；计算或读取失败是错误，不能折叠成“没有占用”。

## 密钥版本与核验

`domain::identity::keys::mobile::Keys::hash` 接收已校验的 `Mobile`，返回独立的 32 字节 `Hash` 类型。业务输入不能指定摘要域、字段组合或保留键版本。保留键只暴露指纹元数据，不参加运行请求的摘要计算。固定向量与活动键切换测试已通过；这些结果不证明数据库占用或换钥流程已经接入。

号码查找值不增加逐行 key ID，也不在运行请求时按多个密钥版本查找。更换活动查找键的停写、重算、事务结局及材料切换见[密钥维护](../operations/keys.md)。

启动和维护核验使用与业务写入相同的编码。保存摘要与规范明文不符是完整性故障，不能折叠为没有占用。原请求输入和微信 code 的按行密钥版本规则不随查找键轮换改变。

## 验收

使用独立固定向量验证两个域、长度前缀字节边界、规范值等价、用途隔离和完整 32 字节结果。期望值不得由被测实现生成。验证不同账户的相同规范号码得到相同查找值，当前身份证号更正后旧版本不再占用，暂停账户仍占用。换钥故障与材料核对按[密钥维护](../operations/keys.md)验证。
