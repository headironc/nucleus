# 网站持久会话目标设计

本文拥有网站登录结果的 cookie 交接、浏览器会话选择、重开与多标签页切换。会话的当前证明与请求同源条件见[当前身份与本人账户读取](current.md)；会话撤销及退出后的清理见[会话撤销与退出](revocation.md)。各登录入口拥有原认证、注册及原结果恢复资格。

## 用户流程与边界

网站用户完成短信登录、正式注册或微信扫码登录后，取得一条固定期限的服务端 Session。关闭标签页或浏览器再打开时，浏览器可凭原 cookie 继续使用仍有效的会话。重开、本人读取和原成功恢复均不延长原到期时刻。网站短信会话默认 24 小时，网站微信身份会话默认 30 天；到期、撤销、暂停、注销及适用的微信解绑仍由服务端当前资格决定。

每条 Session 保存创建时的实际网站 AppID 和认证方法。服务端按可信认证来源决定传递方式，客户端不声明期望交接。网站短信及网站微信授权对应 `cookie`，小程序手机号及小程序微信身份对应 `bearer`；R2 继承待注册凭据的原认证来源。服务器在新办理和原成功恢复时核对原来源，请求额外提供的传递头不改变结果。需要网站同源检查的入口先检查来源，再消费认证材料或写入业务事实。

## 服务端交接

网站成功结果返回 `session: { id, expiresAt }`，外层保留 `code`，不回显请求标识，JSON 不含会话 token。小程序的 Bearer 结果由所属登录入口维护，两种结果形状互斥。网站把原随机 Session token 写入名称为 `__Host-nucleus-session-<SessionId>` 的独立 cookie；名称中的 Session ID 不是登录秘密。

cookie 固定使用 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 `Domain`。`Expires` 取原会话到期时刻向上取整到秒后的 HTTP 日期，不设置会覆盖绝对到期时刻的 `Max-Age`。服务端保存的精确时刻仍是拒绝会话的依据。每个 Session ID 对应不同 cookie 名，迟到响应不能覆盖另一会话的 token。日期转换失败保留技术错误，不修改原到期时刻。

仅新登录成功或原成功在其有限恢复期内交接原有效 Session 时设置 cookie。恢复沿用原 Session ID、token 和到期时刻，不新建、不续期，也不把加密保存原 token 的短期交接记录延长到整个会话期。待注册、进度、提交未知、授权回调跳转、业务读取及失败结果均不设置登录 cookie。响应中出现 Session 只说明服务端已创建它；网站客户端还须用该 Session ID 成功读取本人账户，确认浏览器能回传 cookie 后才进入已登录页面。

网站请求使用同源 `fetch` 并携带 credentials。受保护请求发送当前选定的 `Session-Id`；服务端只读取对应 cookie 并按[当前身份设计](current.md)重新验证。token 不进入 JSON、脚本变量、Web Storage、IndexedDB、URL 或应用日志。cookie 丢失、被拒收或站点存储被删除时，不凭 Session ID、旧页面状态或原交接记录重建长期会话；可按仍有效的原结果恢复协议交接，否则重新登录。

## 浏览器选择与并发

IndexedDB 只保存非秘密的 BrowserSession：格式版本、选中 Session ID、原 `expiresAt`、选择修订和当前登录尝试 Operation ID。它不保存 token、实名、人员档案或业务列表。开始登录尝试、比较原尝试后接纳结果、按原选择清空，都在各自独立的 `readwrite` 事务中完成；网络等待不放进本地事务。浏览器持久存储不可用或记录损坏时，遮蔽旧私有内容并要求重新验证或登录，不默认为已登录。

登录发起前登记尝试。成功、待注册、进度及失败响应都先比较原尝试和选择修订；迟到响应不能覆盖后来登录、注册输入、页面或会话选择。即使旧成功响应已设置自己的 cookie，也不得改变当前选中的 Session。无法接纳的旧成功仍保留其原定位；客户端可用那条确切会话调用当前退出入口释放资源，但不得清理后来选中的会话。

页面及在途请求固定发出时的 Session ID 和本地修订。新业务请求前重新核对浏览器选择；选择变化时遮蔽旧受限页面并加载新身份。迟到结果只有在原选择仍匹配时才可更新页面。标签页通知仅提示重新读取 IndexedDB，不充当认证证明。关闭后重开、`pageshow`、可见性变化和重新获得焦点时，先读取选择，再按原 cookie 验证当前账户和权限；可靠复查前不展示旧私有资料。断网或暂时依赖故障时显示待连接，不把一次失败解释为退出，也不离线办理。

服务器返回 401 时，浏览器仅在本地仍选中该请求的 Session ID 与修订时清除登录选择；403 清除相应受限资料并重读权限。两种状态都不能证明此前写请求未提交。退出成功只删除本次认证指向的准确 cookie，并按相同本地比较规则清空选择；原退出结果读取不清除当前 cookie。清理不使用宽泛的 `Clear-Site-Data`，不为腾出 cookie 容量自动撤销其他有效会话。Cookie 请求头受统一 8 KiB 上限约束，达到上限时显式拒绝新请求或引导用户结束确切会话。

## 验收

以真实浏览器和可控响应顺序验证：短信、注册、微信登录各自设置原绝对期限 cookie；原结果恢复保持同一 Session ID、token 和期限；进度或未知结局不设置 cookie；关闭重开仍可使用原有效会话，过期和撤销无法继续。并行标签页与倒序响应不能让旧登录覆盖新选择或旧账户页面；存储拒绝、cookie 丢失、离线、401、403 和退出响应丢失分别按上述边界处理。检查 JSON、脚本可读存储、URL 和日志没有会话 token，且删除 cookie 只命中原 Session ID。
