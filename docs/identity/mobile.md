# 手机号更换

本文拥有两种换号、号码验证、原结果和短期事实。发码及供应商监督沿[短信认证与原结果交接](authentication.md)的共同协议；逐会话失效沿[会话撤销与退出](revocation.md)；事务和未知提交核对见 [架构恢复协议](../architecture.md#原操作与恢复)。

## 用例与不变量

手机号更换只在网站办理，各入口只接受当前有效的网站会话。本人须有正常账户，先验证账户当前手机号，再验证拟使用的新手机号。原号无法使用时，机构角色当前含 `institution.accounts` 的管理者可核实本人并建立协助换号，代替原号验证；办理者机构等级须严格高于目标且不能是本人，目标可处于暂停状态。协助不规定固定证明材料清单，也不建立独立审批流程。管理者确认已核实本人必须是受当前权限约束的明确输入，单独的 `verified=true` 不授予任何权力。

成功更换只替换原账户的当前手机号及查找值，保留 Account、Person、实名版本、微信绑定、头像、机构角色、领域授权和业务历史。原手机号释放，新号由该账户占用；暂停账户仍占用其当前号。更换使目标账户当次全部网站与小程序会话失效，但不解除账户或领域暂停，不恢复已结束的授权、角色、申请或会话。原协助者的会话不受目标换号影响。新号与当前号相同返回 409 `state_conflict`；新号已由其他未注销账户占用时，在验证码通过后返回 409 `mobile_taken`，不改变原号。

流程不创建注册凭据或微信绑定，不把匿名登录短信变为换号许可。每次建立的换号绑定建立它的网站会话，固定有效期 10 分钟。同一人员后来建立的新换号使此前尚未完成的换号失效；已经完成的旧结果仍可按原身份解释。换号处于 `pending`、`completed` 或 `expired`：已完成为 `completed`；未完成且已过 10 分钟有效期或已被后来建立的换号取代为 `expired`；其余为 `pending`。

## 四阶段办理

| 阶段                                                                             | 输入与成功结果                                                                                             | 决定性检查                                                                                                                                                                                      |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原号发码 `POST /api/v1/accounts/current/codes`                                   | 本人网站会话、当前手机号及人机 token；返回 200 Message。                                                   | 只能发往事务内重读的账户当前号；供应商调用沿原 C1 执行与预算。                                                                                                                                  |
| 建立 `POST /api/v1/mobile-changes`                                               | 本人网站会话、原号 `messageId` 和验证码、客户端 Operation-Id；返回 201 Transfer ID 与到期时间。            | 原消息与校验属于本人及该当前号，是该人员该号码最新一条；未过期、错误次数小于 5、验证码正确，且消息发送后该人员未建立换号。                                                                      |
| 协助建立 `POST /api/v1/accounts/{id}/mobile-changes`                             | 管理者网站会话、受控目标确认、`verified=true`、客户端 Operation-Id；返回 201 Transfer ID 与到期时间。      | 当前账户管理权、严格等级、非本人、目标账户与实名版本及查找时手机号仍匹配。                                                                                                                      |
| 新号发码 `POST /api/v1/mobile-changes/{id}/codes`                                | 建立换号的同一网站会话、新手机号、人机 token、客户端 Operation-Id；返回 200 Message。                      | Transfer 最新、未过期、未完成；目标当前号不同；协助者当前权限和等级仍成立。此时不查询或泄露新号占用。                                                                                           |
| 完成 `PUT /api/v1/accounts/current/mobile` 或 `PUT /api/v1/accounts/{id}/mobile` | 同一建立会话、新手机号、新号 `messageId`、验证码、客户端 Operation-Id；返回 200 Completion ID 与生效时刻。 | Transfer 最新、未过期、未完成；目标实名版本仍为原确认；验证码属于同一目标和发码人，发送在 Transfer 建立之后、发往准确新号、为该号最新一条、未过期且错误次数小于 5。协助者当前权限与等级仍成立。 |

全部写入口要求 Operation-Id、原 Session-Id、所选 cookie 及准确 Origin，成功和拒绝均不设置 cookie。字段直接反序列化为受控值，未知字段及非法值返回 422。发码使用 C1 预算，建立和完成使用已认证写入预算；最多等待 30 秒，取消等待不取消已接纳工作。

原号和新号发码正文为 `mobile`、`token`。原号发码固定原人员和网站会话，匿名发码不能接管该原操作；新的接纳、许可和发送占用分别复查原会话及当前手机号。新号发码的路径 ID 是 Transfer ID，非法路径值返回 400；申请缺失、非原会话、已过期、被取代或目标实名已更正时，新增发码统一返回 410 `verification_required`，新号等于当前号返回 409 `state_conflict`，此时不查询新号占用。正确的原输入返回原 Message 和 200。资格失效后不开始新的外呼，已开始的调用仍保存原结论；已有 Message 的回读核对原申请、会话、手机号和 token，当前会话有效时，申请到期或被取代不阻断原结果回读，也不授予新的外呼资格。协助发码另复查当前管理权、严格等级和原会话；原协助发码回读也要求当前管理资格，但不重查申请期限或目标原版本，也不获得再次外呼的许可。

本人建立正文为 `messageId`、六位 `code`。建立成功返回 201、`code: ok` 和 `transfer: { id, expiresAt }`。错误码返回 403 `verification_invalid`；不适用、过期、耗尽或已消费的验证码返回 410 `verification_required`。原输入不符返回 409 `request_mismatch`，当前资格失效返回 401，原号输入不符返回 409 `target_changed`。

协助建立正文为 `personId`、`revisionId`、`mobile` 和 `verified: true`，消费[共同账户候选](account.md#管理候选)，不消费原号验证码，返回同一 Transfer 封套和固定期限。`verified` 缺席、false、未知字段和非法标识返回 422。当前管理权缺失返回 403 `permission_denied`；目标不存在、本人或等级不低于办理者返回 404 `target_unavailable`；新申请的目标版本或手机号变化返回 409 `target_changed`。原申请回读核对保存的原输入，仍要求当前管理资格。

本人完成正文为 `mobile`、`messageId` 和六位 `code`，成功返回 200、`code: ok` 和 `completion: { id, completedAt }`。同号与占用号分别返回 409 `state_conflict`、`mobile_taken`；只有验证码正确才判断新号占用。协助完成沿同一错误码，另有 403 `permission_denied` 和 404 `target_unavailable`；它先核对当前读取资格，再核对原输入，原成功不重查新办理的申请期限和验证码效力。暂停目标可以没有待撤销会话，协助完成仍有效，原暂停保持；办理者会话保持有效。办理者后来实名更正不改原申请和 Completion 的办理者版本。

申请期限和验证码期限在实际落笔时判断。期限在发码许可建立前经过时返回 410；已有 Message 时保存并返回原失败结果。建立或完成时期限已过，成功和错码两条路径均返回验证过期，计错、换号、撤销和交接删除全部回滚。

本人原号与新号发码分别使用人机用途 `send_mobile_change_code`、`send_mobile_binding_code`，对应持久 `mobile_change`、`mobile_binding` purpose 和独立 PNVS 模板 `MESSAGE__TEMPLATE__MOBILE_CHANGE`、`MESSAGE__TEMPLATE__MOBILE_BINDING`。两个模板代码必须非空且不含空白或控制字符；前者文字写明修改当前手机号，后者写明绑定新手机号，均使用供应商的 `code`、`min` 变量。两者与登录发码共用手机号、来源和部署预算，但验证码校验记录只属于换号；登录 Check 与换号 Confirmation 不能互用。新号验证码不能用于创建 Session 或建立下一份 Transfer。两次供应商调用各有自己的 Operation-Id 和 OutId；恢复原发码只读取原阶段，不自动再次调用供应商。建立及完成不外呼供应商。

有效验证码答错时，在同一事务增加错误次数，并保存本动作的原操作、规范原输入和确定拒绝。同一原操作重放只回读，不重复计错；改变验证码必须使用新 Operation-Id。同键异输入返回 request_mismatch。达到 5 次后不再接纳猜测。无效、过期或不适用的验证码不计错，也不创建 Transfer 或 Completion。本人原号验证码最多建立一个 Transfer；成功完成使此前适用的换号验证码失效。

## 事实与约束

每条换号 Message 恰有一条 Confirmation，登录 Message 恰有一条 Check，不能两者兼有。Confirmation 记录目标人员、办理者当时的实名版本、受保护验证码、错误次数和固定到期时刻；发往号码及可信来源沿 Message 取得。最新验证码按同一人员和同一号码的已保存发送事实判断。验证码不保存明文。

错误猜测保存为独立的短期拒绝，按动作和原 Operation-Id 唯一，绑定原 Confirmation、办理者、目标、原会话、用途和原输入。原拒绝与计错共同提交；保留到验证码截止之后至少 24 小时，并覆盖原操作恢复及执行。最后结果按[共同保留边界](../architecture.md#原操作与恢复)清理，原验证码失效或消费不因删除而改变。该记录不表示换号成功。

Transfer 记录目标人员、原办理者实名版本、目标当时实名版本、建立时网站会话、建立时刻、唯一非空 Operation-Id 及原输入。有效期从固定建立时间起算。办理者为目标本人即本人换号，否则为管理协助；受控权限仍在用例中验证。新号发码与完成都必须使用原网站会话，仅持有 Transfer ID 不能继续办理。

Completion 与成功 Transfer 共用 ID，记录所属账户、目标人员、原办理者版本、原会话与消息、完成时刻、唯一非空 Operation-Id 和原输入。一个换号至多成功一次；账户手机号变化与完成事实共同成立，且申请当时仍然最新且有效。成功完成及其原输入按[永久账户历史](account.md#建立与当前占用)保留，注销不删除这些事实。Confirmation 和 Transfer 按短信技术记录期限清理，默认 24 小时；Transfer 还须等待原消息和引用它的新号发码记录删除。原会话及原号消息只作历史绑定，不阻止其合法清理。即使 Transfer 已清理，原 Completion 仍可定位已完成状态。

原输入分别覆盖本人或协助入口、原 Operation-Id、办理者与目标、目标实名版本和网站会话；本人建立另覆盖原号 Message 与原码，协助建立另覆盖已核实确认与查找时手机号，完成另覆盖 Transfer、规范新手机号、新号 Message 与新码。原输入按原密钥版本核对，不进入响应或普通日志；错误尝试不能仅凭 Message ID 重放拒绝。密钥退役须覆盖仍保留的错误尝试、Transfer 和 Completion。

换号只改变账户当前手机号；人员、实名、绑定、头像和授权不由换号修改。清理不能提前释放供应商调用和短信次数预算。

## 原请求、读取与会话

每个写入口使用独立的客户端 Operation-Id。原发码沿原发码事实定位原阶段；原建立沿 Transfer，原完成沿 Completion。按原密钥版本核对规范原输入、原操作者、目标、会话、手机号、消息及确认内容；同标识异输入返回 409 `request_mismatch`。先定位原成功，再检查当前资格和所属业务期限。原成功重试只回读原事实，不重发短信、不再次建 Transfer 或撤销新会话。

`GET /api/v1/mobile-changes/{id}` 使用当前有效的网站会话。对象本人或当前有 `institution.accounts` 且机构等级严格高于对象的管理者可以读其最小状态，暂停目标仍可读取；本人读取不要求管理权。响应为 `code: ok` 和 `transfer: { status, ... }`：`pending` 附 `expiresAt`，`completed` 附 `completedAt`，`expired` 无附加字段。GET 拒绝查询参数和正文，HEAD 返回同样状态且无正文。当前会话失效返回 401；不存在与无权统一返回 404 `target_unavailable`。身份、权限、等级和状态在同一[只读快照](../http/lists.md)内确认；普通查询故障返回 503，必要事实损坏同时关闭接纳。

本人换号成功后原会话已撤销，重放完成 PUT 返回 401；本人以新号重新认证后可用 GET 核对原 Completion。协助者会话仍有效，符合当前权限时可重放原 PUT；后来失权不能借原操作取得读取权。仍保留的旧 Transfer 到期或被取代返回 `expired`，已完成优先返回 `completed`；Transfer 已清理且无 Completion 时返回 404。GET 不发码、不改状态，也不把查无事实解释为原事务回滚。

完成固定 `transfer` 撤销模式，为目标账户当次所有尚未撤销的会话形成撤销，沿本次完成 Operation-Id 与同一时刻成组保存；对应 Handoff 删除。手机号替换、Completion、撤销集合、Handoff 删除共同提交。即使目标此前已有退出或暂停撤销，仍准确撤销当次未撤销会话；不为已有撤销的会话再次撤销，也不撤销协助办理者的会话。登录先提交时新会话在完成的撤销范围内；换号先提交时，旧登录的最终接纳须因号码或账户状态变化拒绝，不能随后建立原号可用会话或待注册凭据。用户须用新号重新认证。

## 并发、故障与验收

业务事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、账户、手机号、Message、Transfer 及目标会话，再重查原结果、当前会话、目标实名版本、管理权限、验证码、时间及号码唯一性。换号、注册、登录、暂停、注销、实名更正和再次换号按提交先后决定资格；R2 与换号只有一个新号占用者。协助发码等待管理权变化时，本人发码和原结果回读不受阻挡。失败仅保留所属协议明确允许的验证码错误计数或发码预算，不留下部分手机号或撤销后果。建立换号的普通拒绝在确认回滚后交付，回滚失败返回依赖故障。完成换号的拒绝与收尾遵守[内核错误模型](../architecture.md#错误模型)。已核对的原成功或原计错结论不被收尾失败覆盖。HTTP 断连不取消已开始的受监督事务。

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原 Transfer 或永久 Completion。完成换号的内部恢复核对封装原输入与永久结果，不要求刚被本次完成撤销的会话仍有效。注销和短期会话清理不抹去完成依据。确认未提交后，新的请求按原输入和当前条件重新判断。原号不能登录、会话 401、当前手机号变化或短期原结果合法删除，都不能独自证明原办理结局。

验收覆盖原号、新号及协助三条路径的权限、等级、目标更正、暂停及会话绑定；跨登录验证码用途隔离、最新码、过期、五次错误、同一错误原操作只计一次、重复建立、后建 Transfer 取代旧流程（人机响应在途时阻止短信，短信已开始时保存原结论）、同号及占用号；验证码通过前不泄露占用，手机号唯一冲突整次回滚；落笔时申请或验证码到期的整体回滚；网站与小程序全会话失效、已有撤销及新登录交错、协助者会话保持；同标识异手机号或验证码拒绝，短期结果清理后旧验证码不能再次使用、原成功回读、本人旧会话 401、新会话 GET、Transfer 清理后 Completion 仍可读；管理状态读取的准确权限、同级与更低等级、暂停目标、过期、保留结果及注销后的隐藏；供应商无响应、晚提交、进程重启与清理交错。还须验证 Message 用途互斥、Transfer 与 Completion 同人同办理者、账户手机号变化与 Completion 配对，以及任何撤销或交接失败都不产生部分成功。
