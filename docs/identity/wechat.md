# 微信身份登录与共享绑定目标设计

本文拥有网站扫码、小程序微信身份登录、本人显式绑定与解绑、当前共享关联、原结果恢复及供应商 code 的单次交换。手机号认证与正式注册分别见[短信认证](authentication.md)和[正式注册](registration.md)；写入准入、未知提交与启动屏障见 [架构恢复协议](../architecture.md#原操作与恢复)。

## 用例与业务不变量

本人先经手机号登录或注册，再主动绑定微信身份。绑定后，网站和小程序经同一可信微信身份登录同一账户。微信身份登录只访问已绑定且当前可用的账户；没有绑定时拒绝，不自动注册、合并账户或创建领域授权。手机号认证与登录不自动绑定微信，绑定和解绑都要求本人当前有效会话及明确操作，不追加短信验证。

当前账户至多有一份微信绑定；同一开放平台账号下的一个 UnionID 至多绑定一份未注销账户，暂停账户继续占用。新绑定若与现有账户或身份冲突，拒绝并保留原关联。已是同一绑定可完成“无需变更”，不推进绑定代次。解绑仅解除本人明确确认的当前修订，不自动移交身份；之后重新绑定即使 UnionID 相同，也建立新修订。

解绑共同撤销网站和小程序中依赖原绑定的全部微信身份会话，并关闭这些会话仍可交付的短期凭据。手机号会话按自己的资格继续。账户暂停、换号、注销及适用退出同样使原会话按所属规则失效。网站关闭标签页或浏览器后，原有效持久会话仍可使用至原到期；重新打开、结果恢复与重放均不续期。微信身份会话默认期限为 30 天。

## 可信身份与部署边界

服务端只使用固定网站应用或固定小程序应用成功交换所得的 UnionID 定位共享绑定。前端提供的 UnionID、OpenID、昵称、手机号相似性或应用角色声明都不能建立关联。UnionID 是共享身份键；OpenID 只说明本次验证的应用来源，不建立第二份账户映射，也不作为长期业务资料保存。身份值按非空、无空白或控制字符、最多 256 UTF-8 字节接纳，不修剪或改变大小写。

供应商确认交换成功却未提供有效 UnionID 时，本次原办理以 `wechat_identity_unavailable` 确定拒绝；不能退回 OpenID 定位、再次交换原 code 或把它当作待完成进度。

本能力只接入一个固定微信开放平台账号，网站和小程序的两个 AppID 必须确实归属该账号且彼此不同。部署前须核验应用角色、归属、网站回调域名和真实凭据；公开接口说明或本地格式校验不能代替该证明。跨开放平台或应用身份迁移不属于本次能力，不能在更换 AppSecret 时顺带改变 AppID 或解释旧绑定。供应商暂时故障只阻断依赖本次外呼的新办理，已有有效会话、手机号路径及不依赖供应商的本人操作继续。

nucleus 入口从固定设置装载两个公开 AppID、准确网站 HTTPS origin 和各自的受保护 AppSecret 文件。网站回调与完成页由该 origin 加固定路径得到，不接收 Host、转发头、客户端 URL 或任意回跳地址作为信任来源。秘密文件仅由受控凭据目录按固定文件名读取，不经普通环境变量、日志或响应输出；两端材料不能互为后备。启动校验保留的请求、协议执行、会话与绑定来源和当前固定应用身份是否一致；矛盾时拒绝开放 Identity 入口，不改写旧来源。真实平台归属仍由部署核验。网站 origin 改变须先结束原授权、其恢复和旧网站会话，再按新回调登记切换；普通同源重启不要求清空会话。

当前绑定只保存受保护 UnionID 及其查找摘要。查找不含当前登录应用，使两端定位同一关系。查找键轮换须核对所有当前关联及仍保留的 code 占用并验证唯一性，旧键有引用时继续保留，见[密钥维护](../operations/keys.md)。解密、摘要、键元数据或当前绑定代次不一致时拒绝开放相关写入与认证，不把错误解释为未绑定。

## 入口与结果

JSON 正文拒绝未知或重复字段，服务端限制正文、查询及 code 长度。每笔新办理使用客户端 Operation-Id 和独立随机 secret；重试保持原标识、证明、用途、可信应用来源与输入。网站入口要求准确 Origin，网站会话使用 cookie 与 Session-Id，小程序使用 Bearer；两种传递方式不能由正文选择。

| 入口                                       | 办理与结果                                                                                                                       |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/sessions`，网站分支          | 输入与授权结果见[匿名身份办理 HTTP](../http/identity.md)；创建限期网站授权并交付流程 cookie。                                    |
| `POST /api/v1/sessions`，小程序分支        | 输入与会话结果见[匿名身份办理 HTTP](../http/identity.md)；固定小程序来源，原请求只恢复同一会话。                                 |
| `POST /api/v1/accounts/current/union-id`   | 当前本人输入对应端的 `{ secret, credential }`，网站创建授权，小程序验证 code；成功返回 `completion: { id, revision, changed }`。 |
| `DELETE /api/v1/accounts/current/union-id` | 当前本人携 `Binding-Revision`、secret 与 Operation-Id；同事务解绑并撤销原关联会话，返回原完成。                                  |
| `GET /api/v1/authorizations/callback`      | nucleus 处理网站微信回调，只接收唯一 code 与 state；证明成立且 code 占用提交已知后，以 303 到固定完成页。                        |
| `GET /authorizations/completion`           | 网站托管交付同源静态完成页，从原标签页取得短期证明并读取后端原结果。                                                             |
| `POST /api/v1/authorizations/{id}`         | 网站原流程结果读取，携原 Operation-Id、secret 和流程 cookie；只返回原会话、原绑定完成、可靠进度或原拒绝。                        |
| `POST /api/v1/changes`                     | 独立最小完成读取，以原 Operation-Id 与 `{ action, secret }` 定位绑定，解绑另需原修订；不依赖当前登录会话。                       |

回调豁免 Operation-Id；完成页由独立网站托管，不校验或回显该头。网站交付与部署路由见[网站与后端边界](../http/site.md#托管与路由归属)。其他后端入口按原请求契约校验。`POST /api/v1/changes` 只返回成功绑定或解绑的原最小完成，不提供登录结果、微信身份历史或任意账户资料。解绑成功后原会话可能正是被撤销的会话，因此原 DELETE 不能重放时可经该独立入口核对。原证明不授予新的绑定、更换账户或读取当前本人资料的权力。

当前本人读取可以显示有无绑定及其当前修订，以供明确解绑；不输出 UnionID、OpenID、供应商 token 或会话秘密。绑定成功结果的 `revision` 是实际新关联 ID；无需变更返回原关联 ID；解绑返回被删除的原关联 ID，不返回随后生成的未绑定代次。原完成不随着后来的解绑、重绑、退出或注销改写。

| 结果                                                                            | HTTP 状态 | 含义                                                                       |
| ------------------------------------------------------------------------------- | --------- | -------------------------------------------------------------------------- |
| `wechat_not_bound`、`wechat_in_use`、`binding_changed`、`authorization_started` | 409       | 分别为无可用绑定、身份已被占用、期望修订失效、原授权已进入交换或已有结论。 |
| `authorization_invalid`、`authorization_expired`                                | 400、410  | 分别为授权输入无效、首次接纳时授权已过期。                                 |
| `wechat_identity_unavailable`                                                   | 503       | 可信交换已结束但未取得有效 UnionID；这是原办理的确定拒绝。                 |
| `result_unavailable`、`recovery_expired`                                        | 404、410  | 分别为独立完成读取无可靠可交付结果、已匹配原成功但恢复期已结束。           |
| `verification_required`                                                         | 410       | 原登录成功，但原会话已不能恢复。                                           |
| `outcome_unknown`、`dependency_unavailable`                                     | 503       | 分别为数据库提交结局待核对、依赖读取失败；均不宣称原业务失败。             |

## 网站授权与浏览器证明

网站发起时，同一事务固定原请求用途、应用来源、secret 证明、限期授权及绑定时的本人会话与期望代次。服务端生成彼此独立的高熵 state 与浏览器流程 cookie。state 放入固定微信授权 URL；流程 cookie 采用独立流程名、Secure、HttpOnly、SameSite=Lax、Path=/ 且不设 Domain。授权默认自发起起 300 秒，流程 cookie 最长 900 秒；重发只使用剩余期限。发起已进入交换或已有结果时，不重发授权 URL，仅给原授权 ID 引导结果读取；一次查无结果或前端断连不能触发新授权。

网站新授权把可信代理规则解析的原来源 IP 固定为持久发起额度的统计来源；原请求重试不更换该来源，也不再次占用额度。

网站在原页面嵌入固定来源的微信授权组件，扫码与供应商提供的快捷登录都继续原用途。父页面在发起前把 Operation-Id、secret、用途与原登录或本人会话选择保存于原标签页的 sessionStorage；保存失败不得展示可办理的授权。iframe 不接收本系统 token、secret 或 Session-Id，也不以加载事件或消息认定业务成功。供应商回跳只到固定顶层 callback；完成页从 fragment 中取公开流程 ID，在原标签页找证明并立即移除 fragment，再同源读取结果。缺少本地证明只能提示无法取回，不能推断原办理失败或自动换标识重办。完成页无第三方资源，响应及错误禁止缓存，访问日志不记录回调查询、cookie、证明或正文。

callback 先以 state 找原授权，再核对该流程 cookie；两项缺失或不匹配时拒绝，不用其他登录 cookie、IP、User-Agent 或前端传来的身份代替。首次接纳还检查原授权截止、用途、应用与绑定本人的当前资格。正确重复回调只匹配原 code 占用，不重新套首次 300 秒接纳窗口，不再次外呼；同一授权换 code 返回 `request_mismatch`。不同授权已占用同 code 时拒绝且不披露占用者。占用提交已知后即可 303 到固定完成页；303 只说明回调已接纳，业务结果须由原结果读取。

结果读取联合核对授权 ID、原 Operation-Id、secret、流程 cookie 和准确 Origin；不能共同识别时统一返回认证失败。可靠等待或正常交换返回 `progress: { status: pending, retryAfterSeconds: 1 }`。提交待核对返回 `outcome_unknown`，依赖读取失败返回 `dependency_unavailable`，两者均不能伪装成进度或确定业务失败。已保存原登录成功时，仅在原恢复期内、原账户及会话仍有效且原绑定修订仍是当前值时重交付同一会话和到期时间。已保存绑定成功时，只在原恢复期内返回最小完成，不要求原本人会话或当前关联仍有效；要读当前状态须重新认证。

## 占用、共同提交与恢复

每个应用协议的同一 code 只准启动一次交换。小程序手机号 code、小程序微信身份 code 和网站授权 code 分属独立协议；小程序微信登录与绑定共享一次性占用，网站登录与绑定也共享一次性占用。占用摘要见[原输入证明](proofs.md)。新占用在同一协议内跨所有仍保留的摘要键版本判定唯一。占用事务提交已知后，原受监督执行者才在事务外调用固定供应商接口；同一 code 的重试、断连或重启均不发起第二次交换。每次交换的本地等待预算为 10 秒，超时后仍须核对监督工作及原结果，不能重启交换。供应商结果在有界内存中交给原执行者，不能把上游 token 或 session_key 当系统会话 token。

| 阶段                      | 共同事务与最终依据                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 网站发起                  | 原 Request、授权、浏览器证明及适用绑定原资格共同提交。                                                                 |
| 小程序接纳或网站 callback | 原请求、对应登录或绑定办理及 code 占用共同提交；网站 callback 绑定原授权。                                             |
| 登录结果                  | 原协议终态、Authentication 结论、适用微信 Session 与限期 Handoff 共同提交。无有效绑定或账户不可用时只保存原确定拒绝。  |
| 绑定结果                  | 原协议终态与 Change 结论共同提交；锁后复查原本人会话、账户、期望绑定代次及双向唯一，实际变化时建立共享关联并推进代次。 |
| 解绑                      | 原 Request 与成功 Change、依赖原关联的会话撤销、适用 Handoff 删除、关联删除及新未绑定代次共同提交；不调用微信。        |

每份微信会话保存建立时的账户、可信应用来源和绑定修订。决定性认证读取在同一快照中核对当前账户、会话期限及撤销、同账户当前关联与原修订；登录中间件的一次旧检查不授予随后业务写入。绑定仍存在时，普通退出的已撤销会话可保留原关联；解绑移除关联时，已撤销会话只可失去关联，不得改挂到后来新绑定。未撤销的微信会话不能失去当前关联。解绑在删除关联前按原修订撤销所有未撤销的两端会话，包括尚未清理的过期会话；文件或短期技术记录的清理不能代替撤销。

登录与解绑竞争时，登录先提交则随后解绑撤销新会话；解绑先提交则登录不能使用旧关联。两个目标账户竞争相同 UnionID 时仅一份绑定可提交，其他请求得到确定冲突而不覆盖。登录交换成功尚不决定账户归属，最终事务按届时的有效绑定选择账户。绑定外呼期间原本人退出、暂停、换号、注销或解绑时，旧会话及期望代次复查拒绝迟到结果，不能改办成登录。旧解绑和旧结果重放不能作用于新绑定。

每笔数据库阶段遵守共用屏障与所属阶段的恢复契约。提交未知时暂停原操作推进，按[原操作恢复](../architecture.md#未知提交)取得数据库结束边界，再核对原请求、协议占用与业务事实。占用已提交后不再外呼；原执行者仍持可信结果且最终业务事务已确认回滚时，才可在原期限内重试本地提交。进程重启不扫描或接管旧交换；旧请求重试或清理触及时按需核对，可信结果已丢失且确无业务终态时保存需要重新验证的原结论，不释放仍有效的 code 占用。原操作重放先核对证明和输入，再按原结果与当前交付资格决定响应，不新建会话、绑定或期限。

## 保留、清理与验收

当前关联只保留当前 UnionID 密文、摘要及修订。显式解绑或真实注销删除该身份材料，不建关联历史或空壳。绑定和解绑的有限期 Change 保存原账户、会话、期望代次、结论与完成时间，供原结果核对；原成功或拒绝不随当前关联变化。独立 `POST /api/v1/changes` 只在证明、原成功、账户存在及恢复截止均成立时返回完成。可靠查无可交付完成返回 `result_unavailable`，不证明原命令失败；已匹配成功但恢复期结束返回 `recovery_expired`。数据库失败不能伪装成前者。

绑定与解绑的原成功最小结果默认可恢复 600 秒，允许部署设置为 60–600 秒；每笔办理创建时固定截止，重放不延长。技术结果至少保留至完成后 24 小时且覆盖原恢复窗口，清理不改变此前已发生的业务结论。

授权、协议占用、原请求、Handoff 与 Change 各按固定截止、结果恢复、计数窗口和真实引用清理。网站新授权的持久 24 小时额度及原 callback、往返与恢复都结束后，才可删除授权；浏览器证明随授权整行消失。Change 的正常清理与原 Request 共同核对，注销可先关闭账户所属完成读取，但不提前释放协议占用。协议占用至少保留到完成后 24 小时并覆盖 code 剩余有效期；原外呼、数据库执行或未知提交未结束时不得删除。等待授权到期不能重开，仍在交换的授权不能按时间直接释放并发占用。账户注销可删除个人绑定与完成读取资格，仍须保留防止 code 二次交换所需的技术父记录，直到其独立清理条件成立。原 Operation-Id 的最后结果证据按[共同保留边界](../architecture.md#原操作与恢复)清理。清理不使旧 code 或已结束授权重新有效；新办理仍需满足本协议的证明与占用条件。

协议占用合法删除后，本地不永久识别已失效的旧 code；上游须拒绝失效凭据，使其不能形成新业务成功。不建立永久 code 黑名单，也不把请求输入摘要充作永久占用记录。

验收以真实事务交错覆盖两端绑定同一 UnionID、双向唯一冲突及同绑定无需变更。还须覆盖解绑后重绑的代次隔离、登录与解绑的两种提交顺序、原本人在外呼中失权，以及微信与手机号会话的不同后果。一次性 code 的跨用途竞争、换钥后的占用、响应丢失、未知提交与重启后按需核对分别验证。

网站验收覆盖原标签页证明、并行流程 cookie、错误或重复 callback、授权与恢复期限分离、只读结果状态以及秘密不进入跳转或日志。部署验收须取得两个真实应用同属固定开放平台账号、网站回调登记及供应商凭据有效的实际证据；协议替身和文档检查不能证明这些外部前提。
