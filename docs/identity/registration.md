# 正式注册 R2

本文拥有 R2 正式注册的业务结果、持久事实、事务与恢复规则，入口为 `POST /api/v1/registrations`，成功后可用原 Session 读取[本人资料](current.md)。共用写入屏障和提交未知核对见[架构恢复协议](../architecture.md#原操作与恢复)；待注册凭据由[短信认证](authentication.md)及对应的手机号认证入口产生。

## 业务边界与不变量

用户先验证手机号。没有未注销账户时，认证只产生有限期的待注册凭据。R2 凭有效凭据、完整姓名和居民身份证号，一次建立人员、首份实名资料、账户、默认头像、机构默认角色及登录会话。注册不建立 Workforce 或其他领域授权。手机号和当前身份证号各只能被一份未注销账户占用；暂停账户仍占用，注销后的新注册建立新的人员身份，不取得旧人员的历史或授权。

待注册凭据只许可办理其原注册流程。同一手机号后来已有账户时，旧凭据不能转为该账户的登录证明，用户须重新认证。当前占用拒绝不披露占用者的账户、姓名、手机号、人员标识或授权。
手机号验证不永久证明自然人身份。本期不识别或特殊处置手机号回收再分配，也不增加这类核验前置条件。

姓名先去除首尾空白并作 NFC 规范化，须有 1 至 64 个 Unicode 标量且无控制字符。身份证号只接受 18 位居民身份证号码，末位小写 `x` 规范为 `X`；出生日期须真实且不晚于办理日，校验位须通过 MOD 11-2。办理日从取得对象协调后的可信时点换算为 Asia/Shanghai 日期。输入校验不证明外部身份真实性。原结果重放只规范化并比较注册时的输入，不重新用今天的办理日判断原输入是否合法。

身份证号前 17 位必须是 ASCII 数字，末位必须是 ASCII 数字或 `X`。前 17 位的校验权重依次为 `[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`，加权和模 11 后按 `10X98765432` 取校验位。不按现行行政区划拒绝历史地址码，也不从号码推导业务年龄权限或性别。该规则只接受居民身份证号，不扩展到其他证件。

姓名和身份证号的规范值同时供新办理、原输入匹配与历史实名校验使用。只有新办理检查本次可信处理日；历史明文必须已经是规范形式，读取时不得静默修正。原完成的证明与规范输入匹配先于新办理的日期检查；格式错误不形成 Attempt。持久时间与 HTTP 时间仍使用 UTC，不能从客户端时区推导办理日。

R2 使用独立于 R1 的客户端 Operation-Id。原请求保持相同凭据 ID、token、姓名和身份证号。凭据 token 同时是原请求恢复证明，不另发行 secret。手机号、认证方法、可信应用来源及会话传递方式从原待注册凭据及其认证链取得；HTTP 不接收这些派生事实或账户 ID。网站短信来源使用 cookie 会话，小程序手机号来源使用 Bearer 会话；原来源不能由客户端覆盖。R2 不再调用短信、人机或微信供应商。

## 事实所有者与持久约束

| 事实               | 所有权与约束                                                                                                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registration       | R1 或其他手机号认证保存有限期凭据、可信手机号、认证身份及固定截止。新认证替换同手机号未完成的旧凭据；R2 成功消费原凭据。                                                                                            |
| Attempt            | 每笔已接纳 R2 的不可变短期结果及计数依据。按原 Operation-Id 唯一，保存凭据 ID、token 证明、[原输入证明](proofs.md#正式注册)、受保护手机号、接纳时点和 `registered`、`mobile_taken` 或 `id_number_taken` 结论。      |
| Receipt            | 原成功的账户生命周期依据。按原 Operation-Id 唯一，关联本次 Account、Person 及首份实名版本，保存原凭据 ID 与 token 证明；与成功 Attempt 使用同一完成 ID。Receipt 不保存会话 token，也不依赖会被消费的 Registration。 |
| 正式身份与角色     | Person 固定身份归属；首份实名版本保存注册时姓名和身份证号；Account 代表当前登录资格。账户默认头像与修订、Access 的“普通账户”Holder 及首条指派同时建立。角色指派的办理人与实名版本均为注册本人本次首版。             |
| Session 与 Handoff | R2 创建唯一新 Session，并以原认证身份建立限期 Handoff。原 R1 认证结果保持 `registrable`，不能凭 R1 交付 R2 的会话。Handoff 保存同一原会话的短期交接，不延长 Session 的期限。                                        |

证明先于输入比较，输入按原 Attempt 的密钥版本核对；不能因旧密钥不在活动版本而改用新密钥。同一凭据可以对应多笔 Attempt，Attempt 也不依赖可被消费、替换或清理的 Registration。Receipt 凭原 token 证明、凭据 ID 及注册时实名版本匹配原成功，不能改用当前实名版本；每个原操作与每个账户各至多一份 Receipt。证明、摘要与密文不进入普通响应或日志。

首份实名版本必须属于本次 Person，Session 与 Handoff 必须属于本次 Account 和原认证来源；注册成功由完整关系证明，不能只凭写入数量推断。Receipt 与已保留的成功 Attempt 的完成 ID、原操作、凭据 ID 和证明必须一致；Attempt 合法清理后 Receipt 独立定位原成功。拒绝 Attempt 不得附带本次正式身份、Receipt 或 Session；保留 Receipt 时，同一原操作也不能另有确定拒绝。

人员的个人事件顺序初始为 0，后续个人事件从 1 推进。首条机构指派使用 Holder 自有顺序 1，固定所选默认角色的变更，不登记个人事件。Receipt 按固定账户鉴别原注册首条指派，不要求目标当前仍持有默认角色。机构 Holder 与指派的规则由[角色与指派](../access/roles.md#当前事实与历史)拥有。

## 单事务办理顺序

应用按用例与原操作标识合并当前进程的重复执行。原证明和规范输入匹配后才可等待在途工作；进程内登记不代替持久事实。R2 没有事务外供应商调用；客户端取消不取消已开始的受监督事务。匹配者只等待工作结束，随后重新读取原结果，不共享其他请求的回执；错误证明或输入不等待原事务。

可靠业务拒绝先有界回滚，确认事务结束后再交付。收尾失败保留原原因及收尾原因；未进行业务写入的拒绝不因回滚失败而变为提交未知。

未完成初始化时不能开放 R2，因为首次指派需要机构默认角色。

| 顺序          | 判断与结果                                                                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 原完成     | 按 Operation-Id 先查 Receipt，再查 Attempt。命中时先验证原 token，再核对凭据 ID、规范输入和来源；匹配后只读取原结论。成功但交接已关闭时也不进入新办理。                                                                           |
| 2. 新办理资格 | 没有原结果时检查 Registration 的 token、来源及固定截止；再按可信办理日验证输入。凭据不成立前不披露手机号或身份证号占用。                                                                                                          |
| 3. 接纳额度   | 同手机号滚动一小时最多接纳 5 笔新 R2。只计已提交的成功和确定拒绝 Attempt；重放、格式错误、错误证明、未接纳及回滚不计。额度与本次 Attempt 共同裁决；账户注销、换密钥、凭据替换或更换认证入口均不重置窗口，额度读取失败不能当成零。 |
| 4. 当前占用   | 在原操作、凭据、手机号、身份证号及适用账户协调后，复查当前占用。手机号或身份证号已由未注销账户占用时，只保存相应确定拒绝 Attempt；原有效凭据保留，改资料须使用新 R2。                                                             |
| 5. 成功提交   | 共同建立 Person、首份实名版本、Account、默认头像及修订、Access 当前角色与首条指派、Session、Handoff、成功 Attempt、Receipt，并消费 Registration。所有事实在同一提交中成立。                                                       |

决定性事实在对象协调后重新读取，号码唯一性是最后裁决。明确的号码占用只撤销本次正式创建，再以原接纳时点保存相应拒绝 Attempt；其他约束或数据库错误使整个办理回滚，不伪造业务拒绝。初始机构角色创建失败同样共同回滚，不留下没有角色的账户。Account 与 Session 的创建时间使用同一成功时点；Receipt 的原完成时间由 Account 取得。原接纳时点不因重试改变。默认头像按可信手机号末位选择；Session 期限由原认证方法决定，网站短信默认 24 小时，小程序手机号默认 30 天，客户端平台或 User-Agent 不得改变该期限。

## 原请求恢复与故障

原成功先于新办理的待注册凭据检查。证明和注册时资料匹配后，只在原 Handoff 恢复期、原 Session 和 Account 都仍有效、来源一致时交付同一会话 token 与原到期时间。恢复期默认自 R2 成功起 10 分钟；网站和小程序按原可信来源交付各自的会话形状。恢复不新建或续期 Session，不重建默认角色或首条指派，也不因后来的实名更正、头像更换或角色变化改写原完成。交接、账户或会话已不可用时返回 `verification_required`，由用户重新认证；不提供历史注册结果读取。

原拒绝只返回原 `mobile_taken` 或 `id_number_taken`，即使号码后来释放或其他 R2 消费了同一凭据。原 token 证明错误返回 `authentication_invalid`，证明正确而注册 ID、规范输入或来源改变返回 `request_mismatch`；这两类错误不披露原值，也不计入注册次数。成功 Receipt 因合法注销消失而成功 Attempt 仍在时，原请求已完成但会话不可恢复，不能转入新注册。原结果的最后一份证据按[共同保留边界](../architecture.md#原操作与恢复)清理；即使时钟回退，已过期的原凭据也不能形成第二份正式身份。

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原 R2 的 Attempt、Receipt 和所属成功或拒绝事实。可靠确认未提交后，才可在当前凭据、期限、次数和唯一占用条件下重新办理。保留期内单次查无 Receipt 或 Attempt 不证明回滚；后续合法清理按原实体身份核对。必要核对因技术故障中断时，结局仍为未知；证明或输入不匹配只确认本请求被拒绝，不证明原成功已通过交付核验。已经得出的结论不因后续只读收尾失败而改变。

首次办理丢失提交响应后，只有恢复出的 Session 确为本次工作创建时才返回 `201`。原成功重放返回 `200`，包括该重放自身丢失提交响应后再次恢复；未知结局不交付会话，也不标为新创建。

## 清理与验收

R2 使用独立操作家族，同 UUID 的 C1、R1、初始化不混淆结果。HTTP 等待者退出不终止已接纳工作。

Registration 到期即不能使用，物理清理仍须等待实际引用与执行结束；成功消费或新认证替换时删除原凭据。Handoff 默认在成功后 10 分钟关闭交付资格，删除须等待关联执行和引用结束。Attempt 至少保留到接纳时点后 24 小时，覆盖滚动小时计数及原恢复；最后一份防重放证据的清理遵循[共同保留边界](../architecture.md#原操作与恢复)。Receipt 随账户保留，只在账户注销时删除；Person、实名版本及需要的历史不随技术结果清理。

删除最后一份原结果证据前，核对恢复期已结束且原凭据不能再次使用。清理后的标识不再承担永久防重，新的注册仍满足全部凭据与唯一占用条件；事实矛盾时停止新写入并报告完整性故障。删除结局未知时按原实体回读：原目标全部消失即清理责任已满足，原对象仍留存时保留未提交结论，读取未完成时结局仍为未知。

验收以真实事务交错覆盖：同一操作并发重试和响应丢失；同一手机号或身份证号的竞争；暂停账户占用；凭据被另一认证替换；成功与角色首条指派原子提交；拒绝计数与凭据保留；唯一冲突只撤销本次创建；实名更正、会话撤销及账户注销后的原结果读取；业务回滚、未知提交和进程重启后的按需核对。验证已提交原成功只交付原会话，已回滚且资格仍有效才重新办理，且任何失败不留下部分人员、账户或角色。R2 不发起供应商外呼。

输入验收独立推导闰日、无效日期和末位 `X` 的期望校验位，覆盖非 ASCII 数字、姓名规范化与控制字符边界；不使用被测实现生成期望。原结果重放与历史读取分别验证不套用当前办理日，历史非规范明文须报错。HTTP 验证首次 `201`、重放 `200`、占用拒绝 `409` 和交接失效 `410`；诊断不包含秘密、实名、号码及原始数据库详情。
