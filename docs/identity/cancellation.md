# 账户注销目标设计

状态：目标设计，尚未实施。本文拥有本人和管理注销的资格、共同提交、原结果及注销事实。写入准入和未知提交核对见 [架构恢复协议](../architecture.md#原操作与恢复)。账户暂停对本人服务的限制见[账户暂停与恢复](suspension.md)。

## 用例与业务边界

本人只能注销当前正常账户，使用当前有效会话并明确确认自己的账户。机构角色当前含 `institution.accounts` 的管理者，可以注销机构等级严格低于自己的其他账户；目标即使暂停也可注销。办理者须有正常账户和当前有效会话，不能经管理入口注销自己。只有 Workforce 管理权不授予账户注销权。办理时核对当前机构角色、等级、账户关系与固定目标，不以候选读取或路径 ID 代替提交时的判断。

注销成功后，原账户、全部会话和本人服务资格结束。该账户的手机号、当前身份证号及微信关联不再占用当前账户或绑定名额。重新注册产生新的人员身份、普通机构角色和新授权；号码相同也不连接或授予旧身份与历史。已注销人员的合法人员编号继续占用原编号池；核实同一自然人后的编号撤销与恢复由 Workforce 所有，不由注册或注销自动转移。

注销自动结束该人员全部领域授权及其当前领域角色，也结束其机构当前角色。不逐份制造管理者结束、角色更换或暂停恢复事实。旧申请停止办理，原阶段和原提交保持；有权管理者仍可明确结束旧申请。注销不要求先审批未发放成品、逐张核实实体卡或等待申请管理者结束。注销前已经成功保存的发放及时间保持；注销后不得补记旧申请的发放或把成功时间回填到注销之前。

注销不影响该人员过去为其他人建立的授权、角色指派、审批或发放。邀请是否继续可用按创建者当前授权判断；创建者的领域授权因注销结束时，未使用邀请码永久失效，既有接纳及容量消耗保持。必要的人员、实名、注销、授权、编号、申请、工牌和政治面貌历史按所有者原地保留；原经办人后来注销不改变他人的业务事实归属。历史读取仍由各所有者按当前权限控制，旧身份和相同号码不授予读取权。

## 入口、确认与原结果

| 入口                                   | 输入与成功结果                                                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `POST /accounts/current/cancellations` | 当前正常账户的本人，固定本人目标确认与客户端 Operation-Id；成功返回 200、原 Cancellation 的 ID 和生效时刻。      |
| `POST /accounts/candidates`            | 管理者以规范手机号精确定位当前账户，取得脱敏目标与受控确认；读取本身不授权注销。                                 |
| `POST /accounts/{id}/cancellations`    | 当前 `institution.accounts`、固定目标确认及客户端 Operation-Id；成功返回 200、原 Cancellation 的 ID 和生效时刻。 |

本人目标确认绑定当前 `accountId`、`personId` 和实名版本 ID。管理候选确认还绑定查找时的规范手机号；事务重查原账户仍对应原人员、期望实名版本及原手机号。确认内容发生变化须重新取得目标并明确确认。响应不输出完整身份证号、完整手机号或与注销无关的资料。网站入口使用准确 Origin、cookie 和 Session-Id；JSON 成功与错误均不缓存。

管理 POST 的原成功重试先按 Operation-Id 定位原 Cancellation，核对原操作者人员、目标人员、目标版本及原确认；不匹配返回 409 `request_mismatch`。匹配后只回读原事实，不再次删除对象。交付原结果仍要求管理者当前有 `institution.accounts`，原操作标识不授予历史读取权。其他有权管理者通过所属历史读取入口查看结果，不冒用原 POST。

本人注销后原会话被删除，以原会话重放 POST 返回 401。不设匿名完成查询或恢复秘密。401 和无法登录都不证明原事务结局；响应丢失后客户端停止自动重发，由重新认证和有权历史核对解释状态。新办理使用新 Operation-Id，原标识识别与保留遵守[共同协议](../architecture.md#原操作识别与保留)，不从 UUID 推断接纳窗口。

## 永久事实与数据库约束

`identity.cancellations` 为每位人员保留至多一条永久事实：独立 UUID `id`、唯一 `person_id`、办理者当时实名版本 `operator_id`、对象当时实名版本 `revision_id`、注销时手机号的受保护值、`cancelled_at`、该人员的成功事实顺序号及唯一非空 `operation_id`。这些字段全部非空。办理者版本所属人员等于对象即本人注销，否则为管理注销；不另存同义模式。对象版本与人员用组合真实引用，办理者版本引用永久实名历史。手机号按注销事实的字段和行身份独立封装，不复制 Account 密文；历史不保留原账户的当前查找摘要。

Cancellation 只追加，不更新或普通删除。注销事实与原 Account 删除必须在同一事务成立；账户删除保护在提交时核对原人员的 Cancellation、账户不存在及其账户所属当前结果已清理。删除依赖账户的行时，在原账户仍存在的语句内核对它所属人员及本次注销事实，不能待账户删除后凭失去父行的状态猜测来源。`person_id` 唯一既阻止第二次注销，也保留历史来源。原 Person、实名版本与各所有者的永久业务事实不得因账户删除级联消失。

机构指派和领域授权的历史按原 `person_id` 定位 Cancellation 来解释注销来源，不为每个授权复制 Cancellation ID。当前机构角色和领域角色在注销事务中移除，历史角色定义与指派保持原值。注销不自动释放当前人员编号，也不删除已生成工牌、已成功发放和受保护文件。无保护的本人照片在同一事务进入 `deleting`，由文件清理按原资源 ID 完成字节删除及 `deleted` 终态；注销本身不在事务内执行文件删除。头像当前引用随账户移除，文件释放遵守头像资源的引用和清理规则。

## 共同事务与在途工作

核心事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、办理者、目标账户、目标会话及所有受影响的领域授权和资源。锁后重查原完成、当前认证、权限、等级、目标确认及数据库时间。保存 Cancellation、结束全部本人领域授权与当前角色、移除机构当前角色、清理账户所属当前资料、删除 Account；任一步失败整笔事务回滚。本人或管理者的原成功先于后来权限变化时，原事实保持原结果；注销先提交后，旧会话和旧授权不得继续办理。

删除顺序遵守实际引用。先终结该账户的微信绑定、绑定变更结果、注册回执和换号完成，再删除 Handoff、Revocation、Session 和 Account；微信解绑不因此生成虚假的本人解绑完成。注册与登录的计数、供应商 code 占用和必要的协议终态仍按各自期限保留；只移除能够恢复旧账户访问的材料。仍被真实协议子项引用的技术父记录保留防重所需字段，待引用释放后清理。原 Cancellation 保留注销完成依据，不因账户子项删除失去原完成定位。

注销核心事务不等待供应商外呼。所有相关结果在最终接纳时重新核对原账户、原会话、原绑定修订及当前资格；注销先提交时，晚到结果不得重建关系或改挂同号新账户。协议占用和必要父事实独立保留，当前账户删除不释放 code 或发送机会。已进入数据库的冲突事务由共同对象锁裁决。文件清理仍等待实际工作结束，不因注销成功提前删除在用候选。

政治面貌历次取值由 Center 所有，注销后原地保留；注销核心不调用 Center。已保存的 Workforce 申请、工牌和发放依原授权与注销事实判定资格，不用一次扫描生成逐申请后果。注销引起的文件清理沿原注销 Operation-Id 与资源 ID 收尾，不生成无来源的后台办理。管理者注销目标时，办理者的会话不受目标账户的删除影响。

## 失败、重启与验收

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原 Cancellation 及其共同提交的注销后果。未提交时仍须核对当前权限和原目标。单看账户查无、会话 401、手机号可注册或文件已删除都不足以证明结局。永久 Cancellation 不到期清理。

验收覆盖本人正常与暂停、管理同级与越级、操作者失权、目标更正或换号、候选后的身份变化及原请求异输入；网站与小程序会话、微信绑定、未完成登录外呼和晚到供应商结果；全部领域授权、当前角色、邀请、未完成申请、已生成工牌、成功发放及无保护照片；任一子项删除或状态转换失败时整笔回滚；注销后同号码重新注册不取得旧身份、历史或授权；原管理结果回读、本人旧会话 401、响应丢失、数据库晚提交和普通重启的按需核对。真实数据库验证账户删除保护、组合引用、永久事实唯一性，以及注销后历史仍可按原人员和操作者追溯。
