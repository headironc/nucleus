# 账户注销目标设计

本文拥有本人和管理注销的资格、共同提交、原结果及注销事实。写入准入和未知提交核对见[架构恢复协议](../architecture.md#原操作与恢复)。账户暂停对本人服务的限制见[账户暂停与恢复](suspension.md)。注销历史列表的可见范围另行确定。

## 用例与业务边界

本人只能注销当前正常账户，使用当前有效会话并明确确认自己的账户。机构角色当前含 `institution.accounts` 的管理者，可以注销机构等级严格低于自己的其他账户；目标即使暂停也可注销。办理者须有正常账户和当前有效会话，不能经管理入口注销自己。只有 Workforce 管理权不授予账户注销权。办理时核对当前机构角色、等级、账户关系与固定目标，不以候选读取或路径 ID 代替提交时的判断。

注销成功后，原账户、全部会话和本人服务资格结束。Account 保留永久墓碑，清空当前手机号、身份证号占用和暂停指针，保留固定人员、创建时间、头像修订和微信绑定修订。手机号和当前身份证号因此释放；微信关联的占用与后果按所属目标设计处理。重新注册产生新的人员身份、普通机构角色和新授权；号码相同也不连接或授予旧身份与历史。已注销人员的合法工号继续占用原号码池；核实同一自然人后的工号撤销与恢复由 Workforce 所有，不由注册或注销自动转移。

注销自动结束该人员全部领域授权及其当前领域角色，也结束其机构当前角色。这些结束都以注销为来源，不记作管理者结束、角色更换或暂停恢复。旧申请停止办理，原阶段和原提交保持；有权管理者仍可明确结束旧申请。注销不要求先审批未发放成品、逐张核实实体卡或等待申请管理者结束。注销前已经成功保存的发放及时间保持；注销后不得补记旧申请的发放或把成功时间回填到注销之前。

注销不影响该人员过去为其他人建立的授权、角色指派、审批或发放。邀请是否继续可用按创建者当前授权判断；创建者的领域授权因注销结束时，未使用邀请码永久失效，既有接纳及容量消耗保持。必要的人员、实名、注销、授权、工号、申请、工牌和政治面貌历史按所有者原地保留；原经办人后来注销不改变他人的业务事实归属。历史读取仍由各所有者按当前权限控制，旧身份和相同号码不授予读取权。

## 入口、确认与原结果

| 入口                                          | 输入与成功结果                                                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/accounts/current/cancellations` | 当前正常账户的本人，固定本人目标确认与客户端 Operation-Id；成功返回 200、原 Cancellation 的 ID 和生效时刻。      |
| `POST /api/v1/accounts/candidates`            | 管理者以规范手机号精确定位当前账户，取得脱敏目标与受控确认；读取本身不授权注销。                                 |
| `POST /api/v1/accounts/{id}/cancellations`    | 当前 `institution.accounts`、固定目标确认及客户端 Operation-Id；成功返回 200、原 Cancellation 的 ID 和生效时刻。 |

本人目标确认绑定当前 `accountId`、`personId` 和实名版本 ID。管理候选确认还绑定查找时的规范手机号；事务重查原账户仍对应原人员、期望实名版本及原手机号。确认内容发生变化须重新取得目标并明确确认。响应不输出完整身份证号、完整手机号或与注销无关的资料。网站入口使用准确 Origin、cookie 和 Session-Id；JSON 成功与错误均不缓存。

精确候选由[共同账户候选](account.md#管理候选)提供，暂停目标仍可被披露。管理注销路径固定 `accountId`，正文必含强类型 `personId`、`revisionId` 和规范 `mobile`。输入拒绝未知字段；非法或缺失值先返回 422。业务判断随后复查准确权限，再核对原结果或新目标。新目标不存在、本人、同级或更高级统一返回 `404 target_unavailable`；确认变化为 `409 target_changed`。管理成功始终保留办理者会话，不设置 cookie。

管理 POST 先核对当前身份和 `institution.accounts`，再查原成功。完成记录绑定原办理人员、固定账户、目标人员、目标版本及规范手机号；不匹配返回 409 `request_mismatch`。匹配后只回读原事实，不再次删除对象。原操作标识不授予历史读取权。其他有权管理者通过所属历史读取入口查看结果，不冒用原 POST。

本人注销后原会话被删除，以原会话重放 POST 返回 401。不设匿名完成查询或恢复秘密。401 和无法登录都不证明原事务结局；响应丢失后客户端停止自动重发，由重新认证和有权历史核对解释状态。新办理使用新 Operation-Id，原标识识别与保留遵守[共同协议](../architecture.md#原操作识别与保留)，不从 UUID 推断接纳窗口。本人与管理注销属于同一原操作家族，原结果同时区分办理者归属；管理请求不得承接本人完成。

本人入口的 JSON 必须包含强类型 `accountId`、`personId`、`revisionId`，拒绝未知字段；格式或值不合法返回 422 `invalid_input`。当前身份失效返回 401 `authentication_invalid`，有效身份与目标确认不同返回 409 `target_changed`，原操作属于其他已完成注销时返回 409 `request_mismatch`。两个注销入口均返回 `code: ok` 和 `cancellation`，后者只含 `id`、`cancelledAt`。沿用 8 KiB 正文上限和共享写入预算；HTTP 最多等待 30 秒，等待结束不取消受管工作。

本人成功只为本次认证选中的 Session 返回空值、过去 Expires 的清理 cookie，保留原 Secure、HttpOnly、SameSite=Lax 和 Path=/。其他 Session 的 cookie 由其后的 401 处理，迟到响应不会清除后来建立的会话。失败不设置 cookie。

两个入口共用执行器的工作容量。容量耗尽返回 `429 rate_limited` 和 `Retry-After: 1`，不产生注销事实或部分后果。

## 永久事实与数据库约束

每位人员至多有一条永久注销事实，记录原账户与人员、办理者当时的实名版本、对象当时的实名版本、注销时手机号的受保护值、注销时刻、个人历史顺序号及唯一非空原 Operation-Id。原 Account 以墓碑保留，注销事实仍属于原人员。办理者为对象本人即本人注销，否则为管理注销。Person 的注销事实推进其封印状态顺序，保留当前实名版本；Account 和机构 Holder 的注销投影分别推进各自历史顺序。

本人注销要求正常账户，办理者即对象本人。管理注销要求另一个正常当前账户、办理者当前版本、准确机构权限及严格较低的目标等级，允许目标暂停。

永久完成记录与注销事实一一配对，共同提交。完成记录区分本人和管理动作，保留规范确认输入及办理者原实名版本。原操作、动作、目标、办理者及生效时刻保持一致。任一侧缺失或错配均拒绝提交；完成记录也禁止更新和删除。

注销时手机号单独受保护保存，保留期不随当前账户终结，不复制账户当前材料，也不保留原账户的当前查找摘要。原结果核对与启动都鉴别该值；保留旧键义务见[密钥引用](../operations/key-scope.md#启动与交付)。

注销事实只追加，不修改或普通删除。注销事实、Account 注销投影与墓碑必须共同成立，所属当前访问材料同时清理。依赖账户的当前资料按本次注销的人员和事实清理，不能凭墓碑或残缺状态猜测注销来源。每位人员只能注销一次。原 Person、实名版本与各所有者的永久业务事实继续保留；墓碑缺失、篡改或重新激活属于损坏，不能当作正常无账户。

Workforce 当前成员关系随注销共同结束，Grant 与首条 Assignment 永久保留；原准入重放返回 terminated。先自行退出再重新加入时，注销只结束剩余成员关系，旧结束继续作为旧 Grant 的结束来源。不能保留当前成员关系而只完成一半注销。其余领域后果随各消费者接入。

注销在同一事务追加 Holder 及未结束 Grant 的注销投影。投影固定原注销、人员、双方当时身份、Operation-Id 和生效时刻。各对象推进自有顺序，保留墓碑及最后指派。Grant 明确保存 cancellation 结束模式；已人工结束的 Grant 保持原来源。机构及领域用权资格自此终结，历史角色定义与指派保持原值。永久保留规则见[角色与指派](../access/roles.md#当前事实与历史)和[授权生命周期](../access/grants.md#人工结束与注销)。

注销不自动释放当前工号，也不删除已生成工牌、已成功发放和受保护文件。无保护的本人照片在同一事务进入 `deleting`，由文件清理按原资源完成字节删除及 `deleted` 终态；注销本身不在事务内执行文件删除。头像当前引用在注销时释放，墓碑保留原修订身份；文件释放遵守头像资源的引用和清理规则，共享素材保留。

## 共同事务与在途工作

核心事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、办理者、目标账户、目标会话及受影响的领域授权和资源。执行器先鉴别当前身份和权限，再查原完成；新办理随后核对等级、目标确认及可信时间。同一事务保存注销事实和永久完成记录，推进 Account、Holder 和未结束 Grant 的墓碑，并清理当前资料。任一步失败整笔回滚。注销先提交后，旧会话和旧授权不得继续办理。

账户所属的交接、会话状态、签发和撤销记录按完整组清理，注册交接结果和当前头像引用同时结束。永久暂停、恢复、换号和退出记录随 Account 历史保留，原换号完成也不因短期材料清理而丢失。后续微信绑定及绑定变更结果沿所属目标设计终结，不生成虚假的本人解绑完成。注册与认证的计数、供应商 code 占用和必要的协议终态仍按各自期限保留；只移除能够恢复旧账户访问的材料。仍被真实协议子项引用的技术父记录保留防重所需内容，待引用释放后清理。原注销事实保留注销完成依据，不因账户子项删除失去原完成定位。

注销核心事务不等待供应商外呼。所有相关结果在最终接纳时重新核对原账户、原会话、原绑定修订及当前资格；注销先提交时，晚到结果不得重建关系或改挂同号新账户。协议占用和必要父事实独立保留，账户注销不释放 code 或发送机会。已进入数据库的冲突事务由共同对象协调裁决。文件清理仍等待实际工作结束，不因注销成功提前删除在用候选。

政治面貌历次取值由 Center 所有，注销后原地保留；注销不调用 Center。已保存的 Workforce 申请、工牌和发放依原授权与注销事实判定资格，不用一次扫描生成逐申请后果。注销引起的文件清理沿原注销 Operation-Id 与资源收尾，不生成无来源的后台办理。管理者注销目标时，办理者的会话不受目标账户注销影响。

## 失败、重启与验收

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对永久完成、原注销事实及共同提交的后果。单看账户查无、会话 401、手机号可注册或文件已删除都不足以证明结局。永久注销事实和完成记录不到期清理。

本人内部恢复只由已确认原身份与完整输入的受管工作进入。恢复按共同协调规则鉴别永久完成、注销事实和全部后果，包含已经结束的领域授权。恢复不重新认证已删除的 Session。完成记录与注销事实都缺席才确认本操作未提交，本次返回 `dependency_unavailable`，不自动重办；必要核对无法完成时返回 `outcome_unknown`。新的显式办理重新核对当前身份和输入。已知成功不因后续收尾失败改成未知。

原事实读取和启动核验都鉴别配对完成记录及其输入。缺失完成、孤立完成、错配归属、篡改确认或未来时刻均属损坏。即使孤立完成的封印有效，也不能交付原成功或通过启动。运行中发现损坏时关闭写入接纳。

管理内部恢复使用首次办理时核验的办理人员核对永久原结果。原目标已注销，不要求目标当前资格或等级仍成立。原结果绑定办理者、目标账户、人员、实名版本及原手机号；办理者后来更正实名、退出或失权不改变这笔已接纳工作的完成依据。新的请求仍要求当前身份及管理权限，恢复不自动重办。

验收覆盖本人正常与暂停、管理同级与越级、操作者失权、目标更正或换号、候选后的身份变化及原请求异输入；网站与小程序会话、微信绑定、未完成登录外呼和晚到供应商结果；全部领域授权、当前角色、邀请、未完成申请、已生成工牌、成功发放及无保护照片；任一子项删除或状态转换失败时整笔回滚；注销后同号码重新注册不取得旧身份、历史或授权；原管理结果回读、本人旧会话 401、响应丢失、晚提交和普通重启的按需核对。

另验证 R1、实名更正、权限变更与注销的两种提交顺序：撤权先完成则拒绝新办理，注销先提交则内部恢复返回原结果。完整性负例覆盖缺少注销来源、错配目标、部分删除、错误顺序、提前释放、损坏手机号、缺失办理者、未来时刻和未释放头像，均阻止提交、原结果交付或启动。Holder 及 Grant 另验证注销投影缺失或错配、墓碑被删除或重激活，以及对象顺序与个人顺序混用。注销后历史仍可按原人员和操作者追溯。领域资格结束及原 Grant 保留另由[准入验收](../access/grants.md#验收)覆盖。
