# 账户暂停与恢复目标设计

本文拥有账户暂停、恢复、原结果与历史事实。逐会话撤销使用[会话撤销与退出](revocation.md)的事实与约束；写入屏障和提交未知核对见 [架构恢复协议](../architecture.md#原操作与恢复)。

## 用例与不变量

机构角色当前含 `institution.accounts` 的管理者，可以暂停或恢复机构等级严格低于自己的其他账户。不比较 Workforce 角色等级，也不能对自己使用管理入口。办理者须有正常账户和当前有效会话。目标可以处于暂停状态；管理资格以当前机构角色、目标当前角色及账户关系在决定性事务中重新判断。没有人工理由字段，不接受追溯或预约生效时点。

暂停从成功提交起阻止目标账户的全部本人服务，包括本人退出 Workforce、取消未发放申请及本人注销。它使目标账户当次全部会话失效，网站和小程序均受影响。手机号、当前身份证号和微信绑定继续由该账户占用；人员身份、实名、机构角色、领域授权和历史保持。机构角色在账户暂停期间不能用于办理。恢复使账户重新具备按当前条件办理的资格，但不复活旧会话，不解除任何独立的领域暂停，也不恢复已经结束的授权、角色或申请。用户须重新认证取得新会话。

账户状态保存当前暂停 ID，资格判断直接读取已鉴别状态，不从暂停历史推导。一个账户同时至多有一条未恢复的暂停。已经恢复的历史保持不变，后来再暂停建立新的暂停；恢复只能清空当前相同的暂停 ID，旧恢复不能解除后来那次暂停。同状态的新请求返回 409 `state_conflict`，不制造历史事实。

## 入口、目标与结果

| 入口                                            | 输入与成功结果                                                                                                                         |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/accounts/candidates`              | 使用[共同账户候选](account.md#管理候选)，取得固定身份及当前开放 Suspension ID。                                                        |
| `POST /api/v1/accounts/{id}/suspensions`        | 当前 `institution.accounts`、目标确认和客户端 Operation-Id；成功返回 201、原 Suspension 的 ID 与生效时刻。                             |
| `POST /api/v1/accounts/{id}/resumptions`        | 当前 `institution.accounts`、目标确认、明确的 `suspensionId` 与新的客户端 Operation-Id；成功返回 200、原 Resumption 的 ID 与生效时刻。 |
| `GET /api/v1/accounts/{id}/suspensions` 及 HEAD | 当前 `institution.accounts`；分页读取未注销、机构等级严格较低的其他账户的永久暂停及对应恢复历史。                                      |

暂停和恢复消费[共同账户候选](account.md#管理候选)，与管理注销保持同一披露范围。两个办理 POST 沿网站 cookie、Session-Id、必填准确 Origin、已认证写入预算及 8 KiB 正文上限。路径固定目标 Account，在认证前解析。暂停正文必含强类型 `personId`、`revisionId` 和规范 `mobile`；恢复正文在同一层另含必填 `suspensionId`，不增加嵌套确认对象。暂停成功及匹配重放返回 `201`、`{ code: "ok", suspension: { id, suspendedAt } }`。恢复返回 `200`、`{ code: "ok", resumption: { id, resumedAt } }`，其中 ID 为原 Suspension ID。

传输认证先于 JSON。未知、重复、缺失或非法正文字段返回 422，再判断业务权限和原操作。原身份失效为 401，缺少 `institution.accounts` 为 403。原输入不同为 `409 request_mismatch`；新目标不存在、本人或等级不可披露为 `404 target_unavailable`。旧身份确认返回 `409 target_changed`。新暂停要求目标正常，新恢复要求所确认的暂停仍开放，否则返回 `409 state_conflict`。三个入口最多等待 30 秒，取消等待不取消已接纳工作；响应均为 no-store，不设置管理员 cookie。

目标确认固定 `accountId`、`personId` 和当前实名版本 ID；管理者若从手机号查找目标，确认还绑定查找时的规范手机号。事务必须核对该账户仍代表原人员、仍有期望实名版本，且手机号若被用于确认仍指向原账户。候选响应和完成响应不输出完整手机号、身份证号或其他超出管理任务的资料。目标 ID 和路径不替代当前权限与等级检查。

每条 POST 静态要求管理者当前认证，使用各自的 Operation-Id。暂停与恢复的原操作各自独立：相同 Operation-Id 可分别完成一次暂停和一次恢复，不混淆原结果。当前办理者的原会话及准确权限先行核对，原结果再先于新目标的当前状态与等级检查。原成功重试按操作标识定位原暂停或恢复，核对原操作者、目标、原手机号和原输入；恢复另匹配所确认的暂停。不匹配返回 409 `request_mismatch`。匹配后只回读原事实，不重新暂停、恢复或选择会话。当前权限仍须允许向该管理者交付目标结果，操作标识本身不授予读取权。后来目标状态、手机号、实名版本或角色发生变化，不改写原事实，也不把旧完成应用于新状态。办理人后来失权不改变原暂停或恢复的完成依据。新办理必须使用新 Operation-Id。

## 历史读取

历史入口沿当前账户管理范围授权。办理者须有有效网站会话及准确的 `institution.accounts`。目标须为未注销的其他 Account，且当前机构等级严格较低。目标暂停不妨碍读取。身份失效返回 401，缺准确权限返回 403；本人、无当前账户、同级或更高级目标统一为 `404 target_unavailable`。不开放本人历史、无当前账户的人员历史或跨账户总表。

`GET /api/v1/accounts/{id}/suspensions` 和 HEAD 接受共同 [分页参数](../http/lists.md)，没有其他筛选。以暂停为分页单位，按 Account 自有的 `sequence DESC, id DESC` 排序，不以 UUID 或同刻时间猜先后。响应为 `{ code: "ok", count, suspensions }`。每条暂停含 `id`、`subject`、`operator`、`sequence`、`suspendedAt`、`operationId` 和必有的 `resumption`。真实未恢复时后者为 `null`；已有恢复包含自身的 `subject`、`operator`、`sequence`、`resumedAt` 和 `operationId`。恢复与所属暂停共用 ID，不重复输出。

两种动作各自披露当时的双方固定实名版本。`subject` 与 `operator` 均只含 `personId`、`revisionId` 和脱敏 `name`；响应不含手机号或身份证号。后来实名变化、原办理者账户注销或旧会话清理均不改写披露。目标当前账户仍是入口资格；历史办理者则不依赖当前账户。

权限、目标、计数与完整页共用[同页快照](../http/lists.md)。必要关联损坏不能过滤为未恢复，所需实名版本缺失不能静默跳过；必要事实损坏关闭写入接纳，普通查询故障不误关。任何必要步骤失败都不交付半页或伪造空集。历史读取不产生原操作或未知写入结局。HTTP 使用共同元数据预算及读取同源协议；Origin 存在时必须准确，缺省时要求 `Sec-Fetch-Site: same-origin`。响应为 no-store，不设置 cookie；HEAD 保留状态和头且无正文。

## 事实、约束与权限

暂停记录原账户与人员、办理者和目标当时的实名版本、原手机号、生效时刻、Account 历史顺序和非空原 Operation-Id。恢复与所属暂停共用 ID，另记录原人员、办理者和目标当时的实名版本、恢复时手机号、恢复时刻、更大的 Account 顺序和本次非空 Operation-Id。两份事实各自按 Operation-Id 唯一，不对两个动作施加跨动作唯一性。暂停和恢复推进账户状态与自身历史，不推进 Person 的个人事件顺序；账户注销后历史与墓碑共同保留。

历史手机号受保护保存，不参与当前号码查找；不同事实的手机号互不替代，即使暂停与恢复共用 ID 也不能互换。原输入从永久事实核对，不另设输入证明。暂停与恢复事实以及必要的办理者、目标身份历史在账户注销后原地保留；手机号当前占位与历史值分别解释，不用现在的手机号改写历史。历史不可修改，也不参与普通清理。一个账户同时至多一条未恢复暂停；恢复只指向原暂停；恢复不早于暂停，并在暂停之后办理。

暂停固定当次全部尚未撤销的保留会话集合，包含已经过期的会话。每条撤销绑定原暂停 ID 与原请求 Operation-Id。暂停事实、账户状态、会话撤销及对应 Handoff 删除共同提交。更早的合法撤销保持原时间与原因，不能冒充本次暂停的撤销；已经清理的完整会话组允许缺席。即使目标没有会话，暂停仍是本次成功的原结果；不得要求至少一条撤销才承认暂停。集合边界在持锁决定时固定，不按时间戳猜测。恢复只清空当前暂停指针，不创建会话，不改写旧记录或固定集合。

每次状态办理依据已提交的前一状态：同一次办理不能既暂停又恢复，也不能既恢复又再次暂停。账户暂停期间不能建立 Session 或 Handoff，恢复完成前同样不能。两种状态动作均保持当前机构角色不变。

## 事务、并发与恢复

业务事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、办理者、目标账户及目标会话，再重查原结果、双方当前账户与角色、`institution.accounts` 权限、严格机构等级、目标身份确认、当前暂停状态和可信时间。首次候选读取不能决定最终目标。权限变化、角色变化、目标换号、更正、注销和新的登录均按提交先后决定结果。

新暂停检查目标当前正常，再建立暂停，撤销当次全部尚未撤销的会话并删除这些会话的 Handoff。登录先于暂停提交，新会话在撤销范围内；暂停先于登录提交，旧登录的最终接纳须发现账户已暂停并拒绝，不能随后建可用会话。与本人服务并发时，先提交的本人操作保留原结果；暂停先提交后，本人旧会话不能继续写入。暂停不追加后台任务扫描后来会话。

新恢复必须明确指向目标当前唯一未恢复的暂停。它保存共享 ID 的恢复，不创建新会话，也不触碰其他领域事实。恢复先提交后，用户可按当前登录条件重新认证；仍在使用的旧会话保持撤销。原恢复重试先定位原完成，不能拿它解除新一轮暂停。暂停、恢复都没有事务外供应商调用，HTTP 取消不取消已开始的受监督业务事务。

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原暂停／恢复和所属共同后果，并保留首次办理时核验的办理人员。可靠确认未提交后，仍须核对当前权限、原目标和状态。完整确认原结果后，只读收尾失败不抹去结论。永久暂停和恢复事实不参与到期清理；后续账户状态或会话变化不能改写原完成。

## 验收

暂停生命周期从真实初始化、R1/R2 和在线指派开始，核对暂停事实、原角色、逐会话撤销和 Handoff 删除；原暂停与原指派在后续更换及普通重启后仍返回原结果。验证管理员会话保持有效、目标当前会话失效，同一原输入返回原 ID 与时刻，异输入和新请求分别拒绝；零会话目标仍可暂停；保留的过期未撤销会话被撤销，近期退出的原时间与退出事实不变。

交错验证 R1 与暂停的两种提交顺序、同级目标不可披露、等待期间失去准确权限的办理者不能写入，以及提交确认丢失、确认回滚、晚提交、恢复读取失败和取消等待；办理人在内部恢复完成前退出不改变原结果，新请求被拒绝，重启仍认可历史。完整性负例覆盖残缺撤销组、暂停后追加会话或交接、本次先写的退出冒充原失效、历史手机号与版本损坏；原结果与启动核验都不能将损坏当作成功或输入不匹配。共同候选见[账户验收](account.md#验收)。

恢复生命周期验证暂停与恢复复用同一 Operation-Id 时分别保存各自原结果；恢复保持原角色与原撤销后果，旧会话保持失效，新 R1 才建立可用会话。再次暂停后，旧恢复重放仍返回旧 ID 与时刻，新操作携带旧暂停确认则拒绝。恢复后同刻建立的新会话不进入旧集合；旧会话与暂停同刻而缺少撤销时，原结果与启动都拒绝损坏。同一次办理暂停后恢复、恢复后再次暂停均被拒绝。HTTP 另覆盖扁平强类型正文、准确权限、严格等级、三个 POST 的共享预算、200 恢复结果及不设置 cookie。

历史读取验证满页完整记录、恢复使用另一办理者、目标在暂停后更正而旧披露保持原版本、分页按历史顺序且不受同刻时间影响。读取期间并发完成恢复、再次暂停、办理者失权和目标升等时，当前请求仍返回原快照，后续请求按新事实判断。必要实名、历史手机号或版本损坏使整页失败并关闭接纳，普通查询失败不关闭接纳；读取截止、取消、HEAD、405 Allow 和同源认证顺序分别验证。领域授权消费者接入时验证自身暂停不因账户恢复而解除。
