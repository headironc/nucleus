# 账户暂停与恢复目标设计

状态：目标设计，尚未实施。本文拥有账户暂停、恢复、原结果与历史事实。逐会话撤销使用[会话撤销与退出](revocation.md)的事实与约束；写入屏障和提交未知核对见 [架构恢复协议](../architecture.md#原操作与恢复)。

## 用例与不变量

机构角色当前含 `institution.accounts` 的管理者，可以暂停或恢复机构等级严格低于自己的其他账户。不比较 Workforce 角色等级，也不能对自己使用管理入口。办理者须有正常账户和当前有效会话。目标可以处于暂停状态；管理资格以当前机构角色、目标当前角色及账户关系在决定性事务中重新判断。没有人工理由字段，不接受追溯或预约生效时点。

暂停从成功提交起阻止目标账户的全部本人服务，包括本人退出 Workforce、取消未发放申请及本人注销。它使目标账户当次全部会话失效，网站和小程序均受影响。手机号、当前身份证号和微信绑定继续由该账户占用；人员身份、实名、机构角色、领域授权和历史保持。机构角色在账户暂停期间不能用于办理。恢复使账户重新具备按当前条件办理的资格，但不复活旧会话，不解除任何独立的领域暂停，也不恢复已经结束的授权、角色或申请。用户须重新认证取得新会话。

账户当前是否暂停由该人员是否有一条尚无对应恢复的 Suspension 推导；Account 不另存同义状态。一个人员同时至多有一条未恢复的 Suspension。已经恢复的历史保持不变，后来再暂停建立新的 Suspension；旧恢复请求只能对应自己的原暂停，绝不能解除后来那次暂停。同状态的新请求返回 409 `state_conflict`，不制造历史事实。

## 入口、目标与结果

| 入口                              | 输入与成功结果                                                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /accounts/candidates`       | 当前 `institution.accounts`；以规范手机号精确定位当前账户，返回脱敏目标、当前暂停状态、受控目标确认和适用的原 Suspension ID。候选读取不授权后续写入。 |
| `POST /accounts/{id}/suspensions` | 当前 `institution.accounts`、目标确认和客户端 Operation-Id；成功返回 201、原 Suspension 的 ID 与生效时刻。                                            |
| `POST /accounts/{id}/resumptions` | 当前 `institution.accounts`、目标确认、明确的 `suspensionId` 与新的客户端 Operation-Id；成功返回 200、原 Resumption 的 ID 与生效时刻。                |

目标确认固定 `accountId`、`personId` 和当前实名版本 ID；管理者若从手机号查找目标，确认还绑定查找时的规范手机号。事务必须核对该账户仍代表原人员、仍有期望实名版本，且手机号若被用于确认仍指向原账户。候选响应和完成响应不输出完整手机号、身份证号或其他超出管理任务的资料。目标 ID 和路径不替代当前权限与等级检查。网站入口按准确 Origin、cookie 和 Session-Id 认证；成功及错误 JSON 均不缓存。

每条 POST 静态要求管理者当前认证，使用各自的 Operation-Id。原成功重试先按操作标识定位原 Suspension 或 Resumption，核对原操作者、目标和原输入；不匹配返回 409 `request_mismatch`。匹配后只回读原事实，不重新暂停、恢复或选择会话。当前权限仍须允许向该管理者交付目标结果，操作标识本身不授予读取权。后来目标状态、手机号、实名版本或角色发生变化，不改写原事实，也不把旧完成应用于新状态。新办理必须使用新 Operation-Id。

## 事实、约束与权限

`identity.suspensions` 保存独立 UUID 事实 ID、`person_id`、办理者当时实名版本 `operator_id`、目标当时实名版本 `revision_id`、目标当时手机号的受保护值、`suspended_at`、该人员的成功事实顺序号和非空 `operation_id`。`identity.resumptions.id` 复用被恢复的 Suspension ID，另保存原人员、恢复办理者和目标当时实名版本、恢复时手机号的受保护值、`resumed_at`、更大的人员顺序号及本次非空 Operation-Id。两份事实各自按 Operation-Id 唯一；恢复的共享 ID 真实引用原 Suspension，不为一次恢复另造对象 ID。

目标当时实名版本与 `person_id` 使用组合真实引用，办理者引用当时自己的实名版本。受保护手机号按各事实字段与行身份封装，不能复制另一行密文换用身份。暂停与恢复事实以及必要的办理者、目标身份历史在账户注销后原地保留；手机号当前占位与历史密文分别解释，不用现在的手机号改写历史。历史无 UPDATE，也无普通清理 DELETE。运行身份只有所属受控读取和插入权限；数据库保护一个人员同时至多一条未恢复暂停、恢复只指向原暂停、恢复时间不早于暂停时间及人员成功顺序严格前进。

会话撤销使用 `identity.revocations`，模式固定为 `suspension`，每行的 Operation-Id 为该次暂停原请求标识。暂停事实、该账户所有尚未撤销的会话 Revocation、对应 Handoff 整行删除在一笔业务事务共同提交。提交时核对目标账户仍存在、原暂停事实配对、当次会话已全部失效以及撤销集合的账户与时间一致。即使目标没有会话，Suspension 仍是本次成功的原结果；不得要求凭至少一条 Revocation 才承认暂停。恢复事实在一笔事务提交，不删除旧 Revocation、Handoff 或 Suspension。

## 事务、并发与恢复

业务事务按[共同锁顺序](../architecture.md#锁与决定性读取)协调原操作、办理者、目标账户及目标会话。锁后以新语句重查原结果、双方当前账户与角色、`institution.accounts` 权限、严格机构等级、目标身份确认、当前暂停状态和数据库时间。首次候选读取不能决定最终目标。新增竞争键使事务回滚并按完整集合有界重试；权限变化、角色变化、目标换号、更正、注销和新的登录均按提交先后决定结果。

新暂停检查目标当前正常，再建立 Suspension，撤销当次全部尚未撤销的会话并删除这些会话的 Handoff。登录先于暂停提交，新会话在撤销范围内；暂停先于登录提交，旧登录的最终接纳须发现账户已暂停并拒绝，不能随后建可用会话。与本人服务并发时，先提交的本人操作保留原结果；暂停先提交后，本人旧会话不能继续写入。暂停不追加后台任务扫描后来会话。

新恢复必须明确指向目标当前唯一未恢复的 Suspension。它保存共享 ID 的 Resumption，不创建新会话，也不触碰其他领域事实。恢复先提交后，用户可按当前登录条件重新认证；仍在使用的旧会话保持撤销。原恢复重试先定位原完成，不能拿它解除新一轮暂停。暂停、恢复都没有事务外供应商调用，HTTP 取消不取消已开始的受监督业务事务。

提交未知按[阶段恢复依据](../architecture.md#原操作与恢复)核对原 Suspension／Resumption 和所属共同后果。可靠确认未提交后，仍须核对当前权限、原目标和状态。永久暂停和恢复事实不参与到期清理；后续账户状态或会话变化不能改写原完成。

## 验收

真实事务交错须覆盖：同级、越级和本人管理拒绝；办理者失权、账户暂停、目标角色变化与候选读取后的目标变化；无会话、有网站及小程序会话、已有撤销会话和登录并发时的准确撤销；任一 Revocation、Handoff 或历史插入失败的整体回滚；恢复只对应原暂停、旧恢复晚到与再次暂停；恢复后旧会话和领域暂停不复活；原成功重试、异输入拒绝、响应丢失、数据库晚提交及普通重启的按需核对。数据库约束还须证明不同人员的版本不能拼接、同一人员不能有两条开放暂停、恢复不能指向错误暂停或倒退顺序，并验证无会话目标也能留下完整暂停事实。
