# 账户当前事实目标设计

状态：目标设计，尚未实施。Account 是一名 Person 当前可登录身份及号码占用的所有者。注册建立账户，暂停改变使用资格，手机号更换和实名更正改变相应当前号码；注销结束账户。各动作的权限、原结果和事务由所属 [Identity 用例](../README.md#identity-用例)规定。

## 建立与当前占用

注册从有效待注册凭据取得可信手机号，从同一份完整注册输入取得首版实名资料及当前身份证号。Account 固定引用新 Person；其建立时点与本次 Session 使用同一个数据库成功时点，原注册接纳时点单独保存。账户初始头像修订与微信绑定修订分别生成，即使尚未绑定微信也有初始修订身份；两种修订的意义和变更互不替代。账户、默认头像、人员、首版及原注册成功结果共同提交，任一密钥、随机、文件或数据库失败均不得留下部分账户。

当前手机号和当前身份证号各有独立的确定性查找摘要。编码、用途和换钥见[号码查找摘要](lookup.md)。手机号密文以新 Account 的身份与字段用途重新封装，使用新 nonce；不能复制待注册凭据中的密文。身份证号密文只归实名版本，Account 保存当前占用摘要，不复制第二份身份证号密文。当前两类号码的唯一约束包含暂停账户；历史实名版本不独立占用当前身份证号。手机号或身份证号预查须区分确实无占用与查询失败，最终以同事务的唯一约束裁决，不能凭预查结果承诺注册成功。

## 修订与读取

头像和微信绑定分别推进自身修订，写入者保留另一修订；更正当前身份证号时同步更新当前查找摘要。当前账户读取须保留固定人员关系、原建立时间和两项真实修订，不在行解码时重新构造、解密、重算摘要或补造缺失字段。手机号认证查找包含暂停账户，再按该人员的当前暂停事实分流；注册将已有暂停账户视为占用。`GET /accounts/current` 在同一决定性快照中组合账户、当前实名、头像和绑定，所需关系损坏或解密失败不得伪装成未绑定、空资料或无账户。

数据库唯一错误只在 SQLSTATE、schema、table 与允许的约束名准确匹配时映射为号码占用；其他唯一、外键、解码及驱动错误保留技术原因。明确占用按注册用例的保存点流程处理，顶层提交失败及结局未知由[写入协调](../architecture.md#原操作与恢复)处理。账户构造完成或插入返回都不证明业务事务已提交。

## 验收

验证新账户手机号封装与待注册密文不能互换、手机号和身份证号摘要用途隔离、暂停账户仍占用、历史实名版本不占用当前号码、头像与微信修订互不覆盖、部分注册回滚、准确唯一错误映射，以及当前读取对损坏或缺失必要事实的拒绝。
