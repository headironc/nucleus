# 会话事实与签发目标设计

认证或注册用例在可信成功事务中签发 Session；当前请求证明和资格复查由[当前身份](current.md)负责，撤销由[会话撤销与退出](revocation.md)负责。短信 Session 固定原账户、会话 ID、token 摘要、认证方法、实际应用身份、建立和到期时间。HTTP 仅取得所属响应投影，不直接输出存储事实。

## 来源与秘密

Session 连同签发记录及适用的撤销记录组成完整短期历史。保留期间，同一 Session ID 不能再建会话或交接。保留期结束后，所属用例共同清理 Handoff、签发记录、撤销记录和 Session；合法缺席的 Handoff 不免除会话自身核验。退出的永久原结果由 Account 保存，不随短期会话组删除。

会话采用不透明随机 token，不使用 JWT。服务端生成 32 字节安全随机材料，以规范无填充 Base64url 交付，只保留原字节的 SHA-256 摘要。网站通过受保护 cookie 传递，小程序通过 Authorization Bearer 传递。两者的 token 格式相同，每条会话的来源固定。Bearer 是传递方式，不要求 token 为 JWT。每次用权鉴别当前 Session 和 Account 状态，再判断撤销、期限及账户资格；不从客户端签名声明或历史聚合替代这些事实。

本设计不增加 refresh token、滑动续期、BFF 或单独的登录网关。到期、原结果交接与重新认证继续由所属协议决定。会话传递方式共用业务路由，凭据选择与冲突拒绝由[当前身份](current.md#凭据选择与来源)拥有。

会话 token 与待注册凭据 token 是独立秘密，不能互换或仅因格式正确而视为有效。两者按所属协议验证原始字节与规范编码，不在普通序列化、诊断或日志中泄露。短信会话固定使用网站 AppID 与 cookie。其他来源的目标约束为：网站微信使用网站 AppID 与 cookie，小程序手机号和小程序微信使用小程序 AppID 与 Bearer。来源组合只证明方法与应用角色相容，不能替代供应商结果、原请求、真实登录资格或当前绑定检查。可信应用身份在启动、签发和原结果读取中使用同一组固定设置，不由客户端传递或事后重新解释。

## 建立与解码

Session 始终来自真实认证。R1 会话不属于注册结果；R2 会话另属于所属注册结果，原认证仍为 `registrable`。Handoff 使用新 Session 绑定独立 token。R2 的交接窗口从注册成功开始，不延续原 Registration 的截止。两个用例按自己的原操作清理会话子项；R1 清理不能越过 R2 的真实引用删除原认证。

服务端生成新会话 ID 与原 token；所属认证流程提供已验证账户和来源，适用微信关联由相应目标设计确定。在对象协调后取得决定性时点作为建立时间，按认证方法的会话期限计算严格晚于建立时间的到期时点，时间加法溢出即失败。同一个原 token 用于本次有限期交接。会话建立与原业务成功、交接及执行结果共同提交。提交结局未知时先核对原事实，不另签一条替代会话。

Session 使用自身历史顺序，不再捕获个人事件顺序。签发为第 1 条记录，固定原认证、适用的 R2 原结果和签发 Operation-Id；一次撤销为第 2 条记录。状态与记录共同封印，撤销后的会话不能再次撤销或重新激活。撤销固定原操作及退出、账户暂停或换号的真实原因；原签发字段保持不变。

账户存在开放暂停时不签发会话，恢复尚未完成时同样不签发。暂停撤销的原集合是暂停成立前已建立的会话；恢复后新建的会话即使与旧暂停同刻，也不属于旧集合。

合法到期及撤销的旧会话仍可鉴别原事实。已匹配会话损坏是依赖故障，不伪装成错误凭据。会话事实本身不建立可信 Actor；一次请求必须按[当前身份](current.md)重新核对原 token、来源、账户和期限。Session 建立后不能改挂账户、替换摘要、来源或期限。微信关联及解绑后果仍由相应目标设计约束，不从短信会话推导绑定资格。

## 原结果读取与核验

原结果查询由 Session 所有者按原认证或原注册结果定位会话，并鉴别状态封印及锚定。R1 按原认证定位，R2 按原注册结果定位。取得 Session 不要求 Handoff 仍存在。

原证明通过后，所属用例在原对象协调内读取 Session 与交接，清理及退出不能插入交付过程。交付核对固定部署 AppID、可信时间、原 token 摘要和双方期限。Handoff 截止必须晚于 Session 建立时点，且不超出会话期限。仍保留的交接先鉴别，再判断到期，损坏材料不被伪装成正常到期。撤销和暂停检查仍由原用例完成。

Handoff 缺席时无法再次交付 token，但客户端已有的 token 仍可验证 Session。普通会话认证不读取 Handoff。核验失败沿用技术失败及关闭接纳的处理，不构造业务成功。

## 验收

验证四类合法来源与非法交叉组合、两类秘密不可互用、同一原 token 的摘要与交接、期限溢出及等于建立时间的拒绝、历史合法终态读取、损坏会话报依赖故障、旧微信关联清空后的撤销，以及未知提交不补发会话。原结果重放保留同一 token、会话 ID 和到期时间；交接清理后的认证及重启仍可使用原会话。

账户恢复不会复活旧会话；恢复后同刻建立的新会话不进入旧暂停集合，旧会话仍必须具备原撤销。恢复未完成或存在开放暂停时不签发会话。具体范围见[暂停恢复验收](suspension.md#验收)。
