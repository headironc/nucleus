# 会话事实与签发目标设计

状态：目标设计，尚未实施。认证用例在可信成功事务中签发 Session；当前请求证明和资格复查由[当前身份](current.md)负责，撤销由[会话撤销与退出](revocation.md)负责。Session 固定原账户、会话 ID、token 摘要、认证方法、实际应用身份、适用微信关联、建立和到期时间。HTTP 仅取得所属响应投影，不直接输出存储事实。

## 来源与秘密

会话采用不透明随机 token，不使用 JWT。服务端生成 32 字节安全随机材料，以规范无填充 Base64url 交付。持久会话只保存原字节的 SHA-256 摘要。网站通过受保护 cookie 传递，小程序通过 Authorization Bearer 传递。两者的 token 格式相同，每条会话的来源固定。Bearer 是传递方式，不要求 token 为 JWT。每次用权仍查询当前会话、撤销和账户资格，不从客户端持有的签名声明替代这些事实。

本设计不增加 refresh token、滑动续期、BFF 或单独的登录网关。到期、原结果交接与重新认证继续由所属协议决定。会话传递方式共用业务路由，凭据选择与冲突拒绝由[当前身份](current.md#凭据选择与来源)拥有。

会话 token 与待注册凭据 token 是独立秘密，不能互换或仅因格式正确而视为有效。两者按所属协议验证原始字节与规范编码，不在普通序列化、诊断或日志中泄露。会话方法只有短信、手机号和微信身份；网站短信和网站微信使用网站 AppID 与 Cookie，小程序手机号和小程序微信使用小程序 AppID 与 Bearer。来源组合只证明方法与应用角色相容，不能替代供应商结果、原请求、真实登录资格或当前绑定检查。可信应用身份在启动、签发、解码和原结果读取中使用同一组固定设置，不由客户端传递或事后重新解释。

## 建立与解码

服务端生成新会话 ID 与原 token；所属认证流程提供已验证账户、来源和适用微信关联。在对象协调后取得数据库决定性时点作为建立时间，按认证方法的会话期限计算严格晚于建立时间的到期时点，时间加法溢出即失败。原 token 的 32 字节生成材料计算 SHA-256 摘要；同一个原 token 用于本次有限期交接。会话建立与原业务成功、交接及执行结果共同提交。提交结局未知时先核对原事实，不另签一条替代会话。

存储行解码保留原 ID、摘要、来源、关联和时间，不重新生成 token、摘要、期限或标识；合法到期、撤销及已清空关联的旧行仍可解码。`expires_at` 必须严格晚于 `created_at`；应用身份与方法组合、摘要长度和关联形状也须符合存储约束。已匹配行损坏是依赖故障，不伪装成错误凭据。解码本身不建立可信 Actor；一次请求必须按[当前身份](current.md)重新核对原 token、账户、撤销、期限和当前微信关联。Session 建立后不能改挂账户、替换摘要、来源或期限；微信解绑只可在撤销原会话后按受保护关系清空旧关联。

## 验收

验证四类合法来源与非法交叉组合、两类秘密不可互用、同一原 token 的摘要与交接、期限溢出及等于建立时间的拒绝、历史合法终态解码、损坏存储行报依赖故障、旧微信关联清空后的撤销，以及未知提交不补发会话。
