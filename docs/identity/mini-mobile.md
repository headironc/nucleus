# 小程序手机号认证目标设计

状态：暂缓实施的后续设计参考，不属于当前内部工牌交付范围。恢复本能力前按[简化架构](../architecture.md)重新核对需求和技术方案；以下旧目标不要求当前功能建立封印、版本链、后台恢复或其他前置设施。

本文拥有小程序取得可信手机号、匿名登录或待注册分流、一次性 code 占用，以及原认证结果恢复。短信认证见[短信认证](authentication.md)，正式建户见[正式注册](registration.md)，共用执行与提交核对见 [架构恢复协议](../architecture.md#原操作与恢复)。微信身份登录与绑定由[微信身份设计](wechat.md)拥有。

## 用例与不变量

用户在小程序主动提供微信手机号授权 code。服务端用固定小程序身份交换，并从可信结果取得大陆手机号。当前已有未注销且可登录的账户时，本次认证创建独立会话；没有账户时，只创建限期注册凭据。注册前不创建账户、人员或实名资料。暂停账户继续占用手机号，认证拒绝，不把暂停解释为无账户。

手机号认证不建立微信身份绑定，也不依赖 UnionID 或另一端先登录。微信手机号授权 code 与微信身份登录 code 属于不同协议，不能互换或由服务端猜测用途。同一手机号的新一次成功认证替换尚未完成的旧注册凭据；原认证结果重读不复活旧凭据。若其他办理先注册该号码，旧凭据不能转换成登录许可，用户须重新认证。

手机号只支持规范化的中国大陆号码。手机号控制权只由本次可信交换确认，不由客户端提交的号码、OpenID、昵称、设备资料或已有微信身份绑定推断。号码可能在现实中重新分配；本次认证不宣称永久识别自然人。

## 输入与供应商边界

小程序登录的 HTTP 输入和 Bearer 结果见[匿名身份办理 HTTP](../http/identity.md)。本用例只接纳自身的手机号授权 code；新 code 必须使用新操作标识。可信小程序 AppID、凭据、会话传递方式和认证方法由服务端固定，客户端不能选择或覆盖。

服务端只向固定微信小程序手机号接口发送该协议的原 code。后台访问凭据按固定小程序 AppID 与受保护 AppSecret 取得，并仅在进程内缓存；缓存不承载业务结果。缓存可用期以供应商返回的实际剩余期限减去 60 秒裕量为准，剩余不足裕量时不发起 code 交换。普通获取不强制刷新在途凭据；缓存失效时从固定供应商入口重新取得。网站用户授权 token 不进入此缓存。

准备凭据和交换共用一次 10 秒本地预算，不因内部重试重新计时。固定 HTTPS 目标须校验证书和主机名，拒绝自动重定向。调用不在数据库事务内，HTTP 层不自动重试 code 交换。供应商响应体上限为 64 KiB；最终诊断只记录静态操作名、数值错误码和耗时，不记录请求 URL 的查询串、正文或供应商敏感材料。供应商凭据错误、限流、超时或响应结构错误属于依赖故障，不能冒充用户输入错误。

可信交换结果必须同时满足成功状态、完整手机号资料及水印 AppID 等于固定小程序 AppID。服务端由国家码与纯号码构造规范值，并核对供应商给出的完整号码一致；完整号码可采用带或不带 `+` 的国际形式，国家码为 `86` 时也可采用相同的国内形式。结构缺失或矛盾作为依赖故障处理，不猜测或修剪号码。可信交换成功但国家码不是 `86`，或规范号码不在项目允许号段时，保存本次确定的 `mobile_unsupported` 拒绝，不建立会话或注册凭据。手机号接口不要求 UnionID；供应商 token、code 和原手机号不进入日志或普通响应。

## 原请求、占用与结果

`Request` 按 Operation-Id 唯一，保存原用途、固定小程序来源、secret 证明及规范输入摘要；字节编码见[原输入证明](proofs.md)。原请求重试先核对 secret，再匹配完整原输入；错误证明返回 `authentication_invalid`，证明正确但输入或来源改变返回 `request_mismatch`。两者都不交换 code，也不泄露原值。

独立的 `Verification` 保存手机号 code 的一次性占用和执行身份；`Authentication` 保存本次登录或待注册的业务结论。占用摘要见[原输入证明](proofs.md)。新占用在同一 code 对象协调下跨所有仍保留的密钥版本判定唯一。占用与原 Request、待决 Authentication 共同提交。确认提交后，只有原受监督执行者可在事务外交换一次；并发重试只等待或读取原办理。占用提交未知时先核对，不能外呼。

协议执行有固定接纳截止与一次终态。可信交换成功表示手机号验证可用，不表示账户一定能登录。最终事务锁后按当前手机号占用和账户状态分流，并把协议终态、Authentication 结论及下列适用事实共同提交：

| 当前事实             | 本次原结果                                                                             |
| -------------------- | -------------------------------------------------------------------------------------- |
| 可登录账户占用号码   | 新建小程序 Session 与限期 Handoff，保存 `authenticated` 结论。会话默认 30 天。         |
| 暂停账户占用号码     | 保存确定拒绝，不建会话或待注册凭据。                                                   |
| 无账户               | 保存 `registrable` 结论与默认 10 分钟的 Registration；同事务替换同号码的旧未完成凭据。 |
| 可信号码不在允许范围 | 保存 `mobile_unsupported` 确定拒绝，不建上述事实。                                     |

原请求重放只返回已保存的原结论。原成功登录只在 Handoff 恢复期、原账户和会话仍有效且来源相符时重交付同一 token 和原到期时间；不创建或续期会话。原 `registrable` 只在原注册凭据仍有效时重交付它；被新认证替换或已被注册消费时不重新签发。认证恢复与注册 R2 的原成功恢复是两个独立流程，不能互借证明。会话或凭据已不可交付时返回 `verification_required`，提示重新认证，不把原业务改写成失败。

| 结果                                        | HTTP 状态 | 含义                                                                         |
| ------------------------------------------- | --------- | ---------------------------------------------------------------------------- |
| `authentication_invalid`                    | 401       | 原证明错误，或供应商明确拒绝原 code；两种来源不得泄露原凭据。                |
| `request_mismatch`                          | 409       | 原证明成立，但请求用途、来源或输入与原办理不同。                             |
| `mobile_unsupported`                        | 403       | 可信交换成功，但规范手机号不在允许范围；保存确定拒绝。                       |
| `verification_required`                     | 410       | 原登录或待注册结果已不能交付，或原交换结局无法可靠恢复。                     |
| `dependency_unavailable`、`outcome_unknown` | 503       | 分别为供应商或数据库依赖失败、数据库提交结局待核对；均不宣称成功或业务拒绝。 |

确定无效的 code 保存原 `authentication_invalid` 结论。供应商调用结果未知、超时或进程重启时，不再次交换已占用 code；待原执行与数据库提交核对结束，可信结果已丢失且没有业务终态时，原办理关闭为需要重新验证。客户端必须取得新 code 并使用新 Operation-Id。执行者仍持可信结果且最终事务已确认回滚时，可在原接纳截止内只重试本地结果提交。普通网络断连只结束客户端等待，不取消原受监督工作。

## 并发、清理与验收

手机号当前占用、账户暂停与恢复、待注册凭据替换、正式注册及账户注销使用同一对象协调顺序，并在锁后读取决定性事实。两次认证同时取得同一号码时，后提交的有效认证替换旧待注册凭据；已登录账户的两次成功认证各有独立会话。注册与认证竞争时，最终事务按当时的当前账户事实决定，旧凭据不能变成登录许可。最终以号码唯一性裁决，数据库错误不伪装成无账户。

占用至少保留到执行完成后 24 小时，并覆盖 code 剩余有效期、原结果恢复、全部实际父引用及执行结束。运行中或提交结局未知的占用不得因本地截止到达直接删除；先清理可删除的协议子事实，再按各自条件清理 Authentication 和 Request。原 Operation-Id 的最后一份结果证据清理遵循[共同保留边界](../architecture.md#原操作与恢复)。密钥轮换时仍检查所有保留的摘要版本，旧键有引用时不得退役。

验收覆盖小程序可信手机号、错误水印与号码、非大陆号段、已有账户、暂停账户和无账户分流。以事务交错验证相同 code 并发与换钥占用、重复请求、同号码凭据替换、注册竞争、会话并存及旧凭据失效。还须验证供应商明确拒绝、依赖故障、外呼未知、响应丢失、提交未知和重启后的按需核对；每个已占用 code 至多一次外呼，所有业务完成均无部分事实。真实平台 AppID、凭据和手机号授权资格须在部署验收中证明；协议替身和文档检查不能证明这些前提。
