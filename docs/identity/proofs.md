# Identity 原输入证明目标设计

本文规定 C1 原 token 证明、创建 Session、绑定、解绑、正式注册的原输入证明，以及三种微信 code 的占用。原操作证明只用于识别同一办理；业务资格、期限和结果由[短信认证](authentication.md)、[正式注册](registration.md)、[小程序手机号认证](mini-mobile.md)及[微信身份](wechat.md)各自判断。密码用途由[密钥材料](../keys.md)拥有，字节编码由代码及其独立向量固定。

## 输入与编码

证明覆盖的值先完成解析和规范化。手机号使用[匿名身份办理 HTTP](../http/identity.md#请求字段) 的规范值，姓名和身份证号使用[正式注册](registration.md#业务边界与不变量)的规范值；短信验证码保留六位 ASCII 数字及前导零。微信平台 code 使用原受控字符串，不修剪、不转换大小写或作 Unicode 规范化。

JSON 字段顺序、缩进及等价转义不改变证明；缺失、重复或未知字段由原输入契约拒绝。原操作重放使用原记录的密钥版本，不能以当前活动键重算旧记录；密钥缺失是依赖故障，不是输入不匹配。

## C1 原 token 证明

C1 原 token 证明使用 `lookup` 派生用途及其专属的域，与其他摘要隔离，只覆盖原 token 本身，不修剪或规范化，也不加入 Operation-Id、手机号、发码用途或来源，使同一 token 换用这些输入后仍可查出占用。原操作、用途、规范手机号与来源继续由 Challenge 事实绑定。换号入口另核对原人员、会话及适用申请，规则见[手机号更换](mobile.md#原请求读取与会话)；证明不替代这些核对。

新证明使用活动键，原请求按记录的密钥版本核对；缺键不得回退到活动键或解释为证明不匹配。新 token 占用在同一稳定对象协调内跨全部保留版本查询，没有命中才形成占用。原 token 不持久保存，因此不能通过换钥重算旧占用。旧材料保留到对应 Challenge 的占用与原证明比较依赖全部结束。供应商 token 过期不终止原结果核对，也不允许用新 token 替代原证明。

证明不能代替唯一性、对象协调或供应商调用占用；持久事实及恢复见[短信认证](authentication.md#首次接纳边界)。证明与密钥材料不提供普通文本或调试输出。

## 创建 Session、绑定与解绑

网站短信 R1 的原输入证明由认证结果保存；小程序手机号由专属 Exchange 保存，并与终态 Authentication 保持相同证明。其他微信流程的先行事实见所属设计，不建立全系统操作账本。证明覆盖固定命令、实际 AppID、Operation-Id、可信传递方式及下表的规范输入。实际 AppID 与传递方式由可信认证来源决定，传递方式只取 cookie 或 bearer；客户端不声明传递方式。命令标识是证明的固定文本，与已保存的证明一同固定，不随 HTTP 路径前缀变化。

| 原命令                     | 证明覆盖的规范输入                |
| -------------------------- | --------------------------------- |
| 网站短信创建 Session       | 原 Message ID、手机号与短信验证码 |
| 小程序手机号创建 Session   | 手机号授权 code                   |
| 小程序微信身份创建 Session | 微信登录 code                     |
| 网站微信创建 Session 发起  | 仅命令本身                        |
| 小程序绑定                 | 微信登录 code                     |
| 网站绑定发起               | 仅命令本身                        |
| 解绑                       | 原 `Binding-Revision`             |

网站短信分支使用固定网站 AppID 和 `cookie`。网站微信发起时尚无供应商 code；回调不能改写原证明。

客户端原 secret 是 43 字符的规范无填充 Base64url，表示 32 字节值。服务端只保留解码后字节的 SHA-256 证明，不哈希文本；比对使用常数时间。secret 解析错误的细节不得写入日志或响应。secret 文本及其证明均不加入输入证明。命中原请求时先核对 secret，再核对用途、应用、来源和完整原输入。绑定或解绑另存的原账户、会话与期望修订仍按所属用例核对；不把重放时的新会话或当前修订替换进去。独立结果读取只用所属原证明，不要求重新提交 code 或完整命令。

## 正式注册

R2 使用独立输入证明，覆盖 Operation-Id、可信传递方式、正文中的凭据 ID 以及规范姓名与身份证号；注册 token 按规范无填充 Base64url 解码为原 32 字节，只保留其 SHA-256 证明。传递方式、手机号与实际 AppID 从待注册凭据的可信原认证来源取得，客户端不能另行指定。

原成功依靠长期注册结果的凭据 ID、token 证明及注册时实名版本核对；短期尝试清理后，不能以当前实名资料重建原证明。原拒绝则使用该尝试的密钥版本和原输入核对，不依赖已消费的待注册凭据。

## 微信 code 占用

三种协议分别是小程序手机号、小程序微信身份及网站授权；同协议内的登录和绑定共享 code 占用。占用由服务端固定的协议、实际应用标识和原 code 决定，协议不由请求者选择；不加入用途、Operation-Id、请求 ID、secret 或浏览器证明。

新占用先跨所属协议的全部保留密钥版本查询，未命中才以活动键形成；原 code 没有保存明文，换钥不能重算并替换旧占用。原命令重放仍需核对原证明和输入；正确重复 callback 核对原 state、流程 cookie 与 code 占用，不重新交换。占用匹配不替代期限、当前账户、原会话或绑定修订检查。秘密和摘要不进入普通日志。

## 验收

用独立固定向量验证全部命令分支和三种微信协议的编码。算法向量与项目编码向量分别验证，不能用被测实现产生期望值。覆盖同键异输入、错误 secret、规范等价的 JSON、code 跨用途占用、跨应用与跨协议隔离、旧密钥版本保留及合法退役。验证原结果读取不要求重新提供一次性 code，也不因证明匹配绕过当前资格检查。
