# 内容草稿、版本与上线目标设计

首版范围与旧目标的取舍见[网站公开内容](../engineering/delivery.md#网站公开内容)，实际交付状态见[能力台账](../README.md#能力状态)。以下尚未实施的设计须在首个内容消费者实施前按简化架构重新评估，不因内容纳入首版而自动采用全部机制。

本文拥有文章与首页编排共用的草稿、永久版本、上线事件和当前上线指针，以及这些事实的并发、原操作与读取规则。内容形状与发布校验由[文章](articles.md)和[首页编排](home.md)分别拥有，栏目见[栏目](columns.md)，图片见[内容图片](images.md)，入口与错误码见[内容 HTTP](http.md)。共同事务、锁和恢复协议由[架构](../architecture.md#原操作与恢复)拥有。

## 对象与不变量

一篇文章或唯一的首页编排称为一个内容对象。每个内容对象拥有一份当前草稿、零或多个永久版本、零或多个上线事件和一个当前上线指针。

| 事实     | 含义与不变量                                                                                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 草稿     | 每个对象恰有一份，可反复整体替换。每次实际变化生成新的服务端 UUIDv4 `revision`，记录最后保存的办理人实名版本与时间。首页的初始草稿由迁移安装，见[首页编排](home.md#初始草稿)。草稿不公开，不保留历史 |
| 版本     | 发布时从当时草稿生成的不可变快照。对象内 `number` 从 1 连续递增，保存完整内容、来源草稿 `revision`、办理人实名版本、生成时间和 Operation-Id，永久保留                                                |
| 上线事件 | `publish`、`withdraw` 或 `restore`。对象内 `sequence` 从 1 连续，保存动作、所指版本（撤回为空）、前一当前版本、办理人实名版本、时间和 Operation-Id                                                   |
| 当前指针 | 对象当前对外的版本或空。只随上线事件在同一事务改变，并始终等于最后一个事件的结果：发布与恢复指向所指版本，撤回置空；尚无事件时为空                                                                   |

版本、上线事件与[栏目变更](columns.md#动作与历史)是永久事实，按[事实封印](../architecture.md#事实封印)保护，读取与启动核验沿同一规则；它们不占个人顺序，同一对象的版本与事件不能互换。

公开读取只读当前指针所指的版本。草稿、历史版本和事件只供有权管理读取。版本与事件不能修改或删除；版本号、事件序号唯一且连续，当前指针始终与最后事件配对。

版本记录“内容是什么”，事件记录“何时由谁让哪个版本上线”，两者分开保存。站内目前不设发布审核，发布即上线。将来若在草稿与发布之间插入审核，只新增引用草稿快照或版本的送审与审核结论事实，发布改为引用审核通过的版本。已有版本、事件和当前指针的含义不变，无须迁移；审核引入前的版本不补造审核记录。以后的投稿与审稿沿同一扩展点接入。

## 动作与成立条件

| 动作     | 请求确认                                      | 成立条件                                                                               | 共同提交                                       |
| -------- | --------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 保存草稿 | expected 草稿 `revision` 与完整内容           | revision 相等；内容通过所属形状校验；引用的图片可用                                    | 草稿内容、新 revision、草稿图片引用、原完成    |
| 发布     | expected 草稿 `revision` 与 expected 当前版本 | 两项均相等；草稿通过所属发布校验；草稿内容与当前上线版本不同                           | 新版本、版本图片引用、`publish` 事件、当前指针 |
| 撤回     | expected 当前版本                             | 当前指针非空且相等                                                                     | `withdraw` 事件、当前指针置空                  |
| 恢复     | 目标版本 ID 与 expected 当前版本              | 目标属于该对象且不同于当前版本；当前指针相等；目标通过所属发布校验中依赖当前事实的部分 | `restore` 事件、当前指针                       |

expected 当前版本以版本 ID 或 `null` 表达，`null` 表示确认当前未上线。首页编排不提供撤回，理由见[首页编排](home.md#上线与回退)。

保存的内容与当前草稿完全相同时仍为成功，保留原 revision，只追加原完成。发布时若当前已上线且草稿与之相同，返回 `409 draft_unchanged`，不生成重复版本；当前为空时允许以相同内容生成新版本。恢复不修改草稿。需要以历史版本继续编辑时，客户端读取该版本全文，再以普通保存草稿写回，仍须确认当前草稿 revision。

## 资格

办理与管理读取要求有效网站会话、正常账户，以及所属专题指定的机构权限，权限划分见[权限目录](../access/capabilities.md#网站公开内容权限)。内容动作不以他人为目标，不比较机构等级。账户暂停阻止办理与管理读取。办理人后来失权、暂停或注销，不改写已有草稿保存记录、版本或事件。

## 事务、锁与并发

每个动作是一笔写事务，遵守[锁与决定性读取](../architecture.md#锁与决定性读取)：在原操作、机构权限范围及所涉栏目、文章、首页和图片协调后，复查会话、账户、权限、expected 值和引用条件，决定性时间取自协调之后。

| 交错                  | 结果                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------ |
| 两次保存同一 revision | 先提交者成功，后到者 revision 不符，返回 `409 draft_changed`，不覆盖                 |
| 保存与发布            | 发布锁定对象后读取草稿并核对 revision；后到的保存基于新 revision，不改变已生成的版本 |
| 两个发布、撤回或恢复  | 后到者 expected 当前版本不符，返回 `409 publication_changed`                         |
| 角色修改与内容办理    | 权限范围保护使角色定义修改不能穿过已通过的权限检查                                   |

同一对象的事件顺序产生；时间不早于上一事件，先后以 `sequence` 解释。版本号为已保存最大值加一。写入经共同 Work 与有界工作容量执行，HTTP 等待结束不取消已接纳工作。

## 原操作与恢复

发布、撤回和恢复使用各自的动作家族。事件（发布另含版本）直接保存 Operation-Id，在所属家族内唯一。重放先核对当前会话与权限，再比较动作、对象和规范输入：发布比较版本保存的来源草稿 `revision` 与事件的前一当前版本，撤回比较前一当前版本，恢复比较所指版本与前一当前版本，均取自永久事实，不依赖之后已变化的草稿。完全相同时返回原事件和当时的版本，即使之后又有其他事件；任一项不同返回 `409 request_mismatch`。

保存草稿、文章创建与删除、图片上传与删除改变可变状态，原完成采用与 [Workforce 配置原请求](../workforce/completions.md#完成事实)相同的完成记录模型和 24 小时保留：原 Operation-Id、封闭动作、规范目标、规范输入的 SHA-256 摘要和事务时间。草稿保存的输入摘要编码 expected revision 与完整规范内容。匹配重放返回原完成（Operation-Id 与完成时间）和 `replayed: true`，不再次写入，也不返回 revision：完成记录不保存原操作生成的 revision，而当前 revision 可能已由他人推进，返回它会让客户端以旧内容配新前提覆盖他人修改。客户端须重新读取草稿，比较内容后再决定是否继续保存。后来他人保存不使原完成失效。对象已被删除时（例如保存后文章随即被删除），重放仍返回成功和 `deleted: true`，不返回 404，也不伪造被删内容，与 [Workforce 配置原请求](../workforce/completions.md#重放与条件写入)对已删除对象的处理一致。没有保留原完成的新请求按 expected 条件判断。

提交结局不明时按[未知提交](../architecture.md#未知提交)核对：独立恢复连接取得原操作锁，读取事件或完成记录，再由所属用例解释原成功、确定未提交或仍未知。内部恢复沿首次核验的办理人，不因后来失权重新写入。完成记录到期由 Content 后台清理，沿[共同保留边界](../architecture.md#清理)绑定原记录删除；版本与事件不清理。

## 读取

管理读取包括当前草稿、版本分页、单个版本全文和事件分页，遵循[列表读取](../http/lists.md)。版本按 `number` 降序，事件按 `sequence` 降序，均以 ID 稳定并列。权限、计数与本页来自同一只读快照。版本和事件的办理人以固定脱敏身份返回，复用共同固定脱敏身份投影；草稿的最后保存人同样只返回固定脱敏身份。

公开读取只解析当前指针。从未发布或已撤回的对象，对公开读取等同不存在。公开读取不返回版本号、事件、草稿或办理人。

## 验收

验证：版本与事件不可改删；版本号、事件序号连续；只写事件或只改指针被拒绝；指针始终等于最后事件。覆盖保存并发、保存与发布交错、两个发布者竞争、撤回后再发布与恢复、恢复到当前版本被拒绝、发布未变化草稿被拒绝。原操作覆盖同键重放、同键异输入、后续事件后的原结果回读、草稿完成清理后的条件判断，以及真实 COMMIT 拦截后的提交未知恢复。权限覆盖暂停账户、失权后的新请求与原工作内部恢复。
