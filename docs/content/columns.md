# 网站栏目目标设计

已有栏目创建领域组件继续按本文合同维护，包括永久原结果、导航顺序及封印核验。首版范围与旧目标的取舍见[网站公开内容](../engineering/delivery.md#网站公开内容)，实际交付状态见[能力台账](../README.md#能力状态)。以下尚未实施的扩展须在首个内容消费者实施前按简化架构重新评估，不因内容纳入首版而自动采用全部机制。

本文拥有栏目的事实、顺序、启用状态、删除条件和永久变更历史。文章如何归属栏目见[文章](articles.md)，首页的栏目入口见[首页编排](home.md)，入口与错误码见[内容 HTTP](http.md)。

## 业务边界

栏目是公开导航和文章分组，例如首页稿中的“线上展馆”“知识科普”。栏目只有一层，不设父子关系。公开导航平铺展示，文章直接归属一个栏目。

栏目修改直接生效，不经草稿与发布。栏目只有名称、说明和顺序等导航信息，变化少且没有正文；为它另设版本会让每次改名都多一步发布，而栏目自身的永久变更历史已足以追溯。

## 事实与不变量

| 字段          | 规则                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| `id`          | 服务端 UUIDv4，内部引用使用                                                                                     |
| `key`         | 公开地址段，2 至 32 个小写 ASCII 字母、数字或连字符，以字母开头；全部栏目（含已删除）中永久唯一，创建后不可修改 |
| `name`        | 1 至 20 个 Unicode 标量，NFC 规范化，去首尾空白，不含控制字符；现存栏目中唯一                                   |
| `description` | 0 至 100 个 Unicode 标量，同上规范化；用于栏目页简介与搜索引擎描述                                              |
| `enabled`     | 启用的栏目出现在公开导航并有栏目页；停用的栏目对公开读取不存在                                                  |
| `index`       | 管理定义的顺序，在现存栏目中连续且唯一                                                                          |

顺序从 0 开始；创建占用现存栏目数量对应的位置。

`key` 不可修改，也不在删除后分配给其他栏目，是为了保持已被收录或收藏的栏目地址不会指向无关内容。数据库以不随栏目删除的永久 `key` 占用保护这一点，曾用 `key` 同时记录在变更历史中。栏目总数上限初值为 100，完整列表一次返回，不分页。

停用的栏目不出现在公开导航，栏目页为 404，也不能作为新发布或恢复的目标栏目。其中已上线的文章仍可经文章地址读取，并出现在全站文章列表和首页引用中；公开文章结果只返回栏目名称，不附栏目页地址。

栏目只有在没有任何文章草稿、文章版本或首页草稿与版本引用时才能删除；否则返回 `409 column_in_use`，可改为停用。删除后名称可以复用，`key` 永久保留，新栏目使用它时返回 `409 column_key_in_use`。

## 动作与历史

| 动作 | 请求确认                          | 结果                                                                          |
| ---- | --------------------------------- | ----------------------------------------------------------------------------- |
| 创建 | 完整字段（`index` 追加到末尾）    | 新栏目与 `create` 变更                                                        |
| 修改 | expected 当前变更 ID 与完整替换值 | 更新名称、说明、启用状态，追加 `update` 变更                                  |
| 排序 | expected 完整顺序与新完整顺序     | 整体替换全部 `index`，追加一条 `reorder` 变更                                 |
| 删除 | expected 当前变更 ID              | 删除当前行并把其后栏目的 `index` 各减一，追加 `delete` 变更；不能再有后继变更 |

每次变化在同一事务追加永久变更，保存栏目 ID（排序变更不属于单个栏目，栏目 ID 为空）、动作、变化后的完整值（删除保存删除前的值）、办理人实名版本、时间、Operation-Id 和规范输入的 SHA-256 摘要。当前行指向以自己为目标的最新创建或修改变更，提交时检查二者一致；修改与删除的 expected 当前变更 ID 即此指针。排序与删除变更保存变化后的完整顺序，它们改变其他栏目的 `index` 但不移动其他栏目的指针，也不为每个栏目另追加变更；按栏目筛选历史时，返回以该栏目为目标的变更，以及完整顺序中含该栏目的排序与删除变更。名称、说明与启用状态均未变化的修改返回 `409 column_unchanged`。

办理使用栏目权限，资格见[权限目录](../access/capabilities.md#网站公开内容权限)。创建、排序和删除改变顺序，先取得栏目集合锁再锁定所涉栏目，在同一快照内计算追加位置或前移后继，确保顺序连续；修改不改变顺序，只锁定目标栏目。expected 不符返回 `409 column_changed`；重名或 `key` 冲突按具名唯一约束分别返回 `409 name_in_use` 和 `409 column_key_in_use`。

原操作以变更中的 Operation-Id 识别。重放比较动作、目标与输入摘要：相同返回原变更，即使栏目后来被修改或删除；不同返回 `409 request_mismatch`。提交未知按[共同协议](publication.md#原操作与恢复)核对变更记录。

## 读取

管理读取返回全部栏目（含停用），以及按时间倒序、再按变更 ID 降序分页的变更历史，可按栏目 ID（含影响其顺序的排序与删除变更）和 Operation-Id 筛选，办理人以固定脱敏身份返回。公开读取只返回启用栏目的 `key`、名称、说明和顺序。

## 验收

验证 `key` 不可修改、两项唯一约束、顺序连续、停用后公开导航与栏目页消失而已上线文章仍可读取、被引用栏目拒绝删除、删除后名称可复用而 `key` 仍被拒绝。覆盖 expected 冲突、并发排序、删除中间栏目后的顺序前移、删除与创建或排序并发、未变化修改、原操作重放与异输入、删除后的原结果回读和提交未知。
