# 网站交付与后端边界

网站独立构建和托管，Rust 后端不交付网站页面或构建资源。本文拥有网站托管、路由归属、渲染分工、公开页面路径与搜索引擎收录要求、后端入口、公开设置与浏览器交付的边界。普通业务 HTTP 的请求头、响应封装及豁免清单由 [HTTP 入口与响应](api.md)拥有。页面和功能范围见[网站与小程序页面](../client/pages.md)，技术栈与组件见[网站工程](../client/website.md)。

公开内容管理、小程序及微信扩展暂缓；下文相关未交付页面与服务端渲染要求只作后续参考，不阻塞内部工牌。既有固定首页、登录及账户托管继续有效。

## 托管与路由归属

网站由 halo 的 Node 服务和静态资源目录交付 HTML、脚本、样式、构建资源和微信授权完成页。Node 服务由 systemd 管理。nucleus 负责业务请求、上传和受控文件读取。微信回调、健康检查和 OpenAPI 也由 nucleus 交付；其中健康检查与 OpenAPI 留在后端根路径，不经 Nginx 暴露。业务事实、权限、事务和恢复仍归后端能力。网站不连接业务数据库，也不承担工牌渲染或文件清理。

生产 Nginx 按路径分流：

| 路径                     | 去向                        | 说明                                                      |
| ------------------------ | --------------------------- | --------------------------------------------------------- |
| `/api/` 前缀             | nucleus                     | 原样转发，规则见[路径前缀与版本](api.md#路径前缀与版本)   |
| `/assets/{build}/{file}` | 网站静态目录，由 Nginx 提供 | 只提供发布清单内的资源；缺失时直接 404，不转给 Node 服务  |
| 其余全部路径             | halo 的 Node 服务           | 公开页面、应用页面、微信完成页和未知路径的 404 均由它响应 |

健康检查和 OpenAPI 只能在本机直接访问后端端口，理由见[路径前缀与版本](api.md#路径前缀与版本)。代理责任见 [HTTP 接入目标](api.md#nginx-接入与传输目标)。网站与浏览器使用的后端入口保持同一准确 HTTPS origin，现有 Cookie 与同源要求不变。Node 服务的监听地址只允许 Nginx 访问。微信回调由后端核验证明并处理原操作，再跳转到网站的固定完成页。回调与完成页的路径、证明和结果判断见[微信身份](../identity/wechat.md)。

网站拥有 `/api/` 以外的全部路径。公开页面和登录后的应用页面都位于根路径，使用普通路径路由，命名见[路由命名](../client/pages.md#路由命名)。后端仍保持单实例、单应用进程；这一限制不要求网站与后端共用进程。网站发布不要求重新编译或重启 nucleus。

## 渲染与网站服务

公开页面在服务端渲染。[网站公开内容](../content/publication.md)交付后，Node 服务匿名调用[内容公开读取](../content/http.md#公开读取)取得数据，路径与收录要求见[公开内容页面](#公开内容页面)。在此之前，首页内容随网站发布固定。

应用页面在服务端只输出应用外壳和加载状态，不含人员、授权或工牌资料。私有数据由浏览器直接请求 `/api/v1`，会话按[网站持久会话](../identity/website.md)选择。

同源部署下，浏览器的会话 cookie 也会发给 Node 服务。Node 服务必须忽略 Cookie 请求头：不解析、不转发、不写入日志或错误上报，也不据此改变响应。Node 服务从不代替浏览器读取私有资料，调用 nucleus 时不携带任何浏览器凭据。来源转发见[网站服务的后端读取](admission.md#网站服务的后端读取)。

## 公开内容页面

本节是目标设计，随[网站公开内容](../content/publication.md)的公开页面渲染切片交付。

| 路径                | 内容                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                 | 首页。首页编排已上线时按编排渲染；公开读取返回 `home_unpublished` 时渲染随网站发布的内置首页                                                                         |
| `/columns/{key}`    | 启用栏目的栏目页，列出该栏目当前上线的文章；`?page=n` 分页，第 1 页的规范地址不带参数                                                                                |
| `/articles`         | 全站当前上线文章的列表；`?page=n` 分页，第 1 页的规范地址不带参数                                                                                                    |
| `/articles/{id}`    | 当前上线文章的文章页；`id` 为文章 ID                                                                                                                                 |
| `/sitemap.xml`      | 首页、全站文章列表第一页、全部启用栏目页和全部当前上线文章的地址；文章的 `lastmod` 取当前版本上线时间，条目超过 50,000 时改为 sitemap 索引，指向 `/sitemaps/{n}.xml` |
| `/sitemaps/{n}.xml` | 拆分后的第 `n` 份子 sitemap，`n` 从 1 起，按[游标枚举](../content/http.md#公开读取)的顺序每份至多 50,000 条；不需要拆分或 `n` 超出范围时返回 404                     |
| `/robots.txt`       | 允许公开页面和 `/api/v1/public/images/`，禁止 `/api/` 的其余路径与应用页面所在路径，并给出 `sitemap.xml` 的绝对地址                                                  |

搜索引擎收录要求：

- 公开页面的完整正文、标题和站内链接都在服务端 HTML 中，爬虫不执行脚本也能读到内容并发现全部栏目和文章。站内导航使用普通 `<a href>`；轮播的服务端输出包含全部条目的图片、替代文字和链接。
- 每页输出 `<html lang="zh-CN">`、唯一的 `<title>`、`<meta name="description">`（栏目说明或文章摘要；首页以及说明或摘要为空时使用随网站发布的固定站点描述）、绝对地址的 `<link rel="canonical">`，以及 Open Graph 的标题、描述、类型和图片绝对地址。文章有封面时图片取封面；首页、栏目页和无封面的文章使用随网站发布的固定分享图。绝对地址使用部署配置的站点 HTTPS origin。
- 文章页只有一个 `<h1>`，即文章标题；正文标题从 `<h2>` 起，与[文章正文结构](../content/articles.md#正文结构)一致。正文按结构化节点由 React 组件输出，不使用任意 HTML 注入。
- 图片使用公开图片的相对路径，带替代文字和宽高，避免版面跳动；首屏以外的图片设置 `loading="lazy"`，使单页图片分批请求，不在同一时刻耗尽图片预算；它们同源，满足 CSP 的 `img-src 'self'`。本片不输出 JSON-LD 等内联数据块；以后需要时同样携带本次 nonce。
- 文章或栏目不存在、未上线、已撤回或已停用时返回真正的 404 错误页并设置 `noindex`；分页超出范围或 `page` 非法同样返回 404。nucleus 不可用且没有可用缓存时返回 503 错误页并附 `Retry-After`，不返回 200 的空页面。
- 应用页面保持 `noindex`，并在 `robots.txt` 中禁止抓取。测试等非生产环境的 `robots.txt` 禁止全部抓取，页面同时设置 `noindex`，防止测试内容被收录。
- `sitemap.xml` 由 Node 服务按[游标枚举](../content/http.md#公开读取)读取全部条目后一次生成，sitemap 沿同一内存缓存，只列当前上线的内容；`robots.txt` 按部署环境生成。二者响应为 `no-store`。

公开页面的 CSP 与普通页面相同，不为内容放宽任何指令。轮播用 [Embla Carousel](../client/website.md#组件)，不需要内联样式元素。

## 入口与响应

| 入口                                                           | 交付者         | 成功响应                                                     | 失败与请求标识                                              |
| -------------------------------------------------------------- | -------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| `GET /` 及其他公开页面                                         | Node 服务      | 200；服务端渲染的公开 HTML，不含人员资料                     | 不校验或回显 `Operation-Id`                                 |
| `GET /sitemap.xml`、`GET /sitemaps/{n}.xml`、`GET /robots.txt` | Node 服务      | 200；按[公开内容页面](#公开内容页面)生成的 XML 或纯文本      | 同上                                                        |
| 应用页面                                                       | Node 服务      | 200；应用外壳与加载状态，设置 `noindex`，不含私有资料        | 同上                                                        |
| `GET /authorizations/completion`                               | Node 服务      | 200；微信授权完成页，按[微信身份](../identity/wechat.md)隔离 | 同上                                                        |
| 未知路径                                                       | Node 服务      | 404；不含资料的错误页，设置 `noindex`                        | 同上；不返回首页或应用外壳                                  |
| `GET /assets/{build}/{file}`                                   | Nginx 静态目录 | 200；构建清单内的固定字节和准确媒体类型，匿名可读            | 不校验或回显 `Operation-Id`；无匹配资源返回 404             |
| `GET /api/v1/settings`                                         | nucleus        | 200；`code: "ok"` 与具名 `settings` 对象                     | 普通 JSON 读取，要求有效 `Operation-Id`；响应不回显请求标识 |

应用页面指登录注册及登录后的本人、管理页面；页面清单见[网站与小程序页面](../client/pages.md)。只有已装配的路由返回 200，其他路径一律返回真正的 404，不回落到首页或应用外壳。

`settings` 只含公开的 `challenge.turnstile.siteKey`。nucleus 从已校验的非秘密设置投影该值。响应不包含 AppSecret、凭据或完整应用设置。前端 `build_id` 由网站发布清单拥有，不进入后端设置或该响应。网站构建不嵌入各环境的秘密。小程序只配置自己的公开 AppId 与批准的 HTTPS API origin。

网站的成功响应直接返回 HTML 或资源字节，不套 JSON。404 及其他错误页设置 `no-store`，不反射输入路径或操作头。非法资源路径不返回文件字节。后端保留未知业务路径的 JSON 404；部署入口不得把后端错误改成网站页面。

## 构建、发布与缓存

网站构建生成发布清单，固定 `build_id`、资源路径、摘要和媒体类型。发布过程核对清单与实际字节，不一致时拒绝发布。Node 服务代码与静态资源来自同一构建，不混用其他版本的字节。静态目录只开放清单内的固定资源，不按用户输入拼接任意路径。禁止目录列举和后端私有文件树访问。

nucleus 不嵌入网站构建产物，启动与就绪检查不读取网站发布清单。后端业务依赖、文件挂载和默认业务资源仍按[启动规则](../architecture.md#启动顺序)核验。网站发布和端到端可用性单独验收；后端就绪不证明网站已正确发布。

HTML 一律 `no-store`，因为每次响应的 CSP nonce 不同。`GET /api/v1/settings` 同样 `no-store`。带摘要的静态资源长期以 `immutable` 缓存；私有 JSON 和业务图片按所属用例的缓存协议交付。网站不使用 service worker 或离线业务写入队列。旧页面发现 `build_id` 变化、资源缺失或响应结构不匹配时停止发起新动作并提示重新加载。仍合法的原操作定位按[客户端原操作恢复](../client/recovery.md)保留，页面不自动重放写入。

Nginx 的 `/api/` 保留上游缓存策略。该 location 声明自己的安全响应头，按 [Nginx 响应头继承规则](https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header)隔离网站的 `no-store` 默认值。签名业务图片仍使用所属接口的私有缓存。

Node 服务可在内存中短时缓存公开内容数据；nucleus 不可用时可以用旧数据渲染公开页面。新鲜期和旧数据的最长使用期尚待确认，推荐见[待确认事项](../engineering/delivery.md#网站公开内容待确认事项)。nucleus 明确返回 404 时，Node 服务丢弃对应缓存并返回 404，撤回因此在下次刷新时生效，不会被旧数据无限延长。私有资料不进入该缓存。

当前构建标识由网站的 `GET /build.json` 提供，响应为 `{"buildId":"…"}`，设置 `no-store`。页面在发起 C1 请求前及从后台返回时核对构建标识。标识不符时只保留原材料并提示重新加载，不自动重放。nucleus 的公开设置接口不维护前端构建标识。前端以固定的后端契约构建，独立发布仍须验证[客户端协议](../client/protocol.md)。

初始 HTML 在样式与模块资源之前加载同源的阻塞脚本，捕获当前构建的脚本、样式和图片加载失败。页面保留该失败及 hydration 不匹配信号，组件挂载后仍停止新动作；早期脚本自身未加载时同样停止。供应商脚本加载失败由安全验证组件处理，不标记网站构建失效。要求重新加载时，活动 C1 材料先保存新的退避截止，迟到响应不得重新开启办理。

## 浏览器边界

普通应用使用预编译模板和外部脚本，不执行动态模板、`eval` 或任意 HTML 注入，不用 URL 传递会话。Node 服务对每个 HTML 响应生成新的随机 nonce，写进 CSP 响应头和框架输出的内联脚本。

| 指令              | 普通页面                                               | 发码页面增补         |
| ----------------- | ------------------------------------------------------ | -------------------- |
| `default-src`     | `'self'`                                               | 不变                 |
| `script-src`      | `'self'` 与本次 nonce                                  | Turnstile 脚本来源   |
| `style-src-elem`  | `'self'`                                               | 不变                 |
| `style-src-attr`  | `'unsafe-inline'`                                      | 不变                 |
| `img-src`         | `'self'` 与已校验的头像 origin；实际预览需要时 `blob:` | 不变                 |
| `connect-src`     | `'self'`                                               | 不变                 |
| `frame-src`       | `'none'`                                               | Turnstile frame 来源 |
| `object-src`      | `'none'`                                               | 不变                 |
| `frame-ancestors` | `'none'`                                               | 不变                 |
| `form-action`     | `'self'`                                               | 不变                 |

放开 `style-src-attr 'unsafe-inline'` 的理由：服务端渲染的组件会输出 `style` 属性，而本项目不允许任意 HTML 注入。`style-src-elem` 不放开；Base UI 通过其 CSP Provider 关闭内联 `<style>` 元素，所需样式由外部样式表补齐。

Node 服务启动时必须提供非秘密的 `HALO_AVATAR_ORIGIN`，取值为头像图片所在 HTTPS origin，可带一个根路径斜杠。输入不得含凭据、业务路径、查询、片段、通配符、CSP 分隔符或需解析器修复的字符。缺失或非法时在监听前失败，没有默认值。

每个 HTML 响应生成自己的 CSP，并把规范化后的准确 origin 加入 `img-src`。登录或注册成功后的页内导航沿用发起文档的 CSP，因此该 origin 不能只出现在直接访问 `/account` 的响应中。CSP 只来自部署输入，不从账户投影、浏览器状态或图片链接推导。

Turnstile 的 script 和 frame 来源只在发码页面的响应里放行，准确来源按 [Turnstile CSP 说明](https://developers.cloudflare.com/turnstile/reference/content-security-policy/)核对。其他页面链接到发码页面时强制整页跳转，不做客户端路由切换，保证浏览器使用该页面响应的 CSP。发码页面离开到其他页面时同样整页跳转。

微信授权组件及完成页按[微信身份](../identity/wechat.md)的独立浏览器隔离交付，不继承普通应用的人机校验许可。Node 服务负责 HTML 响应的 CSP、`X-Content-Type-Options: nosniff` 和 `Referrer-Policy: no-referrer`；Nginx 对静态资源设置同样的 `nosniff` 与 `Referrer-Policy`。构建产物不发布 source map，也不包含测试秘密。网站不把业务资料写入控制台、埋点或错误上报正文；诊断只记录必要的错误码、公开构建标识和受控操作定位。Node 服务与部署入口的访问日志沿用后端敏感路由的去值规则，并且不记录 Cookie 头。

承载微信授权的父页面只为该组件增补准确的 frame 来源，不执行供应商脚本。若实际组件需要本地网络访问委派，只对已核验的准确来源声明该权限；浏览器或用户拒绝后保留同一授权的扫码办理，不扩大来源、不重发授权或改走新的原操作。真实浏览器、协议替身和真实平台结果分别记录，不能以任一项替代其他项的验收。

## 验收

通过实际部署入口验证 Nginx 三路分流。逐项核对媒体类型、公开字段、缓存头和请求标识边界。覆盖未知页面路径、未知业务路径、清单外资源、非法路径、目录列举与私有文件访问：未知页面返回 404 错误页，其余不得返回首页、应用外壳或文件字节。核对应用页面设置 `noindex`，深链刷新得到同一页面的外壳。核对微信回调进入后端，固定完成页由网站交付。后端 OpenAPI 只描述实际后端路由，不收录网站页面。

带会话 cookie 访问公开页面和应用页面时，Node 服务的响应不随 cookie 变化，日志与错误上报不含 Cookie 头，Node 服务也不向 nucleus 发出携带浏览器凭据的请求。应用外壳不得泄露受限资料。

公开内容页面在禁用脚本的情况下核对正文、标题、描述、canonical 和站内链接均在服务端 HTML 中；覆盖未上线、撤回、停用栏目和越界分页的 404，nucleus 不可用时的旧数据渲染与无缓存时的 503，以及撤回在缓存刷新后生效。用搜索引擎的站点验证工具核对 `sitemap.xml` 与 `robots.txt`，确认非生产环境禁止抓取。

篡改网站清单或资源字节时拒绝发布。验证网站发布无需重启后端，后端无需网站产物即可启动。用浏览器验证构建版本变化和资源缺失。核对每次 HTML 响应的 nonce 不同，HTML 不被缓存。在真实浏览器中确认普通页面、发码页面与微信完成页的 CSP 分别生效且无违规报告；从普通页面进入发码页面为整页跳转。检查构建产物不含秘密和 source map。配置验证与真实环境部署分别验收，当前交付范围见[能力状态](../README.md#能力状态)。
