# HTTP 来源与入口资源预算

状态：C1 发码组已接入单值来源交接，其余请求组仍为目标设计。真实 Nginx 部署尚未验证。本文拥有 HTTP 来源识别、进程内预算、逐级扣额和容量故障。发码许可见[短信认证](../identity/authentication.md)，注册次数见[正式注册](../identity/registration.md)。原请求恢复见 [架构恢复协议](../architecture.md#原操作与恢复)。请求标识和错误封装见 [HTTP 入口与响应](api.md)。各能力拥有自己的认证与业务结果。

当前来源解析由根 `source` 拥有，Identity 入口预算由 `nucleus::identity::admission` 拥有。`process` 创建 C1 预算并注入请求状态，Router 不再新建预算。共享状态与多监听的装配边界见[架构](../architecture.md#装配状态与监听)；当前仍只有一个监听地址和 C1 消费者。

共同中间件先验证操作标识。来源提取器再用 Axum 的 `ConnectInfo` 取得直接对端。`source::Settings::resolve` 校验对端信任和单值来源头。来源只解析一次，交给预算与业务消费者。此时尚未读取正文。响应不回显请求标识；共同协议见 [HTTP 入口](api.md#路由与请求边界)。

## 接纳顺序与事实归属

入口先校验适用的 `Operation-Id`，再确定可信来源并检查本地预算。之后才读取正文与凭据，执行用例。请求标识豁免不自动豁免资源预算；只有明确分配预算组的路由才按本表扣额。一次 HTTP 接纳只消费本进程的请求资源。它不代表业务事务已接纳、数据库已提交或供应商已受理。

进程内桶在普通重启后重新开始。数据库持久保存短信许可、验证码次数、注册受理次数和原请求结果。短信许可覆盖手机号、来源和部署范围，不能由进程内桶代替。相同原操作的 HTTP 重试仍占本次入口资源，但不重复扣持久发送或注册次数。入口预算不足不证明该操作此前未提交；客户端保留原标识和原材料，按所属用例核对。

## 可信来源

### 代理交接

生产请求统一经过受控 Nginx，网络边界见 [Nginx 接入与传输目标](api.md#nginx-接入与传输目标)。Nginx 拥有上游代理链的信任配置与来源解析。它向 nucleus 覆盖写入唯一的 `X-Real-IP`，值为已经确定的客户端 IP。不得透传客户端提交的同名值。若 Nginx 前还有代理，仅信任明确配置的上游。相关能力见 [realip](https://nginx.org/en/docs/http/ngx_http_realip_module.html) 与 [proxy_set_header](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)。

应用只信任配置范围内的直接 Nginx 对端。来源提取要求 `X-Real-IP` 为唯一、无端口的 IP 地址。对端不可信时返回 HTTP 403、`permission_denied`。头缺失、重复、多值及格式错误时返回 HTTP 400、`invalid_input`。应用忽略 `X-Forwarded-For` 和 `Forwarded`，不从其他头或代理地址补造客户端来源。可信配置只登记直接代理地址，不接受空数组或全网信任。这是代理到应用的交接要求，外部客户端不负责填写该头。当前由 C1 消费来源，健康检查与 OpenAPI 不提取来源。网络隔离仍覆盖整个应用监听端口。

来源键保留完整规范主机地址。IPv4-mapped IPv6 归一化为 IPv4；IPv6 不作前缀聚合。同一出口 IP 的用户共享其来源预算。来源交接只确定限流与业务输入，不证明调用者身份。

## 逐级扣额与回收

每次检查通过消耗一单位。来源桶与进程总桶连续补充、容量封顶。单调时钟决定补充；UTC 时钟回退不补额。入口先检查并扣除来源额度，再检查并扣除进程额度。来源不足时不检查总桶；总桶不足时不返还已扣的来源额度。后续无效凭据或业务拒绝也不返还额度。来源分配、回收和检查处于短临界区，期间不进行认证、数据库操作或网络调用。

| 请求组                                  | 来源补充与容量                               | 进程补充与容量                         |
| --------------------------------------- | -------------------------------------------- | -------------------------------------- |
| `POST /codes`                           | 每分钟 6，容量 2；仍受更严格的持久发码规则。 | 与登录注册组共用每秒 20、容量 40。     |
| `POST /sessions`、`POST /registrations` | 两入口共用每分钟 60、容量 10。               | 与发码组共用同一每秒 20、容量 40。     |
| 当前身份与头像元数据读取                | 每秒 20，容量 40。                           | 每秒 100，容量 100。                   |
| 匿名头像图片                            | 每分钟 120，容量 20。                        | 每秒 100，容量 100；独立于元数据读取。 |
| 已认证头像、绑定及会话写入              | 每秒 2，容量 4。                             | 每秒 10，容量 20。                     |

发码组与登录注册组各有来源存储，但共享表中的进程总桶。其他行使用各自的来源存储与总桶。表中为已采用的目标初值，其他路由接入前由所属能力确定预算组。业务持久额度另按其所有者检查，不能因本地桶尚有额度而省略。

当前每个来源及进程总额各持有一个 `governor` 0.10.4 原生 [RateLimiter](https://docs.rs/governor/0.10.4/governor/struct.RateLimiter.html)。入口调用 `check()`，由库计算补充、扣额和拒绝等待。限流器跨请求保留，不重建候选状态或自定义限流算法。来源容器拥有数量硬上限与容量回收。默认 keyed 存储的回收接口不能独自保证该硬上限。尚未装配的登录注册组不另建空桶。

只回收已与新建满桶等价的来源状态。允许延后回收，按间隔清理或在容量紧张时清理；不要求精确时点或特定索引。来源拒绝不推迟补满时点，总桶拒绝前已扣的来源额度仍参与计算。每组来源存储最多 10,000 项。达到上限时先清理可回收项。仍满时保留既有来源，拒绝新来源分配，返回 HTTP 503、`dependency_unavailable`。记录容量耗尽，不淘汰尚未恢复的来源。

当前 C1 使用最后一次来源扣额后 20 秒作为安全回收时点。该时长足够从空桶补满，等号允许。只有新来源遇到满容量时，才扫描并清理可回收项。扫描同时保存最早可能回收的时点；此前的容量拒绝不重复扫描。既有来源继续使用原桶，由库正常补充额度。实现不再维护逐项有序索引，空闲状态延后保留也不突破 10,000 项。库的 `retain_recent()` 可承担满桶等价性判断，但不能单独保证来源数量上限。

普通额度不足立即返回 HTTP 429、`rate_limited`，不排队。`Retry-After` 使用本次拒绝层给出的等待时间，向上取整到秒，至少为 1 秒。响应不预留额度，也不保证重试时另一层有额度。来源头格式错误按输入拒绝。必需 `ConnectInfo` 缺失属于装配错误，返回 HTTP 500、`internal_error`。预算状态不可用返回 HTTP 503、`dependency_unavailable`，不进入业务判断。JSON 正文的共同 8 KiB 上限由 [HTTP 入口与响应](api.md)拥有。

## 有界状态与验收

来源补充速率为 `r`、容量为 `b` 时，最后一次扣额后至多 `b / r` 即可补满。总桶拒绝也会留下已扣额的来源，因此不能由总桶吞吐推导来源数量上界。内存边界由 10,000 项硬上限和安全回收共同保障。持续更换地址可耗尽来源容量，这是受控拒绝场景，不代表容量要求已通过真实负载验证。

用可推进的单调时钟和独立期望值验证补充边界。核对来源拒绝不扣总额，总额拒绝保留来源扣额。验证 10,000 项边界和满容量下的既有来源检查。清理前后额度等价，延后清理也不突破容量。并发请求共享同一来源额度，重启只重置本地桶。负载记录区分来源、总桶、图片许可与持久预算的拒绝。场景覆盖共享 NAT 与读写图片混合负载。

应用测试覆盖非可信对端拒绝，以及单值头缺失、重复、多值和非法 IP。验证 IPv4-mapped IPv6 归一化与 IPv6 主机区分。回环 HTTP 测试模拟直接代理交接，覆盖无效来源在业务调用前被拒绝。首次可信来源写入原 Challenge，恢复请求不替换该来源。代理联调仍须验证伪造头被覆盖、业务端口无法绕过，以及有上游代理时的真实来源。真实负载与部署代理行为尚未验证；文档及纯单元模型不构成容量证据。
