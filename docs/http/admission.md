# HTTP 来源与入口资源预算

本文拥有 HTTP 来源识别、进程内预算、逐级扣额和容量故障。已认证写入组包含两种网站退出、机构角色维护、指派候选 POST、角色更换、账户候选与暂停恢复，以及实名更正候选与办理 POST；可选角色、指派历史、账户状态历史和实名更正人员候选 GET 属于元数据组。候选使用所属方法的预算，但不产生业务写入。发码许可见[短信认证](../identity/authentication.md)，注册次数见[正式注册](../identity/registration.md)。原请求恢复见 [架构恢复协议](../architecture.md#原操作与恢复)。请求标识和错误封装见 [HTTP 入口与响应](api.md)。各能力拥有自己的认证与业务结果。

各组预算在进程内共享，所有监听与 Router 使用同一份预算状态。C1/R1/R2 共用办理总桶，元数据、图片及已认证写入各有独立总桶。头像图片与工牌资源共用下述[媒体传输](#媒体传输)许可。共享状态与多监听的装配边界见[架构](../architecture.md#装配状态与监听)。

Workforce 角色维护、更换、准入、暂停恢复及结束共用已认证写入组，所属确认候选也使用该组。在认证和正文解码前扣除来源及进程额度；候选查询不写业务事实。办理许可另由共同工作容量持有，覆盖提交、恢复及排空。具体入口见[角色办理](../access/roles.md#原请求与读取)和[授权生命周期](../access/grants.md#http-入口)。

共同中间件先验证操作标识，再取得直接对端，校验对端信任和单值来源头。来源只解析一次，交给预算与业务消费者。此时尚未读取正文。响应不回显请求标识；共同协议见 [HTTP 入口](api.md#路由与请求边界)。

## 接纳顺序与事实归属

入口先校验适用的 `Operation-Id`，再确定可信来源并检查本地预算。之后才读取正文与凭据，执行用例。请求标识豁免不自动豁免资源预算；只有明确分配预算组的路由才按本表扣额。一次 HTTP 接纳只消费本进程的请求资源。它不代表业务事务已接纳、数据库已提交或供应商已受理。

进程内桶在普通重启后重新开始。数据库持久保存短信许可、验证码次数、注册受理次数和原请求结果。短信许可覆盖手机号、来源和部署范围，不能由进程内桶代替。相同原操作的 HTTP 重试仍占本次入口资源，但不重复扣持久发送或注册次数。入口预算不足不证明该操作此前未提交；客户端保留原标识和原材料，按所属用例核对。

## 可信来源

### 代理交接

生产请求统一经过受控 Nginx，网络边界见 [Nginx 接入与传输目标](api.md#nginx-接入与传输目标)。Nginx 拥有上游代理链的信任配置与来源解析。它向 nucleus 覆盖写入唯一的 `X-Real-IP`，值为已经确定的客户端 IP。不得透传客户端提交的同名值。若 Nginx 前还有代理，仅信任明确配置的上游。相关能力见 [realip](https://nginx.org/en/docs/http/ngx_http_realip_module.html) 与 [proxy_set_header](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)。

应用只信任配置范围内的直接 Nginx 对端。来源提取要求 `X-Real-IP` 为唯一、无端口的 IP 地址。对端不可信时返回 HTTP 403、`permission_denied`。头缺失、重复、多值及格式错误时返回 HTTP 400、`invalid_input`。应用忽略 `X-Forwarded-For` 和 `Forwarded`，不从其他头或代理地址补造客户端来源。可信配置只登记直接代理地址，不接受空数组或全网信任。这是代理到应用的交接要求，外部客户端不负责填写该头。C1、R1、R2、本人、匿名头像、两种退出及原结果读取均消费来源。健康检查与 OpenAPI 不提取来源。网络隔离仍覆盖整个应用监听端口。

### 网站服务的后端读取

本节是目标设计。[网站服务](site.md#渲染与网站服务)将来调用 nucleus 读取公开内容时，把访客 IP 作为唯一的 `X-Real-IP` 转发；该 IP 取自 Nginx 交给网站服务的同名头，不取客户端提交的值。网站服务直接访问 nucleus 的监听地址，其地址登记在 [`NUCLEUS_HTTP__TRUSTED_PROXIES`](../settings.md#9-http-设置) 中作为可信直连对端，与 Nginx 同样只登记准确地址。网站服务不转发浏览器凭据。公开内容读取的预算组见[公开内容读取](#公开内容读取)。

### 来源键

来源键保留完整规范主机地址。IPv4-mapped IPv6 归一化为 IPv4；IPv6 不作前缀聚合。同一出口 IP 的用户共享其来源预算。来源交接只确定限流与业务输入，不证明调用者身份。

## 逐级扣额与回收

每次检查通过消耗一单位。来源桶与进程总桶连续补充、容量封顶。单调时钟决定补充；UTC 时钟回退不补额。入口先检查并扣除来源额度，再检查并扣除进程额度。来源不足时不检查总桶；总桶不足时不返还已扣的来源额度。后续无效凭据或业务拒绝也不返还额度。来源分配、回收和检查处于短临界区，期间不进行认证、数据库操作或网络调用。

| 请求组                                                | 来源补充与容量                               | 进程补充与容量                           |
| ----------------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| `POST /api/v1/codes`                                  | 每分钟 6，容量 2；仍受更严格的持久发码规则。 | 与创建会话与注册组共用每秒 20、容量 40。 |
| `POST /api/v1/sessions`、`POST /api/v1/registrations` | 两入口共用每分钟 60、容量 10。               | 与发码组共用同一每秒 20、容量 40。       |
| 当前身份、机构角色、政治面貌固定名称与头像元数据读取  | 每秒 20，容量 40。                           | 每秒 100，容量 100。                     |
| 匿名头像图片                                          | 每分钟 120，容量 20。                        | 每秒 100，容量 100；独立于元数据读取。   |
| 已认证角色、账户、头像、绑定及会话写入                | 每秒 2，容量 4。                             | 每秒 10，容量 20。                       |

原号发码 `POST /api/v1/accounts/current/codes` 与 `POST /api/v1/codes` 共用发码来源桶和进程总桶，只扣一次入口额度。当前身份中间件复用已提取的来源，不再扣已认证写入组。`POST /api/v1/mobile-changes` 属于已认证写入组。

发码组与创建会话与注册组各有来源存储，但共享表中的进程总桶。其他行使用各自的来源存储与总桶。表中为已采用的目标初值，其他路由接入前由所属能力确定预算组。业务持久额度另按其所有者检查，不能因本地桶尚有额度而省略。

每个来源及进程总额各为一个跨请求保留的令牌桶，补充、扣额和拒绝等待由其计算。来源容器拥有数量硬上限与容量回收。C1 与 R1/R2 使用两个来源组，并共享一个进程总桶。

只回收已与新建满桶等价的来源状态。允许延后回收，按间隔清理或在容量紧张时清理；不要求精确时点或特定索引。来源拒绝不推迟补满时点，总桶拒绝前已扣的来源额度仍参与计算。每组来源存储最多 10,000 项。达到上限时先清理可回收项。仍满时保留既有来源，拒绝新来源分配，返回 HTTP 503、`dependency_unavailable`。记录容量耗尽，不淘汰尚未恢复的来源。

C1 使用最后一次来源扣额后 20 秒、R1/R2 共用组使用 10 秒、元数据及已认证写入使用 2 秒、图片使用 10 秒作为安全回收时点。该时长足够从空桶补满，等号允许。只有新来源遇到满容量时，才扫描并清理可回收项。扫描同时保存最早可能回收的时点；此前的容量拒绝不重复扫描。既有来源继续使用原桶正常补充额度，空闲状态延后保留也不突破 10,000 项。

普通额度不足立即返回 HTTP 429、`rate_limited`，不排队。`Retry-After` 使用本次拒绝层给出的等待时间，向上取整到秒，至少为 1 秒。响应不预留额度，也不保证重试时另一层有额度。来源头格式错误按输入拒绝。必需的直接对端信息缺失属于装配错误，返回 HTTP 500、`internal_error`。预算状态不可用返回 HTTP 503、`dependency_unavailable`，不进入业务判断。JSON 正文的共同 8 KiB 上限由 [HTTP 入口与响应](api.md)拥有。

来源容量、图片传输许可和预算状态故障均返回 503。共同响应边界记录一次技术失败，保留各自原因。事件关联本次请求，不记录来源地址、凭据、正文或签名 URL。普通额度不足仍为 429，不作为技术失败记录。该边界处理进入业务前的拒绝。受管工作仍由[工作完成边界](../architecture.md#就绪与观测)记录最终诊断。

## 媒体传输

签名头像与工牌会话资源共用八个不排队的传输许可。工牌资源先按元数据读取组扣额并验证会话，再登记连接传输；不另扣头像图片组。传输容量不足为 `503 dependency_unavailable`。文件读取与发送共用从登记起算的 30 秒期限，已登记的成功、业务错误及 HEAD 响应均以 `Connection: close` 结束上游 HTTP/1 连接。

许可保留到实际连接发送结束，不能在文件读取返回或响应对象构造完成时释放。阻塞文件读取另持同一许可的引用，调用方退出或连接中止后仍覆盖实际读取。到期、断连或服务停止结束发送后释放连接持有部分；停止可中断已经准备好的慢响应。字节流开始后的错误直接中断，不追加 JSON。

## 公开内容读取

[内容公开读取](../content/http.md#公开读取)的来源沿两条已有路径：网站服务渲染页面时按[网站服务的后端读取](#网站服务的后端读取)转发访客 IP，浏览器加载公开图片时经 Nginx 按[代理交接](#代理交接)进入。两者都以访客 IP 为来源键，网站服务自身的地址不成为来源。

公开 JSON 读取与公开图片各设独立预算组，不与元数据、头像图片或办理组共用来源存储和总桶；公开图片的传输许可也与头像图片分开。两组的补充速率、容量和许可数量尚待确认，推荐值及理由见[待确认事项](../engineering/delivery.md#网站公开内容待确认事项)。网站服务的内存缓存使到达 nucleus 的公开读取远少于页面访问，预算按缓存未命中的请求估算，不能因此省略来源限制。

内容管理入口不新增预算组：写入沿已认证写入组，JSON 读取沿元数据组，图片上传另受[内容图片](../content/images.md#上传与处理)的处理许可约束。签名管理图片字节读取不走元数据组，与公开图片共用公开图片预算组和传输许可，因为图片列表一页至多 100 张缩略图会同时请求；该组容量须同时覆盖单个公开页面和一页图片列表的图片数。

## 有界状态与验收

来源补充速率为 `r`、容量为 `b` 时，最后一次扣额后至多 `b / r` 即可补满。总桶拒绝也会留下已扣额的来源，因此不能由总桶吞吐推导来源数量上界。内存边界由 10,000 项硬上限和安全回收共同保障。持续更换地址可耗尽来源容量，这是受控拒绝场景，不代表容量要求已通过真实负载验证。

用可推进的单调时钟和独立期望值验证补充边界。核对来源拒绝不扣总额，总额拒绝保留来源扣额。验证 10,000 项边界和满容量下的既有来源检查。清理前后额度等价，延后清理也不突破容量。并发请求共享同一来源额度，重启只重置本地桶。负载记录区分来源、总桶、图片许可与持久预算的拒绝。场景覆盖共享 NAT 与读写图片混合负载。

验证非可信对端拒绝，以及单值头缺失、重复、多值和非法 IP；IPv4-mapped IPv6 归一化与 IPv6 主机区分；无效来源在业务调用前被拒绝；首次可信来源写入原 Challenge，恢复请求不替换该来源。代理联调须验证伪造头被覆盖、业务端口无法绕过，以及有上游代理时的真实来源。文档及纯单元模型不构成容量证据。

验证 R1/R2 共享来源桶、跨来源的 C1/R2 共享总桶（观察上限包含实际经过时间可补充的额度），以及格式、Origin 和额度拒绝均先于 R2 持久接纳，不产生 Attempt。

验证多个 Router 交替读取本人资料、机构角色和头像时来源桶与总桶仍共用，且元数据、图片和办理组互不错误扣额；图片许可随真实连接持有至结束，不能因 handler 返回就回收；传输截止与 HTTP 排空见[头像验收](../identity/avatar.md#验收)。

跨 Router 配额与来源容量诊断测试固定入口预算的单调时点。测试按精确额度核对，不以机器吞吐推断桶的共享或回收。HTTP、数据库、图片许可和正常收尾仍真实执行。场景保留外层截止；补充与回收边界另用可推进时钟验证。

容量诊断验证来源状态填满后在最短回收期内的拒绝覆盖匿名办理、本人读取、退出、原退出查询和头像；持有八份许可时第九个图片请求报告传输许可不足；每次故障只有一条关联准确请求的 ERROR，普通限流和无效链接不产生技术失败；预算状态故障沿共同响应映射。这些检查不代替真实负载验收。

当前退出和全部退出验证同一来源四个突发额度和跨来源的共享总额，元数据组不被退出扣额。来源预算先于认证，因此无效凭据仍扣本地额度。GET 原退出结果沿元数据组，DELETE 沿已认证写入组；头像、绑定等后续写入口接入时复用该组。

机构角色 `POST /api/v1/roles`、`PUT /api/v1/roles/{id}` 沿同一已认证写入组和来源容器，与两种退出共用额度，不另设管理配额。PUT 先校验路径 ID；两种入口均先扣来源与总桶，再认证、解码正文及核对权限。办理许可复用运行时共同工作容量，HTTP 取消不释放实际任务持有的许可。
