# HTTP 入口与响应

已交付的路由、方法、请求与响应形状以实际装配生成的 [OpenAPI 文档](#openapi-与实际入口)为唯一来源。本文拥有普通请求标识、提取器边界、JSON 封装、通用应用码，以及 Router 与 OpenAPI 的一致性。各业务能力拥有自己的路径、认证条件、结果字段和专用应用码；[项目标识](../identifiers.md)拥有服务端 UUID 生成，Identity 当前会话证明见[当前身份设计](../identity/current.md)。

## Nginx 接入与传输目标

生产访问统一经过 Nginx，由 Nginx 终止 HTTPS。Nginx 只把 `/api/` 前缀原样转发给 nucleus，见[路径前缀与版本](#路径前缀与版本)。nucleus 的上游监听地址仅允许受控 Nginx 访问，不向外部客户端开放；目标设计中，网站服务读取公开内容时也直接访问该地址，见[网站服务的后端读取](admission.md#网站服务的后端读取)。由部署者配置并验证代理与网络边界。应用的来源校验沿[单值来源交接](admission.md#代理交接)，不重复解析完整代理链。

Nginx 负责外部连接数量、请求头读取、正文读取、空闲连接和慢客户端保护。C1 JSON 正文完整缓冲后再转发，避免外部慢正文长期占用应用连接。缓冲和大小限制共同生效，见 [proxy_request_buffering](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_request_buffering)。应用继续限制 8 KiB 正文、入口预算和已接纳工作容量。应用传输以 128 个连接许可和最多 60 秒的连接寿命为界，与业务工作容量分开；连接关闭才释放许可。

目标不要求应用连接统一在 60 秒时关闭。取消当前总寿命限制前，先实现并验证上述代理边界。正文读取间隔超时不等于总传输时限；持续缓慢发送仍可能维持外部连接。代理验收同时覆盖慢请求头、慢正文、空闲保活和连接容量，不能只检查一个超时值。相关语义见 [Nginx 请求读取超时](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_body_timeout)。

代理不自动重试业务写入，也不改写应用错误为成功或网站首页。代理自行拒绝或超时不保证应用 JSON 封套，更不证明原办理失败。普通工牌刷新当前状态，不自动重做；短信及未迁移消费者保留原材料，沿所属合同恢复。连接关闭不证明数据库回滚。

隔离联调验证来源头覆盖，以及业务端口无法被外部绕过。再核对缓冲、容量限制和代理断连后的状态刷新，以及适用消费者的原结果恢复。实际部署另行核对有效配置；单元测试不证明生产代理已生效。

## 路径前缀与版本

`/api/` 整个前缀保留给后端，网站拥有其余全部路径。Nginx 只把 `/api/` 前缀的请求原样转发给 nucleus，不剥掉或改写路径；当前全部业务路由位于 `/api/v1/` 下。签名头像 href 由头像 origin 加实际路由路径构成，因此同样带前缀；`NUCLEUS_IDENTITY__AVATAR__ORIGIN` 仍只接受 origin。已保存原输入证明中的规范路由文本（例如 Access 与注册证明的域分隔字段）是编码常量，不随 HTTP 前缀改变。

迁移后，原根路径业务入口和旧 `/openapi.json` 不再响应业务，返回普通 JSON `404 resource_not_found`，不重定向也不设别名。未知路径与不支持的方法在前缀内外分别返回 404 与 405，都先经过共同中间件。

健康检查 `/health/live`、`/health/ready` 和 OpenAPI `/openapi/v1.json` 留在根路径。Nginx 不转发它们，只能在本机直接访问后端端口：健康检查供 systemd 与监控使用，OpenAPI 供 CI 与客户端类型生成使用。客户端按[客户端协议](../client/protocol.md)从已固定的本地文档生成类型，不需要在线读取；不对外暴露也避免安全测评中的接口文档泄露，以及不受入口预算保护的匿名请求。

版本规则如下：

- 同一版本内只做兼容改动：新增字段、新增接口、新增应用码。
- 单个接口需要不兼容改动时，在当前版本内新开资源名，与旧接口并存。
- 只有一批接口需要不兼容改动时才开新版本：后端同时装配 `/api/v2/` 路由并导出单独的 `/openapi/v2.json`，新旧版本并存一段过渡期。
- 目标：小程序上报客户端版本，后端配置最低支持版本，低于时返回专门的应用码。没有真实消费者前不实现。

## 路由与请求边界

路由按资源和用例命名，不把内部 crate 名加入路径。是否要求当前会话由路由静态决定，不能由正文类型、是否重试或浏览器附带 cookie 改变。匿名登录与注册不要求已有会话；本人和管理入口按所属能力验证身份与权限。Router 只装配已交付能力，不用配置开关隐藏承诺入口的依赖缺失。公开、签名读取及技术入口各守自己的证明和媒体类型。GET 路由同时支持无正文的 HEAD，OpenAPI 一并声明这些方法。迁移前办理入口有界等待独立工作，超时返回 `outcome_unknown`，读取失败返回 `dependency_unavailable`。新增工牌直接执行，写入结局未知引导刷新状态，不承诺独立工作完成。适用范围见[架构](../architecture.md#原操作与恢复)。

除本节明确豁免的入口外，所有请求都发送唯一的 `Operation-Id` 请求头，包括普通 GET、匿名调用及健康检查。客户端在发送前生成 UUID；专用中间件在认证、业务限流及读取正文前校验一次。文本接纳形式见[项目标识](../identifiers.md)。缺失、空值、重复、多值、无法解析的文本返回 HTTP 400、`code: invalid_input`。中间件将已验证的 `operation::Id` 放入请求 extensions。后续提取器只读取该值，不重新解析、补造或从其他字段恢复标识。正文中的实体 ID、原办理 ID 与 `Idempotency-Key` 均不能替代请求头；标识本身也不授予读取或执行权。

成功与错误响应均不回显请求标识，不增加替代响应头。客户端保留自己的原操作标识；服务端将合法标识用于内部关联；只有明确提供原操作合同的消费者将它用于恢复。业务结果自身的实体 ID、原完成 ID 等字段继续按所属协议返回。共同中间件也覆盖普通未知路径和不支持的方法，再分别交付 404 或 405。不能因只对已匹配路由挂载中间件而漏过兜底。所有 HEAD 响应均无正文，包括提取失败和兜底错误。

新写操作使用新标识。请求关联不等于幂等保证，新工牌不建立完成记录。短信和未迁移的原操作重试使用原标识与原输入，由所属合同负责证明、结果及保留期限。普通 GET 只校验格式，不因此建立完成记录。查询原操作时，请求头标识本次读取，路径或查询参数中的标识定位原办理，两者分别校验。已合法清理的原结果不能凭旧标识重新执行。

下列后端入口按各自证明和媒体类型豁免 `Operation-Id`：签名头像 `GET /api/v1/avatars/{digest}.webp` 及其 HEAD；`GET /openapi/v1.json` 及其 HEAD；微信 `GET /api/v1/authorizations/callback`；新工牌的会话鉴权资源 GET/HEAD（照片、模板资源及成品 PDF，随真实入口显式登记）；网站公开内容的匿名图片 `GET /api/v1/public/images/{id}.webp` 与签名管理图片 `GET /api/v1/images/{id}.webp` 及其 HEAD，规则见[内容图片](../content/images.md#读取)。头像豁免精确限定单段 `.webp` 路径的 GET/HEAD，不按目录前缀放开其他方法或路径。豁免入口即使收到非法头也忽略它，不从 query、cookie 或数据库另造 HTTP 请求标识。浏览器原生图片读取和供应商回调不要求额外携带该头。业务 JSON 的公开客户端设置读取不因此豁免。新增豁免及适用方法由对应入口明确声明，不能按 HTTP GET、匿名访问或技术用途一概推导。

网站页面、静态资源和微信授权完成页由独立网站托管交付，不进入 nucleus Router。它们不校验或回显 `Operation-Id`。托管归属、部署路由及后端公开设置接口见[网站交付与后端边界](site.md)。

JSON 请求沿用 Axum 的媒体类型判断，接受 `application/json` 和 `application/*+json`。正文形式由 Serde 反序列化决定。接口文档以对象描述字段，也接纳 Serde 支持的结构体序列形式。对象仍拒绝未知和重复字段；必需字段缺失、为 `null` 或类型不符均拒绝。普通 JSON 正文上限为 8 KiB，不设置独立的正文读取超时；更大的上限只由所属能力逐入口声明，例如[内容草稿保存](../content/http.md#管理入口)。传输仍受应用连接数量和寿命限制。目标传输边界见 [Nginx 接入](#nginx-接入与传输目标)。图片上传与签名读取按所属能力的字节、媒体类型和大小限制处理。普通 JSON 响应设置 `no-store`，受保护业务不能从缓存资料推断当前权限。入口来源预算和 `Retry-After` 见 [HTTP 来源与入口资源预算](admission.md)。预算拒绝不证明同标识的先前办理没有提交。

正文包含多种错误时，按反序列化首先报告的错误分类。例如，字段值已无效时可先返回 422，即使后面还有非法 JSON 尾部；字段有效而尾部非法时返回 400。不额外预解析整份正文来保证语法错误优先。

Origin 检查按入口用途选择，不作为全局登录或请求标识条件。网站 cookie 会话的同源条件由[当前身份](../identity/current.md#凭据选择与来源)拥有；匿名 C1 的必填 Origin 由[匿名身份办理](identity.md#路由与装配)拥有。健康、OpenAPI、微信回调和小程序 Bearer 不继承网站的 Origin 要求。

OpenAPI 仅在入口要求必填时，把 `Origin` 列入参数表。不要求必填的 GET/HEAD 不声明 `Option<String>` Origin 参数，浏览器来源的条件校验写在操作说明中。同源 GET/HEAD 通常不发送 Origin，网页脚本也不能自行设置该头，依据 [Fetch 的 Origin 发送规则](https://fetch.spec.whatwg.org/#origin-header)和[禁止脚本设置的请求头](https://fetch.spec.whatwg.org/#forbidden-request-header)。文档表示方式不改变运行时同源检查。

### 提取与错误归属

普通 JSON 入口先取得已验证操作标识、适用的当前身份或可信来源。之后执行入口预算及 Origin 检查，最后读取 JSON 正文。请求体只能读取、解析一次。JSON `Input` 只描述正文，不包含操作标识、来源、预算或其他请求头。处理函数组合各提取结果，调用受控构造器形成领域输入；不为领域输入实现混合这些职责的 `FromRequest`。

R1/R2 的可信来源分别由实际凭据和已核验原证明决定。这两个入口在共享预算之后只解码一次正文，再按[匿名身份合同](identity.md#路由与装配)检查适用的 Origin。缺少 Origin 不构成小程序来源证明。

共享的 Json、Extension、Path 和 Query 适配器通过派生提取委托 Axum。`From` 转换 rejection，`IntoResponse` 生成共同错误响应，并记录安全诊断。路径标识和查询解码失败返回 `400 invalid_input`；路径参数缺失等装配错误返回 `500 internal_error`。Path 和 Query 在正文提取之前执行，非法路径或查询与超限正文同时出现时先返回 400；认证前的路径中间件保留原位置。处理函数以 `Json<Input>` 接收正文，`Input` 不承担请求提取。正文类型由路径集合决定时，处理函数在路径、查询提取后分派对应 `Json<Input>::from_request`。每个请求仍只解码一次，错误沿用共享 Json 映射。处理函数返回 `Result` 不会接住先于它发生的提取失败。要求存在的 extension 缺失是装配错误，返回 500。不得伪装成客户端遗漏或依赖不可用。字段形状归反序列化结构，值规则归值类型，跨字段规则归对应构造器。JSON 字段优先使用已有受控值类型，通过验证式反序列化复用构造或解析规则，不为后置解析保留 String。C1 的手机号、Turnstile token 与 R1 的 Message ID、secret、手机号和验证码直接完成该校验；秘密文本先由可清零缓冲接收。处理函数只组合已验证值与独立提取的请求上下文，不叠加第二套字段校验。由可信来源确定的应用身份和会话传递方式由服务端派生，不要求请求重复声明。

错误层次保留解析原因、领域拒绝、依赖失败和结局未知的区别。HTTP 适配只分类一次，依据结构化原因确定状态与应用码，不在两个枚举间重复同一组分类。错误保存原因和响应所需的受控数据，不保存提前生成的 `Response`。`From` 和 `IntoResponse` 同步，不访问数据库或供应商。可信时间采样等异步工作留在显式调用流程，不能藏进错误转换。请求技术失败在最终拒绝边界记录一次安全诊断，不重复记录业务 worker 的失败。公共响应编码拥有 JSON 形状及响应头，不承担认证、业务判断或重试策略。

JSON 响应直接委托 `axum::Json` 序列化和生成，不添加序列化失败兜底。当前响应使用受控的公开字段；序列化失败沿用框架默认的 500 文本响应，不承诺共同 JSON 封套。HTTP 解析器在进入应用前的拒绝、连接断开和已开始的字节流也无法保证返回 JSON。Axum 行为依据见[提取拒绝定制](https://docs.rs/axum/latest/axum/extract/index.html#customizing-extractor-responses)与 [Json](https://docs.rs/axum/latest/axum/struct.Json.html)。

### 协议适用范围

目标入口按[根包职责](../architecture.md#根包入口目标)装配。共享代码只实现共同规则，路由明确选择适用的证明、请求形状和响应方式。请求头解析不创建 Actor；Identity 核验当前身份后，所属用例仍按[当前资格](../identity/current.md)复查。

| 入口类别      | 适配边界                                                        |
| ------------- | --------------------------------------------------------------- |
| 普通业务 JSON | 共同标识、正文形状与上限；当前认证及用例错误由所属能力决定      |
| 业务上传      | 所属证明、媒体类型、字节与计算预算；不套普通 JSON 正文上限      |
| 签名文件读取  | 所属签名与期限；成功返回字节及私有缓存，错误沿所属协议返回 JSON |
| 微信回调      | 原授权证明、输入与固定跳转；不套普通业务标识或当前登录要求      |
| 健康检查      | 校验共同请求标识；探测结果按技术契约返回                        |
| OpenAPI       | 返回标准文档，保留请求标识豁免                                  |

`/health/live` 只报告进程可响应。`/health/ready` 使用业务共享的持久可信时间，再检查已装配服务的共同接纳状态。两者的 GET 和 HEAD 都先校验 `Operation-Id`；标识无效时返回 400，不执行就绪探测，HEAD 保留相应状态但不返回正文。就绪探测失败仅返回 503 和 `code: dependency_unavailable`，不调用供应商。响应统一设置 `X-Content-Type-Options: nosniff`，不回显请求标识。普通响应及所有错误设置 `Cache-Control: no-store`；成功的签名图片字节保留所属私有缓存头。

C1 的连接寿命、结果等待和已接纳工作具有各自的生命周期与预算，不能用一个全局超时替代。连接关闭不等于已经接纳的工作超时；等待方结束也不证明工作结束。缓存头按响应契约设置，不用全局 `no-store` 覆盖合法的签名文件缓存。字节传输开始后发生故障时中断流，不追加 JSON。

共同 `response` 模块只拥有封装和响应头编码。各能力入口直接依据结构化用例错误映射状态与应用码，不用公开字符串反向驱动错误分类。未提交、结局未知及收尾失败保留原有区别；日志归[最终处理边界](../architecture.md#类型构造与查询)。

用例的结构化失败区分业务拒绝、额度、结局未知和依赖不可用，并保留未知结局及收尾失败的优先级；HTTP 层据此选择应用码，不递归解释内部错误。状态码与 `Retry-After` 归 HTTP 适配，原错误继续保留在请求错误中。

## JSON 结果与应用码

自有 JSON 请求和响应的字段名统一使用 `camelCase`，包括嵌套对象。Rust 字段保持 `snake_case`，接口结构通过 `#[serde(rename_all = "camelCase")]` 声明公开名称，OpenAPI 使用同一名称。请求头、URL 参数、供应商协议和应用码的取值沿各自契约。

具有明确公开表示的值类型直接实现 `Serialize`，接口结构保留该类型，不先转换为字符串或原始值。领域结果需要裁剪字段或改变公开形状时，由接口响应类型完成投影。不得因可序列化而输出秘密、内部事实或未获交付资格的结果。

成功 JSON 使用用例规定的 HTTP 200 或 201、`code: "ok"` 和一项具名业务结果，如 `message`、`registration`、`session`、`account`、`authorization`、`completion` 或 `progress`。不含请求标识，不返回 204，不增加通用 `data` 包装。所属用例明确限制披露时，允许只返回 `code`，如[政治面貌写入](../center/affiliation.md#http-契约)。`progress: { status: "pending", retryAfterSeconds }` 只表示原办理可靠地仍在执行，不能与已经取得的业务结果同报，也不等于结果已提交。`GET /openapi/v1.json` 成功直接返回标准文档；签名图片成功返回所属媒体字节。两者的应用错误仍用 JSON `code`。健康检查成功使用 `code: "ok"` 与 `live: true` 或 `ready: true`；未就绪仅返回 HTTP 503 和 `{ "code": "dependency_unavailable" }`，不再附 `ready: false`。

基础错误正文仅为 `{ "code": "..." }`，不含 `operationId`、`message` 或通用 `details`。`Retry-After` 等受控元数据放在所属响应头。用例若确需公开错误字段，必须在其契约和 OpenAPI 中逐项定义，不能输出任意原因对象。

共同协议拥有通用错误码，专用错误码由所属能力维护。公开错误码类型须可序列化并提供 Schema。枚举自身序列化为稳定字符串，并提供开放字符串 Schema，不列举封闭枚举值。`Failure<C: AsCode>` 直接派生序列化，内联使用错误码类型的 Schema，不覆盖字段类型。其 `code` 字段直接构造，在 OpenAPI 中为必填字符串。新增能力无需扩大全局枚举；内部技术错误也无需逐个增加公开码。

原结果读取若成功取得一份已保存的业务拒绝，本次读取仍是 `code: "ok"`；原拒绝放在所属具名结果中。这不增加注册历史查询。错误 JSON 使用稳定、区分大小写的非空 ASCII `lower_snake_case` 应用码，不输出 `error.kind`。HTTP 状态表示通用类别，`code` 区分调用方需要采取的不同行动。同一 HTTP 状态可以有多个应用码；客户端遇到未知码或状态与码矛盾时保留原写入定位，不认定成功，也不自动换键重办。公开值不得随内部类型重命名改变含义；提示文字和本地化不作为流程判断依据。错误详情只包含用例允许的受控字段，不输出内部异常、供应商原文或秘密。

| `code`                   | HTTP               | 通用含义                                                                                          |
| ------------------------ | ------------------ | ------------------------------------------------------------------------------------------------- |
| `invalid_input`          | 400、413、415、422 | 头或 JSON 语法错误为 400；正文过大为 413；媒体类型不符为 415；JSON 字段形状、类型或值错误为 422。 |
| `internal_error`         | 500                | 必需的 extension 缺失等由应用映射的内部错误。                                                     |
| `authentication_invalid` | 401                | 当前会话或适用的原证明不成立，不透露对象细节。                                                    |
| `permission_denied`      | 403                | 当前操作者没有该动作或对象的权限。                                                                |
| `resource_not_found`     | 404                | 未装配的路径或所属协议确认不存在的公开资源。                                                      |
| `method_not_allowed`     | 405                | 已知路径不支持该方法，附 `Allow` 说明支持的方法。                                                 |
| `request_mismatch`       | 409                | 可识别原办理，但命令、来源或规范输入与原请求不同。                                                |
| `result_unavailable`     | 404                | 本次可靠读取没有可向所持身份或证明返回的原完成；不证明原命令失败。                                |
| `rate_limited`           | 429                | 资源预算不足，附 `Retry-After`；不说明先前办理结局。                                              |
| `dependency_unavailable` | 503                | 依赖或必要事实无法可靠取得；不伪造业务拒绝。                                                      |
| `outcome_unknown`        | 503                | 提交结局尚未确认；普通工牌刷新状态，短信及未迁移消费者按原合同核对。                              |

专用码由各能力定义，但同一公开码不得在不同能力改作矛盾含义。用例在已确定拒绝、仍在执行、提交未知和成功之间保留明确边界；网络断连或 HTTP 超时不证明回滚。错误映射由 HTTP 适配负责，业务模型不保存 HTTP 状态。

## OpenAPI 与实际入口

`GET /openapi/v1.json` 返回 OpenAPI 3.1 文档，只描述 v1 路由，以及同在根路径的健康检查与文档入口自身。文档中的路径就是实际请求路径，业务路由带 `/api/v1` 前缀，不用 `servers` 字段表达前缀。nucleus 入口从实际装配的 Router、请求及响应类型和必要注解构造描述，启动时包含文档入口自身，汇总公共参数、认证与错误，序列化一次并保存不可变字节。组装或序列化失败使启动失败。未装配的能力不能出现在已交付接口清单；已装配的路由也不能缺失描述。独立网站托管的页面与构建资源不属于后端 OpenAPI。

每条路径描述真实的请求头、当前认证、同源条件、媒体类型、状态、响应头和可出现的具名结果。不同成功分支使用各自完整的响应 schema；同状态有多个合法形状时显式表达互斥。缺失字段与 `null` 分别建模。错误 schema 的 `code` 保留可扩展字符串，列出已知语义；不能用封闭枚举使旧客户端拒绝未知码。`format: uuid` 不代替实际解析和用例期限校验。OpenAPI 操作对象中的 `operationId` 是稳定的接口名称，继续保留；它不是响应中的请求标识回显。

一个组件名只标识一种公开数据形状。完整值与其脱敏投影采用不同名称，共享同一投影的入口引用同一组件。移动或共享响应类型后，沿生成文档的 `$ref` 核对所有受影响输入与输出。核对范围包括新增与既有路由，防止组件被另一种形状覆盖。

业务 JSON 类型、图片原始字节、图片成功媒体类型及 JSON 错误分别描述，不把图片表示为 JSON 数组或 base64 文本。HTTP 适配使用受控响应类型，避免直接序列化领域秘密或数据库行。验收用实际 HTTP 请求逐路径核对 Router、状态、头、结果形状、错误和 OpenAPI；语法通过或文档可下载都不能单独证明一致。

共同协议实施时验证标识只解析一次，普通兜底与健康检查不漏检，豁免不校验非法头。检查所有 HEAD 无正文，成功和失败均无请求标识回显。另验证 Axum 默认 JSON 媒体类型、Serde 输入形式及 400/413/415/422 的区别。缺失 extension 必须产生安全的 500；非 JSON 成功与流中断按各自协议验证。生成 OpenAPI 必须随实际实现同步调整；不能只改描述使当前入口看似符合新协议。本文认可不授权同时实现会话认证、全部后续路由或日志设施。

## 进程命令行

`nucleus` 无参数时启动服务。`--help` 和 `--version` 在设置装载前成功退出。参数错误以状态码 2 退出，不回显无效参数；运行失败以状态码 1 退出，并保留脱敏诊断。
