# 列表读取目标设计

本文规定业务分页列表的共同参数、快照和计数语义。各能力拥有具体读取权限、筛选、排序、记录形状及业务错误。[HTTP 入口与响应](api.md)规定请求标识与 JSON 封装。

分页列表使用 `page`、`size`，均为整数。`page` 从 1 开始，省略时为 1；`size` 为 1 至 100，省略时为 20。只对省略值应用默认，显式无效值返回 HTTP 400、`invalid_input`。响应包含当前权限和筛选范围内的 `count` 及具名记录数组，例如 `corrections`、`admissions` 或 `applications`；无记录返回 `count: 0` 和空数组，越界页保留当前总数并返回空数组，不用 `null`。

分页值及 `(page - 1) × size` 偏移须可表示为 64 位有符号整数。超出表示范围、重复参数和未知参数同样返回 400。该界限来自整数表示，不是业务页数上限。业务用例复用同一受控分页值与解析。

每页在同一决定性快照中核对当前权限、计算总数并读取记录。排序由所属用例固定，使用业务时间或个人顺序，再以唯一 ID 稳定并列；不能凭 UUID 大小猜业务先后。复杂一致读取使用只读 `REPEATABLE READ` 事务，预算最多 3 秒；超时或必要事实缺失使整页失败，不拼接不同授权时点的半份结果，也不把失败计数当 0。

客户端以 `page × size < count` 判断是否还有下一页。不同页之间不承诺同一数据库快照；翻页期间新增或变化可移动后续页，刷新从第一页开始。分页不授予权限，也不让 `count` 包含无权对象。当前授权摘要、完整目录树及其他必须一次返回的聚合不因含数组而拆页。

[Grant、暂停、恢复及结束历史](../access/grants.md#历史读取)使用共同分页。分别按 `grantedAt`、`suspendedAt`、`resumedAt` 或 `terminatedAt` 降序，再按 ID 降序稳定排序。结束历史合并人工与注销派生来源，派生项的标识及原操作语义归授权生命周期所有。人员、Grant 及原操作筛选取交集；筛选不缩减对本页所涉人员保留授权链的完整性核对。资格和状态均取自本页快照，后续失权适用于下一请求。

手机号、身份证号、邀请码及文件路径不作 URL 查询条件。手机号精确候选使用所属用例的 POST `candidates` 入口，手机号放正文；成功必有候选对象，无可返回目标是 404，当前职责不足是 403，依赖失败不能伪装为未命中。本人和管理入口各自固定认证与授权，不通过客户端字段切换。

验收覆盖缺省、最小和最大参数、显式无效值、空集、越界页、权限收窄、筛选后的计数、同时间排序及跨页变化。用受控并发验证权限和记录在一页内来自同一快照，并注入读取超时与缺失事实。各列表的专属筛选随所属消费者验证，例如[角色验收](../access/roles.md#验收)。
