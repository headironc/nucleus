# Claude Code 调用契约

本文拥有 Claude Code 的调用、工具与审批语义、结果处理和恢复边界。采用 [agents 调用契约（069cb54）](https://github.com/silence-force/agents/blob/069cb54d6ceb8eafb8fc462320db657028a94e97/delivery/policy/claude-code.md) 的只读、有界执行、权限与恢复规则，保留项目的 Figma 专用路线。分工、模型偏好、授权复用和报告接纳由[模型政策](models.md#claude-code-与-deepseek-委派)拥有。本仓库不交付 Claude Code 可执行文件或调用执行器。

## 服务、输入与运行边界

模型接口只允许 DeepSeek 官方与 OpenCode 官方服务。DeepSeek 的 Anthropic 兼容端点为 `https://api.deepseek.com/anthropic`。OpenCode 的 Go 端点为 `https://opencode.ai/inference/go/anthropic`，通用端点为 `https://opencode.ai/inference/anthropic`。按官方文档核对本次实际地址。兼容别名、第三方转发或自建网关不因使用同一模型名而进入允许范围。扩大接收方必须有用户明确决定。核对实际接收端点、凭据来源、模型与 effort，不显示密钥或鉴权头。客户端名、配置中的模型名及响应模型名都不证明实际上游身份。模型服务授权不代替业务操作授权或宿主审批。

调用前绑定实际 CLI 与 SDK 版本、接收端点、有效参数、输入材料、任务范围和预期报告。复用已授权凭据。通过标准输入提供材料，避免将内容放进命令参数。工具读取的文件、自动加载的指令、插件上下文及 MCP 返回内容同样属于材料范围，调用前核对。保留可信 hooks、宿主审批和平台权限；CLI 参数不代替宿主隔离。

保留现有个人配置，只在本次子进程设置模型、effort 及必要的网关地址。`CLAUDE_CODE_EFFORT_LEVEL` 优先于 `--effort`；将选定值同时用于 CLI、子进程环境和本次 `--settings` 的 `env.CLAUDE_CODE_EFFORT_LEVEL`，核对有效覆盖，不写入持久配置。`--bare` 会跳过 hooks、自动发现的指令等功能，不作为通用调用默认值。只有确认未移除适用约束，且输入与凭据来源明确时，才采用相应的隔离调用；不得跳过配置以规避拒绝。

## 只读模式与有界执行

只读模式用于只读分析、初步审查和边界用例建议。使用 print 模式 `-p`；材料已完整提供且无需工具时，以 `--tools ""` 禁用内置工具。需要读取源文件时，只开放适用的读取工具。另用 `--no-session-persistence` 避免保存会话历史。MCP 选择按[工具与权限](#工具与权限)执行。核对有效输入没有额外工具或未授权材料。验证所需的临时写入按[检查范围](verification.md#检查范围)限定命令与输出位置，不授权修改被审查源码。

有界执行使用 `-p` 和 `--no-session-persistence`。按[模型政策](models.md#claude-code-与-deepseek-委派)绑定完整任务、材料、候选与唯一写者。按任务开放实际需要的读写、编辑和命令工具，核对命令效果、目标及输出位置。执行期间，负责人不同时修改同一写区。执行者遇到未决业务或范围变化时报告，继续独立的范围内工作。

在用户自己的已授权开发仓库中，Claude Code 与负责人沿用同一任务范围和宿主权限规则。正常读写、命令与测试不因委派而增加单独审批或强制沙箱要求；委派也不提供绕过宿主拒绝的权限。只有实际材料来源或执行效果出现具体边界问题时，才处理受影响的调用；不把假设中的恶意仓库当作当前仓库已受攻击的证据。保留宿主已有审批政策、审批器、沙箱、可信 hooks 和 deny。执行权限不授予发布、合并、部署、秘密或凭据操作；这些仅在另行覆盖的有效授权下执行。

返回实际差异、产物位置、检查命令和结果、当前候选及遗留进程。失败和未知外部写结果分别报告；由负责人按[模型政策](models.md#claude-code-与-deepseek-委派)接纳。

## 工具与权限

`--tools` 限制内置工具集合，不限制 MCP。`--allowedTools` 提供免提示许可，不构成封闭白名单。继承的权限数组会合并。`dontAsk` 拒绝原本会询问的调用，已许可或无需询问的动作仍可执行，不作为无人值守开发的通用默认。内部 Bash 预检仍可能把匹配允许前缀的命令转交审批；直接拒绝这类请求不能证明任务没有授权。不要通过反复变换等价命令或补丁、更换执行者或服务商来解除拒绝。

调用前核对继承权限、技能的 `allowed-tools`、hooks、其他审批扩展、插件及实际 MCP 集合。按有效授权设置本次必要许可，不要求用户逐个批准技术参数。没有 MCP 需要时，使用 `--strict-mcp-config` 且不传入 server 配置；需要时使用 `--strict-mcp-config --mcp-config`，并核对实际载入的服务器集合。

工具许可与路径约定不构成宿主隔离，服务器选择也不证明 Figma `fileKey` 隔离。保留可信 hooks、宿主和平台权限；无法满足边界时暂停依赖执行。不得全局跳过权限、禁用适用 hooks 或修改持久配置来解除限制。明确拒绝后，核对原因并沿正常支持机制处理，不换路规避拒绝。

### 权限模式与实际生效

已授权的有界开发优先使用受支持的 `auto`。CLI 显式传入 `--permission-mode auto`，SDK 使用 `permissionMode: "auto"`。`auto` 使用安全审查模型判断待审批动作，不等于跳过权限。核对实际 CLI 与 SDK 版本、组织限制、有效模式和审批模型。print 与 SDK 的启动默认值随版本和配置变化，不依赖默认值推断本次模式。请求 `auto` 不证明其门禁或分类器实际工作。

当前官方支持以 `CLAUDE_CODE_AUTO_MODE_MODEL` 指定审批模型，要求 Claude Code 2.1.302 或更高版本。仅在本次子进程设置，并核对继承的模型映射。审批请求同样受本文的服务商和材料授权约束；不要让默认审批模型引入未授权接收方。变量被接受或主模型能响应，都不证明审批模型兼容。DeepSeek 或 OpenCode 路线的审批兼容性仍须真实验收。

在真实必要动作中核对有效模式及判定记录。客户端审批可从受限调试日志的 `classifier_request_started` 核对实际本地审批模型；配置被忽略时核对对应原因。服务端审查可能没有这条记录，应另核对受支持的状态及实际判定。日志先按本文要求脱敏。仅设置 `auto`、模型别名或变量，不足以宣称生效。无法核实有效 effort、模型身份或判定时保留未知，不用请求值或客户端标签反推。

### 正常审批转交

`auto` 不可用或需要正常转交审批时，使用官方 SDK 的 `canUseTool`，或 CLI 支持的 `--permission-prompt-tool` 接收请求。CLI 提示工具必须来自本次明确加载的 MCP 集合。需要时在本次调用使用 `default` 加审批回调。回调只处理实际到达的请求，不保证覆盖先前已允许或已拒绝的动作。无人值守调用必须有实际可工作的审批接收者。未收到回调、classifier 无判定或工具仍被拒时，按具体原因报告，不能当作成功回退。

原负责人依据有效用户授权，逐项审查实际到达的完整请求，绑定请求或工具调用标识。审查覆盖完整工具名与原始输入、目标和真实工作区、预期效果、真实判定理由及候选绑定。支持的 SDK 可提供 `decisionReason` 与工具调用标识；缺失时保留缺口。正常界面允许负责人判断且范围已覆盖时，仅批准当前请求。保持输入不变，并保留原始输入与决定证据。不返回扩大许可的 `updatedPermissions`，不按工具名或命令前缀批量允许。不伪造分类器模型、禁用 hooks、全局绕过权限或修改持久配置。原有 deny、可信 hook 拒绝和专属用户决定继续阻断。正常审批不代替缺失的业务或操作授权。

保留 Codex 宿主已有审批政策、审批器和沙箱。Claude Code 的模式及审批模型只在本次调用内选择。区分宿主拒绝、客户端待审批和运行失败，沿各自支持的机制处理。实际拒绝解除后，核对原运行、真实差异、终态与匹配候选的检查。机制已确认、候选修法和端到端成功分别报告。

## 结果、失败与恢复

结构化采集使用 `--output-format stream-json --verbose`，保留完整任务报告及必要的运行元数据。分别记录请求的模型、effort、响应中的模型标识和已核实的有效 effort。服务端未证明的具体版本、档位或身份保留未知。日志省略凭据、鉴权头和原始 thinking，不记录图片 base64。工具参数及结果也先脱敏；不因块类型为 text 或 tool_result 就认定安全。保留可读预览位置及必要调用证据。客户端费用估算不作为 DeepSeek 账单。

完成要求进程退出码为 0、结果的 `is_error` 为 false，且报告满足本次输出合同。核对终止原因与已知流错误；只有 `subtype: success` 或 HTTP 200 不足以证明完成。缺少结构化结果、截断或只有 thinking 时，按未完成处理。负责人接纳时核对原始完整运行、退出、结果与终止状态。另核对实际差异和匹配候选的检查。配置已保存、离线包装测试、初始化或部分报告均不构成完成证据。报告有效不等于其中的判断正确。

单写者身份在任务及子进程存续期间保持绑定。调用方超时或本地取消不证明原任务、其子进程或外部写入已经结束。核对原运行句柄、部分产物和原目标；写结果未知时先回读同一目标，再决定是否重试。不盲目重复同一失败或结果未知的写入。失败后先检查实际版本、地址、模型、参数和原运行句柄。核对已产生的差异、子进程及外部操作状态。再沿正常支持机制修复已确认原因，或由负责人接回剩余工作。

同一任务中出现重复违约时，通过原句柄停止。核实原任务的终态与子进程均已结束，之后才由负责人收回唯一写者身份。保留部分成果、原证据及其覆盖范围，不把停止本地等待当作远端操作结束。

输出截断可能触发 CLI 自动续写。上游在 Claude Code 2.1.303 的本地模拟中观察到单次启动产生四次请求，`--max-turns 1` 未限制这类续写。该观察仅覆盖被测版本和条件，不是固定重试次数。核对实际请求及终止状态，不能把轮数限制当作请求次数上限。超时取消后核实本地进程终止；服务端完成状态未知时保留未知，不直接重发。

## 设计路线导航

Figma 设计沿用 DeepSeek Max Effort 加 Design critique 的专用路线，交付原生可编辑 Figma 输出。负责人打开实际原始渲染图验收；页面要求仍由[网站 UI 设计](../client/pages.md#网站-ui-设计)及[页面验收](../client/pages.md#验收)拥有。保留设计任务的材料、服务商、目标和写入边界，普通开发不继承 Figma 权限。
