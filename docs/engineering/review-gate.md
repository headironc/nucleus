# 已退役的审查与准入关卡

旧 CI 门禁及 dev/main 自动准入、凭据签发和可信合并程序已移除。固定 Docs 配方、共享执行器分发与准备入口一并删除。新 CI 由 Nucleus 独立维护，从零建立，不要求兼容旧 S/P、报告或状态协议。

当前交付遵循[交付规则](delivery.md#审查关卡与证据复用)与[普通分支保护](delivery.md#普通分支保护)。平台强制当前四项原生 CI 通过。交付负责人另行验收适用本地检查、业务验收、独立代码与安全审查及发现处置，然后按有效授权执行普通 PR 合并。普通保护不恢复旧 Cladiron 检查、人工批准或队列；旧门禁退役不豁免当前 required CI。

## 历史恢复

删除前的[源码和原操作恢复合同](https://github.com/headironc/nucleus/blob/e09919bb2fbdc28999fa7b01086d95cb81d2f9a1/docs/engineering/review-gate.md)保留在 Git 历史。外部原件、原请求身份、未知结果和各原工作区保留。历史操作继续按原版本和原责任恢复，不重新绑定，也不通过恢复旧门禁重复发送。

源码删除不改动 App、密钥或其他消费者，不部署生产配置。历史协议中的 workflow 路径保留原含义，不作为新工作流必须实现的接口。

## 两层原生 stack

项目的实现 PR 仍面向 `dev`，必要的依赖链保留各层完整业务结果和独立审查。旧 stack 准入控制器已移除；具体平台入口按其实际能力使用，不用旧状态放行新候选。

## dev 队列检查

旧队列及其专属检查已退役。原队列身份只用于历史恢复，当前 PR 不入该队列。

## 个人 main 固定发布候选

旧自动晋级程序已移除。dev/main 的业务分支与提升要求继续由[分支流程](delivery.md#分支测试与提升)拥有，不恢复旧控制器作为交付前提。

## 个人 dev 严格同步 PR

旧自动准入与可信 squash 程序已移除。当前普通 PR 的审查、授权和结果读回由[交付规则](delivery.md#审查关卡与证据复用)拥有。
