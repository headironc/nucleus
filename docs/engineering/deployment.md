# 数据库部署工具

独立 `deployment` crate 拥有迁移、首次密钥登记、Access 空库初始化、停机指派及系统管理员实名更正入口。它依赖 domain 与 platform，nucleus 不依赖它；应用启动不运行迁移。迁移库只进入部署工具的生产依赖图。package 组织见[架构](../architecture.md#crate-与模块组织)。

## 执行入口

先构建 `cargo build -p deployment --locked`，再执行 `target/debug/deployment migrate`、`keys init`、`admin initialize`、`admin appoint` 或 `admin correct`。生产部署选择 release 产物。命令不接收密码、连接串、SQL 路径或任意密钥文件参数。错误使用脱敏 `Debug`，成功退出码为零。

每个命令在数据库操作前取得[实例锁](../architecture.md#实例锁)。应用或另一命令持锁时立即拒绝，不等待；持锁后在独占屏障内推进代次，等待旧事务结束。迁移尚未建立代次结构时只取实例锁。管理命令以运行身份构造与在线相同的应用，执行全量启动核验并建立锚定。锁保留到请求排空和最终 stdout 刷新结束，再结束运行上下文。迁移、密钥登记及旧更正入口沿用各自的实例会话。工具不检查 systemd，也不替运维者停止服务。输入和恢复规则见[停机维护](../operations/maintenance.md#目标命令与互斥)。

管理员先在明确选定的新数据库建立部署身份与运行身份，在同一连接中通过参数化 `set_config` 设置 `nucleus.deployment_user` 和 `nucleus.runtime_user`，依次执行 `deployment/roles.sql` 与 `deployment/prepare.sql`，任一步失败立即停止。脚本不创建角色、不包含密码、不创建业务结构。它收回 PUBLIC 权限并建立[数据库身份边界](../database.md#登录身份与部署)。两个身份均拒绝高权限角色及[服务器文件与程序角色](../database.md#c1-接纳与可信时间)的直接、间接成员关系，包含仅可 SET ROLE 的授权。运行身份可成为部署身份时也拒绝准备。拒绝不自动更改角色授权。此步骤未在任何真实数据库执行。

## 设置与文件

`migrate` 和 `keys init` 从环境装载嵌套 `migration` 输入。`USER` 提供部署登录用户名，`RUNTIME_USER` 指定运行登录用户名；这两个入口要求提供两者。管理命令读取应用的数据库连接设置和真实网站 AppId，使用运行身份。两类入口的准确键名及选择边界见[部署设置](../settings.md#迁移工具)和[管理命令设置](../settings.md#管理命令)。输入先反序列化，再通过共享构造器校验。入口不自动加载 `.env`；TLS、数据库名及证书沿用 Platform 的校验规则。装配连接本身不建立数据库会话。

`CREDENTIALS_DIRECTORY` 必须是绝对目录。迁移、密钥登记及旧更正读取 `migration-password`；管理命令读取 `database.json`。内容均为 JSON 对象，包含整数 `version: 1` 和字符串 `password`，拒绝多余字段。密码接受条件与应用[数据库密码](../database.md#密码凭据)一致。两个文件互不回退。

`migrate` 不加载业务密钥。它先运行迁移和历史核对，再核验密钥表所有权及运行权限。权限失败不将已完成迁移改报未知。`keys init` 与 `admin` 读取唯一的根[密钥文件](../keys.md#2-根版本与派生用途) `keys.json`。入口复用[密钥输入及转换](../keys.md#4-指纹编码)，校验根版本并派生全部用途，同时生成非秘密元数据。`keys init` 只使用元数据；管理命令保留全量核验与执行所需材料。秘密文件缓冲与解码文本释放时清零，错误不回显内容或目录。

`credentials` 模块通过 `Filename` 枚举限定文件名，区分目录缺失、目录无效、读取和解析错误。文件打开后交给[共享凭据读取](../platform/credentials.md#装配与验收边界)，版本检查复用同一实现。`database` 模块拥有部署文件来源，复用[数据库装配与密码转换](../database.md#已交付的连接库)。环境输入转换调用共享设置构造器，文件读取后显式构建密码并装配连接。错误保留结构化原因，诊断隐藏凭据内容和路径。集合错误保留重复 ID、重复材料或缺活动键的具体类别及数字 key ID。迁移与初始化的结局诊断区分原失败和恢复失败，递归展示项目自有的安全错误。原始数据库和迁移库错误只保留在来源中，不直接打印。

## 迁移与原结局

部署工具使用 [Refinery 0.9.2](https://docs.rs/refinery/0.9.2/refinery/struct.Runner.html) 的异步 `tokio-postgres` 适配。SQL 嵌入程序，迁移历史保存在 `deployment.migrations`，采用库提供的版本、名称和内容校验值。运行拒绝缺失或内容不同的历史，不提供 fake、跳过校验或降级入口。库的分组事务把本次迁移 SQL 与对应历史写入共同提交。元数据模式和空历史表可先存在，不代表业务迁移完成。

迁移会话检查两个登录角色存在且不同，拒绝高权限角色及运行身份继承部署身份。检查部署身份可创建结构、运行身份不能创建结构后，取得会话级锁 `(1314210636, 2)`，覆盖历史检查与迁移事务。这个锁只用于部署串行化，独立于 Identity 业务屏障。每次执行及失败后的回读分别限制为 300 秒。连接阶段另受 Platform 默认预算限制。

写入前的校验或等待失败直接返回原错误。结构写入开始后发生失败或超时，工具中止并等待原驱动结束。新会话取得同一锁，再只读核对全部嵌入迁移的版本、名称及校验值。全部匹配才确认完成；没有记录表示迁移未提交。矛盾或无法读取则保留不明结局并失败退出。程序不会在这次失败处理中再次执行迁移。后续人工重跑仍先核对历史，不覆盖已应用记录。

分组提交已确认后，驱动收尾失败仍保留“迁移已完成”。恢复已完整核对历史时，后续驱动错误也不改变已完成或未提交的结论。恢复路径同时保留原执行失败与收尾失败。收尾错误使命令失败退出；授权是否完成按失败阶段报告，权限核验尚未执行。每次执行和回读仍各用原有的 300 秒预算，不为中间步骤重新计时。

Refinery 的历史读取先结束内部事务，再返回历史集合。内部 COMMIT 失败时，工具尚未取得完整读取结果，仍报告未知。收到历史查询行本身不等于读取接口成功。

首个迁移建立唯一的根版本元数据表，结构见[密钥材料](../keys.md#持久元数据)。对象归当前部署登录身份所有。迁移不含运行授权：分组迁移提交后，`migrate` 在原会话执行由[权限清单](../database.md#c1-接纳与可信时间)生成的授权语句。迁移锁与独占运行屏障持续持有到授权结束，共用原有执行预算；中间不释放连接，防止继任进程先推进代次、旧命令再覆盖权限。它先收回运行身份在部署身份所拥有对象上的全部权限，再按清单授予，重复执行结果相同；运行用户名通过参数传入，SQL 使用 `format('%I', ...)` 引用。授权失败时报告迁移已完成但授权未确认。原连接失效后，即使回读确认迁移完成，也不恢复授权写入；后续显式执行重新取得实例锁、核对迁移历史并补做授权。授权完成后，部署入口再核验权限。迁移执行器不查询密钥业务表。更换授权接收者后重跑会向新身份授权，但不收回原身份的权限，原身份不参与核验。新增迁移随实际消费者交付。迁移一旦应用于持久数据库就不再修改；隔离测试不冻结迁移文件。

`deployment::permissions` 在同一独立会话中完成两项核验，共用 300 秒预算。它先确认部署身份拥有密钥元数据表及仍用于更正的永久绑定，再调用共享运行权限核验。部署端不另列授权规则。部署错误单独标识所有权不符，其余错误保留共享模块的安全结构化原因。密钥初始化模块仍负责登记事务与原结局恢复。

重设运行权限时，一并收回经由该身份转授的依赖权限链，保留其他身份独立授予的权限。收回旧权限与授予清单在同一授权块中完成；数据库执行错误使整块回滚，连接中断则保留授权未确认的结果，不自动重试。

迁移、密钥初始化及部署权限核验均等待原连接驱动结束。操作失败且驱动也失败时，错误同时保留原原因与连接结束原因；原结局回读失败遵守同一规则。驱动结束失败不单独证明提交或回滚，也不跳过原结局核对。回读确认完整结果且收尾成功时才成功返回，其余失败保留各阶段的安全诊断。

当前迁移为 V1 至 V12，定义按外键依赖排序。V1 建立全部 key ID 引用的根版本元数据表；V2 建立 Identity、可信时间、Person/Revision、Transfer 和引用它的 Challenge。V3 定义 Message、Check、Confirmation、发送占用、Authentication；V4 增加 C1 清理、发送序列及删除保护。V5 定义网站短信 R1 凭据、完整 Account 和 Session 引用的 Receipt。V6 增加默认头像、Identity 更正及 Access 事实，系统管理员更正以同事务完成记录永久绑定。V7 定义 Attempt，并交付 R2 权限、共同开户保护及唯一版本的 R1/R2 共用凭据保护。V8 交付 Rejection、Transfer 的建立保护，以及原号、新号发码的资格保护。V9 交付 Center 政治面貌；V10 交付邀请码；V11 交付工号及分配保护。V12 交付分组、实际科室及配置原完成，包含名称范围、树关系、写入配对与清理保护。运行身份只取得清单中的[已交付权限](../database.md#c1-接纳与可信时间)。部署与启动共用权限核验。

迁移只在隔离数据库验证。当前支持明确选定的新库或可重建隔离库：准备角色、执行 V1 至 V12、用根文件运行 `keys init`，再通过 `admin initialize` 办理 Access 初始化。初始化后的 R2 只创建普通账户，不重建系统角色。迁移不回填旧的最小预置账户，密钥登记不自动补齐部分版本。工具与启动均拒绝不一致的元数据。保留旧数据的升级必须另有受控方案；不得清空登记或放宽校验来绕过。

## 密钥初始化与核验

数据结构和匹配规则归[密钥材料](../keys.md#持久元数据)。部署入口只接受由校验后的根版本生成的 `Metadata`，不接收随意拼装的指纹列表。

初始化先核对当前登录身份是 Security 模式所有者。首次初始化在 READ COMMITTED 事务中取得独占锁 `(1314210636, 1)`。锁后用新语句检查元数据：表为空才原子写入全部根版本；全部相同则只读成功。部分记录或不一致均拒绝，不覆盖、不补齐、不切换活动键。该锁与维护屏障共用；与应用的互斥由命令持有的实例锁承担。

初始化以执行阶段区分尚未开始、已确认回滚与结局待核对。尚未进入登记阶段的失败直接返回原错误。初始化校验失败且回滚成功时，返回原校验错误。首次锁后已确认元数据完整匹配时，直接保留原目标已完成的结论。随后的只读 COMMIT 或驱动收尾失败只增加技术原因，不依赖再次读取证明完成。新写入提交失败、超时或无法证明回滚时，先结束原驱动，再用新连接和同一事务锁回读。完整匹配表示原目标已完成；全空表示未提交。不一致或读取失败表示不能确认，保留原失败和恢复失败。失败恢复不再次写入。进程退出后的人工重跑沿相同锁与比较规则办理。

初始化执行与原结果回读各有一次 300 秒预算。各阶段沿用所属预算的同一截止，不重新计时。Metadata 拒绝后的回滚失败或超时保留原校验原因。工具随后结束原驱动并只读核对。原结果读取成功后，完整匹配或全空已经确定结局。只读回滚失败、超时或驱动失败均保留这个结论。错误同时报告原初始化原因和实际收尾原因。只有读取失败或事实不一致才报告未知。直接 COMMIT 已确认后发生驱动失败，同样明确报告已完成。收尾失败仍使命令失败退出，不代表登记未完成，也不触发再次写入。

在线调用方可用 `domain::keys::database::verify` 只读核验。单条查询读取同一快照，成功只证明根版本元数据与装载的根版本一致。身份、Access 和 Center 的持久引用另由启动业务核验检查，元数据匹配不证明服务已就绪。

## 初始化维护的安装边界

工具以持有私有输入文件的运维操作系统用户执行，无须本地锁文件或 root 权限。管理命令全部使用运行数据库身份。先停止 nucleus.service；应用仍在运行时，实例锁会拒绝命令：

```bash
target/debug/deployment admin initialize --input /private/initialize.json --operation OPERATION_UUID --dry-run
target/debug/deployment admin initialize --input /private/initialize.json --operation OPERATION_UUID
target/debug/deployment admin appoint --input /private/appointment.json --operation APPOINTMENT_UUID
target/debug/deployment admin correct --input /private/correction.json --operation CORRECTION_UUID
```

用本次 UUID 替换示例中的 Operation-Id 占位符。重跑沿用原 UUID 和原输入。输入 JSON 的字段及 stdout 边界见[管理协议](../operations/maintenance.md#目标命令与互斥)。输入文件必须由当前有效 UID 持有，模式恰为 0600，且为单链接常规文件；命令不自动改权限。

`admin correct` 的输入字段、判断与永久绑定见[更正实现](../identity/correction.md#系统管理员的运维更正)。输入文件沿用上述私有文件要求；命令不生成计划、确认码或 journal。原输入重放、未知结局和输出顺序见[维护协议](../operations/maintenance.md#共同屏障与未知提交)。这些说明不代替真实宿主安装和验收。

## 验证边界

`cargo test -p deployment --locked` 复用[共享数据库测试设施](../database.md#交付验证)，每项数据库测试各有独立数据库。连接构造、建库、角色准备和虚构密钥材料归部署测试。部署测试在同一互斥区内启动服务、准备角色，再发布弱引用供并发测试复用。虚构数据库密码由 fixture 提供。密钥装载测试使用唯一的根文件，旧的按用途文件不作为来源，不装配数据库连接。仅活动测试持有服务，最后持有者释放后停止并清理；凭据、角色和证书都是虚构材料。

实例锁测试在未迁移的库上只取锁，迁移后每个命令把代次加一。应用持锁时命令以 `Held` 拒绝且命令体不执行，代次不变；命令持锁时应用无法取锁；应用停止后命令再次成功。

验证覆盖自定义用户名（含引号）、身份重合与越权拒绝、迁移重跑、内容校验不符、真实迁移失败时结构与历史共同回滚、运行身份的查询及写入拒绝、集合不符、并发初始化等待与锁后读取，以及原驱动结束后的提交和回滚核对。根版本元数据验证活动版本唯一、缺版本、缺活动版本、活动版本不同与额外版本均被拒绝，部分状态不补齐，旧用途指纹被拒绝。Challenge 外键验证未登记的根拒绝、已登记的保留根允许及被引用的版本阻止删除。保留调用方丢弃成功结果后的恢复测试，协议故障覆盖见下文。测试不访问真实数据库或供应商。它不证明生产主机、角色、systemd 或密码配置正确。

清单测试先确认迁移并授权后的实际目录与清单双向一致，再逐类（schema、类型、序列、函数、表、列）验证：去掉一条清单条目时该授权报告为多余，收回一条授权时该条目报告为缺失；生成的授权语句在存在多余授权或缺少条目后重跑，均恢复为清单。权限回归对密钥元数据表核对缺少 SELECT 与额外表级、列级写入权限。直接授权、PUBLIC、继承及仅 SET ROLE 的授权均由共享核验拒绝。更换该表所有者时，运行权限仍通过，部署核验拒绝；恢复所有者后通过。

连接双失败测试在回环 TLS 代理收到首个 Parse 帧后暂停转发，再断开传输。此时三个部署入口均已取得 Session 并启动驱动，正在等待前置查询，尚未开始业务写入。测试分别解构迁移、密钥初始化和权限核验的错误，确认原查询连接关闭原因及驱动实际传输错误共同保留，安全诊断不含数据库名和密码。

重跑前通过独立 SQL 比较迁移历史、根版本登记及其写入事务，再复核原迁移、密钥和权限。同步不再依赖连接启动期间的目录锁；连接建立失败不作为查询与驱动双失败的证据。该测试不修改实际权限，也不证明提交未知恢复的全部传输故障组合。

迁移协议测试通过公开 `migration::run` 执行实际嵌入 SQL。分组提交丢响应或被中断后，测试核对恢复的完成与未提交结论。代理保留 PostgreSQL 的 COMMIT 成功响应，再附加合成 FATAL。测试证明真实驱动错误不覆盖已知结果；故障不是数据库主动终止后端。另一例丢弃历史读取自身的 COMMIT 响应，验证结局仍为未知。测试在重跑前独立检查全部历史与代表性结构，并另查原后端和恢复后端已经结束。重跑后核对历史内容、写入事务和结构身份保持；未提交组只有后来显式重跑才建立结构。测试不证明真实网络故障的全部组合或部署权限已核验。

密钥初始化的协议测试覆盖原 COMMIT 回执丢失和真实提交拒绝。回读后另验证回滚失败、确认超时和驱动失败。测试在公开 initialize 入口核对原原因、已知结局和实际收尾错误。独立 SQL 在重跑前检查元数据表事实。非事务序列统计全部 INSERT 尝试，防止回滚或重跑掩盖重复写入。回读失败及不一致仍报告未知；正常 Metadata 拒绝保持原错误类别。

首次锁后已完整匹配的测试另扣住只读 COMMIT 回执，并拒绝第二次 BEGIN。公开入口仍以错误报告已完成及收尾失败。独立 SQL 核对元数据表内容和写入事务未变，非事务计数证明未再次尝试 INSERT。测试还确认原后端已结束。

回滚超时测试等数据库返回实际 ROLLBACK 完成回执，再由代理扣住响应。此时才推进 Tokio 虚拟时间，生产的 300 秒预算保持不变。驱动失败测试保留实际 CommandComplete 和 ReadyForQuery。代理在成功回执后追加合成 FATAL 协议帧。断言分别确认成功结果和驱动实际返回的 SQLSTATE。该故障不等同于数据库主动终止后端。诊断隐藏合成错误 detail。释放代理后另查旧后端已结束，本地驱动结束不代替这个观察。

管理入口的验收核对 dry-run 零业务写入、完整初始化、系统指派及原输入重放，并覆盖实例互斥与收尾。提交故障和未知后晚提交按共同执行器的恢复边界验证。更正按原 UUID、原输入和永久完成核对重放，不另设计划、确认码或 journal。隔离文件、数据库锁或协议代理的结果不代替真实宿主和生产部署演练。
