# 数据库部署工具

独立 `deployment` crate 交付迁移和首次密钥初始化。它依赖 domain 与 platform，nucleus 不依赖它。迁移执行库只进入部署工具的生产依赖图。应用启动不运行迁移。C1 首次接纳已实现库级启动核验与原操作恢复；完整服务和换钥维护仍未交付。目标 package 组织见[架构](../architecture.md#crate-与模块组织)。

## 执行入口

先构建 `cargo build -p deployment --locked`，再显式执行 `target/debug/deployment migrate` 或 `target/debug/deployment initialize-keys`。生产构建按部署选择 release 产物。命令不接收密码、连接串、SQL 路径或任意密钥文件参数。错误使用脱敏 `Debug` 输出，成功退出码为零。运行前由部署调用方停止应用并证明旧进程不能再提交。工具本身不管理 systemd，也不证明进程已退出。

管理员先在明确选定的新数据库建立部署身份与运行身份，在同一连接中通过参数化 `set_config` 设置 `nucleus.deployment_user` 和 `nucleus.runtime_user`，依次执行 `deployment/roles.sql` 与 `deployment/prepare.sql`，任一步失败立即停止。脚本不创建角色、不包含密码、不创建业务结构。它收回 PUBLIC 权限并建立[数据库身份边界](../database.md#登录身份与部署)。两个身份均拒绝高权限角色及[服务器文件与程序角色](../database.md#c1-接纳与可信时间)的直接、间接成员关系，包含仅可 SET ROLE 的授权。运行身份可成为部署身份时也拒绝准备。拒绝不自动更改角色授权。此步骤未在任何真实数据库执行。

## 设置与文件

部署工具从导出的 `NUCLEUS_` 环境变量装载嵌套 `migration` 输入，键名见[部署设置](../settings.md#迁移工具)。私有 Serde 结构拒绝未知字段，再显式转换并构建已验证设置。部署进程只提供自己的配置，不自动加载 `.env`。`USER` 提供部署登录用户名，`RUNTIME_USER` 指定运行登录用户名，两个命令均必填。TLS 主机、端口、数据库名和证书沿用 Platform 的校验及连接规则。工具使用独立会话，不借在线池；连接配置中的最小池容量不产生在线连接。

`CREDENTIALS_DIRECTORY` 必须是绝对目录。部署数据库密码固定读取该目录内的 `migration-password`。内容为 JSON 对象，包含整数 `version: 1` 和字符串 `password`，拒绝多余字段。密码接受条件与应用[数据库密码](../database.md#密码凭据)一致。两者文件名不同，互不回退。

`migrate` 不加载业务密钥。入口先调用 `deployment::migration::run` 完成结构迁移及历史核对。随后调用 `deployment::permissions::verify`，核验密钥表所有权及运行权限。权限核验失败使命令失败，不将已完成迁移报告为提交未知。`initialize-keys` 另外读取四个已交付用途的[密钥文件](../keys.md#2-封闭用途)。入口复用[密钥输入协议与显式转换](../keys.md#4-指纹编码)，再调用各用途集合构造器。`deployment::keys::credentials::load` 从已构建集合提取非秘密清单，交给 `deployment::keys::initialize`；初始化拥有连接、事务、提交和原结局回读。文件缓冲和解码后的秘密文本在释放时清零，错误不回显内容或目录。

`credentials` 模块通过 `Filename` 枚举限定文件名，区分目录缺失、目录无效、读取和解析错误。文件打开后交给[共享凭据读取](../platform/credentials.md#装配与验收边界)，版本检查复用同一实现。`database` 模块拥有部署文件来源，复用[数据库装配与密码转换](../database.md#已交付的连接库)。环境输入转换调用共享设置构造器，文件读取后显式构建密码并装配连接。错误保留结构化原因，诊断隐藏凭据内容和路径。集合错误保留重复 ID、重复材料或缺活动键的具体类别及数字 key ID。迁移与初始化的结局诊断区分原失败和恢复失败，递归展示项目自有的安全错误。原始数据库和迁移库错误只保留在来源中，不直接打印。

## 迁移与原结局

部署工具使用 [Refinery 0.9.2](https://docs.rs/refinery/0.9.2/refinery/struct.Runner.html) 的异步 `tokio-postgres` 适配。SQL 嵌入程序，迁移历史保存在 `deployment.migrations`，采用库提供的版本、名称和内容校验值。运行拒绝缺失或内容不同的历史，不提供 fake、跳过校验或降级入口。库的分组事务把本次迁移 SQL 与对应历史写入共同提交。元数据模式和空历史表可先存在，不代表业务迁移完成。

迁移会话检查两个登录角色存在且不同，拒绝高权限角色及运行身份继承部署身份。检查部署身份可创建结构、运行身份不能创建结构后，取得会话级锁 `(1314210636, 2)`，覆盖历史检查与迁移事务。这个锁只用于部署串行化，独立于 Identity 业务屏障。每次执行及失败后的回读分别限制为 300 秒。连接阶段另受 Platform 默认预算限制。

写入前的校验或等待失败直接返回原错误。结构写入开始后发生失败或超时，工具中止并等待原驱动结束。新会话取得同一锁，再只读核对全部嵌入迁移的版本、名称及校验值。全部匹配才确认完成；没有记录表示迁移未提交。矛盾或无法读取则保留不明结局并失败退出。程序不会在这次失败处理中再次执行迁移。后续人工重跑仍先核对历史，不覆盖已应用记录。

首个迁移建立按用途分表的密钥元数据及其只读授权，结构见[密钥材料](../keys.md#持久元数据)。对象归当前部署登录身份所有；运行用户名通过参数传入，SQL 使用 `format('%I', ...)` 引用授权对象名。迁移历史核对完成后，部署入口再核验权限。迁移执行器不查询密钥业务表。更换授权接收者不会自动重授历史权限，核验不符即失败。新增迁移随实际消费者交付。迁移一旦应用于持久数据库就不再修改；隔离测试不冻结迁移文件。

`deployment::permissions` 在同一独立会话中完成两项核验，共用 300 秒预算。它先确认当前部署身份拥有全部四张密钥表，再调用 `domain::database::permissions`。共享模块统一核验密钥、C1 事实和可信时间的运行权限，部署端不另列运行授权规则。部署错误单独标识所有权不符，其余数据库核验错误保留共享模块的结构化原因与脱敏诊断。初始化模块仍负责登记事务与原结局恢复。

迁移、密钥初始化及部署权限核验均等待原连接驱动结束。操作失败且驱动也失败时，错误同时保留原原因与连接结束原因；原结局回读失败遵守同一规则。驱动结束失败不单独证明提交或回滚，也不跳过原结局核对。回读确认完整结果时仍可成功返回，其余失败保留各阶段的安全诊断。

当前有 `V1__keys`、`V2__challenge_acceptance`、`V3__message_sending` 和 `V4__retention`。V1 建立 Security 模式及最初三张密钥表；V2 建立 Identity 模式、可信时间和 Challenge。V3 增加 Message、Check、唯一发送占用及 `security.messages` 密钥表。V4 增加 C1 到期清理、持久发送序列及删除保护。序列从现有最大 ordinal 之后继续，空表从一开始。运行身份只取得[已交付 C1 权限](../database.md#c1-接纳与可信时间)。权限检查与应用启动共用 `domain::database::permissions`。R1 结构尚未交付。

## 密钥初始化与核验

数据结构和匹配规则归[密钥材料](../keys.md#持久元数据)。部署入口只接受由四个受控用途集合生成的 `Metadata`，不接收随意拼装的指纹列表。

初始化先核对当前登录身份是 Security 模式所有者。首次初始化在 `READ COMMITTED` 事务中取得事务级独占锁 `(1314210636, 1)`。锁后用新语句检查现有元数据。四张表全部为空才原子写入四个用途；全部相同则只读成功。任何部分记录或不一致均拒绝，不覆盖、不补齐、不切换活动键。该锁与未来 Identity 维护屏障共用，不能替代停机证明。

初始化以执行阶段区分尚未开始、已确认回滚与结局待核对。尚未进入登记阶段的失败直接返回原错误。初始化校验失败且回滚成功时，返回原校验错误。提交失败、超时或无法证明回滚时，先结束原驱动，再用新连接和同一事务锁回读。完整匹配表示原目标已完成；全空表示未提交。不一致或读取失败表示不能确认，保留原失败和恢复失败。失败恢复不再次写入。进程退出后的人工重跑沿相同锁与比较规则办理。

在线调用方可用 `domain::identity::keys::database::verify` 只读核验。单条查询读取同一快照，成功只证明当前四个用途的元数据与装载集合完全一致。不证明服务已就绪，也不检查尚未交付的业务密钥引用。

## 验证边界

`cargo test -p deployment --locked` 复用[共享数据库测试设施](../database.md#交付验证)，每项数据库测试各有独立数据库。连接构造、建库、角色准备和虚构密钥材料归部署测试。部署测试在同一互斥区内启动服务、准备角色，再发布弱引用供并发测试复用。虚构数据库密码由 `fixture` 提供。密钥装载测试仅依赖四份用途文件和凭据目录，不装配数据库连接。仅活动测试持有服务，最后持有者释放后停止并清理；凭据、角色和证书都是虚构材料。

验证覆盖自定义用户名（含引号）、身份重合与越权拒绝、迁移重跑、内容校验不符、真实迁移失败时结构与历史共同回滚、运行身份的查询及写入拒绝、集合不符、并发初始化等待与锁后读取，以及原驱动结束后的提交和回滚核对。各用途分别验证活动键唯一、缺用途和缺活动键拒绝、额外版本拒绝及部分状态不补齐。Challenge 外键验证错误用途拒绝、正确用途允许及保留引用阻止删键。提交结果丢失测试在调用方边界丢弃成功结果。不宣称注入了 PostgreSQL 线协议的 Commit 回包丢失。测试不访问真实数据库或供应商。它不证明生产主机、角色、systemd 或密码配置正确。

权限回归逐表核对缺少 SELECT 与额外表级、列级写入权限。直接授权、PUBLIC、继承及仅 SET ROLE 的授权均由共享核验拒绝。逐表更换所有者时，运行权限仍通过，部署核验拒绝；恢复所有者后通过。

连接双失败测试锁住隔离数据库的目录查询，再断开回环 TLS 代理的传输。迁移、密钥初始化和部署权限核验均保留查询失败与驱动失败。解除测试锁后，原迁移历史、密钥及权限仍可核验。该测试不修改实际权限，也不证明提交未知恢复的全部传输故障组合。
