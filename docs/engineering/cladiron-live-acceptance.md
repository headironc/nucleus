# Cladiron prepare 与启动原件验收

本文件用于独立的验收候选。先验证合法普通 `dev` PR 的 `prepare`。再捕获 Code Review 和 Security Review 的启动原件。候选保持未合并，结果以实际运行和产物为准。

## 验收目标

首次 `prepare` 使用开放、非草稿、同仓库且包含当前 `dev` 基线的 PR。观察程序能否输出绑定该 PR、完整 head 和基线的待发请求正文。首次运行不传额度来源或启动 artifact。

后续由一次明确的 Code Review 请求启动观察。另核对联动的 Security Review。在两个 lane 实际处于 running 时捕获启动原件。核对请求、完整 head、基线与提供方身份。另核 producer run、attempt 和执行修订。检查上传产物与实际捕获内容一致。

具体输入和证据要求由[批准机器合同](review-approval.md#持久摘要的启动观察)拥有。本文件不修改合同，也不把准备操作视为已经执行的验证。

## 证据边界

`prepare` 输出待发正文，不发布评论或触发供应商审查。仅在实际捕获 running 原件后，才记录对应 artifact。错过窗口、运行失败或缺少产物时，保留原结果并说明缺口，不用完成态补造启动事实。

运行记录区分“合法准备成功”和“启动原件捕获成功”。分别保存准确的 PR、head、基线和日志。另存 run、attempt 与 artifact 身份。工作流成功本身不能证明捕获成功。

## 排除范围

本候选只增加本文件。工作流、机器合同、运行配置和凭据配置保持原状。验收不读取真实 App 秘密，也不申请 installation token。不执行批准、撤回或部署。

本次不验收供应商完整终态、CI 准入或真实 App 写入能力。Security 的 Boolean 终态及完整提交绑定仍按机器合同判断。启动捕获结果不代表真实批准已可用。
