# Workforce 目录与显示规则

现有目录、名称、树关系与分类显示规则继续使用。简化目标保留这些实际配置，写入改为普通事务和统一审计，退出配置完成证明、独立恢复与额外锁。科室目录只是可选打印资料，不是人员归属；新增工牌不以目录选择推导管理范围。

下文办理入口及原结果要求描述迁移前合同。新工牌直接保存当时文字和资源，目录后来变化不修改快照。暂不为简化扁平化现有目录或重写配置数据。

本文拥有分组、实际科室、全域职务字典 `positions`、科室职务配置 `rosters`、职称树 `categories`/`disciplines`/`titles`、人员分类默认规则及当前可选目录读取。这些内容供工牌申请选择与展示，不建立任职或雇佣事实。人员分类的固定代码由[工号](numbers.md#工号与占用)拥有；配置原请求见[完成记录](completions.md)。

## 名称与目录身份

六类目录分别为 `groups`、`departments`、`positions`、`categories`、`disciplines`、`titles`。每项有稳定 UUID ID、创建它的原 Operation-Id、规范名称、启用状态与非负显示顺序 `index`。名称经过 NFC、首尾空白去除，长度为规范化后 1 至 64 个 Unicode 标量，拒绝空串和控制字符（即使在首尾）；不自动改大小写、合并相近名称或改变条目类型。同级排序号可以相同或留空洞，相同顺序号按 ID 稳定显示，不表达业务等级。

三个名称唯一范围彼此独立：分组与所有层级实际科室在整个 Workforce 共用一个范围；所有职务共用第二个范围；职称分类、系列与完整职称共用第三个范围。跨分组、跨父级或职称层级仍不能同名。启用及停用项均占用名称，停用不释放。不同范围之间允许同名。相同范围的同时创建或改名最多一方成功；名称冲突只返回 `409 name_in_use`，不从错误文本推断业务结果。

## 科室树与职务

`groups` 是目录分组，不可作为实际科室。每个 `department` 必须直接属于一个真实分组；顶层没有父科室，下级的父科室必须属于同一分组。实际科室可以有子科室且仍可被选择，分组可以暂时没有科室。不能以自身或后代为父；改父级时检查完整祖先链与循环。

跨分组移动先确定目标父级与完整子树，在同一办理中改变子树全部科室的分组和移动根的父科室；其他子科室父关系保留。移动到分组顶层时父级为空。并发新增子科室与移动按受影响范围协调：新增先完成时随子树移动，后完成时依据新父节点所属分组判断；失败整体回滚。原目录 ID、科室职务配置与已确认打印文本不改变。停用分组或路径上任一祖先使该科室不再可用于新选择；不追改旧申请。

`positions` 是 Workforce 全域职务字典。`rosters` 为每个实际科室明确配置可选职务，固定 `id`、`department_id`、`position_id`、`enabled`、`index`，同一科室与职务组合唯一，条目的科室与职务不可改绑。一个职务可供多个科室，各科室独立排序；配置不从父科室继承。调整一科室的完整职务列表须比较原列表并一次保存。已有提交引用的组合不能删除或改绑，只能停用。新选择要求实际科室及祖先、职务项与该科室组合均启用；该人员分类也须允许职务。科室没有配置职务仍可被选择，职务留空。未选职务时显示实际科室名，选中时显示实际科室与职务组合。

## 职称与分类规则

职称树是分类 `categories`、系列 `disciplines`、完整职称 `titles` 三层。系列必须属于真实分类，职称必须属于真实系列；只有完整职称可被选择和展示。停用任一祖先使其后代不可用于新选择。职称可不选；缺失时固定打印“无”，而“无”不是目录条目。职务与职称的选择独立。

每个固定人员细分类在 `rules` 中有一条配置：`id` 是人员细分类代码，`department_id` 必需且引用真实实际科室，`position` 表示是否允许选择职务。当前产品配置仅 902（实习）的职务开关为 false；开关由配置值决定，代码不按细分类硬编码。所有申请者，包括实习人员，都必须明确确认实际科室；默认科室只在首次选择时预选，可以更换，服务端不能用默认值补齐缺失输入。配置时默认科室、全部祖先及所属分组须启用；后来停用或移动到停用路径则保留原引用，提示重新选科室。职称仍独立可选。规则不可删除；被规则引用的科室不能删除，规则更新到另一真实科室后原科室可按无引用规则删除。

初始化先建立真实科室，再补齐全部 16 种分类规则，之后才开放工牌申请。配置缺行是依赖故障，不是允许空默认或任意职务；管理配置入口仍可用于补齐。不能用虚构科室、首个科室、分组或 NULL 充当默认科室。改变默认规则只影响之后的预选，不覆盖已确认内容。原提交保存实际目录 ID 与显示文本，目录、职务组合、规则或名称以后变化不改写历史。新办、增办、换证均按本次选择、当前可选状态与分类开关判断，不要求来源工牌。

## 办理入口

`departments` 另有必需分组和可选父科室；`disciplines` 另有必需分类；`titles` 另有必需系列。同一创建 Operation-Id 在六类目录中至多定位一个条目，原完成被清理后仍成立；创建正文必须明确提供 `name`、`enabled`、`index`，不设默认值。被历史提交、目录子项或配置引用的条目不能删除；无引用且没有子项时才可删除，包括已注销人员原提交的引用。停用、启用、改名、移动、排序使用带完整 expected 与 replacement 的条件更新，不能用旧请求覆盖后来修改；条目 ID 与创建原操作不可改变。父级停用不阻止创建或移动，可选性由选择时按完整启用路径判断；系列可改到另一真实分类，职称可改到另一真实系列，后代保持不变。

| 路由                                                           | 用途                                                 |
| -------------------------------------------------------------- | ---------------------------------------------------- |
| `GET /api/v1/workforce/directories`                            | 本人或相关管理者读取当前可选择树、科室职务和分类规则 |
| `GET /api/v1/workforce/directories/{collection}`               | `workforce.directory` 管理读取，包含停用项           |
| `POST /api/v1/workforce/directories/{collection}`              | 创建封闭六类中的条目，`201`                          |
| `PUT /api/v1/workforce/directories/{collection}/{id}`          | 比较完整 expected 后更新，`200`                      |
| `DELETE /api/v1/workforce/directories/{collection}/{id}`       | 无引用且无子项时删除，`200`                          |
| `GET /api/v1/workforce/directories/departments/{id}/positions` | `workforce.directory` 读取该科室完整职务列表         |
| `PUT /api/v1/workforce/directories/departments/{id}/positions` | 比较并替换该科室完整职务列表，`200`                  |
| `GET /api/v1/workforce/rules`                                  | 读取分类默认配置，初始化期间可见缺项                 |
| `PUT /api/v1/workforce/rules/{subtype}`                        | 创建缺失规则或比较 expected 后更新，`201` 或 `200`   |

配置写入使用当前会话、`workforce.directory` 和 Operation-Id；全部管理入口要求正常、未暂停的当前 Workforce 成员持有准确的 `workforce.directory`，机构权限和其他领域权限不替代。网站会话、写入必填 Origin、读取条件同源、8 KiB 正文、共享读写预算和 30 秒 HTTP 等待复用既有管理协议；响应使用 `no-store`，不设置 cookie；等待写入超时不取消已接纳工作。新工牌提交与目录、科室职务、规则编辑共用写入协调，在同一决定性快照判断选择。目录读取、规则缺失或数据库损坏不能伪装成空树、默认值或客户端错误。

`collection` 只接受 `groups`、`departments`、`positions`、`categories`、`disciplines`、`titles`；其他值和非法路径 UUID 在认证前返回 `400 invalid_input`。查询参数一律拒绝；GET/HEAD 也拒绝正文。路径中的集合决定创建、更新、删除正文的具体类型。

管理读取返回 `{code: "ok", items: [...]}`，一次返回完整集合，不分页，包含停用项，按 `index`、ID 升序；当前权限与内容共用一个只读快照。`index` 上界为 32 位有符号整数最大值。分组、职务与分类的创建正文只有 `name`、`enabled`、`index`；科室另有必填 `groupId`，`parentId` 省略或 null 表示顶层；系列另有必填 `categoryId`，职称另有必填 `disciplineId`。更新的 `expected`、`replacement` 为完整条目；删除正文只有完整 `expected`。条目包含 `id`、创建 `operationId` 及上述业务字段，更新不得改变两个身份字段。

成功写入返回 `{code: "ok", item: ...}` 或 `{code: "ok", deleted: true}`。创建及其重放为 201，更新、删除及其重放为 200。新的删除或更新遇到已不存在的目标均返回 `404 target_unavailable`，不保存完成；原操作重放仍返回其原完成。名称冲突为 `409 name_in_use`；旧确认冲突为 `409 data_changed`；存在引用或子项为 `409 item_in_use`；父链异组或循环为 `422 invalid_parent`。必需分组、父科室、分类或系列不存在，或以其他集合的 ID 作为父级，为 `404 target_unavailable`。同键异输入使用 `409 request_mismatch`；其他数据库失败不映射为这些业务码。

科室职务读取 `GET/HEAD .../departments/{id}/positions` 返回 `{code: "ok", positions: [...]}`，包含停用条目及引用停用职务的条目，按 `index`、条目 ID 升序。条目只有 `id`、`positionId`、`enabled`、`index`；科室由路径给出。缺失科室或用分组 ID 冒充科室为 `404 target_unavailable`。替换 `PUT` 正文为 `{expected, replacement}`。`expected` 是当前完整条目列表；`replacement` 列出保留或新增的每个职务，各含 `positionId`、`enabled`、`index`，不提供条目 ID。保留的职务沿用原条目 ID，新职务由服务端分配，未列出的职务删除。两份列表的顺序不影响判断和原输入；同一职务或条目重复出现为 `422 invalid_input`。当前列表已等于 replacement 时只追加完成，否则要求当前列表与 expected 完全相同，其余为 `409 data_changed`。替换引用的职务须真实存在，否则为 `404 target_unavailable`；停用的科室、祖先、分组或职务允许预先配置，选择时再判断可用性。成功及重放均为 200，返回替换后的完整列表；科室后来被删除时，原请求重放返回 `{code: "ok", deleted: true}`。被列表引用的科室与职务不能删除。

规则读取 `GET/HEAD /api/v1/workforce/rules` 返回 `{code: "ok", rules: [...], missing: [...]}`。已配置行包含 `id`、`departmentId`、`position`；缺项明确列出细分类代码，两数组均按代码升序。读取不创建配置或补默认。`PUT /api/v1/workforce/rules/{subtype}` 以 `{departmentId, position}` 创建缺失规则，成功及原请求重放为 201；已有规则的新创建请求为 `409 data_changed`。更新正文为 `{expected, replacement}`，两者均为含三个字段的完整规则，ID 必须匹配路径；成功及重放为 200；缺失规则的更新为 `404 target_unavailable`。当前已等于 replacement 时只追加完成，否则要求当前等于 expected，其余返回 `409 data_changed`。两种新成功都重新检查 replacement 的科室路径；原操作重放只回读当前规则，不受后来停用影响。成功封套为 `{code: "ok", rule: ...}`。非法或未知路径代码在认证前返回 `400 invalid_input`；查询参数、GET/HEAD 正文、未知或缺失 JSON 字段均拒绝。缺失科室或用分组 ID 冒充科室为 `404 target_unavailable`；停用科室、祖先或分组为 `422 invalid_department`。跨路径的完整规则为 `422 invalid_input`。

当前可选目录 `GET/HEAD /api/v1/workforce/directories` 的读取者为正常账户下未暂停的当前 Workforce 成员，不要求领域权限；管理者同样以成员身份读取。不是当前成员或 Grant 暂停为 `403 permission_denied`，会话无效为 `401`。成员资格与内容共用一个只读快照，沿共享读取预算、条件同源和 `no-store`，拒绝查询参数及正文。响应为 `{code: "ok", groups, departments, positions, categories, disciplines, titles, rules, missing}`，只含当前可选项，不返回启用标志、创建原操作或停用项。分组须启用；科室须自身、全部祖先及所属分组启用；`positions` 只列可选科室中启用条目且职务启用的配置，含 `departmentId`、`entryId`、`positionId`、职务名称及条目顺序；系列须连同分类启用，职称须连同系列和分类启用。列表按 `index`、ID 排序，`positions` 按科室 ID、条目顺序、条目 ID 排序。`rules` 列出全部已配置规则及 `selectable`，表示默认科室当前是否可选；后来停用保留引用但不可预选。`missing` 明确列出缺项代码，不补默认值。引用的父级、分组、分类、系列或职务缺失属于数据库故障，读取失败并关闭接纳，不伪装成较小的可选集合。

## 验收

目录验收覆盖六集合的创建、完整条件更新、删除与含停用项读取，名称规范化与三个独立名称范围、跨集合与单集合唯一占用、并发创建和改名、科室循环与子树移动、并发子节点、系列跨分类及职称跨系列移动、叶先删除、删除保护和原结果；运行期不能改写 ID 或创建原操作，原创建 UUID 跨六个集合唯一。HTTP 核对准确权限、强类型正文、状态码、HEAD、Origin、缓存头、重放和 OpenAPI。提交故障、启动核验与完成清理见[完成记录验收](completions.md#验收)。

分类规则验收覆盖初始化缺项、全部固定代码、创建和完整条件更新、旧确认、原输入重放及动作、目标、输入不符。配置时拒绝缺失科室、分组冒充科室及停用路径；后来停用或移动保留引用，被引用科室拒绝删除。并发规则写入与目录编辑交错。启动接受缺项和后来停用，拒绝损坏引用；完成清理保留规则。

科室职务验收覆盖完整列表的创建、条件替换、保留条目 ID、删除未列职务、列表顺序不改变原输入，以及旧确认、已达目标、原输入重放和同键异输入。同一职务可配置于多个科室，子科室不继承父科室列表。缺失科室、分组冒充科室及缺失职务均拒绝；重复职务或条目为输入错误。被列表引用的科室与职务拒绝删除，清空后可删，科室删除后原请求重放返回 `deleted: true`。条目 ID 与两项引用不可改写，列表变化必须伴随同一次替换完成。

可选目录读取验收覆盖普通成员可读、非成员和 Grant 暂停拒绝、恢复后可读，停用分组、祖先、科室、条目、职务、分类与系列各自隐藏后代，规则的可选标志与缺项，以及父级缺失时读取失败并关闭接纳。

工牌消费者验证已有提交引用的职务条目与职称不可删除、停用与提交竞争。实习不能选职务，所有类别必选实际科室，默认只预选；停用路径提示不可用，缺失规则阻止申请。目录编辑不得改写原提交及成品。
