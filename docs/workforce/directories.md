# Workforce 目录与显示规则目标设计

状态：目标设计，尚未实施。Workforce 拥有目录分组、实际科室、职务、职称树、科室职务配置和人员分类默认规则。这些内容供工牌申请选择与展示，不建立任职或雇佣事实。人员分类的固定代码由[人员编号](numbers.md#编号与占用)拥有；配置原请求见[完成记录](completions.md)。

## 名称与目录身份

六类目录分别为 `groups`、`departments`、`positions`、`categories`、`disciplines`、`titles`。每项有稳定 UUID ID、规范名称、启用状态与非负显示顺序 `index`。名称经过 NFC、首尾空白去除，拒绝空串和控制字符；不自动改大小写、合并相近名称或改变条目类型。同级排序号可以相同或留空洞，相同顺序号按 ID 稳定显示，不表达业务等级。

三个名称唯一范围彼此独立：分组与所有层级实际科室在整个 Workforce 共用一个范围；所有职务共用第二个范围；职称分类、系列与完整职称共用第三个范围。跨分组、跨父级或职称层级仍不能同名。启用及停用项均占用名称，停用不释放。不同范围之间允许同名。每张表自有 `UNIQUE(name)`，跨表唯一性另由数据库保护；父级加名称的联合唯一键不能替代全域唯一性。

跨表名称保护由固定 invoker 约束完成，只接受规定的五张表，不接纳客户端指定表名。写事务使用 `READ COMMITTED`，先按[共同锁顺序](../architecture.md#锁与决定性读取)取得适用保护及名称范围锁，再用新的语句快照查该范围所有表，不过滤停用或父级；锁持有到事务结束。应用在 DML 前取得同一协调，触发器复取相同锁。等待锁和查重不能合成旧快照的一条查询；锁预算失败使事务失败。相同范围的同时创建或改名最多一方成功。六个同表及两个跨表具名诊断只映射 `409 name_in_use`，不从错误文本推断业务结果。实施时须以真实运行身份验证这些约束和并发负例。

## 科室树与职务

`groups` 是目录分组，不可作为实际科室。每个 `department` 必须直接引用一个真实分组；顶层缺少 `parent_id`，下级的父科室必须属于同一分组。实际科室可以有子科室且仍可被选择，分组可以暂时没有科室。组合外键 `(parent_id,group_id)` 保证父子同组，独立外键保证顶层的分组有效。不能以自身或后代为父；改父级在事务中检查完整祖先链与循环。

跨分组移动先确定目标父级与完整子树，在同一事务以受控更新改变子树所有 `group_id` 和移动根的 `parent_id`；其他子科室父引用保留。移动到分组顶层时父级为空。并发新增子科室与移动需按受影响范围协调，失败整体回滚。原目录 ID、科室职务配置与已确认打印文本不改变。停用分组或路径上任一祖先使该科室不再可用于新选择；不追改旧申请。

`positions` 是 Workforce 全域职务字典。`rosters` 为每个实际科室明确配置可选职务，固定 `id`、`department_id`、`position_id`、`enabled`、`index`，同一科室与职务组合唯一。一个职务可供多个科室，各科室独立排序；配置不从父科室继承。调整一科室的完整职务列表须比较原列表并在同一事务保存。已有提交引用的组合不能删除或改绑，只能停用。新选择要求实际科室及祖先、职务项与该科室组合均启用；该人员分类也须允许职务。科室没有配置职务仍可被选择，职务留空。未选职务时显示实际科室名，选中时显示实际科室与职务组合。

## 职称与分类规则

职称树是分类 `categories`、系列 `disciplines`、完整职称 `titles` 三层。系列必须属于真实分类，职称必须属于真实系列；只有完整职称可被选择和展示。停用任一祖先使其后代不可用于新选择。职称可不选；缺失时固定打印“无”，而“无”不是目录条目。职务与职称的选择独立。

每个固定人员细分类在 `rules` 中有一条配置：`id` 是人员细分类代码，`department_id` 必需且引用真实实际科室，`position` 表示是否允许选择职务。当前仅 902（实习）的职务开关为 false。所有申请者，包括实习人员，都必须明确确认实际科室；默认科室只在首次选择时预选，可以更换，服务端不能用默认值补齐缺失输入。配置时默认科室及祖先须可选；后来停用则保留原引用，提示重新选科室。职称仍独立可选。

初始化先建立真实科室，再补齐全部 16 种分类规则，之后才开放工牌申请。配置缺行是依赖故障，不是允许空默认或任意职务；管理配置入口仍可用于补齐。不能用虚构科室、首个科室、分组或 NULL 充当默认科室。改变默认规则只影响之后的预选，不覆盖已确认内容。原提交保存实际目录 ID 与显示文本，目录、职务组合、规则或名称以后变化不改写历史。合法增办完整复用来源工牌内容；新的非增办提交按当前可选状态与分类开关判断。

## 存储和办理入口

`groups`、`positions`、`categories` 固定 `id`、`name`、`enabled`、`index`；`departments` 另有必需 `group_id` 和可选 `parent_id`；`disciplines` 另有必需 `category_id`；`titles` 另有必需 `discipline_id`。`rosters` 的科室及职务引用不可改，`rules` 只覆盖固定分类代码且默认科室非空。被历史提交、目录子项或配置引用的条目不能删除；无引用且没有子项时才可删除。停用、启用、改名、移动、排序使用带完整 expected 与 replacement 的条件更新，不能用旧请求覆盖后来修改。

| 路由                                                    | 用途                                                 |
| ------------------------------------------------------- | ---------------------------------------------------- |
| `GET /workforce/directories`                            | 本人或相关管理者读取当前可选择树、科室职务和分类规则 |
| `GET /workforce/directories/{collection}`               | `workforce.directory` 管理读取，包含停用项           |
| `POST /workforce/directories/{collection}`              | 创建封闭六类中的条目，`201`                          |
| `PUT /workforce/directories/{collection}/{id}`          | 比较完整 expected 后更新，`200`                      |
| `DELETE /workforce/directories/{collection}/{id}`       | 无引用且无子项时删除，`200`                          |
| `PUT /workforce/directories/departments/{id}/positions` | 比较并替换该科室完整职务列表，`200`                  |
| `GET /workforce/rules`                                  | 读取分类默认配置，初始化期间可见缺项                 |
| `PUT /workforce/rules/{subtype}`                        | 创建缺失规则或比较 expected 后更新，`201` 或 `200`   |

配置写入使用当前会话、`workforce.directory` 和 Operation-Id；`collection` 必须由封闭枚举分派固定查询，不拼接动态 SQL。删除仍受数据库引用保护，包括已注销人员的原提交。新工牌提交与目录、科室职务、规则编辑共用写入协调，在同一决定性快照判断选择。目录读取、规则缺失或数据库损坏不能伪装成空树、默认值或客户端错误。

## 验收

验证三个名称范围的同表与跨表重名，停用仍占名、不同范围可同名、同时创建或改名仅一方成功；真实运行身份下验证旧快照、非 `READ COMMITTED` 与同事务跨表写入。验证科室缺分组、父子异组、循环、完整子树跨组移动及并发新增子节点。验证职务不继承父科室、同一职务跨科室、已引用组合不可删改、停用与提交竞争。验证实习不能选职务、所有类别必选实际科室、默认科室只预选、停用祖先、规则缺失和无引用删除。验证目录编辑不改原提交及成品，错误不映射成空配置。当前没有这些执行结果。
