# 工牌申请目标设计

状态：目标设计，尚未实施。Badge 是 Workforce 内部能力；本文拥有 Application、每次明确提交的 Submission、审批 Review、本人取消和管理员结束。渲染成品和实际发放由后续专题拥有。申请永久绑定原 Workforce Grant；重新加入、注销后新注册或重新取得相同编号，均不能改绑旧申请。

## 申请与自动分类

新申请要求可用正式账户、完整实名、未结束且未暂停的原领域授权、当前合法人员编号，以及本人确认的模板、照片和目录选择。本人可以并行提交多份申请，系统不限制只有一份活动申请。每份 Application 的首个 Submission 序号为 1；驳回后重提追加下一序号并推进当前指针。原提交、决定和内容永久保留；客户端不能提交申请类别或任意来源成品 ID。

系统比较当前请求与该原 Grant 内仍被认可的最新发放展示。没有认可展示为 `issuance` 新办；完全相同为 `duplication` 增办；有认可展示但内容不同为 `replacement` 换证。比较姓名、固定编号版本中的完整编号值、打印科室和职称文字、照片实际效果及模板身份。人员细分类或编号版本 ID 差异本身不等于牌面变化。当前展示从该原 Grant 的适用 Delivery 中按成功保存的 `number` 顺序选取，不按申请创建、实体放置或恢复响应时间。多张相同展示取最近一次成功发放作为唯一增办来源，以 Delivery ID 固定。

增办完整复用合法来源的原牌面、照片、模板、编号版本及已保存布局，不改成当前编号版本或当前模板；普通更正后来源若仍合格，也不能静默替换。新办与换证保存本次确认内容。新发放改变将来新提交的当前展示，不改写并行旧申请的类别、来源、内容、阶段或批准。工牌是身份信息展示物，不作为本系统逐张核验或撤销的通行凭证。原授权结束后机构原则上不再认可旧工牌，旧牌也失去增办来源资格；适用编号撤销同样使旧牌失去来源资格。新授权或同号重获不使旧来源重新合格。换证尚未发放前原展示继续被认可，新发放后旧内容牌不再作为增办来源。不逐张登记实体卡失效、收回或销毁。

每次提交选择本次实际使用模板地点列表中的非空 `location`，保存原地点文字而非数组下标。地点供制作人员放置成品，详情、管理和制作页面显示一致；不打印、不参与牌面比较，增办也可另选地点。发放时不能另选或用后来模板选项覆盖原值。原请求输入比较包含地点，同键换地点为 `409 request_mismatch`。

## 固定提交与确认

Submission 固定所属 Application 和 Person、本申请序号、提交人当时实名版本、提交时间、类别、可选来源 Delivery、原编号版本、实际科室与可选职务、可选完整职称、打印科室及职称文字、Photo ID、领取地点与 Operation-Id。姓名沿固定实名版本读取，完整编号沿固定编号版本读取，不另存可漂移副本；模板由固定 Photo 引出。增办且仅增办必须有来源。全部人员、授权、照片、编号和来源用真实组合引用证明同人，同一来源还必须属于原 Grant。没有职称时固定打印“无”。

提交的受控输入含原授权、实名版本、编号版本、目录 ID 与实际打印文字、Photo ID、模板固定摘要、地点和 `confirmed=true`。服务端在决定性快照重读可信内容和当前资格。非增办按当前编号、模板、目录、职务组合和分类规则检查；合法增办复用原来源例外。确认值、所选来源或实际模板变化时返回 `409 data_changed`，要求重新预览确认；不默默采用重算内容。编号改走又改回同值时，新普通提交仍须确认新版本。短期预览或签名链接不是永久提交事实，原键回读从固定 Submission 重建。

`applications` 保存原 Grant、Person、当前 `submission_id` 与阶段。`submissions` 只追加，当前指针通过组合外键指向同申请最高序号，历史版本不倒退。提交与新申请或指针更新、照片和模板保护同事务保存。读取原结果优先按 Operation-Id 找固定 Submission 并核对原输入；原成功不因后来资料、指针、授权或地点选项变化而重新提交。查询损坏不能映射为无申请。

## 阶段、审批与结束

| 阶段         | 允许的后续动作                                                         |
| ------------ | ---------------------------------------------------------------------- |
| `pending`    | 当前有权者批准、附理由驳回或明确结束；本人取消                         |
| `rejected`   | 本人按当前条件重提或取消；管理者明确结束                               |
| `approved`   | 原尝试继续，明确失败后授权新尝试、制作与发放；本人取消或管理者明确结束 |
| `completed`  | 保留成功发放和历史，不再重提或发放                                     |
| `terminated` | 保留取消或人工结束事实，不能恢复                                       |

有 `workforce.approval` 的当前管理者审批准确的 pending 当前提交。批准同事务保存 Approved Review、首个编号为 1 的 active Render，并把申请置 approved；没有“批准但尚未开始首次尝试”的状态。驳回保存有具体非空原因的 Rejected Review，无 Render，申请变为 rejected。已驳回的重提重新确认且可以重新分类；原来源仍合格的增办沿用来源，来源失格则按当前事实重新准备，旧提交和决定保留。已批准后要改变牌面须明确结束旧申请并新建申请。

管理页面在同一快照展示固定提交、当前姓名和编号版本、账户与原授权、目录及模板、适用发放和已存成品的差异。审批、渲染重试与发放携带所见 Confirmation，办理前在共同写入入口重查；变化需刷新并明确确认。Confirmation 不要求原牌面等于当前资料，也不因签名链接刷新而变化。当前编号版本不同只是差异；适用撤销仍从原提交编号版本沿[人员编号](numbers.md#撤销与恢复)判断。资料更正、目录调整或其他发放不自动改变阶段、类别、来源、批准或在途渲染输入。

本人在账户可用时可取消未发放的单份申请，包含领域暂停和已批准或制作中的申请；不要求文字理由，不结束领域授权或其他申请。账户暂停不开放此例外。管理者以当前审批职责及具体自由文本原因明确结束 pending、rejected 或 approved 申请，即使对象本人已暂停、退出或注销也可办理。取消保存 Cancellation，管理结束保存 Termination；两者与 Delivery 互斥，同事务置 terminated，不借用先前更正或物理操作时间。发放结局未知须先核对，不能以超时判断未发放。终态不能重开；注销不等待管理员逐项结束申请，未结束申请仍保护必要照片和模板。

领域暂停仅停止后续普通办理，原阶段和确认保持；恢复后重新检查当前前提。原授权结束或原编号适用撤销立即阻止旧申请的审批、制作和发放，阶段保留，等待有权管理员明确结束。新授权或同号重获不能继续旧申请。管理者可查看原历史和真实上游变化；依赖故障不能伪装成资格拒绝。

## 存储与 HTTP

`applications` 与 `submissions`、`reviews` 使用真实人员和原授权外键。Review 与所属 Submission 共享 ID，只保存一次批准或驳回、办理人与目标当时实名版本、时间、确认、可选驳回原因和 Operation-Id。Submission 及 Review 不可更新或删除，Application 只可在真实同事务事实保护下推进当前指针与阶段。提交时的事务约束同时检查当前指针、最高序号、Review、首 Render、结束事实和 Delivery 的阶段配对；终态不可重开，不能用旧提交的决定推进当前提交。历史解码使用原固定版本，不能按今天的目录规则重判旧提交。

本人提交、重提、取消和当前详情入口，以及管理者审批、结束与历史入口，均要求当前会话和 Operation-Id 的写入契约。读取他人申请须当前相应管理权；原操作者身份、相同身份证号或编号不能替代读取权。响应区分固定原内容、当前资料差异、实际阶段及允许动作；完整身份证号不因审批开放。所有成功使用标准 JSON `code` 封套，读取失败不能伪装成空申请。

| 路由                                                                              | 办理或读取                                    |
| --------------------------------------------------------------------------------- | --------------------------------------------- |
| `POST /workforce/applications`                                                    | 本人创建 Application 与首份 Submission，`201` |
| `POST /workforce/applications/{id}/submissions`                                   | 本人驳回后重提，`201`                         |
| `POST /workforce/applications/{id}/cancellations`                                 | 本人取消未发放申请，`200`                     |
| `POST /workforce/submissions/{id}/reviews`                                        | 有权管理者批准或附理由驳回，`201`             |
| `POST /workforce/applications/{id}/terminations`                                  | 有权管理者明确结束未发放申请，`200`           |
| `GET /workforce/current/applications`、`GET /workforce/current/applications/{id}` | 本人当前列表和详情，暂停时仅返回取消所需摘要  |
| `GET /workforce/applications`、`GET /workforce/applications/{id}`                 | 有权管理者分页读取当前资料与永久事实          |

## 验收

覆盖并行申请、自动三类判断、相同展示最近发放来源、原 Grant 与同人引用、增办复用固定内容、地点不同但牌面相同、重提序号及当前指针不倒退。覆盖批准与首 Render 同存、驳回无 Render、取消与管理员结束的不同原因、Delivery 互斥、账户和领域暂停差异、注销保留未结束申请。验证资料变化只展示差异、原编号版本适用撤销、旧授权或同号不能复活资格；以运行身份验证指针和阶段配对、无半笔事实、原请求丢响应与同键异输入。当前没有这些执行结果。
