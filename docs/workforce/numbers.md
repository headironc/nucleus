# 工号

## 简化目标

保留当前工号、实际人员分类、分配与更正等办理需求及号码池唯一约束。既有号码显示规则保持；显示文本可能碰撞，不能将它当作唯一键。当前工号与占用变更在同一事务提交。

目标以当前值和必要审计替代不可变版本、更正链、封印及原结果证明。申请直接保存当时完整打印值；管理页对比当前值，只提示差异，不沿历史版本或 tenure_id 判断工牌来源。没有当前合法工号时拒绝新增及后续普通工牌办理。

分配资格、历史补录和涉及两人的占用转移仍有真实业务后果，按完整消费者迁移，不以删历史表代替迁移。停止扩展工号封印或持有期系统。已保存历史与旧引用在适用保留义务结束前保留。

## 迁移前合同

以下章节保留现有工号业务和 API。原工号版本、证明、历史链及适用撤销规则只约束未迁移消费者。新工牌按[申请](applications.md)保存快照，按当前资格办理，不采用这些来源追溯规则。

Workforce 拥有工号及其当前占用、不可变版本、分配、更正、撤销、恢复与永久历史。工号属于固定 Person，退出或重新加入不改变工号。Access 只提供当前领域授权；工牌以固定工号版本解释原提交，并核对适用撤销。工号不证明任职或完整人事关系。

## 工号与占用

`Number` 由人员细分类 `subtype`、完整入职年份 `year` 和顺序号 `serial` 组成。有效细分类恰为 100、200、300、400、500、600、700、801、802、803、804、901、902、903、904、1000；整数除以 100 得大类 1 至 10。同一大类、完整年份共用 1 至 999 的顺序号池。年份为正整数且首次分配工号或录入时不得晚于办理时中国标准时间的自然年；历史读取不按今天重判。显示文本由大类、年份后两位及至少两位顺序号连接，例如 902、2026、5 显示为 92605；显示文本可能碰撞，不能反解析或作为唯一键。

第 8 和第 9 类必须明确选择细分类；其他类别使用本类唯一代码。人员类别没有默认值，由本人领取工号时选择，工牌申请不重复选择。代码身份稳定，显示名称变化不改旧分类；细分类可用于工牌规则，但不表示正式任职、雇主或任职历史。工号显示只使用大类。

每人至多有一个当前工号，它指向该人的一个不可变工号版本，并在 `(subtype / 100, year, serial)` 号码池位置上唯一占用；没有当前工号就没有占用。注销不移除当前占用；已注销人员继续占号，不能因重新注册自动移交。

每个工号版本有独立 UUID，固定所属人员与完整工号，建立后不能修改或删除。相同完整工号可出现在不同历史版本，历史值不参与当前占用唯一性。每个新版本恰有一项分配、更正或恢复创建事实；普通重放不能生成第二个版本。不允许孤立版本、复用版本、分叉或成环的更正链。每人的工号状态保留最新版本，撤销后也保留。历史更正只从该版本前移；当前持有时，状态中的号码与版本同人同值。

## 首次分配工号与补录

正常账户、完整实名、未结束且未暂停的 Workforce 授权，是本人首次领取工号的前提。领取人须从未取得任何工号；当前或以前的分配均排除再次领取。本人只选细分类，系统使用当前中国标准时间自然年，并取得同池最小未占用顺序号；不要求人工审批。号码池与年份在协调该池后决定，等待期间跨年则改用新年度池。池耗尽返回 `409 number_pool_exhausted`，不能扩大范围或伪装成并发冲突。

辅助分配的办理人须为正常账户、未暂停的当前 Workforce 成员，并持有 `workforce.numbers`。目标的机构等级必须严格低于办理人；这里比较机构等级，不比较领域等级。目标不得已注销，须持有当前且未暂停的 Workforce Grant，并从未取得任何工号；目标账户暂停本身不排除办理。办理人声明实际入职年份，必须严格早于办理时中国标准时间的自然年；当年入职者使用自助领取。领域授权生效年份不能替代真实入职年份。办理人提交细分类、非空原因及与 Grant 管理相同的目标确认：`accountId`、`personId`、`revisionId`、`mobile`。系统在相应大类年度池取最小空号，以 `assistance` 保存实际经办人和原因。

发现遗漏的历史工号时，管理者核实原完整工号后补录，不生成替代工号，也不能覆盖他人占用。补录的办理人资格、目标机构等级、目标当前未暂停 Grant 与未注销要求、从未取得任何工号、目标确认及非空原因与辅助分配相同；补录允许不晚于办理时中国标准时间自然年的真实入职年份，不要求最小空号。分配工号和补录在完成事务里保存实际经办人及本次时间；未知的原经办人或原分配时间不能填入当前办理字段。原工号的真实入职年份保留。三种分配来源固定为 `self_service`、`assistance`、`supplement`，每项以唯一 Operation-Id 定位原事实。自助分配没有原因，辅助与补录的原因去除首尾空白、转为 NFC 并拒绝控制字符，且必须非空。分配须晚于该人员的某次 Grant，且早于其注销。

每次分配共同创建版本、分配事实与当前占用。协调相同号码池和相关人员后，在决定性快照查最小空号或核对所补录的顺序号未占用，唯一性仍作最终保护。丢响应按原 Operation-Id 读取分配事实和固定版本，不再次分配工号或改写操作者与时间。

## 普通更正

当前有 `workforce.numbers` 的管理员可按核实事实更正现有工号或细分类，提交目标人员、当时实名版本、`expected` 工号版本、完整 `replacement` 与非空具体原因。替代值不强制为最小空号，也不套用首次分配的入职年份限制，但必须有效且不占用他人的当前号码池。新请求前后完整工号相同即拒绝。当前工号须仍为 expected；即使值改走又改回，也不能重用旧版本确认。

更正共同创建新版本、保存含前后版本的更正事实，并原子替换当前占用。完整号码池变化成功后才释放原池；同一大类内仅改细分类不释放池。已结束授权或已注销人员的已有工号允许由管理员纠错，不能借此新发工号、恢复领域权或开启工牌流程。

普通更正不修改旧版本、申请、批准或成品，也不直接使原申请失格。工牌消费者展示当前值与原确认的差异，由有权管理者处理。更正永久保存同人前后版本、实际经办人与目标当时实名版本、时间、历史顺序号、原因和 Operation-Id；同人链不得分叉。

普通更正的办理人是正常账户下未暂停的当前 Workforce 成员，并持有准确的 `workforce.numbers`。目标仍有当前 Grant 时，机构任职等级必须严格低于办理人。目标 Grant 已结束或目标已注销时，在本用例中没有当前等级，任一上述合格办理人均可纠错。目标账户或 Grant 暂停不阻止更正已有工号。

已撤销且无当前工号的人只能从其最新工号版本追加更正事实和新版本，沿用普通更正入口、正文、权限与等级规则；新版本不建立占用，因此替代值可以与他人当前占用相同，也不改变他人占用。只在本人没有当前工号且曾被撤销时接受这种更正；不是最新版本为 `409 target_changed`，同值为 `422 invalid_input`。撤销是该次持有的结束，撤销后的更正只作历史后继；从被撤销版本起由更正连成的版本均不得占用，即使该人员之后经恢复重新取得工号也是如此。手机号更正候选对无当前工号者返回 `409 target_unavailable`，管理者可经恢复候选取得实名确认、经历史读取取得最新版本。

更正通过独立手机号候选或完整工号持有人定位取得目标确认及当前工号版本。权限之间不相互推导，各管理动作提供自己的候选入口。已注销人员没有账户及手机号，无法由手机号候选定位；完整工号持有人定位覆盖这些人员，只接受完整工号，不提供姓名或身份证号搜索。

## 撤销与恢复

历史持有人误领临时号而原号空闲时，使用普通更正。原号确被他人误占时，管理者核实双方身份、当前工号和原完整号码池，一次恢复必须撤销误占者的当前工号，并给原持有人建立恢复版本。若原持有人另有当前临时工号，同次还须撤销该号。一项或两项撤销与一个恢复、恢复版本及全部占用变化共同提交；任何一步失败整体回滚。原临时号只在整体成功后可重新分配。

同一自然人注销后以新 Person ID 注册并需要原号时，管理者核实同人、旧人员真实注销及仍持有准确旧版本、新人员满足正常办理条件且没有工号。一次办理撤销旧身份的当前工号并给新身份恢复完全相同的原号，恰有一项旧人员撤销和一项新人员恢复。办理原因写明核实依据，不把旧身份解释为误占，不自动按身份证号或显示文本合并人员，也不开放普通转让。新身份不继承旧身份的授权、申请或历史读取权。注销早于该撤销。

每项撤销与恢复都有独立 UUID ID。撤销固定所属恢复、所属人员及其实名版本、被撤销工号版本、操作者、时间、历史顺序号和原因；恢复固定受益人员及其实名版本、新工号版本、操作者、时间、顺序和 Operation-Id。同组操作者、时间与原因一致；各人员的工号记录使用连续独立顺序。受益人同次撤销与恢复依次取得两个顺序号，仍作为一次原子办理。办理须核对一至两项撤销、准确的原占用者、版本号码池、同人关系及关联完整性。自由文本原因不决定业务分支。

每项撤销从被撤销版本沿同人、同完整号码池的连续普通更正链，影响该次持续持有期间的旧申请引用。细分类变化不能使旧提交绕过撤销；跨号码池更正、重新分配工号或后来恢复的新持有不连接旧撤销。同号重获不复活旧申请或旧工牌的增办来源。受影响申请立即停止继续办理，原阶段保留，由管理员明确结束；已经形成的材料和历史继续保留。普通更正则不自动造成这些后果。

## 存储与原结果

工号三个字段及整体均须非空并受值域检查。当前占用只能随分配、更正或恢复建立和改变，只能随撤销移除；注销不能移除占用。版本、分配、更正、撤销、恢复是永久事实，不能修改或删除。分配事实固定版本、来源、实际经办人、时间、顺序与原操作；辅助分配和历史补录另保留原因及完整目标确认。确认账户注销后，原输入仍须保留。更正固定前后版本；恢复与撤销分别固定新旧版本。只允许预定义来源创建版本，不设通用工号事件表。状态、记录、不可变版本及完成记录按共同[状态历史与完整性](../architecture.md#状态历史与完整性)保护。撤销保留人员的工号状态，释放当前占用。缺失或篡改状态不能释放号码。

三类分配、更正与恢复都永久保存封装的规范输入，覆盖全部客户端确认和路径目标。原结果比较与保留期限遵守[完成记录](../architecture.md#完成记录)。启动核验状态、全部记录与取值，以及完成记录的完整性和配对；历史资格不按后来状态重判。

普通分配、更正和恢复分别按自身 Operation-Id 查原事实及其固定版本，在同一快照核对目标、实际办理人、原版本和输入。命中原成功先回读，不按后来占用或注销状态重办；同键异输入返回 `409 request_mismatch`。新办理按当前资格及业务条件判断；查无事实不证明原事务回滚。未知提交按[原操作恢复](../architecture.md#未知提交)核对整组原事实；内部恢复保留首次办理时核验的办理人员，不要求其会话或权限继续有效，新请求仍检查当前资格。原事实引用版本缺失是完整性故障，不能当作未办理。

## HTTP 入口

| 路由                                                    | 用途                                                  |
| ------------------------------------------------------- | ----------------------------------------------------- |
| `GET /api/v1/workforce/current/numbers`                 | 本人读取当前工号或空值                                |
| `POST /api/v1/workforce/numbers`                        | 本人按当年及细分类首次领取工号，`201`                 |
| `POST /api/v1/workforce/numbers/candidates`             | 凭工号管理权精确确认辅助分配或历史补录目标，`200`     |
| `POST /api/v1/workforce/numbers/corrections/candidates` | 凭工号管理权取得普通更正的目标及当前工号确认，`200`   |
| `POST /api/v1/workforce/numbers/corrections/holders`    | 凭工号管理权按当前完整工号取得持有人更正确认，`200`   |
| `POST /api/v1/workforce/persons/{id}/numbers`           | 管理者核实往年首次分配工号，`201`                     |
| `POST /api/v1/workforce/persons/{id}/supplements`       | 管理者补录完整历史原号，`201`                         |
| `POST /api/v1/workforce/persons/{id}/corrections`       | 管理者按 expected 版本及原因更正，`200`               |
| `POST /api/v1/workforce/recoveries/candidates`          | 凭工号管理权按手机号确认恢复受益人及其当前工号，`200` |
| `POST /api/v1/workforce/recoveries`                     | 管理者核实两方并原子撤销与恢复，`200`                 |
| `GET /api/v1/workforce/persons/{id}/revisions`          | 有权者分页读取该人员永久工号办理历史                  |

工号响应 `number` 包含固定版本 `id` 及完整 `subtype`、`year` 和 `serial`。所有写入使用当前会话、Operation-Id、必填准确 Origin、8 KiB 强类型 JSON 与已认证写入预算，拒绝查询参数及未知字段，返回标准 JSON `code` 封套；读取沿网站读取同源规则与元数据预算，拒绝查询参数（分页除外）与正文。HTTP 最多等待 30 秒，全部响应 `no-store`，不设置 cookie。读取他人历史必须有当前工号管理权。原版本 ID、相同显示文本或新身份都不授予旧人员资料读取权。候选与定位只读，不预留号码或办理权，办理仍重新核对当前事实；三者与历史读取都在一个[只读快照](../http/lists.md)内复查会话、准确权限与目标。依赖失败保持 `503 dependency_unavailable`，不伪装成未命中。

本人领取正文只有强类型 `subtype`，不涉及管理权限。成功及原输入重放为 `201`，返回 `code: ok` 和 `number`。已有或曾有分配时返回 `409 number_present`；池耗尽返回 `409 number_pool_exhausted`；无合格成员关系返回 `403 permission_denied`。本人当前读取不要求管理权限或当前授权，退出 Workforce 后仍返回原工号；成功为 `200`，返回 `code: ok` 和 `number`，没有工号时 `number` 为 `null`。当前占用缺少其创建事实属于事实损坏，读取失败并关闭共同接纳，不表现为空值。

分配候选正文只含完整 `mobile`，成功为 `200`，返回 `code: ok`、`identity` 和 `grantId`；身份含 `accountId`、`personId`、`revisionId`、本次输入的 `mobile`、脱敏 `name` 和 `idNumber: { suffix }`，客户端据此组成完整目标确认。辅助分配正文含 `target`、`subtype`、正整数 `year` 和 `reason`；历史补录另含 1 至 999 的 `serial`。成功及重放均返回 `201`、`code: ok` 和固定 `number`。

分配候选与两种办理先复查会话和办理人的当前基本权限，分别拒绝为 `401 authentication_invalid`、`403 permission_denied`。候选中目标不存在、已注销、无当前 Grant、本人或机构等级不严格更低，统一为 `404 target_unavailable`；可披露目标的 Grant 暂停为 `409 state_conflict`；已有或曾有任一来源分配为 `409 number_present`；先检查 Grant 状态再检查既有分配。办理时原成功优先于目标当前状态、确认、等级和年份判断；同键异路径、异操作或异正文均为 `409 request_mismatch`。新办理中无当前 Grant 或已注销目标为 `404 target_unavailable`；确认变化为 `409 target_changed`；机构等级不严格更低为 `403 permission_denied`；目标 Grant 暂停为 `409 state_conflict`；违反来源年份边界为 `422 invalid_input`；历史补录所请求的同大类年度顺序号已被占用时返回 `409 number_occupied`。

更正候选正文只含完整 `mobile`，成功返回 `200`，正文恰含 `code: ok`、`identity` 和 `number`。`identity` 沿用脱敏确认：`accountId`、`personId`、当前 `revisionId`、本次输入的 `mobile`、脱敏 `name` 及 `idNumber: { suffix }`；`number` 是当前版本，不附 Grant 或历史。不存在、已注销或不可管理目标统一返回 `404 target_unavailable`；当前 Grant 目标的机构等级必须严格更低，Grant 已结束的目标免于等级比较；目标账户或 Grant 暂停不排除候选；可管理目标没有当前工号时返回 `409 target_unavailable`。

完整工号持有人定位正文复用 `Number` 的有效 `subtype`、正整数 `year` 和 1 至 999 的 `serial`，只查找当前占用，历史版本不参与定位。成功返回 `200`，正文恰含 `code: ok`、`identity` 和 `number`；`identity` 只含 `personId`、当前 `revisionId` 和脱敏 `name`，不含 `accountId`、`mobile` 或 `idNumber`。未命中、旧版本或不可管理目标统一返回 `404 target_unavailable`；当前 Grant 目标仍须机构等级严格更低，Grant 已结束或人员已注销则免于等级比较。

普通更正的路径固定目标 Person，正文只含 `revisionId`、`expected`、`replacement` 和 `reason`。`revisionId` 确认目标当前实名版本，`expected` 确认当前工号版本，`replacement` 必含有效 `subtype`、正整数 `year` 和 1 至 999 的 `serial`。成功和原输入重放均以 `200` 返回 `code: ok` 和固定 `number`。更正先复查当前会话及准确基本权限，再核对原 Operation-Id；同键异人员、实名版本、expected、替代值或规范原因返回 `409 request_mismatch`。新办理中未知人员或无当前工号为 `404 target_unavailable`，实名确认变化及旧 expected 均为 `409 target_changed`。当前目标等级越界为 `403 permission_denied`，前后完整工号相同为 `422 invalid_input`，他人占用替代号码为 `409 number_occupied`。A→B→A 也产生新版本，旧 expected 不因值相同而重新有效。

恢复的办理人资格与目标等级沿普通更正；任一方仍有当前 Grant 时，其机构等级须严格低于办理人，Grant 已结束或已注销的一方免于等级比较。正文为 `{beneficiary: {personId, revisionId, current, origin}, occupier: {personId, revisionId, current}, reason}`。`current` 为当前工号版本 ID，受益人没有当前工号时必须显式为 null；`origin` 是恢复所依据的原工号版本，恢复建立值完全相同的新版本。受益人由恢复候选按手机号确认，返回脱敏身份及当前工号或 null；占用者由完整工号持有人定位确认；原版本取自受益人的工号历史。

误占恢复的受益人须有账户，即未注销；已注销受益人为 `404 target_unavailable`。占用者可以已注销，其占用照常撤销。双方实名版本或当前工号与确认不符为 `409 target_changed`。同一人、`origin` 不属于受益人，或 `origin` 与占用者当前号不在同一号码池位置时为 `422 invalid_input`。注销后同人以新身份取回原号沿用同一入口与正文：受益人为新身份，`current` 为 null，`origin` 为已注销旧身份仍持有的当前工号版本，占用者为该旧身份，其 `current` 等于 `origin`；新身份须从未取得任何工号版本，并持有当前且未暂停的 Grant，无当前 Grant 为 `404 target_unavailable`，Grant 暂停为 `409 state_conflict`，不满足这些条件而 `origin` 又不属于受益人时为 `422 invalid_input`。

恢复成功及原请求重放返回 `200`：`{code: "ok", recovery: {id, personId, origin, number, revocations}}`，`revocations` 先列占用者，再列受益人自己的撤销。同键异输入为 `409 request_mismatch`。恢复版本以后可照常普通更正，当前读取接受恢复创建的版本。

工号历史读取要求办理人为正常、未暂停的当前 Workforce 成员并持有 `workforce.numbers`；可读取任意人员（含 Grant 已结束人员及已注销人员）的永久工号历史，不按机构等级裁剪，不授予无该权限的本人（`403 permission_denied`）。仅当 Person 与全部工号历史均不存在时返回 `404 target_unavailable`；留存历史缺失所属 Person 属于事实损坏。列表联合分配（`self_service`、`assistance`、`supplement`）、普通更正（`correction`）、恢复（`recovery`）与撤销（`revocation`），每项暴露种类 `kind`、固定版本 ID 及完整工号（更正同时包含 `before` 与 `after`，恢复包含新版本与 `origin`，撤销包含被撤销版本与 `recoveryId`）、时间 `time`、历史顺序号 `sequence`、原操作 `operationId`（撤销取所属恢复）、保留的原因 `reason`（自助分配省略），以及实际经办人的固定脱敏身份 `operator`（`personId`、`revisionId` 与脱敏 `name`）。采用共同分页（`page` 缺省 1，`size` 缺省 20 且上限 100），按 `sequence DESC`、再按事实标识 `id DESC` 排序；越界页保持真实总数并返回空数组。总数取自人员的工号状态，读取核验所取历史窗口的连续性及实际使用的固定版本与办理人身份。页外历史由启动全量核验；不在每次读取时重新判断旧办理的 Grant 或注销先后。消费到损坏事实时，整页失败并关闭接纳。

## 验收

目标验收覆盖 16 个细分类、同大类共池、完整年份、最小空号及耗尽；注销仍占号和普通更正成功后释放。覆盖三类分配、真实经办字段、版本唯一来源、同人关系与永久事实不可修改或删除。验证更正的旧 expected、无当前占用的历史纠错、同池细分类变化；误占恢复的一至两项撤销和注销后同人重新取得的一项撤销，任意部分失败均无残留。验证旧提交沿连续同池链适用撤销、跨池或新持有不误伤，原请求丢响应和未知提交不再生成事实。

分配验收覆盖本人自助、辅助分配、历史补录及其候选和当前读取：机构同级拒绝、基本权限不足、无 Grant、Grant 暂停、注销、来源年份边界、旧确认、已有任一来源分配、同池占用冲突、共享号码池、最小空号及耗尽，补录与辅助分配、本人自助在同一号码池上的并发正确性，以及跨年等待时在池协调后取年份。候选验收覆盖脱敏确认、准确 Grant、无业务写入、权限与目标资格及拒绝顺序；完整工号定位覆盖当前版本、历史旧号缺席、本人及同级或更高目标遮蔽、注销人员的当前脱敏实名并据此完成真实更正。仅含 `workforce.numbers` 的操作员无法使用其他管理候选入口，却能从工号候选及完整工号定位取得确认字段完成办理。

更正验收覆盖跨池更正及释放、同类细分类变化继续占号、非最小替代值、同值拒绝、占号冲突、旧实名与旧 expected、A→B→A、权限及等级拒绝、Grant 暂停、结束和注销目标，以及与自助、辅助分配和补录争用同池。恢复验收覆盖受益人原号被更正走后由另一成员补录占用的场景、同人、外来原版本、异池位置、旧确认与无权成员的拒绝不留下事实、同组记录连续排序且共同提交、占用移动、临时号释放、恢复版本的后续更正；无当前工号的受益人只撤销占用者一项；撤销后的历史更正在之后经恢复重新取得工号时仍成立且不占用；注销后取回原号恰有一项撤销且已有工号者不能借此取得他人号码。

历史读取验收覆盖全部事实种类的混合排序、共同分页与越界总数、后续实名更正后旧历史的固定身份不变、Grant 已结束及已注销人员、办理人权限边界、并发事实与单个快照隔离，以及父 Person 丢失、保留原封印时改写原因、经办人、原操作或确认实名版本、删除最新更正但保留版本及占用、篡改事实顺序、所取窗口封印不符、缺键或缺号时整页失败，以及启动发现页外损坏。各写入覆盖提交丢响应、确定回滚、结局未知和取消等待后只保留一份事实。完整性负例覆盖复合工号为空、占用值与版本不一致、孤立版本、同版本多个创建来源、跨人员指针、更正链分叉或成环、遗漏或伪造第二项撤销、错误人员或号码池、无恢复的撤销、无撤销的占用移除，以及两方分别注销后仍保持完整关联；原操作重放不得改变原经办人、时间、顺序或已经保存的撤销集合。HTTP 覆盖各路由的状态码、强类型确认、稳定拒绝码、重放、来源、正文边界、缓存、cookie 与 OpenAPI。
