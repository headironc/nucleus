# 人员编号目标设计

状态：目标设计，尚未实施。Workforce 拥有人员编号、当前占用、不可变版本、发号、更正、撤销、恢复与永久历史。编号属于固定 Person，退出或重新加入不改变编号。Access 只提供当前领域授权；工牌以固定编号版本解释原提交，并核对适用撤销。编号不证明任职或完整人事关系。

## 编号与占用

`Number` 由人员细分类 `subtype`、完整入职年份 `year` 和顺序号 `serial` 组成。有效细分类恰为 100、200、300、400、500、600、700、801、802、803、804、901、902、903、904、1000；整数除以 100 得大类 1 至 10。同一大类、完整年份共用 1 至 999 的顺序号池。年份为正整数且首次发号或录入时不得晚于办理时中国标准时间的自然年；历史读取不按今天重判。显示文本由大类、年份后两位及至少两位顺序号连接，例如 902、2026、5 显示为 92605；显示文本可能碰撞，不能反解析或作为唯一键。

| 大类             | 固定细分类代码和名称                           |
| ---------------- | ---------------------------------------------- |
| 1 临床           | 100 临床                                       |
| 2 护理           | 200 护理                                       |
| 3 医技           | 300 医技                                       |
| 4 药剂           | 400 药剂                                       |
| 5 财务           | 500 财务                                       |
| 6 行政           | 600 行政                                       |
| 7 后勤           | 700 后勤                                       |
| 8 第三方人员     | 801 第三方公司、802 保安、803 物业、804 志愿者 |

第 8 和第 9 类必须明确选择细分类；其他类别使用本类唯一代码。人员类别没有默认值，由本人发号时选择，工牌申请不重复选择。代码身份稳定，显示名称变化不改旧分类；细分类可用于工牌规则，但不表示正式任职、雇主或任职历史。编号显示只使用大类。

当前 `workforce.numbers` 行同时表示该人的当前编号与号码池占用；没有编号就没有行。`id` 为 Person ID，`revision_id` 引用其不可变编号版本，`number` 是与该版本准确相同的受约束值副本。组合外键保证同人同值，唯一占用索引按 `(subtype / 100, year, serial)` 建立。注销不删除当前占用；已注销人员继续占号，不能因重新注册自动移交。

`workforce.revisions` 的 `id` 为 UUID，另存 `person_id` 与完整 Number，建立后不能更新或删除。相同完整编号可出现在不同历史版本，历史值不参与当前占用唯一性。每个新版本恰有一项分配、更正或恢复创建事实；普通重放不能生成第二个版本。数据库在提交时核对版本、创建事实及人员引用，不允许孤立版本、复用版本、分叉或成环的更正链。

## 首次发号与补录

正常账户、完整实名、未结束且未暂停的 Workforce 授权和没有当前编号，是新的本人发号前提。本人只选细分类，系统使用当前中国标准时间自然年，并取得同池最小未占用顺序号；不要求人工审批。管理员凭当前 `workforce.numbers` 管理权为往年入职且从未取得编号者核实后发号，明确实际入职年份并取对应池最小未占用号。领域授权生效年份不能替代真实入职年份。池耗尽返回 `409 number_pool_exhausted`，不能扩大范围或伪装成并发冲突。

发现遗漏的历史编号时，管理者核实原完整编号后补录，不生成替代编号，也不能覆盖他人占用。发号和补录在完成事务里保存实际经办人及本次时间；未知的旧经办人或旧发号时间不能填入当前办理字段。原编号的真实入职年份保留。三种分配来源固定为 `self_service`、`assistance`、`recording`，每项以唯一 Operation-Id 定位原事实。

每次分配同事务创建 Revision、Allocation 与当前占用。锁定相同号码池和相关人员后，在决定性快照查最小空号；唯一索引仍作最终保护。丢响应按原 Operation-Id 读取 Allocation 和固定版本，不再次发号或改写操作者与时间。

## 普通更正

当前有 `workforce.numbers` 的管理员可按核实事实更正现有编号或细分类，提交目标人员、当时实名版本、`expected` 编号版本、完整 `replacement` 与非空具体原因。替代值不强制为最小空号，但必须有效且不占用他人的当前号码池。新请求前后完整编号相同即拒绝。当前指针须仍为 expected；即使值改走又改回，也不能重用旧版本确认。

更正在同一事务创建新版本、保存含 `before_id` 与 `after_id` 的 Correction，并原子替换当前占用。完整号码池变化成功后才释放原池；同一大类内仅改细分类不释放池。已结束授权或已注销人员的已有编号允许由管理员纠错，不能借此新发编号、恢复领域权或开启工牌流程。已撤销且无当前编号的人只能从其最后一个版本追加更正事实和新版本，不建立占用，也不触碰合法新持有者的占用。

普通更正不修改旧版本、申请、批准或成品，也不直接使原申请失格。工牌消费者展示当前值与原确认的差异，由有权管理者处理。Correction 永久保存同人前后版本、实际经办人与目标当时实名版本、时间、人员顺序、原因和 Operation-Id；同人链不得分叉。

## 撤销与恢复

历史持有人误领临时号而原号空闲时，使用普通更正。原号确被他人误占时，管理者核实双方身份、当前编号和原完整号码池，一次恢复必须撤销误占者的当前编号，并给原持有人建立恢复版本。若原持有人另有当前临时编号，同次还须撤销该号。一项或两项 Revocation 与一个 Recovery、恢复版本及全部占用变化共同提交；任何一步失败整体回滚。原临时号只在整体成功后可重新分配。

同一自然人注销后以新 Person ID 注册并需要原号时，管理者核实同人、旧人员真实注销及仍持有准确旧版本、新人员满足正常办理条件且没有编号。一次办理撤销旧身份的当前编号并给新身份恢复完全相同的原号，恰有一项旧人员 Revocation 和一项新人员 Recovery。办理原因写明核实依据，不把旧身份解释为误占，不自动按身份证号或显示文本合并人员，也不开放普通转让。新身份不继承旧身份的授权、申请或历史读取权。

每项 Revocation 与 Recovery 都有独立 UUID ID。Revocation 固定 `recovery_id`、所属人员及其实名版本、被撤销编号版本、操作者、时间、人员顺序和原因；Recovery 固定受益人员及其实名版本、新编号版本、操作者、时间、顺序和 Operation-Id。同组操作者、事务时间与原因一致；各人员使用自己的顺序号，受益者同次撤销与恢复共享该人员顺序号。提交约束核对一至两项撤销、准确的原占用者、版本号码池、同人引用及关联完整性。自由文本原因不决定业务分支。

每项撤销从被撤销版本沿同人、同完整号码池的连续普通更正链，影响该次持续持有期间的旧申请引用。细分类变化不能使旧提交绕过撤销；跨号码池更正、重新发号或后来恢复的新持有不连接旧撤销。同号重获不复活旧申请或旧工牌的增办来源。受影响申请立即停止继续办理，原阶段保留，由管理员明确结束；已经形成的材料和历史继续保留。普通更正则不自动造成这些后果。

## 存储与原结果

`workforce.number` 复合值的三个子字段及整体均须非空并受值域检查。`numbers` 只允许受控插入、同时更新版本和值，以及有同事务 Revocation 才能删除；注销不能删除占用。`revisions`、`allocations`、`corrections`、`revocations`、`recoveries` 是永久事实，运行身份不能更新或删除。人员及实名版本使用真实组合外键。分配事实固定 `number_id`、来源、实际经办人、时间、顺序与原操作；更正固定前后版本；恢复与撤销分别固定新旧版本。只允许预定义来源创建版本，不设通用编号事件表。

普通分配、更正和恢复分别按自身 Operation-Id 查原事实及其固定版本，在同一快照核对目标、实际办理人、原版本和输入。命中原成功先回读，不按后来占用或注销状态重办；同键异输入返回 `409 request_mismatch`。新办理按当前资格及业务条件判断；查无事实不证明原事务回滚。未知提交按[原操作恢复](../architecture.md#未知提交)核对整组原事实。历史查询按各人的事实顺序联合分配、更正、撤销和恢复，使用真实固定版本解释值；结构缺失和关系损坏不是空历史。

## HTTP 入口

| 路由                                       | 用途                                    |
| ------------------------------------------ | --------------------------------------- |
| `GET /workforce/current/numbers`           | 本人读取当前编号或空值                  |
| `POST /workforce/numbers`                  | 本人按当年及细分类首次发号，`201`       |
| `POST /workforce/persons/{id}/numbers`     | 管理者核实往年首次发号，`201`           |
| `POST /workforce/persons/{id}/recordings`  | 管理者补录完整历史原号，`201`           |
| `POST /workforce/persons/{id}/corrections` | 管理者按 expected 版本及原因更正，`200` |
| `POST /workforce/recoveries`               | 管理者核实两方并原子撤销与恢复，`200`   |
| `GET /workforce/persons/{id}/revisions`    | 有权者分页读取该人员永久编号办理历史    |

编号响应包含固定版本 ID 及完整细分类、年份和顺序号。所有写入使用当前会话及 Operation-Id，返回标准 JSON `code` 封套；读取他人历史必须有当前编号管理权。原版本 ID、相同显示文本或新身份都不授予旧人员资料读取权。

## 验收

覆盖 16 个细分类、同大类共池、完整年份、最小空号及耗尽；注销仍占号和普通更正成功后释放。覆盖三类分配、真实经办字段、版本唯一来源、同人外键与运行身份禁止改删。验证更正的旧 expected、无当前占用的历史纠错、同池细分类变化；误占恢复的一至两项撤销和注销后同人重新取得的一项撤销，任意部分失败均无残留。验证旧提交沿连续同池链适用撤销、跨池或新持有不误伤，原请求丢响应和未知提交不再生成事实。当前没有这些执行结果。

数据库负例还须覆盖复合编号整体或任一子字段为空、占用值与版本不一致、孤立版本、同版本多个创建来源、跨人员指针、历史版本更新或删除。更正链验证同值、分叉、成环和 A→B→A 后旧 expected 不再有效；撤销恢复验证遗漏或伪造第二项撤销、错误人员或号码池、错误身份版本和原因，以及两方分别注销后仍保持完整关联。原操作重放不得改变原经办人、时间、顺序或已经保存的撤销集合。
