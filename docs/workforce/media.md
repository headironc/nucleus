# 工牌模板、照片与预览

首版使用一个部署配置的单面固定模板。实际交付范围见[能力状态](../README.md#能力状态)，PDF 见[成品与发放](fulfillment.md)。暂不建设在线模板编辑器、字体库、模板激活状态机或字形轮廓 Layout。申请见[申请规则](applications.md)。

## 模板与固定资源

模板包含背景、物理尺寸、照片区域，以及姓名、工号、科室和职称文字区域。使用明确的字体、字号、坐标和必要换行规则，不提供任意脚本或用户 SVG。布局参数按类型与范围校验，输出不能超出画布。

首版背景、字体与布局由维护者提供并通过真实中文和打印样本验收。使用具备实际部署和打印许可的字体；既有页面稿字体不自动证明服务器使用许可。资源缺失或缺字时明确失败，不静默用系统默认字体代替。

每次申请保存所用布局与固定资源标识。更换模板只影响后续申请；背景、字体取得新标识，保留旧申请引用的原字节。这里固定资源是为了重现原快照，不采用封印、摘要确认或细粒度版本核验。

领取地点是部署配置中的非空选项，本人明确选择。申请保存当时文字，不保存数组下标。地点不打印；配置后来变化不覆盖历史申请。

表单先读取 `GET /api/v1/workforce/application-template`，返回 `{code: "ok", template, pickups}`。正常账户、有效会话和活跃 Grant 可读，不要求当前工号。`template` 只有 `backgroundId`、`fontId` 与 `layout`，没有模板版本或激活实体。来源文件路径不返回客户端。JSON GET 沿用共同关联头和来源规则；依赖失败不返回空模板。

`layout` 的物理量使用整数微米：画布为 `widthUm`、`heightUm`；照片区域为 `photo: {xUm, yUm, widthUm, heightUm}`；文字区域为 `name`、`number`、`department`、`title`，分别包含 `area`、`fontSizeUm`、`lineHeightUm` 和 `wrap`。`area` 使用同一种矩形形状。坐标原点是画布左上角，区域非空且完整位于画布内；零字号或零行高拒绝。`wrap` 明确决定该区域是否换行，不把所有字段限制成单行。

## 字体输入

以下是已实现字体净化组件的合同，继续保留。首版固定模板使用部署提供且经该组件接纳的字体，不因此开放字体上传管理页面，也不要求为模板建立原请求完成记录。

字体只接纳单一字体的原始 OpenType SFNT：TrueType 魔数 `0x00010000` 或 OpenType 魔数 `OTTO`。TTC 集合、WOFF/WOFF2 包装及其他格式均按不支持拒绝。上传字节必须非空，且不超过 32 MiB。格式识别后还须完整净化，才能取得可供保存的字体明文。

上传原字节与净化输出分别记录 SHA-256 和精确大小。原请求以上传原字节识别；保存与读取以净化输出鉴别。净化不得改变原上传身份，也不得以原上传摘要代替输出摘要。

净化输出必须非空，且不超过 32 MiB。输出的实际 SFNT 类型决定 `font/ttf` 或 `font/otf`。输出超限、写入、定位或资源失败分别保留原因，不得统称字体格式错误。部分输出不得成为净化结果。净化成功不证明字形覆盖、字体许可或正式打印效果；这些要求仍由模板与排版验收负责。

测试使用 OFL 1.1 的 Source Sans 3 原字节及原许可，仅作为测试输入。来源与摘要见[字体夹具](../../domain/tests/fixtures/fonts/README.md)。

## 文字排版

使用确定的模板规则排版。首版不实现通用字号搜索、字形轮廓持久化、增办 Layout 重封装或跨版本像素复现。姓名、科室等完整文字不能截断或省略；无法容纳、缺字或资源缺失时给出明确错误，由维护者调整后续模板，原申请必要时取消并重建。

最终打印使用服务端正式 PDF。浏览器预览只辅助本人确认，不能把客户端截图当作正式成品。具体排版库随实施选择，不在设计阶段预建通用渲染框架。

服务端只使用配置中已净化的固定字体，进行文字塑形、双向文本处理和安全断行。实际墨迹及行高须位于所属区域内；不压缩字号、截字或切开组合序列制造成功。缺字明确失败，系统字体不作为备用。

快照 `text` 按 `name`、`number`、`department`、`title` 保存实际行。每行包含 `start`、`end`、`xUm`、`baselineUm`、`widthUm` 和 `direction: "ltr" | "rtl"`。`[start, end)` 是对应完整打印文字的 UTF-8 字节范围，不复制独立可编辑的行文字。范围连续覆盖原文且落在字符边界。`xUm` 是从画布左侧起算的行左对齐排版原点，`baselineUm` 是从画布顶部起算的文字基线。行定位可含小数微米，JSON 往返必须保留数值，不能因序列化改变确认内容。

浏览器加载同一字体后按服务端行展示，不自行换行、压缩文字或关闭正常字距和连字。浏览器与后续 PDF 均保留完整原文及既定行布局；预览辅助确认不承诺不同引擎逐像素一致。生产中文字体、许可、物理模板和打印样本另行验收。

## 照片与客户端预览

上传只接受完整解码的静态 JPEG、PNG 或 WebP。原字节最多 8 MiB，边长最多 4096，总像素最多 1600 万；重编码去除元数据。本人明确选择裁剪效果，服务端不静默拉伸或裁剪。

`POST /api/v1/workforce/application-photos` 接收已确认裁剪的原始图片字节，声明准确 `Content-Type`。成功为 `201`、`{code: "ok", photoId, resourceId, width, height, mediaType: "image/webp"}`；服务端完整解码并保存无原始元数据的无损 WebP，保留方向和透明度。体积超限为 `413 invalid_input`，媒体声明不支持为 `415 invalid_input`，坏图、动画或像素预算不符为 `422 invalid_input`。不接收客户端文件路径或源图裁剪坐标。

照片完整放入固定区域，使用同一个缩放因子保持宽高比，并水平、垂直居中。区域和整数像素不必精确同比，允许留白。本人确认的预览必须展示这一实际效果，不先以 `cover` 暗裁剪。半透明像素和留白透出固定背景，客户端不额外铺白或黑。合成次序为背景、照片、文字。后续 PDF 使用同一规则，不分别取整宽高而造成形变。

照片随本人提交保存为申请快照的固定资源，不建立通用照片资产管理。文件 ID 由服务端生成并绑定本次申请人；客户端不能用他人的照片 ID 替换。上传与预览的暂存内容在提交时核对归属，提交成功后保留引用字节。

本人预览姓名、工号、科室、职称、照片及牌面，并选择领取地点。服务端提交时核对可信资料与实际确认内容；变化时提示重新确认，不引入实名版本或完整页面 Confirmation。预览、审批和渲染的资源规则一致。当前资料后来变化只在管理页面提示。

## 存储与原结果

资源放在[私有文件目录](../storage/files.md)，服务端生成路径，不原地覆盖。新工牌文件不采用应用层逐文件加密或短期签名链接；保留会话鉴权、文件系统权限及加密备份。已实现的敏感字段加密不受影响。

文件先写完整，再保存申请或成品引用。失败可留无引用文件，维护窗口人工核对清理。申请引用的照片、背景和字体不按年龄删除。暂不提供模板、字体或照片的独立管理 CRUD，也不为它们新增配置完成记录。

上传响应丢失或预览失败按当前页面重新准备；提交响应丢失先看申请列表，不自动补交。三种申请类型均使用本次确认材料，不依赖过去成品。

照片、当前模板资源及本人历史引用的模板字节通过 `GET /api/v1/workforce/application-resources/{id}` 读取；HEAD 无正文。资源 ID 取自受控响应，不能把 `photoId` 当成字节定位。该精确媒体路由忽略 `Operation-Id`，仍要求有效网站会话、正常账户、活跃 Grant 及对象授权。Grant 暂停或结束后不开放照片、背景或字体；不可披露对象统一为 `404 target_unavailable`。成功类型是实际的 `image/webp`、`font/ttf` 或 `font/otf`，错误为 JSON，全部 `no-store`，不设置 cookie。

## 验收

验证固定模板可打印、字体覆盖与许可材料、长姓名及科室不截断、照片无静默变形、上传预算与元数据去除。验证他人照片不可引用，模板更新不改变旧快照及旧资源。验证文件失败没有假成功、残留可人工清理、下载需权限，以及备份包含所有被引用的资源。
