# 工牌成品与发放

状态：简化后的目标设计，尚未实施。批准先保存，随后按固定申请快照生成成品。失败或中断由有权人员重试，不建立 Render 记录、执行代次、后台队列或自动接管。申请状态由[申请专题](applications.md#阶段审批与结束)拥有。

## 成品格式

正式成品采用单面静态无损 WebP。下载响应使用 `image/webp`，文件名以 `.webp` 结尾。牌面内容、排版与透明度遵守[固定媒体规则](media.md)。

生产物理尺寸和输出像素尺寸尚待确认。正式模板、字体的服务器使用和打印许可、实际打印样本分别验收。隔离测试模板及其输出参数不代表生产参数。

## 渲染尝试

采用一个固定模板、确定的背景与字体，使用申请快照中的姓名、工号、科室、职称、照片和布局。领取地点只在办理页面展示，不打印。新办、增办、换证均从本次快照生成，不复用来源 Layout。

批准成功后可在当前请求继续尝试生成，也可由管理页面明确触发。两者都先检查申请仍为 approved、当前办理人有审批权及对象范围、申请人资格有效。生成不持有数据库业务事务。

完整输出先写入服务端唯一文件名。随后短事务再次检查权限、资格与 approved 状态，以条件更新将申请改为 ready，插入唯一成品并写审计。任何一步失败则事务整体回滚。取消已先保存时，不接纳晚到文件。

生成失败时保持 approved，并尽力保存安全的 render_error；错误保存本身失败不改变已批准事实。错误写入仅接受仍为 approved 的申请，成功采用成品时清空该字段，避免晚到错误覆盖成功状态。页面显示“重试”。进程重启不扫描或自动执行遗留工作。没有成品且没有错误记录也允许人工生成，不要求证明上一次计算已经失败。

偶然并行生成允许重复计算和无引用文件。状态条件及每申请一个成品的唯一约束决定唯一采用结果，不覆盖已经采用的文件。未采用文件在停止相关写入的维护窗口清理。连接错误不证明结果未提交，客户端刷新详情后再决定操作。

## 成品接纳与永久保护

成品存在表示完整文件已保存并被采用，没有 pending 成品。文件缺失时明确报错，由维护者按备份处理，不用空文件或当前资料重新生成假冒原成品。

快照、照片、模板效果和成品继续保留。换模板和更改个人资料不改写已保存成品。打印失败、重打和次品由现场处理，不逐次登记打印，不承诺不同渲染器版本生成逐像素相同的输出。

## 实际发放

具有发放权限及对象范围的当前人员明确点击“已发放”。申请须为 ready，申请人资格有效，且成品记录存在。短事务同时将申请改为 issued、保存发放人和数据库时间、写审计。更新条件失败不覆盖第一次记录。

系统记录登记成功的时间与操作人，不要求记录领取人、代领人、实体卡取走时间或同 Grant 发放序号。领取地点使用申请快照。实体制作在事务外；响应丢失后刷新详情，不自动重复发放请求。

## 数据结构

成品使用 workforce.badges，与申请一对一。文件路径由成品 ID 在私有目录生成，无须通用文件表或可输入路径。文件格式沿用[成品格式](#成品格式)。

| 字段           | 类型        | 规则                                     |
| -------------- | ----------- | ---------------------------------------- |
| id             | uuid        | 主键，同时定位不可覆盖的成品文件         |
| application_id | uuid        | 非空、唯一，引用 workforce.applications  |
| generated_by   | uuid        | 非空，引用实际触发生成者的 Person ID     |
| generated_at   | timestamptz | 非空，数据库记录时间                     |
| issued_by      | uuid        | 引用实际发放者的 Person ID，未发放时为空 |
| issued_at      | timestamptz | 与 issued_by 同时有值或为空              |

ready 对应未发放成品，issued 对应有发放字段的成品。cancelled 可保留未发放成品。用同一事务维护跨表配对，数据库以外键、唯一约束和行内 CHECK 兜底。没有独立 Delivery、Layout 或渲染尝试表。审计表由[架构](../architecture.md#审计)拥有。

## 原结果与 HTTP

| 路由                                             | 结果                             |
| ------------------------------------------------ | -------------------------------- |
| POST /api/v1/workforce/applications/{id}/renders | 有权者生成或人工重试             |
| GET /api/v1/workforce/badges/{id}.webp           | 当前本人或有权管理者下载正式成品 |
| POST /api/v1/workforce/badges/{id}/deliveries    | 登记已发放                       |

renders 和 deliveries 是动作入口，不代表存在同名记录表。详情从申请读取状态及成品信息，不设按 Operation-Id 恢复的 GET。使用当前会话鉴权，不另签短期下载 URL。未收到响应时刷新；成品图片与错误响应不泄露凭据或他人信息。

## 验收

验证批准已保存但未生成、生成错误、请求断开和进程重启后均可人工继续。验证渲染只消费快照，文字不截断、照片不拉伸，实际中文模板及打印尺寸可用。核对输出为完整静态无损 WebP，媒体类型与下载扩展名一致；像素尺寸及实际打印尺寸符合已确认的物理模板。

验证文件完成前没有成功记录、事务回滚允许残留文件、重复生成不覆盖采用结果、取消后不接纳晚到输出。验证 ready 才可发放，状态、发放人与时间、审计共同提交；重复点击保留第一次结果。验证越权下载拒绝、缺文件明确报错、备份恢复后原成品可读。
