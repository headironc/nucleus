# 工牌成品与发放目标设计

状态：目标设计，尚未实施。本文拥有批准后的 Render 执行、静态成品 Badge、实体卡制作和实际发放 Delivery。Application、固定提交与审批见[工牌申请](applications.md)，模板与布局见[工牌模板与照片](media.md)，文件发布与清理由所属存储协议维护。成功生成并保存的成品永久保留，即使最终未发放、申请后来结束或人员注销。

## 渲染尝试

批准与首个 Render 在同一事务保存，首尝试编号为 1、状态为 active、开始时间为共同事务时间。后台稍后计算、请求连接断开或进程重启，仍属于原 Render ID，不形成新批准。执行代次与候选成品 ID 只用于围栏和恢复。明确失败后，当前有 `workforce.approval` 的管理者在申请仍 approved 且资格有效时重新确认页面并授权新尝试；新编号接续，不能自动重试为新的业务尝试。同一提交最多一个 active 尝试，同一 Application 最多一个成功成品。

正式渲染使用有界许可，事务外读取固定 Submission、原编号版本、背景、照片及主备字体。普通新办或换证执行服务端文字排版；增办复用合法来源 Badge 的固定 Layout，再合成单面静态无损 WebP、编码并加密。执行期间不随姓名、编号或目录变化替换输入，原批准者后来失权也不撤销已授权的在途尝试。目标暂停前已开始的计算可以保存真实结果，但暂停时不能开始新计算；原授权结束、适用编号撤销、本人取消或管理员结束先于接纳时，晚到输出记 aborted，不能形成 Badge。

资源预算候选为照片准备并发 1、正式渲染并发 1，不设无界排队；画布最多 1600 万像素，最终 WebP 最多 32 MiB，模板资源合计最多 32 MiB，内部 Layout 编码最多 8 MiB。文字适配、轮廓提取与合成共用一次正式渲染许可；超限明确失败，不裁掉轮廓。照片接收观察上限 15 秒、正式渲染 30 秒；等待超时不代表 worker 已结束，许可直到实际工作结束才释放。无许可返回 `429` 及 `Retry-After`。线程内存与中文排版耗时需用真实样本验证。

`renders` 固定所属 Submission、Person、尝试编号、实际授权者与目标当时实名版本、Confirmation、开始时间及 Operation-Id。状态为 active、successful、failed、aborted；终态时间不早于开始时间。failed 保存安全错误类别，successful 配对准确代次和 Badge。所属 SQL 发布意图登记候选 Badge ID；文件与 Layout 的 AAD 都绑定该 ID，不能重绑另一份字节。工作许可保持到实际执行结束。

普通重启完成旧进程退出证明和启动屏障后，后台按索引发现 active Render，无需客户端再次请求。按原 Render、执行代次和 SQL 发布意图核对候选。继续同一尝试不产生新批准；重新计算必须先证明旧工作结束且旧候选未采用，再分配新代次和新候选 ID。未知提交保留原候选，明确失败后才允许管理者授权新 Render。

## 成品接纳与永久保护

实际工作按[文件发布与接纳](../architecture.md#发布与接纳)处理候选。正式文件持久发布后，在短事务核对执行代次、原 Render、当前原授权、编号资格、申请阶段及既有成功。共同保存 Badge、Layout、Render.successful 和材料永久保护。Badge 存在即表示成品已接纳，没有 pending 状态；未接纳输出按所属 SQL 意图清理。

Badge ID 等于已登记候选 ID，固定 Application、Person、成功 Render、完整文件元数据与 Layout。Application 和 Render 各至多对应一个 Badge；Badge 必须来自本申请当前提交的成功 Render。尺寸及 DPI 沿已固定模板取得。成品字节、确认内容、照片和模板效果在生成后不可改写；增办沿原布局重封装到新 Badge ID，不重新排字。渲染器升级不重制旧成品。制作端按模板物理尺寸和成品 DPI 打印，现场处理打印失败、重打、次品与质量检查；系统不逐次登记打印或限制重打次数。

## 实际发放

制作人员确认实体卡内容和质量，放在本次 Submission 固定的领取地点。放置和点击本身都不是完成事实。当前持有 `workforce.delivery` 的人员在系统可用时明确点击发放，命令固定 Badge ID、原 Application ID、成品摘要及管理页面 Confirmation；后台不能替人发起。发放不接受另选地点、客户端时间、旧操作者或补记理由。系统不记录领取人、代领人或实际取走时间。

发放用例先识别原 Operation-Id 完成，再在共同写入入口核对当前权限、原申请、成品、原授权、编号适用撤销及所见页面。成功事务同时插入 Delivery 并将 Application 置 completed，才算已发放。`Delivery.id` 与 Badge ID 相同，只能有一行；固定实际发放者和目标当时实名版本、数据库事务时间、同原 Grant 的成功发放序号、Confirmation、Operation-Id 和原输入证明。时间只表示成功保存的业务时点，不表示放卡或点击时间；失败回滚后新请求取得新时间。

发放序号在该原 Grant 的全部已保存 Delivery 中取最大值加一，首项为 1；与本次事实及阶段同事务提交。不同 Grant 的序号不比较，时间相同时仍以序号判断先后。数据库保护正数、同原 Grant 唯一及新插入值恰为当前最大值加一；不新增计数表或序列，也不把申请提交序号当发放序号。达到 bigint 上限时拒绝技术写入，不溢出或重编号。原成功回读保留原序号、人和时间，不再分配下一值。发放 HMAC 使用 `input_proof` 用途及封闭域 `nucleus/badge-delivery/v1`，绑定原操作者 Person、Badge、Application、成品摘要和规范 Confirmation；证明不永久保存会话凭据，密钥退役须覆盖其历史。

取消、管理员结束、原授权结束、适用编号撤销或注销先于成功保存时，发放拒绝且不回填先前放置时间。暂停或发放者失权也按当前资格拒绝。已保存的 Badge 及材料仍永久保护。系统不可用时客户端等待恢复后再点击，不设离线队列或人工补记。实体动作与数据库提交分开解释；没有“业务结局不明”终态。

## 原结果与 HTTP

请求发送前客户端保留 Operation-Id 和固定输入。原 POST 重放须有当前相应权限、同一原操作者 Person 及完全相同输入；新会话可恢复原结果，其他管理者用有权读取入口查看历史，不冒用原 POST。已经由另一个操作发放的 Badge 只显示实际 Delivery，不能称作本次成功；新发放请求返回 `409 application_closed`，不覆盖原人、时间或序号。

响应丢失时按原标识读取。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对原 Delivery。核对未完成返回 `503 outcome_unknown`，不能根据查无记录或超时判定失败。确定未提交后，按当前资格、下一序号和本次数据库时间办理；无关操作继续。

| 路由                                        | 结果                                                                        |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| `POST /workforce/applications/{id}/renders` | 有权管理者在明确失败后授权新尝试，`201`                                     |
| `POST /workforce/badges/{id}/deliveries`    | 有权者确认实际发放，成功保存返回 `200`                                      |
| `GET /workforce/badges/{id}/delivery`       | 有权者按本次 Operation-Id 读取原事实；可靠无结果为 `404 result_unavailable` |
| `GET /workforce/badges/{id}.webp`           | 凭有效短期签名读取静态无损成品字节                                          |

图片读取不生成新业务事实。JSON 成功返回标准 `code` 封套，原成功后读取权限丧失返回当前认证或权限结果，不能据此否认旧事实。依赖异常不能映射成未发放。

## 验收

覆盖批准与首 Render 同存、单提交一个 active、明确失败后有权新授权、原尝试重启接管及执行围栏。验证文件发布后提交回滚、提交未知、旧候选与新候选 ID 不混用，晚到结果在结束或编号撤销后不成为 Badge；成功 Badge 无 pending 状态且永久材料受保护。覆盖放置早于点击、保存失败不发放、一次成功发放唯一且同 Grant 序号连续、相同时间按序号、并行发放、响应丢失原结果与另一个操作已成功的区分。以运行身份验证事实引用、状态配对、禁止改删及签名图片范围。当前没有这些执行结果。
