# Workforce 配置原请求

状态：仅保留给未迁移的目录配置消费者。简化目标使用普通事务、状态查询和[统一审计](../architecture.md#审计)，不再新增配置完成记录。新工牌模板、照片与申请不接入本合同。以下原请求、重放和清理规则在对应代码及客户端完整迁移前有效，退出时保留必要历史。

Workforce 的可变配置包括目录、科室职务列表、分类规则、模板草稿、字体及照片。配置保存当前状态，删除资格由各所有者规定。完成记录保存配置写入的原请求完成，以便响应丢失后准确重放。业务配置由[目录与显示规则](directories.md)及工牌专题拥有，共同封装与核验机制见[架构](../architecture.md#完成记录)。

## 完成事实

每次配置写入都保存原完成，业务变化与完成共同成立或不成立。完成以原 Operation-Id 为身份，固定动作、非空目标、规范输入与完成时间。动作包括创建、更新、删除，科室职务列表另用整体替换。完成不保存已删除配置的副本，不因重放而重建对象。完成不可修改，只按下述保留规则清理。

目标标记本次受影响对象。现存对象的更新或删除用其 ID。科室职务列表整体替换用路径中的科室 ID，规则配置用人员细分类整数代码。新对象创建时用所属集合或父对象的固定标识，具体新内容由规范输入区分。被删对象仍能匹配原目标。

创建的规范输入取完整创建正文，修改取 expected 与 replacement，删除取被删对象的 expected。科室职务列表的两份列表与顺序无关。输入比较不包含当前会话或此次 HTTP 请求标识。后续格式调整必须保持已有完成的可比性。创建字体仍核对原文件摘要，创建照片仍核对上传原字节摘要。材料核对不能代替原请求匹配。目录同名冲突返回 `409 name_in_use`，同名不能证明原创建完成。

## 重放与条件写入

在当前会话及对应配置权限成立后，按 Operation-Id 查询原完成。其他当前有权者也可重放同一目录原请求，原办理人不同本身不构成冲突。命中时比较动作、目标与规范输入，任一项不同返回 `409 request_mismatch`。完全相同则返回原完成，不再次执行，即使别人后来删除对象或把状态改回 expected。对象仍存在时返回当前有权可见的内容；对象已删除时返回成功封套与 `deleted: true`。

没有保留原完成的请求使用条件幂等：当前等于 expected 则执行并追加记录；当前已是目标状态则不改配置，但追加本次完成记录；其余为 `409 data_changed`，不覆盖期间变化也不追加记录。两种成功均返回所属动作的成功状态。原完成清理后，同一 UUID 也按当前条件判断；命中保留完成时仍返回原结果。

原完成保留期间，该顺序保护两类往返变化：创建条目或模板草稿后被删除，原请求重放仍返回原完成而不创建新 ID；他人把修改对象的状态改回 expected，原请求重放也不执行第二次。相同 Operation-Id 换目标或换 replacement 必须返回 mismatch，不能返回旧对象的成功。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对完成记录。

## 清理

完成记录至少保留 24 小时，期间承担原请求防重放。恢复与执行责任结束后，按[共同保留边界](../architecture.md#原操作与恢复)清理，不另存永久标识。清理只删除到期的原完成，保留配置及其他未到期完成。原标识复用产生的新完成不受旧完成清理影响。

## 验收

原创建、更新、删除与列表替换遵守相同的原请求匹配规则。规则后来停用后，原请求仍可回读。配置变化与完成保持一致，HTTP 等待者退出不取消已接纳工作。提交结局不明时仍按原标识恢复。
