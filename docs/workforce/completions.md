# Workforce 配置原请求目标设计

状态：目标设计，尚未实施。Workforce 的目录、科室职务列表、分类规则、模板草稿、字体及照片等可变配置由各自表保存当前状态；创建后可删除，修改原地进行。`workforce.completions` 记录这些配置写入的原请求完成，以便响应丢失后准确重放。业务配置仍由[目录与显示规则](directories.md)及工牌专题拥有。

## 完成事实

每次配置写入在同一事务中追加完成记录，业务变化与记录共同提交或回滚。完成表只有五个非空列：`operation_id` UUID 主键、`action` 封闭动作码、`target` 非空规范文本、`input` 规范输入的 SHA-256、`created_at` 本次事务时间。它是技术完成事实，原 Operation-Id 即其身份，不另设 ID；不保存已删除配置的副本、原输入明文、HMAC 或密钥引用。运行身份只能 SELECT、INSERT 与受保护的清理 DELETE，不能 UPDATE。

`target` 标记本次受影响对象，不能为空。现存对象的更新或删除用其 ID；科室职务列表整体替换用路径中的科室 ID；规则配置用人员细分类整数代码的规范文本。新对象创建时用所属集合或父对象的固定标识，具体新内容由 `input` 区分。`target` 采用文本是因为规则主键并非 UUID，且被删对象仍须匹配；它不以外键指向可删除配置。

`input` 对创建取完整创建正文的规范表示，对修改取 expected 与 replacement 的规范表示，对删除取被删对象的 expected。摘要是普通 SHA-256：这些配置内容不作为秘密，摘要仅用于同键输入比较。创建字体时仍核对原文件摘要、创建照片时仍核对上传原字节摘要；各自对象行的 `operation_id` 和材料摘要不替代完成表。目录条目的同名冲突由名称唯一约束返回 `409 name_in_use`，不能用同名推断原创建结果。

## 重放与条件写入

在当前会话及对应配置权限成立后，按 Operation-Id 查询完成记录。命中时必须同时比较 `action`、`target`、`input`；任一项不同返回 `409 request_mismatch`。完全相同则返回原完成，不再次执行，即使别人后来删除对象或把状态改回 expected。对象仍存在时返回其当前有权可见的内容；对象已删除时返回成功封套与 `deleted: true`，不重建对象，也不伪造被删内容。

没有保留原完成的请求使用条件幂等：当前等于 expected 则执行并追加记录；当前已是目标状态则不改配置，但追加本次完成记录；其余为 `409 data_changed`，不覆盖期间变化也不追加记录。两种成功均返回所属动作的成功状态。原完成清理后，同一 UUID 也按当前条件判断；命中保留完成时仍返回原结果。

原完成保留期间，该顺序保护两类往返变化：创建条目或模板草稿后被删除，原请求重放仍返回原完成而不创建新 ID；他人把修改对象的状态改回 expected，原请求重放也不执行第二次。相同 Operation-Id 换目标或换 replacement 必须返回 mismatch，不能返回旧对象的成功。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对完成记录。

## 清理

完成记录至少保留 24 小时，期间承担原请求防重放。恢复与执行责任结束后，按[共同保留边界](../architecture.md#原操作与恢复)删除，不另存永久标识。清理只删满足条件的完成记录，不删配置；使用 Workforce 所属的后台工作槽位和共同写入协调。删除核对绑定原完成记录，避免标识复用后误删新的完成。

## 验收

以运行身份验证五列非空、封闭 action、无 UPDATE、最后一份完成证据的删除保护及业务写入与完成记录共同提交。覆盖同键换动作、目标、expected 或 replacement；科室职务列表目标为科室 ID、规则目标为整数代码；创建目录项和模板草稿后删除再重放，以及状态改回 expected 后重放。验证新键的当前已达目标状态、冲突状态、丢响应与未知提交；验证清理不影响配置。当前没有这些执行结果。
