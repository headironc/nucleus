# Access 权限目录目标设计

两组固定目录与四个系统角色的权限由[初始化](../operations/access.md#初始化)建立。机构角色维护及读取使用准确维护权；机构更换、候选、可选角色和指派历史使用准确指派权。Workforce 自定义角色维护按明确来源使用领域维护权或机构跨范围管理权；权限代码目录保持固定。本文拥有权限代码、归属和目录一致性；各能力拥有实际办理规则。

## 范围与用权

机构角色只能组合机构权限，Workforce 角色只能组合 Workforce 权限。每项权限只授权其列出的办理范围，不推导另一项权限。本人办理依据当前账户及对应业务条件，不能把它写成默认角色的权限。管理入口还须复查当前会话、账户、适用授权、角色及目标关系；取得权限本身不免除等级或目标确认要求。

机构与 Workforce 分别拥有封闭目录，每项权限属于且只属于一组；角色权限及其历史不能引用另一组的代码。权限集合按精确代码及所属组核对，不以字符串前缀推断归属。对外权限代码与目录保持一致，运行期不能改写目录。

| 机构代码                           | 授权范围                                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `institution.roles`                | 维护较低等级的机构角色并读取定义与变更历史                                                                                      |
| `institution.assignments`          | 更换较低等级目标的机构角色并读取指派历史                                                                                        |
| `institution.workforce`            | 读取全部当前 Workforce 角色定义，维护角色，为较低机构等级的账户建立授权或更换领域角色；不授予领域历史、业务、邀请、暂停或结束权 |
| `institution.accounts`             | 暂停、恢复、注销较低等级目标的账户，协助换号并读取必要核实信息及当前可管理账户的状态历史                                        |
| `institution.corrections`          | 办理与读取范围见[实名更正](../identity/correction.md)                                                                           |
| `institution.affiliations.read`    | 读取他人政治面貌；范围见[人员政治面貌](../center/affiliation.md)                                                                |
| `institution.affiliations.correct` | 更正他人政治面貌；不推导查看权，范围见[人员政治面貌](../center/affiliation.md)                                                  |
| `institution.articles`             | 网站内容的文章权限，范围见[网站公开内容权限](#网站公开内容权限)                                                                 |

| Workforce 代码          | 授权范围                                                          |
| ----------------------- | ----------------------------------------------------------------- |
| `workforce.roles`       | 维护较低等级的 Workforce 角色，读取全部当前定义及全部角色变更历史 |
| `workforce.assignments` | 更换较低等级目标的领域角色并读取授权及指派历史                    |
| `workforce.admission`   | 直接准入，管理本人创建的邀请码并读取本领域准入结果                |
| `workforce.suspension`  | 暂停及恢复较低等级目标的领域授权并读取状态事实                    |
| `workforce.termination` | 结束较低等级目标的领域授权并读取结束历史                          |

| `workforce.production`  | 读取当前可制作成品并现场制作；不逐次登记打印                      |
| `workforce.delivery`    | 发放、原结果恢复并读取相关申请、成品与发放历史                    |

政治面貌的查看与更正分别组合进机构角色。角色定义、指派和权限变更历史只保存权限代码，不保存资料值。普通业务身份不因能运行运维工具而取得目录权限。

Scheduling 的具体权限代码尚未定义。Rota 已确认的 D-034 要求由 Nucleus 的全局 `Permission` 目录持有代码，并按确切操作确定代码。它与本文两组目录的整合边界留待 Scheduling 接入设计；不得预造宽泛的排班管理权限。

### 网站公开内容权限

[网站公开内容](../content/publication.md)的维护权限属于机构目录，因为网站内容面向机构整体，不属于 Workforce 参与。内容维护采用以下两项权限，分别控制栏目与文章、首页编排。权限随对应内容能力交付安装。

| 机构代码               | 授权范围                                                                       |
| ---------------------- | ------------------------------------------------------------------------------ |
| `institution.articles` | 维护栏目；维护文章草稿、发布、撤回和恢复，读取草稿、版本与历史，上传和删除图片 |
| `institution.homepage` | 维护首页编排的草稿、发布和恢复，读取草稿、版本与历史，上传和删除图片           |

两项都不比较目标等级，因为内容动作不以他人为目标。按[系统角色规则](#系统角色与维护)，机构“系统管理员”持有本组全集，安装代码时须在同一维护事务补齐它的权限及变更历史；“普通账户”不持有。其他人员通过自定义机构角色取得。以后的投稿由任何正常注册账户本人办理，不是角色权限；审稿所需的权限随投稿设计确定，不为投稿单设权限领域。

## 系统角色与维护

机构“普通账户”和 Workforce“普通成员”均无权限。机构“系统管理员”与 Workforce“管理员”分别持有本组目录全集；目录增加权限时须在同一维护事务中补齐对应 full 角色及其变更历史。运行身份不能改写或删除目录，已被角色定义历史引用的代码不得删除。功能尚未交付时，目录内存在权限不意味着存在可办理入口。

权限代码在程序中用封闭枚举表示，输入反序列化、数据库取列、输出序列化共用准确映射。未知代码、跨组代码和目录与枚举集合不一致均为错误，不按前缀接纳未来权限。启动须核验两组目录的准确集合、各自唯一的默认角色以及 full 角色权限恰为本组全集；失败时不开放依赖它们的注册、准入或管理入口。

## 验收

验证目录恰为上表 8 项机构权限与 11 项 Workforce 权限。初始化建立各组 full 角色的完整历史，默认角色为空。当前定义与历史一致；启动拒绝默认角色非空、full 角色缺少本组任一权限、未知或跨组代码。即使当前与历史同时缺少权限，也拒绝启动。运行期不能改写目录和系统角色。后续目录维护、失权与跨能力用权随实际入口验收。

内容权限随各自首个消费者纳入准确目录与系统管理员全集。分别验证文章维护者与首页维护者的入口及拒绝状态，普通账户不因注册而取得两项权限。`institution.homepage` 尚不属于安装目录，不接纳该代码的角色输入。
