# Workforce 授权生命周期目标设计

状态：目标设计，尚未实施。本文拥有 Access 为 Workforce 保存的领域授权、暂停、恢复、结束、当前状态与历史。角色和当前指派见[角色与指派](roles.md)，管理入口共同的候选与拒绝顺序见 [Access 管理 HTTP](http.md)，准入来源中的邀请码另由邀请能力拥有。Workforce 的编号和工牌按自身前提使用当前授权，不改变授权事实。

## 授权建立与当前状态

每人每领域至多一份未结束授权，当前只有 Workforce。共同准入前提为：可用正式账户、完整实名、没有未结束的 Workforce 授权。各入口另检查自己的权限、等级、角色和明确确认；不引入在职、政治面貌或排班条件。授权可由有权管理者直接建立、本人使用邀请码接纳，或通过 `institution.workforce` 机构入口建立；直接办理者不能为自己建授权。三条来源均共同保存 Grant、首条指派及当前关系。暂停授权仍占唯一名额，重新加入必须先结束旧 Grant。

直接准入按完整手机号精确定位现有账户，只交付脱敏姓名、身份证号末四位、账户状态和当前授权状态供管理者确认；定位不建立授权，也不授予完整实名或其他资料读取权。提交在事务内重查目标、准入资格和所选角色确认；手机号改属他人或角色定义改走又改回时拒绝旧确认。Workforce 准入权覆盖全域，不按科室或人员类别分管。直接准入默认选择“普通成员”，也允许选择办理人当前有资格指派的其他角色；成功即时生效，不追溯或预约，不要求人工理由。

Grant 是不可变的建立事实，固定持有人、领域、办理人当时实名版本、持有人当时实名版本、建立时间、该人员的操作顺序与 Operation-Id。直接准入的办理人是实际管理者，邀请码接纳以邀请创建者在接纳时的实名版本为办理人，机构入口以实际机构管理者为办理人。邀请码来源另有不可变 Acceptance；没有邀请来源不写 Acceptance。原办理人后来失权或注销，不影响已建立的授权及其持有人。

授权是否结束由领域当前角色行是否存在判断；是否暂停由是否存在未恢复的暂停事实判断。状态投影只有 active、suspended、terminated，不把状态列写回 Grant。数据库提交时必须保证当前行与结束来源恰好存在一个：结束来源是同 ID 的人工 Termination，或该人员的账户注销事实。领域暂停不删除当前行，也不改变指派、申请或机构角色。账户暂停阻止用权，但不自动建立领域暂停事实。

## 暂停与恢复

暂停及恢复由当前可履职、持有 `workforce.suspension` 的领域管理者办理，办理人领域等级须严格高于目标且不能是目标本人。`institution.workforce` 不授予这项业务权。两次办理人可以不同，不要求人工理由。暂停只接受未结束且当前 active 的授权；同一授权恢复后可以再次暂停，每次暂停都取得新的 UUID ID 并永久保留事实。

每次暂停固定原 Grant、同一人员、目标当时实名版本、办理人当时实名版本、时间、人员操作顺序及 Operation-Id。一次恢复与它解除的暂停共享 ID，只能解除该次尚未恢复的暂停，不能解除后来发生的另一暂停。恢复固定同样的人员、两个实名版本、时间、顺序及 Operation-Id，不另存 Grant ID，通过暂停外键到达。恢复时间不能早于暂停时间，顺序须严格更晚。已结束授权不能再暂停或恢复；结束时尚未恢复的暂停仍保留，不补造恢复。

暂停期间，本人业务及领域管理权停止使用；正常账户的本人退出和取消未发放申请仍可办理。其他领域与机构权限不受领域暂停影响。恢复后只按当时的账户、授权、当前角色及定义办理，不复活暂停期间已失去的权限或已结束申请。邀请码创建者暂停只使其旧邀请码暂时不可用，不因暂停本身永久作废。

## 人工结束与注销

管理员结束要求当前持有 `workforce.termination`、领域等级严格高于目标且不是目标本人。本人退出要求账户可用，不要求领域管理权限或等级；领域暂停中仍可退出，账户暂停时不可退出。两者保存同一 Termination 事实，办理人与持有人当时版本相同表示本人退出，否则表示管理员结束，不另存模式列。结束不支持追溯或预约，也不要求人工理由。

一次人工结束在同一事务插入与 Grant 共 ID 的 Termination，删除对应领域当前角色行。Termination 固定持有人、办理人版本、持有人版本、时间、人员顺序及 Operation-Id。账户注销不调用人工结束动作，也不伪造 Termination；注销核心在同一事务保存注销事实并删除该人员全部领域当前角色行。结束不补造角色更换或暂停恢复，不撤销登录会话或其他领域授权；未发放工牌申请停止继续办理，历史材料仍按所有者规则保留。

结束后旧 Grant、指派、暂停和恢复历史均永久保留。邀请码创建者的授权结束使其旧邀请码永久作废，但已接纳者的授权独立持续，已消耗的累计名额不返还。本人退出后重新加入建立全新 Grant 与申请；旧历史不能成为新账户使用旧授权的凭据。注销后同号新注册属于新人员，不继承旧领域历史和用权。

## 存储与原结果

目标结构为 `access.grants`、`access.suspensions`、`access.resumptions` 和 `access.terminations`。Grant 八列为 `id`、`person_id`、`domain`、`granted_at`、`operator_id`、`revision_id`、`sequence`、`operation_id`；暂停八列为 `id`、`grant_id`、`person_id`、`operator_id`、`revision_id`、`suspended_at`、`sequence`、`operation_id`；恢复七列用 `resumed_at` 且不存 `grant_id`；结束七列用 `terminated_at` 且共享 Grant ID。全部列非空；ID 为 UUID，时间为 `timestamptz`，顺序为正整数 `bigint`。人员及实名版本使用真实外键和同人组合引用，不能仅靠程序比对。运行身份只能读取及受配对约束保护的插入，不可更新或删除历史。

Grant 和每个状态事实本身是永久完成依据，不另存通用回执。按 Operation-Id 查原事实、核对办理人、目标、动作和原输入，一致回读原结果；同键异输入为 `409 request_mismatch`。原成功读取优先于当前新办理资格判断，不因原 Grant 后来暂停、结束或原办理人失权而重做。新办理按当前资格和业务条件接纳。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对原事实。

授权、状态、本人当前或最近一份授权及历史的读取必须在同一决定性快照内判断当前会话与权限。管理列表按事实时间倒序分页，支持按人员、Grant 或 Operation-Id 过滤；无权不得取得他人历史。本人最近一份授权包括已结束者，从未取得时为 `404 grant_absent`。当前角色与授权状态分开返回；结束后的当前角色为 `404 role_absent`。原结果读取返回原事实加当前派生状态，不能伪造原事实的状态字段。结构损坏或依赖失败不映射为空、无权或未授权。

授权响应含 `id`、`personId`、建立时脱敏身份、办理人、`grantedAt` 与读取时的派生状态；建立时返回授权及首条指派。暂停响应含 `id`、`grantId`、`personId`、办理人和 `suspendedAt`；恢复与其共享 ID，含 `resumedAt`；人工结束与 Grant 共享 ID，含 `terminatedAt` 与推导的 self 或 manager 模式。注销导致的结束在历史中由注销事实构造 cancellation 模式及其办理人与时间，不伪造 Termination 行。本人投影及管理投影各自按权限裁剪。

## HTTP 入口

| 路由                                                                                      | 办理或读取                                                                                  |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `POST /workforce/grants/candidates`、`POST /workforce/grants`                             | 直接准入或机构入口，精确定位并确认目标、所选角色；已有未结束授权为 `409 already_authorized` |
| `GET /workforce/grants`、`GET /workforce/grants/{id}`                                     | 按当前对应权限读取授权及历史，支持 Operation-Id 原结果过滤                                  |
| `GET /workforce/current/grant`                                                            | 本人最近一份授权及当前状态                                                                  |
| `POST /workforce/grants/{id}/suspensions`                                                 | 有权管理者暂停，成功 `201`                                                                  |
| `POST /workforce/suspensions/{id}/resumptions`                                            | 有权管理者恢复准确的暂停，成功 `201`                                                        |
| `POST /workforce/grants/{id}/terminations`                                                | 有权管理者结束或本人退出，成功 `201`                                                        |
| `GET /workforce/suspensions`、`GET /workforce/resumptions`、`GET /workforce/terminations` | 有权者读取各类永久事实及原结果                                                              |

所有写入要求当前会话和 Operation-Id，返回标准 JSON `code` 封套。管理定位时目标不存在、不是可管理对象或授权不可读为 `404 target_unavailable`；目标确认变化为 `409 target_changed`；状态不适用为 `409 state_conflict`。权限拒绝为 `403 permission_denied`，依赖故障为 `503 dependency_unavailable`，提交结局待核对为 `503 outcome_unknown`。读取失败不能伪装成空列表。

## 验收

覆盖三种建立来源、同人唯一未结束授权、暂停仍占位、并发准入冲突、当前行与首条指派共同提交。覆盖多次暂停恢复、旧恢复不解除新暂停、不同恢复者、结束时未恢复暂停保留、本人暂停中退出、账户暂停拒绝退出、管理员等级与权限、机构权限不能替代领域权。验证人工结束与注销恰有一个来源、旧 Grant 历史和邀请累计使用保留，重新加入不复活旧申请。以运行身份验证八列/七列、同人引用、无更新删除、当前行与结束来源配对；验证同键重放、异输入、丢响应和未知提交。当前没有这些执行结果。
