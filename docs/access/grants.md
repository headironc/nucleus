# Workforce 授权生命周期目标设计

本文拥有 Access 为 Workforce 保存的领域授权及生命周期：准入、本人读取、暂停恢复、自行退出、管理员结束及其历史。角色和当前指派见[角色与指派](roles.md)。管理入口共同的候选与拒绝顺序见 [Access 管理 HTTP](http.md)，邀请码来源由[邀请码](invitations.md)拥有。

## 授权建立与当前状态

每人每领域至多一份未结束授权，当前只有 Workforce。共同准入前提为：可用正式账户、完整实名、没有未结束的 Workforce 授权。各入口另检查自己的权限、等级、角色和明确确认；不引入在职、政治面貌或排班条件。授权可由有权管理者直接建立、本人使用邀请码接纳，或通过 `institution.workforce` 机构入口建立；直接办理者不能为自己建授权。三条来源均共同保存 Grant、首条指派及当前成员关系。暂停授权仍占唯一名额，重新加入必须先结束旧 Grant。

直接准入按完整手机号精确定位现有账户，只交付脱敏姓名、身份证号末四位、账户状态和当前授权状态供管理者确认；定位不建立授权，也不授予完整实名或其他资料读取权。提交在事务内重查目标、准入资格和所选角色确认；手机号改属他人或角色定义改走又改回时拒绝旧确认。Workforce 准入权覆盖全域，不按科室或人员类别分管。直接准入默认选择“普通成员”，也允许选择办理人当前有资格指派的其他角色；成功即时生效，不追溯或预约，不要求人工理由。

Grant 保存固定准入资料和已封印的当前状态。固定资料包含持有人、领域、来源（domain、institution 或 invitation）、双方当时实名版本、建立时间及 Operation-Id。直接准入和机构入口固定实际管理者；邀请接纳固定创建者在接纳时的实名版本。邀请来源另固定原邀请 ID，并共同保存不可变 Acceptance。原办理人后来失权或注销，已建立的授权仍独立持续。

当前状态拥有最后指派、当前角色、未恢复暂停、明确结束来源及准入权限 epoch。首条指派使用 Grant 顺序 1；更换、暂停、恢复、结束及角色失权投影共同推进该 Grant 的连续顺序。五类 Grant 事件退出个人事件索引。重新加入建立新的 Grant，并从顺序 1 开始。封印、锚定及永久记录沿[状态历史机制](../architecture.md#状态历史模块)共同提交。

授权状态为 active、suspended 或 terminated：已有结束来源即为 terminated；未结束且存在尚未恢复的暂停为 suspended；其余为 active。未结束的授权恰有领域当前角色，结束时同时失去当前角色。结束来源优先是同一 Grant 的人工结束；没有人工结束时是该人员的账户注销。先退出再注销保留两个独立事实，注销不替换旧 Grant 的原结束来源。领域暂停不移除当前角色，也不改变指派、申请或机构角色。账户暂停阻止用权，但不自动建立领域暂停。

## 暂停与恢复

暂停及恢复由当前可履职、持有 `workforce.suspension` 的领域管理者办理，办理人领域等级须严格高于目标且不能是目标本人。`institution.workforce` 不授予这项业务权，机构等级也不参与比较。两次办理人可以不同，不要求人工理由。暂停只接受未结束且当前 active 的授权；同一授权恢复后可以再次暂停，每次暂停都取得新的 UUID ID 并永久保留事实。账户暂停中的目标仍可被暂停或恢复领域授权，其账户暂停与旧会话撤销保持。

每次暂停固定原 Grant、同一人员、目标当时实名版本、办理人当时实名版本、时间、历史顺序号及 Operation-Id。一次恢复与它解除的暂停共享 ID，只能解除该次尚未恢复的暂停，不能解除后来发生的另一暂停。恢复固定同样的人员、两个实名版本、时间、顺序及 Operation-Id，经所属暂停到达 Grant。恢复时间不能早于暂停时间，且在暂停之后办理。已结束授权不能再暂停或恢复；结束时尚未恢复的暂停仍保留，不补造恢复。后续结束或注销在暂停之后；该暂停已有恢复时，也在恢复之后。

暂停期间，本人业务及领域管理权停止使用；正常账户的本人退出和取消未发放申请仍可办理，本人当前角色仍可读取。其他领域与机构权限不受领域暂停影响。暂停保留成员关系、指派、账户、会话和机构角色，继续占用授权名额。恢复后只按当时的账户、授权、当前角色及定义办理，不复活暂停期间已失去的权限或已结束申请。邀请码创建者暂停只使其旧邀请码暂时不可用，不因暂停本身永久作废。

## 人工结束与注销

管理员结束要求当前持有 `workforce.termination`、领域等级严格高于目标且不是目标本人；机构权限不授予该动作，机构等级也不参与比较，账户暂停不阻止目标被管理。本人退出要求账户可用，不要求领域管理权限或等级；领域暂停中仍可退出，账户暂停时不可退出。结束记录明确固定 self 或 manager 模式，并核对模式与双方身份。结束不支持追溯或预约，也不要求人工理由。

一次人工结束与 Grant 共 ID，在同一办理中移除领域当前角色。结束事实固定持有人、办理人版本、持有人版本、时间、历史顺序号及 Operation-Id。账户注销不经过人工结束动作；注销导致的结束以注销为来源，不记作本人退出或管理员结束，注销在同一办理中移除该人员全部领域当前角色。结束不补造角色更换或暂停恢复，不撤销登录会话或其他领域授权；账户、会话和机构角色保持。未发放工牌申请停止继续办理，历史材料仍按所有者规则保留。

结束后旧 Grant、指派、暂停和恢复历史均永久保留。邀请码创建者的授权结束使其旧邀请码永久作废，但已接纳者的授权独立持续，已消耗的累计名额不返还。本人退出后重新加入建立全新 Grant 与申请；旧历史不能成为新账户使用旧授权的凭据。注销后同号新注册属于新人员，不继承旧领域历史和用权。

## 原结果

准入、领域指派、暂停、恢复与人工结束使用各自永久完成家族。共同完成记录封装规范输入及办理主体，永久 Grant 记录提供原结果。按 Operation-Id 核对办理人、目标、动作和原输入；同键异输入为 `409 request_mismatch`。原成功读取优先于当前新办理资格判断，后来暂停、结束或失权不触发重做。新请求仍核验当前身份及所选来源的基本权限。提交结局不明时沿[原操作恢复](../architecture.md#未知提交)核对完成记录及原结果，结算待定锚定。内部恢复保留首次核验的主体，不重新授权或写入。

全部 Grant 命令永久保存共同完成记录，包括邀请接纳及本人退出。规范输入固定原码或目标确认、所选角色及入口；仍被引用的封装和封印密钥须保留。准入重放固定所选来源，返回原固定身份、首条角色及当前状态。首条角色使用当次指派固定的角色变更解释，后来角色修改不改写原结果。

## 历史读取

授权、状态、本人当前或最近一份授权及历史的读取必须在同一决定性快照内判断当前会话与权限。管理列表按事实时间倒序、ID 倒序分页，支持按人员、Grant 或 Operation-Id 过滤，组合时取交集；越界页保留筛选总数并返回空数组。查询原操作没有匹配，不证明原写入失败。无权不得取得他人历史。原结果读取返回原事实加当前派生状态，不能伪造原事实的状态字段。结构损坏或依赖失败不映射为空、无权或未授权；必要事实损坏使整页失败并关闭共同接纳，普通查询失败保持接纳。

Grant 历史列表与单份管理读取只接受正常、未暂停成员的当前 `workforce.admission` 权限。读取覆盖全部等级、本人及已结束 Grant，包括退出后重新加入和账户注销前的记录。单独 `institution.workforce`、领域角色维护权或指派权均不授予该历史。双方只披露固定脱敏身份，不返回手机号、身份证号或当前账户资料。状态按本页快照派生，不将建立事实误作当时状态记录。

单份 Grant 管理读取响应为 `{ code: "ok", grant, assignment }`。`grant` 与历史列表单项投影相同；`assignment` 为该 Grant 的首条指派，包含当时完整角色，与准入原结果同形。不存在或不可读目标为 `404 target_unavailable`，失权为 `403 permission_denied`。损坏始终作为技术故障。已锚定 Grant 缺席、实际消费的首条指派或固定身份损坏均报告完整性错误；无锚定的未知 ID 不扫描其他能力的引用。邀请自身读取与启动核验拒绝孤立邀请来源。

暂停、恢复历史列表要求正常账户、未暂停的当前 Workforce 成员持有 `workforce.suspension`。结束历史列表要求同样的读取者持有 `workforce.termination`。有权办理者读取对应种类的全部历史，不按等级裁剪；范围包含全部等级、读取者本人、已结束 Grant 和已注销人员。单独机构权限及其他 Workforce 权限均不授予读取权。双方身份固定并脱敏。

结束列表包含明确保存的 self、manager 和 cancellation 三种模式。注销在共同办理中为每份未结束 Grant 保存结束记录，固定原注销、双方身份、时间及 Operation-Id，并推进该 Grant 的顺序。结束项以 Grant ID 作为 `id`；原操作筛选匹配结束来源的原操作。列表按结束时间降序、Grant ID 降序分页并计数。已有人工结束的 Grant 保留原来源，后续注销不再追加第二项。

准入响应含 `grant` 和 `assignment`。Grant 含 `id`、建立时脱敏 `subject`、办理人 `operator`、`grantedAt`、`sequence`、`operationId` 与读取时派生的 `status`。两份身份各含 `personId`、`revisionId` 和脱敏姓名。Assignment 保留独立 ID、`grantId`、相同双方身份、当时完整角色、顺序、时间及原操作。

暂停响应含 `id`、`grantId`、双方固定脱敏身份、`suspendedAt`、历史顺序号及原操作。恢复与暂停共享 ID，含 `resumedAt` 与原 `grantId`，双方身份固定在恢复时的实名版本。结束与 Grant 共享 ID，含 `terminatedAt` 及明确模式。注销结束项读取固定的 cancellation 记录及其来源，不由当前账户或双方身份猜测模式。各列表项复用所属动作原结果的投影，不附加当前状态；本人投影及管理投影各自按权限裁剪。

本人最近一份授权包括已结束者，按办理先后取最近一份，从未取得时为 `404 grant_absent`。当前角色与授权状态分开返回；结束后的当前角色为 `404 role_absent`。两份身份保持建立时的脱敏版本，不随之后的实名更正改变。自行退出保留会话，本人仍可读取已结束 Grant；注销使旧本人会话失效。同手机号新注册不继承旧人员授权。

## HTTP 入口

| 路由                                                                               | 办理或读取                                                                                  |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `POST /api/v1/workforce/grants/candidates`、`POST /api/v1/workforce/grants`        | 直接准入或机构入口，精确定位并确认目标、所选角色；已有未结束授权为 `409 already_authorized` |
| `GET /api/v1/workforce/grants`                                                     | 凭当前领域准入权读取全部 Grant 历史，支持人员、Grant 及原操作筛选                           |
| `GET/HEAD /api/v1/workforce/grants/{id}`                                           | 按历史列表的准确领域准入权读取单份 Grant 与首条 Assignment，覆盖全部等级及已结束记录        |
| `GET /api/v1/workforce/current/grant`                                              | 本人最近一份授权及当前状态                                                                  |
| `POST /api/v1/workforce/grants/{id}/suspensions`                                   | 有权管理者暂停，成功 `201`                                                                  |
| `POST /api/v1/workforce/suspensions/candidates`                                    | 凭当前领域暂停权限精确确认目标和当前 Grant                                                  |
| `POST /api/v1/workforce/suspensions/{id}/resumptions`                              | 有权管理者恢复准确的暂停，成功 `201`                                                        |
| `POST /api/v1/workforce/resumptions/candidates`                                    | 凭当前领域暂停权限精确确认目标和未恢复的 Suspension                                         |
| `POST /api/v1/workforce/grants/{id}/terminations`                                  | 有权管理者结束或本人退出，成功 `201`                                                        |
| `POST /api/v1/workforce/terminations/candidates`                                   | 凭当前领域结束权限精确确认目标和当前 Grant                                                  |
| `GET/HEAD /api/v1/workforce/suspensions`、`GET/HEAD /api/v1/workforce/resumptions` | 凭当前领域暂停权读取全部暂停、恢复历史，支持人员、Grant 及原操作筛选                        |
| `GET/HEAD /api/v1/workforce/terminations`                                          | 凭当前领域结束权读取人工及注销派生结束历史，支持人员、Grant 及原操作筛选                    |

所有写入要求当前网站会话、Operation-Id 和准确 Origin，沿已认证写入预算及 8 KiB 强类型 JSON，拒绝查询参数及未知字段，返回标准 JSON `code` 封套，成功与失败均使用 `no-store` 且不设置 cookie。管理定位时目标不存在、不是可管理对象或授权不可读为 `404 target_unavailable`；目标确认变化为 `409 target_changed`；状态不适用为 `409 state_conflict`。权限拒绝为 `403 permission_denied`，依赖故障为 `503 dependency_unavailable`，提交结局待核对为 `503 outcome_unknown`。读取沿网站读取同源规则及元数据预算，不接受正文或 `entry`。HTTP 最多等待 30 秒，取消等待不取消已接纳工作。读取失败不能伪装成空列表。

准入候选正文为 `entry`、`mobile`，查询参数仅接受共同 `page`、`size`。机构入口凭准确 `institution.workforce` 权限，定位机构等级严格更低的其他账户。领域入口凭当前 Workforce 角色的 `workforce.admission` 定位其他账户，不比较机构等级；目标已有领域角色时，其等级仍须严格更低，无当前领域角色不借用其机构等级。两种来源必须明确选择，不自动互相替代。一个只读快照返回脱敏身份、当前机构 `assignmentId`、未恢复账户 `suspensionId`、最近 `grant` 确认，以及可选角色总数 `count` 和本页 `roles`；空暂停或从未准入分别返回 null。

可选定义包括两个系统角色和[当前自定义角色](roles.md#原请求与读取)，已删除角色不再出现。机构入口可选择全部 Workforce 定义；领域入口只计入等级严格更低且权限为办理人子集的定义，完整管理员角色不能经领域入口提交。列表按等级降序、名称的 `C` 排序规则、ID 排序，分页遵守[共同列表协议](../http/lists.md)。越界页仍返回完整目标确认和总数，角色数组为空。候选不赋予独立角色维护或全域历史读取权。

准入正文为 `entry`、`target`、`role`。目标包含 `accountId`、`personId`、`revisionId`、`mobile`、机构 `assignmentId`，以及可缺席的 `suspensionId`、`grant`；后两者缺席或 null 都表示已确认没有该事实。Grant 确认包含 `id` 和派生 `status`。所选角色包含 `id`、`changeId`。完整原输入重放先于新办理判断；旧目标确认返回 `409 target_changed`，旧角色确认返回 `409 role_changed`。确认匹配后，暂停账户返回 `422 account_not_ready`，已有当前授权返回 `409 already_authorized`。建立和原输入重放返回 Grant 与首条 Assignment。

`GET/HEAD /api/v1/workforce/current/grant` 只读取当前会话所属人员，不接受查询参数或正文，不要求管理权限，也不延长 Session 或保存读操作。成功返回 `200`、`code: ok` 和 `grant`，不附加 Assignment 或当前角色。原会话失效先返回 `401 authentication_invalid`；必要状态、关系或加密材料损坏返回 `503 dependency_unavailable` 并关闭共同接纳。本人保留的各份 Grant 状态均须通过封印和人员定位锚定核验；已锚定 Grant 缺席不能当成从未准入。当前状态读取不扫描任意旧变更记录，完整历史连续性由历史窗口与启动核验负责。

`GET/HEAD /api/v1/workforce/grants/{id}` 的路径 ID 在认证前解析，非法值返回 `400 invalid_input`，不接受查询参数或正文。列表查询参数仅接受 `page`、`size`、`personId`、`grantId` 和 `operationId`。Grant 列表按 `grantedAt DESC, id DESC`，暂停、恢复与结束列表分别按 `suspendedAt DESC, id DESC`、`resumedAt DESC, id DESC`、`terminatedAt DESC, id DESC` 排序；响应为 `code: ok`、`count` 和 `grants`、`suspensions`、`resumptions` 或 `terminations`。各时间均不得晚于快照的可信时间。

`POST /api/v1/workforce/grants/{id}/terminations` 的空正文表示本人退出，非空 JSON 表示管理员结束；`null` 不代表自行退出。路径是 Grant ID。成功返回 `201`、`code: ok` 和 `termination`：共享 Grant ID、双方固定脱敏身份、`mode: self` 或 `manager`、`terminatedAt`、历史顺序号及原操作。自行退出遇到陌生或他人 Grant 为 `404 target_unavailable`；对已结束 Grant 发起新操作为 `409 state_conflict`。完全匹配的原退出返回原结束，重新加入后也不影响新成员关系；同键换 Grant 或换人员为 `409 request_mismatch`。

管理结束不接受 `entry`。`POST /api/v1/workforce/terminations/candidates` 正文只含完整 `mobile`，在同一只读快照返回脱敏 `identity` 和 `grantId`，不开放独立历史读取。管理结束正文为 `target`，必填 `accountId`、`personId`、`revisionId` 和 `mobile`。管理动作先复查当前身份与准确基本权限，再核对原操作及全部输入。新办理的目标无当前成员关系、自身或等级不可管理均为 `404 target_unavailable`；可管理目标的 Grant、人员、实名版本或手机号与确认不同为 `409 target_changed`。不因机构指派变化拒绝领域动作。目标结束后重新加入，旧操作只返回原结束；新操作携带旧 Grant 则拒绝。

`POST /api/v1/workforce/suspensions/candidates` 正文只含完整 `mobile`，返回脱敏 `identity` 和 `grantId`。`POST /api/v1/workforce/grants/{id}/suspensions` 正文必含 `target`，使用共享成员确认的 `accountId`、`personId`、`revisionId` 和 `mobile`；成功返回 `201`、`code: ok` 和 `suspension`。新办理要求目标是严格较低的其他当前成员，确认未变且授权 active；已暂停授权返回 `409 state_conflict`。旧请求在退出、重新加入、实名更正或注销后只返回原暂停，不暂停新的 Grant。

`POST /api/v1/workforce/resumptions/candidates` 以完整 `mobile` 返回脱敏 `identity` 和必有的 `suspensionId`；没有未恢复暂停时返回 `409 state_conflict`。`POST /api/v1/workforce/suspensions/{id}/resumptions` 使用暂停 ID 和相同的完整 `target` 确认，成功返回 `201`、`code: ok` 和 `resumption`。当前基本权限检查后先核对原结果，新办理再核对可管理成员、目标确认和准确的未恢复暂停。目标已经结束时为 `404 target_unavailable`；暂停已经恢复或路径不是当前暂停时为 `409 state_conflict`。恢复后可再次暂停；新暂停取得新 ID，旧恢复请求只回读原事实。

## 验收

单份管理读取验证低等级准入权读取本人和高等级、已结束 Grant，以及未知 ID；身份更正、定义修改及后续角色更换均保留首条指派与固定身份；机构权、其他领域管理权、失权、领域暂停、退出及失效会话分别拒绝。实际消费的首条指派、封印密钥、身份引用、加密材料、未来时间或 Grant 状态损坏返回完整性错误。孤立邀请码引用由邀请读取及启动核验拒绝。单份结果、历史列表单项和准入首条 Assignment 同形。

结束列表核对三种模式的固定双方身份、结束时间、顺序和原操作，注销不记作人工结束；准确权限覆盖全部等级和本人，机构权限、其他领域权限、领域暂停及账户暂停分别拒绝；人员、Grant、原操作及其交集筛选、跨来源分页、越界页和同时间 ID 排序均成立；注销操作命中派生项，原准入操作不命中；先结束再注销保持原来源；较早 Grant 缺失自身结束时不得由后来的注销代为推导。

暂停、恢复与 Grant 历史列表分别验证准确权限、全部等级及本人范围，领域暂停、账户暂停、退出、失效会话及其他权限的读取者被拒绝；退出、重新加入、实名更正和注销后双方固定身份及原事实不变。计数与取页共用快照；后续锚定冲突时整次重读，按新权限与事实重新判断，无冲突时可交付原快照。必要事实损坏整页失败并关闭接纳，普通查询故障恢复后可重新读取；取消、超时和收尾失败不交付半页；满页读取的查询次数不随人数线性增长。

准入验证两种来源与邀请来源的完整配对、系统角色选择、领域入口拒绝完整管理员角色和权限超出的角色、原确认冲突、角色确认优先、并发两份确认、同键重放、异输入、两种基本权限并存时换入口重放拒绝、注销、重启及办理人注销后的原授权保留；同级领域管理者不能互查候选，直接办理也在旧确认判断前遮蔽目标。提交丢响应、确定回滚、恢复失败、取消等待后的排空，以及办理人会话撤销先于内部恢复时，均只保留一次准入；办理人实名版本缺失使恢复结局保持未知并关闭写入接纳。

退出、管理结束、暂停与恢复分别验证账户、会话和机构角色保持，固定身份经实名更正仍可回读，重新加入后的旧请求不影响新成员关系；同级、自办、错误版本、损坏的完成记录、非法时间、重复动作及半份提交被拒绝；办理人或目标退出、账户暂停排在管理动作前时锁后复查拒绝；提交故障与会话撤销后的恢复保持一次原结果；较旧状态事实损坏不能由新 Grant 遮蔽，仅被旧事实引用的密钥缺失时启动与原请求拒绝。HTTP 覆盖同源、空正文、路径类型、强类型与正文限制、脱敏候选与结果、状态冲突、无 cookie 副作用及 OpenAPI。自定义管理角色暂停恢复后的实际用权交错由角色消费者验收；邀请码的证据见[邀请码验收](invitations.md#验收)。
