# Access 管理 HTTP 目标设计

状态：目标设计，尚未实施。本文拥有角色、指派、直接准入与授权生命周期管理入口共同的候选身份、入口选择和拒绝顺序。具体业务资格、结果字段与历史仍由[角色与指派](roles.md)、[授权生命周期](grants.md)和[邀请码](invitations.md)拥有。普通请求的标识、JSON 封装和应用码见 [HTTP 入口](../http/api.md)。

管理入口要求当前会话和合法 Operation-Id；传递 cookie 或 Bearer 的方式不授予管理权。JSON 拒绝未知字段，普通正文最多 8 KiB。角色和指派使用所属资源路径，Workforce 写入以正文 `entry=domain` 或 `entry=institution` 明确选用领域或机构管理资格，服务端只按所选入口校验相应权限和等级，不自动择优。读取入口不带 `entry`，满足该读取列出的任一种当前权限即可。机构入口的 `institution.workforce` 不成为领域暂停、恢复、结束或业务办理权。

手机号候选只作完整号码的精确定位，并返回办理者有权确认的对象；身份部分固定账户 ID、人员 ID、当时实名版本 ID、脱敏姓名及 `idNumber: { suffix }`。角色更换另确认目标当前指派和角色版本；领域目标还确认原 Grant。授权建立另确认账户和授权状态及选定角色。目标本人、等级不在可办范围或身份不可披露时，候选与未命中一致返回 `404 target_unavailable`。提交按原固定目标、原版本与当前资格复查；定位号码转属他人、目标实名或指派改变返回 `409 target_changed`，选定角色删除或变更返回 `409 role_changed`。候选不授予完整身份证号或无关历史。

同一写入请求的判定顺序如下；不适用的条件跳过，可靠原成功先于新办理的字段和状态判断回读：

1. 校验请求标识、路径 ID 与 JSON 格式，非法为 400。
2. 校验当前会话与账户，失败为 401；再校验所选入口的基本权限，失败为 403。
3. 查同键原事实，匹配则回读原结果，异输入为 `409 request_mismatch`。
4. 校验新办理字段，非法为 422；检查路径对象和披露范围，不可用为 404。
5. 比对目标确认及选定角色变更，分别为 `409 target_changed` 与 `409 role_changed`。
6. 比较本人、双方等级、选定权限集合与系统角色边界，越权为 403。
7. 建立授权时目标账户不适用为 `422 account_not_ready`；已有未结束授权或动作状态不适用为 409。角色名称冲突、仍在使用或定义不变分别使用所属角色的稳定应用码。
8. 必要事实或时钟不可靠为 `503 dependency_unavailable`；提交结局未查明为 `503 outcome_unknown`。

此顺序不把数据库异常伪装成查无目标或业务冲突。角色与授权的结果读取仍按当前权限裁剪；列表按 Operation-Id 过滤时可靠无结果返回总数 0 和空数组，不把它解释成原事务失败。精确路径、成功状态和专用结果形状见各所有者文档。

验收逐步注入同时存在的无会话、无权、原成功、异输入、无效字段、隐藏目标、旧确认、等级不足、状态冲突及依赖失败，检查只暴露该顺序允许的结果。验证 domain 与 institution 入口不能互相偷用、候选不泄露不可办对象、同键原完成不会被后来变化覆盖、未知提交保留原定位。当前没有这些执行结果。
