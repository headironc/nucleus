# Access 角色与指派目标设计

本文拥有角色定义、等级、指派与历史，权限代码归[权限目录](capabilities.md)，管理入口见 [Access 管理 HTTP](http.md)。四个系统角色、完整创建及权限历史和首条机构指派由[初始化](../operations/access.md#初始化)建立；网站 [R2 注册](../identity/registration.md)建立机构普通账户的首条指派；[准入](grants.md#授权建立与当前状态)建立首条领域指派。

## 业务结果与不变量

机构与 Workforce 各自定义角色，不能跨范围组合权限或比较等级。角色由名称、本组权限集合和 1 至 1000 的整数等级组成，等级越大越高。较高等级本身不授予权限。机构“普通账户”和 Workforce“普通成员”各为等级 1、无权限的默认角色；机构“系统管理员”和 Workforce“管理员”各为等级 1000、持本组目录全集的 full 角色。其他角色为等级 2 至 999 的自定义角色，可以同级，同级不能互相管理。四个系统角色不可由业务入口修改或删除。

每个正式账户恰有一个当前机构角色；每份未结束 Workforce 授权恰有一个当前领域角色。不在角色外逐人授予权限，也不给角色预设失效期。注册在开户事务内建立“普通账户”的首条指派；领域授权建立时一并建立选定角色和首条指派。账户注销终结机构 Holder 的用权资格，并保留墓碑；领域授权结束移除相应当前关系。两者不记作角色更换，历史永久保留。账户暂停阻止两组用权，领域暂停只阻止相应领域用权；恢复按当时的当前角色及定义判断。重新注册是新人员，重新取得“普通账户”。

首次系统初始化由运维操作者以本人完整实名资料建立人员、实名版本及账户。同一事务建立四个系统角色及创建历史，并将本人首条机构指派设为“系统管理员”。之后该角色的指派与换下仍只由 [Access 运维动作](../operations/access.md)办理。初始化与停机指派使用运行身份，经同一应用执行器办理。普通 HTTP 不开放这两类停机动作。

角色定义是活引用。修改后全部当前持有人立即按新定义用权，未使用邀请码也按当前定义重新判断；已完成办理和当时的权限历史不能被改写。指派整个角色，不把角色权限复制成个人当前授权。当前用权只从事务内复核的账户、适用领域授权、当前角色及其定义推导，机构权限与领域权限不能互换，不能缓存成跨事务授权令牌。

## 管理资格

机构角色维护要求 `institution.roles`，机构指派要求 `institution.assignments`；领域内角色维护要求 `workforce.roles`，指派要求 `workforce.assignments`。维护与指派权分别判断，不能互相代替，也不能使办理人取得所选角色的业务权限。办理他人不得以本人为目标；办理人当前等级必须严格高于对象同范围等级，不能以其他范围等级替代。

创建角色时，选定等级须严格低于办理人，全部权限须由办理人当前持有。修改只能针对办理人等级严格高于的角色，修改后等级仍须严格低于办理人；新增权限须由办理人持有，移除权限不受此限。名称、等级和权限均未变化时拒绝修改。删除只针对等级更低且没有当前持有人或有效邀请码的自定义角色；历史不删除，已删除的名称可复用。

更换角色时，对象当前角色等级和所选角色等级均须严格低于办理人，所选角色的全部权限须由办理人持有。选默认角色同样如此；同角色不写空指派。领域内更换要求目标有未结束授权，允许目标处于领域暂停或账户暂停状态，但不解除暂停、重建授权或改变申请；办理者仍须具有正常资格。直接准入及邀请码选角色时也使用所选角色等级与权限包含规则。旧确认中的角色定义或目标指派即使改走又改回，也必须拒绝。

角色创建、修改、删除和更换不要求人工理由。操作必须保存实际办理人当时的实名版本，不能用当前账户资料重新解释旧记录。原办理人后来失权、退出或注销，不撤回他人合法取得的当前角色。

`institution.workforce` 是跨范围管理入口：用办理人的机构权限与机构等级判断，不要求办理人持有 Workforce 角色或所选领域权限，不比较领域等级。它可以维护 Workforce 角色，为机构等级更低且满足共同准入条件的账户建立授权及首条指派，或更换已有授权中的角色；修改角色须高于该角色全部当前持有人的机构等级，包括本人、较高及暂停持有人。它可以指派或换下 Workforce“管理员”，领域内入口不能这样办理。它不授权 Workforce 业务办理、邀请码、领域暂停恢复或结束，也不能办理本人。机构“系统管理员”的指派与换下只经停机运维入口，不经 HTTP 入口。

## 当前事实与历史

角色名称去首尾空白、按 NFC 规范化后为 1 至 64 个 Unicode 标量且不含控制字符，在同一范围的现存角色中唯一；历史中的非规范名称是损坏。系统等级在各范围唯一，默认角色无权限，full 角色恰含本范围目录全集。权限集合不含重复或跨组代码。

每次创建、修改、删除都追加一条永久变更，固定独立 UUID、角色 ID、前驱变更、对象内顺序、动作、当时名称与等级、办理人实名版本、时间、Operation-Id 和权限范围；Workforce 自定义变更另固定所选来源 `entry`。创建和修改另固定当次完整权限集合，删除变更不带权限集合，保留前驱名称和等级。首条必须是创建，删除后不能再追加或复建同一角色 ID；修改必须改变定义，同一角色时间严格递增。当前定义与权限必须等于最新未删除变更；删除后永久保留终态，角色不再供选择或用权。历史不可改写；角色删除后，旧变更仍能解释当时的定义及权限。

角色当前权限与当次历史权限分别从已封印定义和变更派生，不另行维护一份权限事实。四个系统角色的定义与创建变更在原初始化事务内一并封印。封印、状态锚定与离线写入共用[状态历史机制](../architecture.md#状态历史模块)，不改变初始化及指派的事务边界。

机构 Holder 以原账户为对象标识，保存角色、最后指派及自有顺序。领域当前资格由 Grant 的封印状态拥有，包含角色及最后指派。每个正式账户和未结束授权恰有一份有效关系。更换角色同时追加指派历史并推进所属状态。角色仍有当前持有人时不能删除，领域暂停中的成员同样算作持有人。注销为 Holder 和未结束 Grant 追加固定原注销的投影。两者推进各自顺序，保留最后指派及明确终态。暂停保留两类关系。

每条指派历史固定独立 UUID、人员、角色 ID、双方当时实名版本、时间、顺序及 Operation-Id。机构指派固定 Holder，领域指派固定 Grant；两者均固定前驱指派及所选角色的 `changeId`。历史以固定角色变更解释当次完整定义。顺序由所属 Holder 或 Grant 拥有，首条为 1；两类指派均退出个人事件索引。首条机构指派与账户建立共同保存。首条领域指派与 Grant 的双方身份、时间及操作标识一致，并使用 Grant 顺序 1。

新指派角色须不同于上一条，当前关系始终指向最后一条指派。每人每次办理至多一次更换。历史不依赖当前角色仍可用，永久保留。持有期从本条指派至下一条指派、授权结束或账户注销。当次定义由固定角色变更解释。指派的历史顺序只在同一持有者内解释，不作为全机构顺序。

机构和领域指派均以固定角色变更确认所选定义，以前驱及所属对象顺序确认先后。同一 Holder 或 Grant 的后继时间不得早于前驱，允许同刻。角色修改与指派同刻不构成冲突；角色自身的修改和删除仍须晚于最后定义。邀请原结果尚按创建时点解释角色定义，因此角色变更暂时保留邀请创建及后续办理所需的时间保护，见[邀请](invitations.md)。

当前机构授权只鉴别已封印的 Holder 和角色当前状态，结合[状态锚定](../architecture.md#锚定)拒绝回退或缺失。当前授权不扫描指派或角色历史。历史页与启动另核验永久记录、固定引用及完整前驱序列。原操作回读核验原记录的封印与字段一致性，并结算对应的待定锚定。角色定义核对权限唯一性与所属范围、名称、等级和时间。必要当前状态、历史或固定身份在相应入口鉴别失败时，关闭共同接纳。后续就绪、读取及写入均拒绝，不回退为普通角色。普通查询故障、失效会话和权限拒绝保持各自后果。存储修复须经重新启动核验，不能自行恢复服务。

## 原请求与读取

角色创建、修改、删除永久保存完成记录，以永久变更及当次权限集合作为原结果。机构和领域更换均保存共同完成记录，以封印后的永久指派及固定角色定义作为原结果。按 Operation-Id 查原事实，核对原办理人、动作、目标、确认的变更或指派，以及规范化名称、等级和权限集合；同键异输入返回 `409 request_mismatch`。原办理人按固定实名版本所属人员匹配，后来实名版本变化不改变原操作身份。成功原结果返回那次角色定义或变更、那次指派，不能用当前角色替代；后来修改、删除、更换、退出、重新加入和注销均不改写原结果。原结果在基本权限之后、新办理所需的等级、权限子集及状态判断之前读取。新办理按当前资格和业务条件接纳。数据库提交结局不明时，沿[原操作恢复](../architecture.md#未知提交)核对原事实；内部恢复保留首次核验的办理人员，后来会话撤销或权限变化不改写原完成，也不重新写入。

初始化、在线机构角色、在线 Workforce 角色、机构指派与领域指派是独立原操作家族，允许复用 UUID；准入首条指派继承 Grant 的 Operation-Id。在线角色办理永久保存封装的规范输入及办理会话主体。同一办理人员的重放按[共同完成记录](../architecture.md#完成记录)核验完整性和规范输入，其他人员的请求拒绝。修改绑定动作、目标、确认的前驱和规范定义，删除绑定动作、目标及确认的前驱。Workforce 另绑定 `entry`，即使后来同时持有两种基本权限也不能换来源重放。

在线机构指派与停机指派共用机构指派家族。两类动作永久保存共同完成记录中的规范输入及办理主体。在线输入绑定目标确认、定位手机号、原指派、所选角色及确认版本。停机输入绑定操作者手机号、目标账户与实名版本及授予或换下选择。初始化保存自身完成记录，R2 首条指派由注册完成关系确认。领域更换使用独立完成家族，规范输入另绑定 `entry` 与 Grant。仍被引用的封装和封印密钥须保留至原比较义务结束。

管理页面先取得精确手机号候选及目标确认，固定账户、人员、实名版本、定位手机号、当前指派 ID；领域指派另固定 Grant ID。写入时复查确认及当前资格。目标不在可办范围时不泄露身份，返回 `404 target_unavailable`；目标变化为 `409 target_changed`，角色变更为 `409 role_changed`。本人可读当前角色；有相应权限者可读角色、变更历史及指派历史。两类指派历史均按固定角色变更解释定义。分页按共同 HTTP 契约；原结果可按 Operation-Id 过滤读取。角色写入成功使用 `200` 或 `201` 的标准 JSON `code` 封套。

名称冲突为 `409 role_name_taken`，删除仍在使用的角色为 `409 role_in_use`，定义未变或指派相同角色为 `409 state_conflict`。名称、等级、权限代码或重复权限无效为 `422 invalid_input`。角色命令与查询共用[用例执行器](../architecture.md#用例执行器)，串行范围暂忙为 `429 rate_limited` 并带 `Retry-After`。授权或数据库依赖故障为 `503 dependency_unavailable`；提交结局仍待核对时为 `503 outcome_unknown`。仅凭维护权或指派权访问另一项入口为 `403 permission_denied`。

角色响应为 `{ id, kind, name, level, permissions, changeId }`，权限按代码排序。`kind` 从等级推导：等级 1 为 `default`、等级 1000 为 `full`，等级 2 至 999 为 `custom`；不是可写输入。创建正文为 `name`、`level`、`permissions`，修改另带确认时的 `changeId`，删除只带该确认。指派所选角色为 `{ id, changeId }`。Workforce 写入正文以 `entry=domain` 或 `entry=institution` 明确授权来源，服务端不自动择优。

### 角色办理

`POST /api/v1/roles` 创建自定义机构角色，正文仅含 `name`、`level`、`permissions`。权限集合拒绝重复及跨组代码，按代码规范排序。合法系统等级 1、1000 返回 403，范围外等级返回 422。成功和匹配重放均为 `201`、`{ code: "ok", role }`。

`PUT /api/v1/roles/{id}` 修改自定义机构角色。正文必含 `changeId` 与完整 `name`、`level`、`permissions`，不接受部分字段修改。路径和确认均按 UUID 值绑定。成功和匹配重放返回 `200`、`{ code: "ok", role }`。新办理的确认已过时为 `409 role_changed`，定义未变为 `409 state_conflict`，对象不存在为 `404 target_unavailable`。系统角色或旧、新等级不低于办理人为 403；权限只检查相对旧定义新增的差集。当前持有人下一次读取与用权立即使用新定义。

`DELETE /api/v1/roles/{id}` 删除自定义机构角色，正文只含必填的 `changeId`。成功和匹配重放返回 `200`、`{ code: "ok", change }`，change 沿用下文历史项结构，action 为 delete 且没有 permissions 字段。新办理要求目标等级严格低于办理人；仍有当前持有人时返回 `409 role_in_use`。删除使角色退出当前可用定义并清空当前权限，保留永久终态；同名新建形成不同角色，原请求仍返回原删除记录。

`POST /api/v1/workforce/roles` 正文必含 `entry`、`name`、`level`、`permissions`，共用名称、等级与集合规则。领域来源要求当前 `workforce.roles`、严格较低等级和权限子集；机构来源要求 `institution.workforce`，无需领域成员关系、领域等级或所选权限。新建角色没有持有人；同一 UUID 和名称可分别用于机构与领域。新定义立即进入所选来源的准入候选分页。

`PUT /api/v1/workforce/roles/{id}` 还要求强类型 `entry`，其余确认、完整定义、响应及错误沿机构修改。领域入口要求 `workforce.roles`，旧、新等级严格低于办理人，只检查新增权限。机构入口要求 `institution.workforce`，办理人的机构等级高于全部当前持有人。领域暂停或账户暂停不移除持有人；本人持有目标角色时也会因同级拒绝。新定义立即影响当前成员，原准入和旧角色办理仍返回当时的定义。

`DELETE /api/v1/workforce/roles/{id}` 正文必含 `entry` 和强类型 `changeId`，响应与机构删除相同。领域来源要求 `workforce.roles` 及严格更高的领域等级，删除不要求持有所删角色的权限。机构来源要求 `institution.workforce`，无需领域成员关系，也不比较领域等级。两种来源都只能删除没有当前成员且未被可用邀请码引用的自定义角色；领域暂停仍属使用中。

### 本人角色与定义列表

`GET /api/v1/accounts/current/role` 及 HEAD 读取本人机构角色，复用[当前身份](../identity/current.md)的选定 cookie、同源要求和受控 Actor，普通账户无需管理权限。返回 `200`、`code: ok` 与完整 `role`。原身份、已封印 Holder 当前状态及角色当前定义在同一决定性快照确认，不扫描指派历史。快照已确认原会话失效时返回 `401 authentication_invalid`，优先于同一快照中的角色损坏。有效身份下的必要角色事实损坏，以及数据库、解码或可信时间故障，返回 `503 dependency_unavailable`。读取不写业务事实，也不启动原操作恢复。

`GET /api/v1/workforce/current/role` 及 HEAD 返回本人当前领域角色，复用完整六字段 `role`，不附加 Grant 或指派历史。普通成员无需管理权限，机构管理权本身不代表领域成员资格。原会话、本人最近授权、当前成员关系与指派配对在同一快照确认。没有当前授权返回 `404 role_absent`；原身份失效优先返回 401，必要授权、关系或角色定义损坏返回 503 并关闭接纳。领域暂停仍可读取保留的角色，实际用权另按授权状态判断。人工结束保留账户和会话，但当前角色已缺席；注销使原会话失效。读取不接受查询参数或正文。

`GET /api/v1/roles` 及 HEAD 要求当前角色持有 `institution.roles`，单独持有指派权返回 `403 permission_denied`。有权者可读全部当前机构角色，包括系统角色、自身及更高等级角色；维护和指派的等级限制不裁剪此列表。每项返回完整六字段，不含 Workforce 角色。分页遵守[共同列表协议](../http/lists.md)，返回 `code: ok`、`count` 和 `roles`，按等级降序、名称的 `C` 排序规则、ID 排序；越界页保留总数并返回空数组。

`GET /api/v1/workforce/roles` 及 HEAD 返回全部当前 Workforce 角色定义。读取要求正常、未暂停的当前成员持有 `workforce.roles`，或当前账户持有 `institution.workforce`；满足任一路径即可，不要求客户端选择 `entry`，未知的 `entry` 查询参数按共同协议拒绝。机构路径不要求领域成员关系，领域暂停或退出不移除机构权限。账户暂停、注销或原会话失效仍阻止两条路径。列表包含系统、自身及更高等级角色，也包含办理者未持有的权限；它不扩大角色维护、指派、历史读取或业务权限。响应、排序和分页沿机构定义列表。

### 变更历史

`GET /api/v1/roles/changes` 及 HEAD 返回机构变更历史，要求准确的 `institution.roles`。参数为共同 `page`、`size`，以及可独立或组合使用的 `roleId`、`operationId`。后两项省略表示不限该条件；空值、非法 UUID、重复或未知参数返回 400。请求头 Operation-Id 只关联本次读取，查询 operationId 定位永久原操作。无匹配时返回 `count: 0`、`changes: []`，不据此判断写事务是否失败。历史按 `changedAt` 降序、ID 降序排列，包含系统创建及各等级记录，不含 Workforce。

响应为 `{ code, count, changes }`。每项包含 `id`、`roleId`、`action`、`name`、`level`、`operator`、`changedAt`、`operationId`。`action` 为 `create`、`update` 或 `delete`；前两者还包含完整 `permissions`，删除项没有该字段。删除项不表示原角色权限为空。办理人只含原 `personId`、`revisionId` 和脱敏 `name`：多个 Unicode 标量取首个再加一个 `*`，单标量为 `*`，不返回手机号或证件号。

`GET /api/v1/workforce/roles/changes` 及 HEAD 返回领域角色变更历史。读取者必须是正常账户下未暂停的当前成员，并持有 `workforce.roles`。有权者可读取全部领域历史，包括系统、较高等级和已删除角色；办理时的等级及目标限制不裁剪历史，单独 `institution.workforce` 不能读取。参数、筛选、排序、响应和固定脱敏身份沿机构历史，但集合只含 Workforce；请求不带 `entry`。

历史仅按永久变更与当次权限集合重建，当前角色删除、办理人账户结束或当前实名改变不覆盖旧事实。筛选不能隐藏所涉角色在页外的历史断裂。办理人固定版本完整鉴别后才交付脱敏投影，任一字段损坏使整页 503。身份和权限检查先于历史解码。

### 指派

`POST /api/v1/assignments/candidates` 正文仅含强类型 `mobile`，要求当前 `institution.assignments`。成功返回 `200` 与 `{ code, identity, assignmentId, role }`。identity 包含 `accountId`、`personId`、`revisionId`、脱敏 `name` 和 `idNumber: { suffix }`；role 是当前完整六字段。不存在、本人或等级不低于办理人的对象均返回 404。该 POST 只读取。

`GET /api/v1/assignments/roles` 及 HEAD 按同一指派权返回可选机构角色，只包含等级严格低于办理人且权限为其当前权限子集的完整定义，包括符合条件的默认角色。响应为 `{ code, count, roles }`，采用共同分页，按等级降序、名称的 `C` 排序规则、ID 排序。此入口不开放要求维护权的 `GET /api/v1/roles`。候选和可选列表都不构成提交授权。

`POST /api/v1/assignments` 正文为 `{ target, role }`。target 必含 `accountId`、`personId`、`revisionId`、规范 `mobile` 和候选的 `assignmentId`；role 为 `{ id, changeId }`。成功及匹配重放返回 `201`、`{ code: "ok", assignment }`。assignment 包含 `id`、`subject`、`operator`、指派时的完整 `role`、`sequence`、`assignedAt` 和 `operationId`。subject 与 operator 均由固定实名版本投影，仅含 `personId`、`revisionId` 和脱敏 `name`。原目标移回同一角色后，旧指派确认仍被拒绝。

`POST /api/v1/workforce/assignments/candidates` 正文为 `{ entry, mobile }`，查询仅接受共同 `page`、`size`。响应为 `{ code, identity, grantId, assignmentId, role, count, roles }`；identity 沿上述脱敏账户投影，role 是目标当前完整角色，roles 是所选来源允许的分页定义。无权或不存在的目标均不披露身份。

`POST /api/v1/workforce/assignments` 正文为 `{ entry, target, role }`。target 在机构确认字段上增加必填 `grantId`，role 仍为 `{ id, changeId }`。来源资格沿[管理资格](#管理资格)，领域入口要求 `workforce.assignments`，机构入口要求 `institution.workforce`。成功及匹配重放为 `201`、`{ code: "ok", assignment }`；assignment 沿机构七字段并增加固定 `grantId`。更换拒绝查询参数，保留原 Grant 及暂停状态，不创建新授权。

`GET /api/v1/assignments` 及 HEAD 返回永久机构指派历史，要求准确的 `institution.assignments`；单独持有维护权返回 403。有权者可读取全部机构历史，包括本人、较高等级和初始化指派；办理时的等级与目标限制不裁剪历史。读取不要求目标当前账户或角色仍可用，注销和角色删除不使历史缺席。永久 Holder 及注销墓碑仍参与历史完整性核验。

`GET /api/v1/workforce/assignments` 及 HEAD 返回永久领域指派历史。正常、未暂停的成员持有 `workforce.assignments` 时，可读全部等级的记录，范围包含本人、首条指派、已结束 Grant 和已注销人员。单独 `institution.workforce` 或 `workforce.roles` 不授予该读取权。读取不接受 `entry`。

两份指派历史的参数为共同 `page`、`size` 及可组合的 `personId`、`operationId`。省略筛选表示不限该条件；空值、非法 UUID、重复或未知参数返回 400。响应为 `{ code, count, assignments }`，每项是上述完整 Assignment。领域指派始终按 `assignedAt` 降序、ID 降序，按人员筛选也不比较不同 Grant 的顺序号。机构指派固定人员时按该持有者 `sequence` 降序、ID 降序，否则按 `assignedAt` 降序、ID 降序。无匹配返回成功空集，越界页保留总数。首条与在线指派可以复用同一 UUID，原操作筛选可同时返回两条，不能按在线家族的唯一性缩成一条。空列表不证明原写事务失败。必要历史、版本或身份损坏使整页失败，不用当前角色或当前姓名补齐。

## 客户端呈现

管理页面展示并确认修改后的完整角色定义和更换时所选角色的完整内容。`kind` 只读，页面不提供系统角色修改删除或“系统管理员”的业务指派入口；Workforce“管理员”只在机构入口可选。角色维护权不开放指派编辑，指派权不开放定义编辑。当前权限页读取当前角色，但页面状态不能代替提交事务内的复核。

## 验收

角色创建、修改与删除验证两种来源的强类型权限、规范名称、严格等级与权限子集，机构入口独立于领域成员关系；同范围重名拒绝，同键更换输入或来源拒绝；修改的旧、新等级、新增权限与完整确认，真实成员在修改后立即取得或失去权限而原准入仍返回旧定义；删除拒绝使用中（含暂停成员）的角色，移除当前定义而保留创建、指派与终态，同名重建及重启不改变旧结果。机构跨范围修改验证本人、较高及暂停持有人参与等级判断；修改与准入、机构更换、删除与准入的两种提交顺序分别得到正确结论，旧定义确认不能穿过修改。

完整性负例覆盖来源缺失或越权、等级及权限扩张、跨范围权限、孤立变更、只写历史或只写当前、同事务隐藏非法前驱、删除后追加后继、复建同一角色 ID、重复原操作和历史改写；时间先于最后定义或领域指派的修改与删除被拒绝。指派负例覆盖孤立指派、只改当前关系、完成依据缺失、旧指派、跳号、系统管理员换入换下、同角色和同一办理中的第二次更换。机构指派另验证固定角色变更、前驱及 Holder 时间回退；同刻办理不因跨对象时间相等被拒绝。提交丢响应、确定回滚、恢复失败、并发原操作，以及办理人会话撤销先于内部恢复时，都只保留一次原结果；固定办理版本损坏则保留未知并关闭接纳。

读取验证完整 JSON、组合筛选、空结果、越界页、重复和非法参数、HEAD、同源约束及 OpenAPI；单独机构资格不能读取领域历史，角色失权、领域暂停或退出、会话撤销立即影响后续请求。计数与取页使用同一快照。视图之后的锚定变化导致角色核验不符时，按[共同读取流程](../architecture.md#用例执行器)重试一次。重试完整重做身份、授权与读取，不沿用首次尝试的授权。取消、超时及收尾失败不交付半页。本人机构角色验证 Holder 缺失、跨人、不可用或封印损坏，以及角色当前定义缺失或损坏，均拒绝并阻止后续写入。指派历史损坏由历史 API 和启动核验拒绝。本人领域角色仍验证成员、指派配对及 Grant 的完整性。已撤销会话先于损坏披露。

机构更换验证精确候选与可选角色、更换到自定义和默认角色后删除旧角色、旧操作仍返回原指派和原定义、在线更换复用 R2 的 Operation UUID 时家族分离、同目标竞争只有一个新指派、双方互指有界结束、所选角色改回旧定义也不能恢复旧确认，以及目标退出不影响他人的更换资格。原结果在办理版本缺失、前驱缺失、固定角色变更错配、完成记录损坏或旧键缺失时拒绝并关闭接纳。注销墓碑、注销投影及永久指派共同保留，不能重新激活旧 Holder。
