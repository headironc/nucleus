# Workforce 邀请码目标设计

状态：目标设计，尚未实施。本文拥有邀请码的创建、调整、作废、接纳、有效性与原结果。共同准入前提由[授权生命周期](grants.md#授权建立与当前状态)拥有，Access 建立唯一 Grant。当前只有 Workforce 使用邀请码。

## 业务结果与不变量

当前可履职且持有 `workforce.admission` 的领域管理者可以创建邀请码，选择按当前等级和权限可由本人指派的 Workforce 角色。邀请码引用角色 ID，不复制角色定义；接纳时按该角色当时的定义取得首条指派。创建者身份、其领域 Grant、所选角色、初始累计容量、到期时刻和原码永久固定。更换所选角色须作废旧码并创建新码，旧接纳与名额不转移。

创建者须设置正整数累计容量和晚于创建时间的明确到期时刻；可以选择较远时刻，不提供无期限值。只有成功建立新 Grant、首条指派、当前角色并保存 Acceptance 才占用一个名额。已有未结束授权，包括暂停中的授权，不能再次接纳、换角或解除暂停。失败、候选检查及原请求重放不占名额。退出、注销和归档不返还名额；后来重新加入并成功使用邀请码再占一个名额。最后一个名额的并发接纳最多一人成功。

成功接纳不要求管理者逐人再次批准。接纳者必须有可用正式账户和完整实名，满足 Workforce 当前准入前提；持有码本身不是授权。接纳保存实际持有人与创建者在接纳时的实名版本，创建者后来失权、退出或注销不撤销既有接纳者的授权。

原创建者当前仍可履职且持有准入管理权时，可以调整自己未到期且无永久不可用原因的邀请码容量或期限。调整只追加一次事实，容量不得小于累计已用数，到期时刻须晚于调整时刻，且至少改变一项。调整不能复活已到期或永久作废的码，不清空使用量。相同资格下，创建者可按 ID 查看和复制仍允许复制的原码；满额本身不禁止复制。创建者可主动永久作废自己仍可操作的邀请码，不要求理由；不能再调整或恢复。

## 秘密与保存

服务端用 CSPRNG 生成 32 字节原码，向使用者表示为无填充 Base64URL 的 43 字符，输入严格解码。原码只在请求正文、创建响应或创建者受权详情中传递，不出现在 URL、日志标签及公开列表中。`invitation_data` 使用 AES-256-GCM-SIV 封装，AAD 为域 `nucleus/invitation/v1`、邀请码 ID 与字段名 `invitation.code`；`invitation_lookup` 用独立 HMAC-SHA-256，对长度前缀域 `nucleus/invitation-lookup/v1` 与原始 32 字节码计算查找摘要。两种用途各自纳入共享密钥元数据、启动核对、停写换钥及退役检查，不复用其他摘要用途。

`access.invitations` 的全部列非空：`id`、`domain`、`person_id`、`grant_id`、`role_id`、`operator_id`、`capacity`、`expires_at`、`code`、`hash`、`key_id`、`created_at`、`operation_id`。`id` 为 UUID；`domain` 当前只允许 workforce；`grant_id` 与 `person_id`、`domain` 组合引用创建者授权，`operator_id` 与 `person_id` 组合引用其实名版本；`role_id` 保留角色匹配值，不引用可删除角色。`capacity` 为正 bigint；`expires_at` 晚于 `created_at`；`hash` 恰为 32 字节，`key_id` 引用共享密钥元数据。`operation_id` 唯一，`(key_id,hash)` 唯一。新原码与全部保留的查找密钥版本下的旧码比较，避免重复。

邀请码行永久保留且不可在线修改或删除。`code` 的封装头与 `key_id` 分属不同密钥用途；只允许停写维护在保持明文不变的前提下重加密或重算后同事务切换。`access.adjustments` 只追加 `id`、`invitation_id`、`capacity`、`expires_at`、`operator_id`、`adjusted_at`、`operation_id`；同一邀请码内调整时间严格递增。当前容量和期限取最近调整，没有调整时取创建值。`access.withdrawals` 用邀请码 ID 作为主键和外键，另存创建者实名版本、`withdrawn_at` 和 `operation_id`，一个码至多主动废止一次。三表的操作标识均为 UUID 且唯一，时间为 `timestamptz`，操作者版本须证明属于原创建者。

`access.acceptances` 只有与 Grant 共享的 `id` 及 `invitation_id`，两列均非空且有外键。Grant 拥有接纳人、接纳时间、原操作和准入责任人的版本；同一事务建立 Grant、首条指派、当前角色与 Acceptance。配对约束验证领域、创建者身份、角色及累计容量。运行身份只能读取并受约束保护地插入永久事实，不可更新或删除。查询索引支持按所选角色判断在用、按邀请码统计接纳、按调整时刻读取当前值及按 Operation-Id 回读结果。

## 当前可用性

邀请码不保存可变作废状态，每次在决定性快照内推导全部原因：

| 原因                | 性质 | 判断                                                       |
| ------------------- | ---- | ---------------------------------------------------------- |
| `expired`           | 永久 | 当前时刻达到当前到期时刻                                   |
| `withdrawn`         | 永久 | 存在主动废止事实                                           |
| `grant_terminated`  | 永久 | 创建者原授权人工结束                                       |
| `account_cancelled` | 永久 | 创建者原授权因账户注销结束                                 |
| `admission_lost`    | 永久 | 创建后任一时刻，创建者所持领域角色的当时定义失去准入管理权 |
| `account_suspended` | 暂时 | 创建者账户暂停                                             |
| `grant_suspended`   | 暂时 | 创建者领域授权暂停                                         |
| `role_unassignable` | 暂时 | 所选角色当前等级或权限超出创建者可指派范围                 |
| `capacity_reached`  | 暂时 | 成功接纳数达到当前容量                                     |

`admission_lost` 根据创建后指派和角色定义的不可变历史判断。换到另一仍含准入管理权的角色不触发该原因；先失去再取得也不复活旧码。创建者授权结束或账户注销使旧码永久不可用，已接纳者的授权独立持续。仅账户或领域暂停、暂时无法指派所选角色、容量满时，原因消失后未到期且无永久原因的码可以再次使用。角色删除时，所选角色仍被未到期且无永久原因的邀请码引用，则视为在用并拒绝删除。

管理端返回全部当前成立的原因，不只返回第一项。接纳者的候选检查及接纳对不存在和任何不可用邀请码统一返回 `409 invitation_unavailable`，不泄露原因或消耗名额。创建者暂停期间不能创建、调整、复制或主动废止；此前发出的码仍按接纳时的全部条件判断。永久原因成立后不能复制、调整、废止或接纳。

## 原结果与 HTTP

每项写入使用当前会话、Operation-Id 和共同原操作规则；接纳期限来自邀请码及本次办理事实，不从 UUID 推导。创建、调整、废止分别以本表永久事实回读；接纳按原 Operation-Id 找到 Grant 与 Acceptance，核对当前持有人及提交原码对应的邀请。相同操作与原输入回读原完成，不因邀请码后来到期、作废或已满额而再占名额；同键异输入返回 `409 request_mismatch`。原创建结果仅在当前创建者仍满足复制条件时返回原码。原事实查询优先于新动作的资格判断，但读取仍要求当前会话及对应读取权。提交结局不明时按[原操作恢复](../architecture.md#未知提交)核对原事实。

| 路由                                           | 结果                                         |
| ---------------------------------------------- | -------------------------------------------- |
| `POST /workforce/invitations`                  | 创建，返回邀请及允许披露的原码，`201`        |
| `GET /workforce/invitations/{id}`              | 原创建者读取当前原因，符合复制条件才包含原码 |
| `PUT /workforce/invitations/{id}`              | 比较 expected 容量和期限并追加调整，`200`    |
| `POST /workforce/invitations/{id}/withdrawals` | 原创建者主动废止，`201`                      |
| `POST /workforce/invitations/candidates`       | 接纳者检查原码，返回可用摘要或统一不可用     |
| `POST /workforce/acceptances`                  | 接纳者取得授权与选定角色，`201`              |

候选检查不授予权限；接纳必须重新核对全部前提及容量。全部响应使用标准 JSON `code` 封套及 `no-store`，正文上限 8 KiB；列表和详情不向非创建者披露原码。依赖损坏与查询故障不能映射成邀请码不存在或不可用。

## 验收

验证创建者和所选角色的权限等级、引用角色的当前定义、三类永久事实及共享 Grant ID 的接纳，最后一个名额并发只成功一人。覆盖全部九种不可用原因、暂停恢复、失权再获权、换到另一有权角色、角色删除在用、过期后调整拒绝及容量不能小于累计使用量。验证重放和丢响应不重复占名额，原码不泄露到 URL 或日志，停写换钥前后仍能查找及按权限复制。以运行身份验证永久事实无法更新或删除、外键与配对约束；当前没有这些执行结果。
