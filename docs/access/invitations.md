# Workforce 邀请码

## 简化目标

保留邀请码、所选角色、有效期、累计容量、已用量及撤销状态。接纳时检查当前账户、参与资格、邀请可用性和可授予权限；用条件更新占用剩余额度，与建立资格及指派同事务提交。失败不消耗名额，退出不返还累计名额。

邀请只授予创建者有权授予的角色和范围，不以取消数字等级扩大授权。创建者当前无接纳权限时旧码不可用，不新增 epoch 或历史权限链。需要永久停用时明确撤销邀请码，撤销后不自动复活。

变更写统一审计，保留实际创建者和接纳者的稳定人员 ID，不新增实名版本、完成证明或封印。原码仍是秘密，日志不输出；现有加密及查找摘要在实际迁移前继续保留。

## 迁移前合同

以下章节是已有邀请与 Grant 接纳合同。旧等级、永久输入证明及历史派生状态不作为新功能目标；接纳与安全约束随对应消费者完整迁移。

本文拥有邀请码的创建、调整、作废、接纳、有效性与原结果。共同准入前提由[授权生命周期](grants.md#授权建立与当前状态)拥有，Access 建立唯一 Grant。当前只有 Workforce 使用邀请码。

## 业务结果与不变量

当前可履职且持有 `workforce.admission` 的领域管理者可以创建邀请码，选择按当前等级和权限可由本人指派的 Workforce 角色。邀请码引用角色 ID，不复制角色定义；接纳时按该角色当时的定义取得首条指派。创建者身份、其领域 Grant、所选角色、初始累计容量、到期时刻和原码永久固定。更换所选角色须作废旧码并创建新码，旧接纳与名额不转移。

创建者须设置正整数累计容量和晚于创建时间的明确到期时刻；可以选择较远时刻，不提供无期限值。只有成功建立新 Grant、首条指派、当前角色并保存 Acceptance 才占用一个名额。已有未结束授权，包括暂停中的授权，不能再次接纳、换角或解除暂停。失败、候选检查及原请求重放不占名额。退出、注销和归档不返还名额；后来重新加入并成功使用邀请码再占一个名额。最后一个名额的并发接纳最多一人成功。

成功接纳不要求管理者逐人再次批准。接纳者必须有可用正式账户和完整实名，满足 Workforce 当前准入前提；持有码本身不是授权。接纳保存实际持有人与创建者在接纳时的实名版本，创建者后来失权、退出或注销不撤销既有接纳者的授权。

原创建者当前仍可履职且持有准入管理权时，可以调整自己未到期且无永久不可用原因的邀请码容量或期限。调整只追加一次事实，容量不得小于累计已用数，到期时刻须晚于调整时刻，且至少改变一项。调整不能复活已到期或永久作废的码，不清空使用量。相同资格下，创建者可按 ID 查看和复制仍允许复制的原码；满额本身不禁止复制。创建者可主动永久作废自己仍可操作的邀请码，不要求理由；不能再调整或恢复。

## 秘密与保存

服务端用 CSPRNG 生成 32 字节原码，向使用者表示为无填充 Base64URL 的 43 字符，输入严格解码，秘密输入缓冲随解析结束清零。原码只在请求正文、创建响应或创建者受权详情中传递，不出现在 URL、日志标签及公开列表中。原码以 `encryption` 派生用途封装保存，并以 `lookup` 派生用途形成查找摘要；两者各用邀请专属的域，与其他字段和摘要隔离，并随根版本纳入共享密钥元数据、启动核对、停写换钥及退役检查。新原码与全部保留查找密钥版本下的旧码比较；重复则重新生成，连续三次重复按事实故障处理。

邀请码永久保留创建事实：所属领域、创建者及其 Grant、当时实名版本、所选角色与确认的定义、初始容量和期限、原码、创建时间及唯一 Operation-Id。所选角色仍受下文的在用保护。创建事实保持不变，停写换钥保持原码明文不变。

邀请码的当前状态拥有容量、期限、累计使用量及作废状态。创建建立首条记录；调整、接纳与作废各追加永久记录，并共同推进当前状态。调整保留办理人的实名版本、时间和唯一 Operation-Id。一个码至多主动作废一次，作废保留创建者当时的实名版本、时间和唯一 Operation-Id。操作者版本必须属于原创建者。

Acceptance 与 Grant 共享 ID，只指向所用邀请码；Grant 拥有接纳人、接纳时间、原操作和准入责任人的版本。同一办理建立 Grant、首条指派、当前角色与 Acceptance，并核对领域、创建者身份、角色及累计容量；不能缺少 Acceptance，也不能向旧 Grant 补接纳。邀请码、调整、作废和接纳均为永久事实，不可修改或删除。

同一邀请码按自身的连续顺序办理。后续事实时间必须不早于前一事实；同一可信时刻可以依次完成多项办理。每项办理保存自己的确认与结果，后来暂停、失权、改角或改定义不改写原结果。历史核验鉴别这些固定事实，不重新判断历史时点的业务资格。全局可信时间仍拒绝回拨。

调整、作废和接纳在完成前复查办理前的有效期限。期限已经达到时整笔回滚，调整不能靠延长期限通过复查。管理操作返回 `409 state_conflict`，接纳返回 `409 invitation_unavailable`。可信时钟故障仍是依赖故障；原结果重放保留原成功，不再次受期限限制。

## 当前可用性

每次读取在决定性快照内判断全部当前成立的原因：

| 原因                | 性质 | 判断                                                       |
| ------------------- | ---- | ---------------------------------------------------------- |
| `expired`           | 永久 | 当前时刻达到当前到期时刻                                   |
| `withdrawn`         | 永久 | 存在主动废止事实                                           |
| `grant_terminated`  | 永久 | 创建者原授权人工结束                                       |
| `account_cancelled` | 永久 | 创建者原授权因账户注销结束                                 |
| `admission_lost`    | 永久 | 创建后任一时刻，创建者所持领域角色的当时定义失去准入管理权 |
| `account_suspended` | 暂时 | 创建者账户暂停                                             |
| `grant_suspended`   | 暂时 | 创建者领域授权暂停                                         |
| `role_unassignable` | 暂时 | 所选角色当前等级或权限超出创建者可指派范围                 |
| `capacity_reached`  | 暂时 | 成功接纳数达到当前容量                                     |

邀请码固定创建者的原 Grant 及创建时的准入权限 epoch。指派或所持角色定义使创建者失去 `workforce.admission` 时，该 Grant 推进 epoch，旧码出现 `admission_lost`。后来重新取得权限也不复活旧码。换到仍含准入权的角色、单独暂停或恢复均保持 epoch。暂停期间发生的真实失权仍推进 epoch；Grant 结束后不再接收角色失权投影。创建者换走后，原角色的后续变更不影响新持有期。

当前可用性读取原 Grant 的封印状态并比较 epoch。历史接纳、调整和作废保留自己的历史依据，后来失权不撤销原成功。创建者授权结束或账户注销使旧码永久不可用，已接纳者的授权独立持续。仅账户或领域暂停、暂时无法指派所选角色、容量满时，原因消失后未到期且无永久原因的码可再次使用。容量按永久 Acceptance 累计，不因 Grant 结束或注销减少。

角色删除时，所选角色仍被未到期且无永久原因的邀请码引用，则视为在用并拒绝删除；判断时点是删除时间。邀请码到期、作废、创建者授权结束、注销或失去准入权后不再阻止删除。

管理端返回全部当前成立的原因，不只返回第一项。接纳者的候选检查及接纳对不存在和任何不可用邀请码统一返回 `409 invitation_unavailable`，不泄露原因或消耗名额。创建者暂停期间不能创建、调整、复制或主动废止；此前发出的码仍按接纳时的全部条件判断。永久原因成立后不能复制、调整、废止或接纳。原码只在当前创建者仍满足复制条件时返回；失去准入权后即使重新取得也不再返回。

## 原结果与 HTTP

持码候选只披露角色名称、角色等级、创建者脱敏姓名和到期时间，另返回接纳确认必需的角色定义 `changeId`。不披露剩余容量、角色权限或原因码。不存在和任何不可用邀请码统一返回 `409 invitation_unavailable`，不占用容量。接纳必须提交候选返回的 `changeId`；可用邀请码的角色定义已变化时返回 `409 role_changed`。

每项写入使用当前会话、Operation-Id 和共同原操作规则。创建、调整及作废分别保留完整输入与永久结果；调整输入包含 expected，创建输入包含角色确认。接纳使用 Grant 的永久完成家族，封装原码及角色确认，并以 Grant、Acceptance 和首条指派回读结果。

相同操作与原输入回读原完成，不因邀请码后来到期、作废或已满额而再占名额。同键异输入返回 `409 request_mismatch`。原创建结果仅在当前创建者仍满足复制条件时返回原码。原事实查询优先于新动作的资格判断，但读取仍要求当前会话及对应读取权。提交结局不明时沿[原操作恢复](../architecture.md#未知提交)核对原完成；内部恢复保留首次核验的人员，后来的会话撤销不使原完成消失。

| 路由                                                  | 结果                                         |
| ----------------------------------------------------- | -------------------------------------------- |
| `POST /api/v1/workforce/invitations`                  | 创建，返回邀请及允许披露的原码，`201`        |
| `GET /api/v1/workforce/invitations/{id}`              | 原创建者读取当前原因，符合复制条件才包含原码 |
| `PUT /api/v1/workforce/invitations/{id}`              | 比较 expected 容量和期限并追加调整，`200`    |
| `POST /api/v1/workforce/invitations/{id}/withdrawals` | 原创建者主动废止，`201`                      |
| `POST /api/v1/workforce/invitations/candidates`       | 接纳者检查原码，返回可用摘要或统一不可用     |
| `POST /api/v1/workforce/acceptances`                  | 接纳者取得授权与选定角色，`201`              |

候选检查不授予权限；接纳必须重新核对全部前提及容量。写入沿网站身份、必填准确 Origin、已认证写入预算、8 KiB 强类型 JSON 及 30 秒 HTTP 等待，拒绝查询参数和未知字段；读取沿网站读取同源规则与元数据预算。全部响应使用标准 JSON `code` 封套及 `no-store`，不设置 cookie；列表和详情不向非创建者披露原码。依赖损坏与查询故障不能映射成邀请码不存在或不可用。

创建正文为 `role`（`id`、`changeId`）、正整数 `capacity` 和 `expiresAt`。创建者须是正常账户下未暂停的当前成员，当前领域角色持有 `workforce.admission`；单独机构权不授予创建。所选角色须是当前 Workforce 定义，等级严格低于创建者，权限为其子集。确认的定义改走为 `409 role_changed`，超出可指派范围为 `403 permission_denied`，到期时刻不晚于可信创建时间为 `422 expiry_passed`。成功及原输入重放返回 `201`、`code: ok` 和 `invitation`：`id`、`roleId`、`capacity`、`expiresAt`、`createdAt`、`operationId`、当前 `reasons`，以及仅在可复制时出现的 43 字符原码 `code`。

详情 `GET` 及 HEAD 由原创建者在当前仍是正常、未暂停成员且持有 `workforce.admission` 时读取，返回相同 `invitation` 投影与全部当前原因，拒绝查询参数与正文。其他创建者的邀请码与未知 ID 同为 `404 target_unavailable`，失去准入权为 `403 permission_denied`。他人记录即使损坏也只表现为缺席；本人必要事实或原码损坏使读取失败并关闭共同接纳，不伪装成缺席。

调整正文为 `expected: { capacity, expiresAt }`、`capacity` 和 `expiresAt`，四个值均必填；只改一项时，另一项仍提交原值。期限精度最多为微秒。成功及匹配重放返回 `200`、`code: ok` 和 `adjustment`，包含 `id`、`invitationId`、`capacity`、`expiresAt`、`adjustedAt`、`operationId`。调整先核对当前基本权限和原结果，再定位本人邀请码。其他创建者与未知 ID 为 `404 target_unavailable`；已到期、作废或其他永久原因为 `409 state_conflict`。符合管理条件后，expected 不符为 `409 target_changed`，两值均未改为 `409 state_conflict`，容量低于累计使用为 `422 capacity_below_usage`，期限不晚于调整为 `422 expiry_passed`。满额或所选角色暂不可指派仍允许调整。期限在检查后、落笔前到期时返回 `409 state_conflict`。旧操作返回自己的固定调整，即使后来已有调整、到期或作废。详情、候选、当前原因、管理资格、角色占用和接纳容量均使用当前取值；历史接纳与作废按当时的期限和累计数解释。

作废 `POST` 不接受查询参数或正文。成功 `201` 返回 `withdrawal`：共享邀请码 `id`、`withdrawnAt` 与 `operationId`。他人邀请码与未知 ID 为 `404 target_unavailable`；已到期、已作废或已有其他永久原因为 `409 state_conflict`，落笔前到期同样如此；同一原操作换邀请码为 `409 request_mismatch`。作废后原因含 `withdrawn`，原码不再返回，所选角色不再因它被占用。

候选正文只有 `code`，成功 `200` 返回 `code: ok` 和 `candidate`：`role`（`name`、`level`、`changeId`）、`creatorName` 及 `expiresAt`，不包含角色或创建者 ID；创建者姓名取同一快照内的当前实名版本。候选复查当前持码人会话、原码鉴别及邀请可用性，不预留名额，也不要求持码人拥有管理权。

接纳正文为 `code` 和 `changeId`。成功和原输入重放均返回 `201`、`code: ok`、既有 `grant` 和首条 `assignment` 投影。Grant 的 subject 固定持码人接纳时的实名版本，operator 固定创建者接纳时的实名版本。已完成原结果先于新办理判断；新办理先统一判断邀请码可用性，再核对角色确认及持有人授权，已有未结束授权（包括暂停授权）返回 `409 already_authorized`。同一持有人并发接受不同创建者的邀请码时只有一份成立。

## 验收

验证创建者和所选角色的权限等级、引用角色的当前定义、三类永久事实及共享 Grant ID 的接纳，最后一个名额并发只成功一人。覆盖全部九种不可用原因、暂停恢复、失权再获权、换到另一有权角色、角色删除在用、过期后调整拒绝及容量不能小于累计使用量。验证重放和丢响应不重复占名额，原码不泄露到 URL 或日志，停写换钥前后仍能查找及按权限复制。验证永久事实无法修改或删除，以及接纳的完整配对。

创建验证同输入重放返回同一原码，容量、到期或角色变化为请求不一致；旧定义确认、同级角色、过去到期及无成员资格分别拒绝，重启后仍可回读；自定义准入角色失去准入权后出现 `admission_lost`，重新取得权限后原结果不再返回原码且所选角色可删除；创建者退出后出现 `grant_terminated`，此后旧角色再失去准入权也不增加 `admission_lost`。详情验证第二位准入管理者看不到他人邀请码、未知 ID、机构权、失权与重新取得权限后的原因保留及原码扣留。作废验证他人、未知 ID 与机构权拒绝、重放、换邀请码不一致、再次作废的状态冲突，以及创建者失权后以旧时间作废被拒绝。

调整验证只改容量、只改期限及同时调整，创建值保持、调整追加与连续顺序；延长后越过初始期限仍可接纳与作废，满额扩容后可继续使用。覆盖同刻依次办理、真实回拨，以及调整与最后名额接纳、作废的两种先后顺序。验证资格与取值反例、旧 expected 和完成前到期回滚。

接纳验证候选的准确披露形状、统一不可用及零容量消耗；角色定义更改、已有 active 或 suspended 授权、到期及作废或满额后的重放、退出后重新加入；双方在创建后更正实名时接纳采用新版本；创建者注销不结束已接纳授权，接纳者注销不返还名额。各写入覆盖提交确认丢失、确定回滚、结局未知和取消等待后只保留一份事实。状态删除、回退、定位篡改、历史缺号、完成错配，以及损坏或缺键的邀请码、调整、作废或接纳必须使读取或启动拒绝。HTTP 覆盖各路由的固定结果、原操作、错误、强类型、Origin、缓存、无 cookie 及 OpenAPI。
