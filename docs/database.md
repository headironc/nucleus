# 数据库

本页的连接库、权限和现有运行协议描述当前实现。简化后的普通业务不新建独立恢复连接或全量历史核验，旧消费者在实际迁移前保留这些依赖。运行身份最小权限、注册事务和数据库约束继续保留；真实数据上线前完成[备份与恢复](operations/backup.md)。

本文规定数据库登录身份、结构交付、连接输入与运行权限的目标边界。业务事实、事务协调和恢复分别见[能力概览](overview.md)、[Identity 写入](architecture.md#原操作与恢复)与[基础设施](architecture.md#设置凭据与部署)。

连接库、nucleus 环境设置及密码与信任证书文件装载已交付，接口及验证见下节。独立[部署工具](engineering/deployment.md)已有迁移、密钥登记和首个正式账户初始化。C1 发码、网站短信 R1 和网站 R2 注册已接入持久结构、受管执行和提交未知核对。本人资料读取使用原 Session 和同一语句快照，默认头像链接以 `link` 派生用途签名。

## 操作安全

`nucleus` 是由 `production` 分支服务的生产数据库，禁止修改或删除。仓库同名不代表数据库目标安全。

本地 `.env` 引用的 `nexus` 是开发数据库，允许删除并重建。任何写入或破坏性命令前必须核实实际连接目标，不能只凭文件名或仓库名判断。`.env` 的维护与加载规则见[部署设置](settings.md#1-加载边界)。

编辑迁移前必须按 [SQL 迁移规则](engineering/sql.md#migrations)核实执行状态。测试与日常检查遵循[验证边界](engineering/verification.md#检查范围)。

## 已交付的连接库

`platform` crate 的 `database::Connections::new` 接收已验证的 `Settings`、`credentials::Password` 和 `rustls::RootCertStore`。构造只装配连接能力，不读取环境或文件，也不建立连接。密码接受条件沿用本文的[密码凭据](#密码凭据)。信任库必须非空，连接构造保留此项检查。TLS 显式选择 ring，仅信任传入的证书，并验证服务端主机名。连接要求 TLS，并设置空 `search_path`。用户名由调用方通过 `Settings` 显式提供，须非空且不含 NUL，保留原文。nucleus 设置转换传入配置的运行用户名；Platform 不选择身份，也不从环境读取用户名。

`database::User` 拥有用户名校验，字段私有，不反序列化部署输入。连接设置构造器与部署设置转换均调用 `User::new`。部署设置 getter、迁移执行和权限核验保留 `User` 类型；SQL 参数通过 `ToSql` 绑定。类型只保证名称格式，角色存在性与权限仍由数据库核验。

`acquire()` 从共用在线池借用会话。池由 `deadpool::managed` 管理，容量由调用方提供，至少为 2，不设固定业务上限。设置校验拒绝超过 Tokio 信号量上限或容器布局可表示范围的容量。布局检查使用包含内部槽位的 Deadpool 公共对象包装，保守防止预分配大小溢出；它不保证内存充足。部署按数据库连接预算确定容量，并为独立恢复连接、维护和其他客户端留出额度。等待、建连和复用检查各有独立预算，默认分别为 3、5、3 秒。显式值须大于零，且可形成当前平台的计时截止点；不设固定的 60 秒上限。建连预算覆盖解析、TCP、TLS 和数据库登录。各预算不等于整笔业务或 SQL 执行预算，也不证明容量满足生产负载。

每个 `Session` 共同持有 Client 与驱动任务。调用方只在事务结局可靠后归还在线会话。复用检查拒绝已结束的驱动或已关闭的 Client。随后分语句回滚残留事务、清除会话状态，并恢复空 `search_path`。任何复用失败或超时均淘汰该会话。复用检查不承担原事务结局核对。

`recover()` 使用相同 TLS 与身份规则另建连接，不占在线池名额。恢复最多一条，等待和建连分别受预算限制。许可由驱动任务持有，随驱动实际结束释放。恢复会话不缓存进在线池。该接口只交付建连能力，尚未执行恢复屏障或业务结局核对。

有疑义的在线会话通过 `Connections::discard` 永久移出池。该方法中止并等待本地驱动，保留非取消类的驱动错误。独立会话使用 `Session::terminate` 消费并收尾。持有会话的组件使用 `Session::stop(&mut self)`，取消等待后仍可继续等待原驱动。完成等待的调用报告驱动错误，后续收尾不重复读取任务结果。直接丢弃 Session 会请求中止驱动，但不提供等待结束的证明。调用方不得据此开放写入。结束本地驱动不证明数据库已经回滚，[写入协调](architecture.md#原操作与恢复)仍要求原操作锁与所属阶段的持久事实核对。

构造返回 `BuildError`，区分空信任库、TLS 配置及池构建失败。`ConnectionError` 只承担建连、建连超时与会话复用失败；池错误包装它，不递归包装外层运行错误。运行 `Error` 区分借池、等待恢复许可、连接和驱动收尾。默认 `Debug` 保留池超时阶段及后端操作，不输出连接目标、密码、SQL 或数据库 detail。原始驱动错误保留在来源链上，供受控检查。密码传入缓冲在释放时清零；驱动 Config 持有的内部密码副本没有清零保证。连接库不记录日志，也不自动重试业务 SQL。

`nucleus::database::load` 从凭据目录读取 `database.json`，再读取 `AUTHORITY` 指定的文件。nucleus 与部署入口共用 `platform::database::assembly::Settings`，它持有已校验的连接参数和证书绝对路径。入口拥有环境键、文件来源与文件读取；设置构建不读取文件。入口调用 `assembly::roots`，将 PEM 字节解析并装入 `RootCertStore`。`Settings::build` 接收已验证密码和信任库，再交给 `Connections::new`。证书解析使用 `rustls-pki-types` 的 PEM 证书迭代器，支持证书集合，忽略非证书段。PEM 格式错误和证书装载错误分别返回 `assembly::Error::Pem` 与 `Certificate`。空信任库由连接构造拒绝。装配不建立连接，不代表启动核验或应用就绪。

## C1 接纳与可信时间

认证、注册和撤销服务消费同一运行上下文的连接能力。在线写入使用 `Connections::lease`；只有明确提交或回滚才调用 `Lease::release`。取消、panic 或直接丢弃 Lease 会将会话移出池，不能交给另一请求。未知结局显式丢弃并等待驱动结束，再使用独立恢复连接。C1 依次确认共享屏障 `(1314210636, 1)` 和原操作锁，锁后另发查询核对原事实。首次接纳恢复只读取，不重新插入。原工作仍持有响应时，结论恢复按[所属阶段](identity/authentication.md#c1-阶段与外部调用)核对并保存，不因本地回写失败重复外呼。

`domain::kernel::time` 拥有事务时间与进程高水位。`Context::now` 在调用方的事务上查询时间，排队和语句共用 3 秒预算。首次观察同时读取持久高水位，后续观察只查数据库当前时间。时间查询与高水位更新共用互斥锁，业务回滚不会回退该值。错误处理及跨重启保证见[时间与个人顺序](architecture.md#时间与个人顺序)。

`domain::runtime` 拥有实例会话和后台持久化。`Context::new` 在 3 秒内建立专用连接，供停机命令及测试使用。在线进程通过 `Context::hold` 让持久化与实例锁复用同一连接。建连失败结束已创建的资源，不返回上下文。请求不使用该连接，当前身份和用例执行器也不再做读后时间确认。

后台每 7 秒发起高水位持久化，排队与提交共用 3 秒预算，预留在 10 秒窗口内。持久化只复制进程已观察的最大时间，不持业务对象锁，也不在提交时持有时间互斥锁。`security.clocks` 保留唯一记录；条件更新与触发器拒绝下降。记录缺失、下降或提交未知均关闭接纳并结束原驱动，不自动替换连接。普通业务时间查询失败由原事务回滚或结束连接，不自行关闭整个进程。

正常停止由后台任务保存最后高水位，再释放实例锁并结束驱动。停止等待被取消时，任务和已取得的错误仍受上下文管理，后续停止继续收尾。`ClockInvalid` 表示时间低于进程或持久高水位，或持久化未更新唯一记录。`ClockClosed` 表示运行上下文已经关闭时间接纳。查询故障与超时保留各自错误，诊断不回显时间值。

`nucleus::process::Application::start` 先以 `domain::runtime::Context::hold` 在专用时钟连接上取得[实例锁](architecture.md#实例锁)，取不到即以 `instance_lock` 阶段拒绝启动，再返回入口独占的 `Application`。专用连接建立、取得启动屏障与权限核验共用 10 秒预算。`domain::database::Barrier::begin` 取得独占屏障，按实际登录身份核对权限，并在同一事务把 `security.instances` 的代次加一，记入运行上下文。`Barrier` 将核验结果、屏障会话与同一上下文绑定。`domain::startup::Services::start` 在该屏障内核对密钥、可信时间、正式身份与 Access。认证、注册、暂停恢复、更正及撤销保留事实也全部通过后，才确认启动事务。校验或收尾失败均不返回可用服务。请求与后台消费者从 Services 取得已核验的用例句柄。

运行身份的全部权限只在 `domain::database::permissions` 的一份清单中声明。迁移不含运行授权：部署工具在迁移后按清单重新授予，部署入口与应用启动用同一清单双向核对实际目录，缺失或多余的权限都拒绝。比对覆盖全部非系统 schema 中的 schema、表、列、序列、函数与类型权限，包括直接、PUBLIC、继承及可通过 SET ROLE 取得的权限；列级写入与 MAINTAIN 也在范围内。下文所称某迁移“开放”的权限，指随该迁移交付的能力在清单中的条目。所有 schema 的 CREATE 权限和所有权均在拒绝范围内。运行身份还不得直接或间接成为 `pg_read_server_files`、`pg_write_server_files`、`pg_execute_server_program` 的成员，包括不继承但可切换的成员关系。这些角色拥有超出业务表授权的服务器能力，见 [PostgreSQL 预定义角色](https://www.postgresql.org/docs/18/predefined-roles.html)。核验拒绝缺失或过量权限，不自动修改授权；失败时保持接纳关闭。

运行身份只使用清单中的权限，不得转授给其他角色。核验拒绝上述六类对象权限及数据库 CONNECT 的 `WITH GRANT OPTION`，覆盖直接、继承与仅可切换的角色。撤销转授权能力后，普通授权仍可通过核验。

角色成员关系的 `ADMIN OPTION` 也属于转授权能力：运行身份自身或可切换身份持有时拒绝。对象权限按当前身份及可切换身份各自能继承的权限核对；既不能继承、也不能切换取得的权限不计入。单纯继承角色不会取得该角色的 ADMIN 能力。

核验也拒绝 `session_replication_role` 的 SET、ALTER SYSTEM 权限，覆盖直接、PUBLIC、继承与可切换角色。该参数能禁用普通触发器与外键，见 [PostgreSQL 复制角色参数](https://www.postgresql.org/docs/18/runtime-config-client.html#GUC-SESSION-REPLICATION-ROLE)。应用启动还核对当前连接的生效值，拒绝从登录默认值带入的 replica 模式。检查不修改参数或授权。

C1 拥有保留行的业务核对：包含过期行，拒绝未来开始或结论时点，并检查类型、用途、原键、密文绑定和号码摘要。阶段与调用次数、结论时点共同核对；供应商时间沿用其 2 秒容差。Message、Check 与 claim 还核对配对、阶段、原键、工作归属和事件时间。历史按每批 128 行读取和核验，每批最多 10 秒，不限制扫描总时长。核验期间保持独占屏障，全部通过后才开放接纳；失败时结束原连接并保持服务关闭。密钥核验、游标建立和关闭、启动事务确认分别限制为 10 秒，可信时间采样沿用 3 秒预算。Challenge 接纳、阶段更新及恢复事务各使用 10 秒预算，借池和恢复建连另受连接设置约束。

调用方通过 `domain::startup::Settings` 提供已交付写入用例的共享工作容量。各用例设置提供发送与注册额度。`nucleus::process::Settings` 拥有停止预算，缺省为 30 秒。`Application::stop(&mut self)` 关闭接纳和新清理选择，等待 HTTP 读取与进程持有的清理任务，再通过 `Services::drain` 等待全部请求任务，最后停止运行上下文。所有阶段受同一个进程停止截止约束。`domain::runtime` 的工作登记与任务集合持有未结束任务和已收集的失败，进程单独持有后台任务及其结束结果。就绪探测或新请求回收异常任务后，接纳保持关闭，原任务失败仍留给排空报告。取消排空等待不会丢失任务或失败；再次排空等待剩余任务结束后，一并返回此前失败。完整排空报告后才取走失败，后续停止不重复报告。`Context::stop` 结束采样，再由 `Connections::close` 关闭池及恢复入口并等待驱动结束。

运行上下文持有时钟连接的停止结果。等待其他连接结束时取消 `Context::stop`，已取得的错误仍保留在上下文中。共享句柄串行执行停止，全部连接结束后才取走结果并报告一次。后续停止不重复报告该错误。

实例锁是时钟连接上的会话级 advisory 锁 `(1314210636, 3)`。该连接开启 TCP keepalive（空闲 5 秒、间隔 5 秒、3 次探测、15 秒未确认超时），每 5 秒心跳核对本会话仍持锁。驱动退出、心跳或高水位持久化失败都关闭共同接纳，就绪随之失败，不重连也不重新取锁。失败后结束实例会话，锁随之释放；代次栅栏阻止旧进程在后来者启动后再开启事务。会话未失败时，停止等待被取消或预算耗尽都不提前释放锁。正常排空后，`Context::stop` 完成最后持久化，显式解锁并结束实例会话；部署命令结束时同样先解锁。会话异常断开时，锁要等服务器结束原后端后才释放，可能晚于客户端观察到断开。停止超时不报告正常排空，调用方必须退出。实例锁不单独证明旧数据库事务结束，遗留事务仍由启动屏障等待。

每个写事务与恢复事务经 `transaction::begin` 取得共享屏障后，对 `security.instances` 取 `FOR SHARE` 并要求代次等于本进程记下的值。代次不符时回滚该事务、关闭接纳并以已关闭接纳报告，原工作的结局留给新进程核对。部署命令取得实例锁后同样在独占屏障内推进代次，见[部署工具](engineering/deployment.md#执行入口)。代次只能逐一递增，由 `security.check_instance` 触发器拒绝其他更新；运行身份只有该表的 SELECT 与 `generation` 列更新权限。

运行身份具有 Challenge 的必要插入权限，以及 `calls`、`status`、`solved_at`、`finished_at` 的列级更新权限。启动检查拒绝缺失或超出的授权，invoker 触发器保护原事实和合法状态迁移。可信时间表和 Challenge 结构由 `V2__challenge_acceptance` 交付，手机号的嵌套类型与约束由[短信认证](identity/authentication.md#challenge-手机号保护)拥有。`V3__message_sending` 定义 Message、Check、Confirmation、claim 及 Authentication；根版本元数据表在 V1 定义。V3 只开放发码所需的查询、插入及 Message 结论列更新；认证表的运行权限由 V5 交付。运行身份对 `security.keys` 只读。

`V4__retention` 增加五张 C1 表的受保护 DELETE，以及持久序列的 USAGE。运行身份不能重设序列。期限、配对、隔离级别和共同提交保护由 [C1 保留与清理](identity/authentication.md#c1-保留与清理)拥有。应用启动和部署共用权限核验；HTTP 就绪探测继续复用持久可信时间。进程停止先结束清理选取，分别等待后台任务与请求任务，再关闭共享连接。

`V5__authentication` 定义 Account、Session 及所属封印记录，也定义 Handoff、Registration 和共同完成记录。V5 同时开放 Authentication 权限及 Check 的 `failures`、`authentication_id` 列级更新，提交约束核对猜错次数或成功消费与认证结论的配对。Authentication 的创建事务值由数据库生成；Session 的原认证、签发与撤销由封印记录绑定。R1/R2 共用的凭据创建与认证删除保护在 V7 定义。Session 失效后保留 24 小时，随后连同签发和撤销记录共同删除。Account 的退出记录及永久原结果继续保留。各实体按真实引用与期限清理；完整通用清理仍按后续切片交付。

## 正式身份初始化与启动核验

`V6__initialization` 定义 [Workforce 准入与状态办理](access/grants.md#授权建立与当前状态)的封印 Grant 状态和永久记录。Grant 合并原 Member 的当前角色与最后指派，并保存暂停、结束来源及准入权限 epoch。首条指派为对象顺序 1；后继记录与状态头共同提交。五类 Grant 事件退出个人索引。未结束授权按人员与领域唯一；结束后保留墓碑。运行身份可读取、建立及推进状态，永久记录只开放 SELECT、INSERT。创建事务值及生成列由数据库提供。纵深约束核对固定准入列、计数推进、头部配对、同人引用及投影来源，不重做授权决定。

领域指派固定所选 `entry`、前驱及角色变更。准入、指派、暂停、恢复及人工结束分别保存永久共同完成记录，规范输入使用现有封装与明文封印。角色定义失权在同一事务为受影响 Grant 追加 epoch 投影；注销为未结束 Grant 追加明确 cancellation 记录。启动核验状态与记录封印、连续顺序、投影来源及完成绑定。运行读取只鉴别所消费的状态和记录。完整权限核验同时拒绝缺失的消费列和多余的写权限。

各表的完整列和可直接声明的约束集中在建表语句，定义按真实依赖排序。Check 包含认证消费字段，Person 包含当前实名指针及个人顺序，Session 包含可缺席的 R2 完成引用；创建事务身份也由各表直接定义。Person/Revision 循环关系在双方建表后补齐剩余外键。Message 与所属校验的配对由真实单向引用、用途互斥和延迟提交约束保护。迁移保留全部真实引用和延迟提交语义。

Person、Revision 在 V2 定义，供带身份的 Challenge 与 Confirmation 真实引用；写入权限仍随消费者开放。`V5__authentication` 定义完整 Account 和 Session 引用的 Receipt。Account 包含两个号码占用、头像和微信修订、建立时点及数据库生成的创建事务身份。`V6__initialization` 建立独立默认头像和 Correction，开放实名读取并保护同人关系。在线与系统更正的两类永久完成在同一事务与更正事实配对，同一 Operation-Id 不能同时具有两类完成。Access 拥有权限目录、四个系统角色及定义历史，以及封印的 Holder、指派与注销投影。首条指派使用 Holder 的顺序 1，固定角色 `change_id`；Person 的首次记录及状态计数从 1 起。初始化与机构指派分别在 `access.completions` 中永久绑定原操作，两家族可复用 UUID。停机指派与在线指派共用机构指派家族。结构、共同提交与重放规则见 [Access 初始化与指派](operations/access.md)，停机和未知提交见[维护协议](operations/maintenance.md)。

Transfer 在 V2 定义，供新号 Challenge 真实引用。原号 `message_id` 在本人路径必填，在协助路径缺席，由约束绑定入口种类。V5 的永久 Replacement 保存换号事实，Session 撤销引用对应 Replacement。换号完成命令经执行器核对身份、原申请、最新码、占用及协助权限，共同提交 Account、Replacement、撤销集合和完成记录。V8 保留尚未迁入的申请及计错保护。原号及新号发码在接纳、许可及占用时检查当前身份；已有外呼的结论不受后来失权或申请被取代阻断。

Confirmation 仍只开放 `failures` 的列级更新。Account 按永久状态表授权，号码更新与本事务新增 Replacement 通过延迟结构约束配对。Replacement 只能插入，原申请仍按自身清理边界保留。共同完成记录封装原输入，只有带到期时间的换号完成可在期限后删除；永久替换事实继续保留。启动核验和清理边界归[手机号更换](identity/mobile.md#事实与约束)。

初始化与停机指派以运行身份经共同应用执行器办理，迁移身份只负责结构部署。运行写权限随实际消费者开放。V6 支持初始化、机构角色维护与指派保护，V7 开放 R2 开户的必要权限。真实同人外键、唯一占用、延迟提交约束及不可变历史保护共同成立。权限核验包含新增 schema 与关系。

在线启动与 `admin` 共用全量事实核验。两者在同一独占屏障内核验 Identity、Access 及其他已接入所有者。核验使用同一会话和可信时间样本，全部通过后才确认屏障事务。`admin` 不构造 HTTP 或供应商客户端。

Identity 核对全部 Account（含注销墓碑）、Session、Person 及所属记录的封印、连续顺序和同人引用，建立状态与定位锚。它还核对实名封装、规范明文、当前号码摘要、头像、更正和注销事实。保留历史按 128 行分批核对，每批查询最多 10 秒，不限制扫描总时长。Person 来源包括首次建立、更正与注销；固定视图只统一读取形状，不储存事件索引。首份实名与 Account 建立事实、更正前后版本及共同完成均须保持原来源关系。

Access 核验角色、Holder 与 Grant 的 State、Record、永久 Completion 和锚定。核验另覆盖固定目录、指派和初始化配对。Holder 与 Grant 指向各自最后一条指派；注销投影推进各自顺序，保留永久墓碑。当前用权鉴别所属状态及角色定义，不扫描历史。启动按 128 行分批核验记录连续性、头部配对与完成来源，每批预算为 10 秒，不限制总扫描时长；全部核验后才安装所属锚定。历史读取核验实际返回的永久指派、固定角色变更及身份，完整窗口另核对前驱顺序。关系查询及目录核对各有 10 秒预算，事实边界见[角色历史](access/roles.md#当前事实与历史)。

两类指派分别使用 Holder 或 Grant 顺序，以前驱及固定 `change_id` 解释历史。原结果与共同完成记录配对。启动解封完成输入并核验明文封印，重放另比较规范输入。永久比较义务及旧键保留见[指派原结果](access/roles.md#原请求与读取)。

同一启动屏障还核对全部[暂停和恢复事实](identity/suspension.md#事实约束与权限)、原手机号封装和对应完成记录。两类永久记录只开放 SELECT、INSERT，与 Account 的对象内顺序配对，不参与认证清理。管理资格与会话后果由命令判断；数据库保留真实引用及状态和新增记录共同提交的结构保护。原手机号使用既有加密用途，不新增部署键。

网站[实名更正](identity/correction.md#永久事实与共同事务)开放 Correction 的必要列 INSERT 和 Person 的 `revision_id` 列级 UPDATE。更正仍维护个人顺序；存在当前 Account 时，同一事务推进其封印状态并追加更正投影。永久事实没有运行期 UPDATE 或 DELETE。数据库保护真实版本引用、个人顺序及结构配对，受控构造负责规范值与摘要。启动核验鉴别密文、版本谱系、投影及当前占用。更正不增加部署密钥，也不参与认证清理。

核验错误保留所属 Identity 或 Access、具体规则及安全技术原因。初始化只包装它实际消费的 Access 目录核验错误。任一核验失败，启动沿原收尾路径结束屏障和运行连接，保持接纳关闭。

机构与 Workforce 角色读取复用运行身份的 SELECT 权限。执行器在同一只读 RR 快照内复查身份与维护权，并共用一个 3 秒截止。当前定义列表验证完整 State 集合后在内存中计数和分页。历史读取保留的 State（含墓碑）与 Record。它不依赖活跃角色或当前办理人账户。所涉角色的完整前驱序列按 128 行分批核对。Identity 按固定 Revision 完整鉴别后只返回脱敏办理人。事务与拒绝后果见[角色读取](access/roles.md#原请求与读取)。

`V6__initialization` 定义角色 State、永久变更和两家族永久完成。`access.roles` 保存当前定义、有序权限、当前变更、序号、版本及封印，删除只推进为 `active=false` 的永久墓碑。`access.changes` 保存完整定义或删除终态、前驱与对象内序号。`access.permissions` 与 `access.entries` 是从 State 和 Record 权限数组展开的只读视图，不再维护独立权限事实。业务输入、等级、来源、严格时间及删除资格由角色命令的纯迁移判断。

运行身份对 `access.roles` 只有表级 SELECT、INSERT、UPDATE。`access.changes` 与 `access.completions` 只授 SELECT、INSERT。两张权限视图只授 SELECT。永久 State、Record 和 Completion 均无运行期 DELETE。角色 State 只有一个延迟结构触发器 `roles_records_check`。它检查版本逐一推进、本次新增序号与本事务记录配对，以及更新保留对象 ID。当前头部与前驱的真实外键、作用域和原操作唯一约束继续保留。触发器不重做授权和业务迁移判断。

自定义变更的 `family` 由 scope 生成，并以延迟复合外键引用 `access.completions(family, operation_id)`。`institution_role` 与 `workforce_role` 各自绑定永久原操作，完成记录封装规范输入和会话主体。系统创建变更的 family 为空，由原初始化事务建立。角色实际行锁与命令判断维护严格时间及最新前驱。当前授权核验 State 与锚定。历史入口核验 Record 封印及完整前驱序列。原操作回读核验原变更，并结算锚定中的同一待定候选。Holder、指派和 Grant 仍保留现行顺序、定义时序、真实引用与业务保护。后续迁入范围见[交付顺序](engineering/delivery.md#架构内核与状态封印)。

机构指派推进 Holder 的状态与永久记录，Person 的状态与顺序保持不变。结构约束核对新指派、同人引用、所属状态头与原完成；授权、等级和等待后的资格由业务命令判断。锁顺序及写入边界见[角色与指派](access/roles.md)和[共同锁顺序](architecture.md#锁与决定性读取)。

隔离验收覆盖保留头像的后续批次、Identity 与 Access 失败分流及查询超时。测试独立观察后端连接、屏障和实例锁释放，并在恢复原数据后验证正常启动。

初始化在业务事务内取得可信时间，回滚不回退进程高水位。当前交付支持新库和可重建隔离库。密钥登记要求根版本元数据为空或与装载集合完全一致，不补齐部分登记。不要将隔离迁移通过解释为持久旧库升级验证。

`V9__affiliations` 定义 Center 的永久加密取值。运行身份只有 SELECT、INSERT，保留人员及原办理人引用、有限时间和同人时间唯一约束。普通事务在目标人员协调内核对资格、首次填写及严格时间，并与共同审计一起提交。当前值直接读取最新记录，不另存状态、序号、封印或完成绑定。启动分批核验保留信封、代码、时间与原实名版本，不建立 Center 状态锚。Center 不参与认证清理或注销删除。业务保留见[政治面貌](center/affiliation.md#存储密码与维护)。

## 当前身份与默认头像读取

`identity::current` 鉴别 Session 与 Account 的封印及锚定，再核对原 token、来源、撤销、期限和账户资格。本人查询在决定性快照重新核对身份。正常缺席的会话拒绝认证；已锚定状态丢失、被篡改或必要关系损坏属于技术失败，并关闭接纳。Handoff 的合法清理不影响会话自身核验。时间在该快照内取得并与进程高水位比较，详见[当前资格](identity/current.md#当前会话资格)。查询失败或超时结束原驱动，不把未确认结束的连接交回池。

这些 GET 不写 Identity 事实。启动仍核对全部保留会话、正式身份和冻结头像，才交出当前身份及头像服务。头像签名引用 V1 定义的根版本元数据；部署核对该表的所有权，在线身份只读。链接不形成持久业务行，默认图片字节来自已核验的嵌入素材。

## 正式注册与保留事实

`V7__registration` 定义 Attempt，并交付 Receipt、Session 注册来源及共同开户的权限和提交保护。首次开户共同建立 Person、Revision、Account 与各自创建记录、Holder 与首指派、Session 与签发记录。Person、Account 和 Holder 均从各自顺序 1 开始。Receipt 与首版 Revision 保持不可变。Receipt 仅在完整注销中删除，Account 保留墓碑；Attempt 按短期责任清理。业务条件与记录保留期由[正式注册](identity/registration.md)拥有。

R2 沿独立动作家族的原操作锁办理，先读 Receipt，再读 Attempt。开户、首指派、Session/Handoff、成功结果及凭据消费共同提交；已接纳拒绝只保存 Attempt。未知提交结束原连接后跨同一原操作锁回读，不在恢复中重新开户。注册额度在手机号协调下裁决，当前手机号与身份证号的唯一约束保留最终裁决权。

R1/R2 共用 `domain::identity::session` 的存储解码、来源与期限校验、token 绑定和固定删除操作。原结果资格、原操作协调和清理选择仍归各用例。R1 不交付或清理 R2 的会话，R2 引用结束前保留其原 Authentication。注册清理核对保留配对后，只删除已结束责任的 Attempt 或 Session/Handoff；Receipt 随账户继续保留。

Session 使用自身顺序，签发为 1，一次撤销为 2；V7 不再捕获个人事件顺序。状态、签发与撤销由各自封印保护，数据库通过延迟外键与配对触发器保证结构完整。状态开放 SELECT、INSERT、UPDATE、DELETE；签发和撤销记录开放 SELECT、INSERT、DELETE。删除权限只供所属用例清理完整短期组，启动和运行读取仍核对封印与锚定。具体约束归[会话事实](identity/session.md#建立与解码)。

两种网站退出经执行器推进 Account，追加永久 Logout 和完成记录。命令在账户协调下选择原会话或全部未撤销会话，共同推进 Session 并删除对应 Handoff。Session 撤销固定 Logout 来源；后来签发的新会话不改变原集合。短期组清理不删除 Account 的退出历史或永久原结果，完整规则见[退出](identity/revocation.md)。

账户注销保存永久 Cancellation 并推进个人顺序，同一事务将 Account、Holder 及未结束 Grant 变为永久墓碑。各对象追加固定原注销的投影并推进自有顺序。号码占用释放，固定身份仍保留。注销删除 Receipt 及所属 Session 短期组，并释放当前头像。`identity.cancelling(uuid)` 只读本事务注销来源，供尚未迁入的依赖删除保护使用，不编排业务。Receipt 删除前先移除引用它的 Session。具体锁序、恢复与验证见[账户注销](identity/cancellation.md#共同事务与在途工作)。

## 登录身份与部署

结构归部署身份，运行期业务归运行身份。两者均由部署配置指定实际登录用户名，不约定固定名称。不设第三个登录身份，也不以命令专属的 `SECURITY DEFINER` 函数编排业务。运行身份不是对象所有者或部署身份的成员；它不持有结构变更、触发器或截断权限。应用不执行 DDL。

Account 与 Session 所有者直接取得状态行锁。管理命令按 Account UUID 顺序锁定办理者和目标，分别使用共享锁与排他锁；相同账户只取一次排他锁。会话修改先协调账户，再锁定会话。R1/R2 及尚未迁入的调用方仍消费已有 `identity.lock_account`、`identity.lock_accounts` 等固定锁函数；R2 另通过 `identity.lock_registration` 锁定待注册凭据。保留函数及权限以唯一清单和实际消费者为准，随消费者迁移删除。

保留的锁函数只加锁并返回 void，不接受输入 SQL、不承担认证或写入编排。它们使用 `SECURITY DEFINER` 和空 `search_path`，收回 PUBLIC EXECUTE，只授权运行身份；启动继续核验函数属性。Account 按永久状态表授予 SELECT、INSERT、UPDATE，不授 DELETE、TRUNCATE、REFERENCES、TRIGGER 或 MAINTAIN。运行身份不能删除永久账户及历史。

部署先建立两个角色，再由高权限身份执行一次性准备：收回 PUBLIC 在数据库和 `public` 模式上的权限，分别授予连接权限，只向部署身份授予结构创建权限，并预先收回其未来函数的 PUBLIC EXECUTE 与未来类型、domain 的 PUBLIC USAGE。准备步骤不建立业务结构，也不包含密码。

结构由独立[部署工具](engineering/deployment.md)交付，应用启动不运行迁移。密钥元数据只保存[非秘密指纹](keys.md#持久元数据)，运行身份只有查询权限；材料仍留在凭据文件。

运行身份的 `search_path` 为空，运行语句写全模式名。每项运行权限随消费者写入唯一清单。Center 与角色按下节的表类别授权。未迁入能力继续采用必要列 INSERT、列级 UPDATE 和受保护 DELETE。未迁入能力的不可变字段、状态迁移、父链、提交完整性与删除资格仍由现有授权及 invoker 触发器保护。运行身份不能删除永久历史。

## 目标保护姿态

下述设计随[架构内核与状态封印](engineering/delivery.md#架构内核与状态封印)逐片落实。当前角色、机构 Holder、Grant、Account、Session 与 Person 状态历史采用该职责划分。Center 只保留加密取值及追加权限。Account、Holder 与未结束 Grant 的注销投影随注销在同一事务追加，状态保留永久墓碑。其他未迁入能力仍按本文各节的现有保护办理。

数据库只承担结构保护，与 Rust 的职责划分见[架构](architecture.md#数据库与-rust-的职责)。运行身份按表的类别授权：永久状态表 SELECT、INSERT、UPDATE；永久变更记录与不可变取值 SELECT、INSERT；短期技术记录 SELECT、INSERT、UPDATE、DELETE。按保留期删除的短期状态（例如会话）连同其变更记录归入短期类别，并授予 DELETE；`Expiry` 在同一事务内、持对象锁先删记录再删状态行，启动规则“记录必有所属对象”保持成立。完成记录授予 SELECT、INSERT、DELETE，模板化触发器只允许删除 `expires_at` 已过的行，永久完成记录不能删除。不再使用列级授权：不可变列由封印保护，记录与取值不可改删由不授 UPDATE、DELETE 保证。运行身份直接对状态行取 `FOR UPDATE` 或 `FOR SHARE`，对尚不存在的对象取事务级 advisory 锁；`SECURITY DEFINER` 锁函数及其启动核验删除。

触发器只保留每张状态表至多一个模板化延迟配对触发器，以及完成记录的到期删除限制。授权、等级、时间与状态迁移触发器，`check_isolation` 语句触发器，触发器中的维护分支以及业务触发器对 `security.clocks` 的比较均删除；隔离级别由内核的 `Tx::begin` 唯一入口保证。C1 保证至多一次外呼的唯一约束保留。持有运行凭据者直接写库时，不再被这些触发器提前拒绝，改为在取用或启动时按损坏发现并关闭接纳，见[威胁模型](architecture.md#威胁模型)。

应用与部署命令持有会话级实例锁 `(1314210636, 3)` 并推进 `security.instances` 代次栅栏，已交付，规则见[实例锁](architecture.md#实例锁)。运行权限的唯一清单也已交付，见[权限核验](#c1-接纳与可信时间)；按表类别收窄授权时只修改该清单。

## 连接输入

迁移与应用各读取自己的部署键，互不回退。两组输入均包含 `HOST`、`PORT`、`NAME`、`USER`、`AUTHORITY`：迁移使用 `NUCLEUS_MIGRATION__*` 和 `migration-password`，应用使用 `NUCLEUS_DATABASE__*` 和自己的数据库密码凭据。环境装载归 nucleus 或部署程序，业务模块只接收已校验的连接能力；部署键规则见[设置](settings.md)。

应用主机使用 `rustls::pki_types::ServerName::try_from` 校验，与数据库 TLS 适配器使用相同解析器。接受其支持的 ASCII DNS 名、IPv4 和不带方括号的 IPv6；国际化域名须提供 ASCII IDNA 形式。保留输入原文，不进行 URL 解析、百分号解码或名称修补。URL、附带端口和 Unix socket 路径均拒绝。库名须非空，不含空白或控制字符，最长 63 字节。证书路径须为绝对路径且不含控制字符。迁移输入只接受声明的字段，未知字段拒绝。

连接固定要求 TLS，仅按 `AUTHORITY` 指向的证书核验服务端；系统信任库不参与。在线请求使用多连接池。恢复能力拥有独立建连途径，不占在线池容量；维护程序使用自己的连接能力。各阶段的等待、建连和复用预算由所属设置给出有效值，缺省值在装载时确定，不把缺省语义留作运行期 `Option`。独立恢复途径与未知提交期间的写入准入见 [Identity 写入](architecture.md#原操作与恢复)。

## 密码凭据

应用数据库密码从服务单元凭据目录中的 `database.json` 读取，不从部署键读取。文件为包含整数 `version: 1` 与字符串 `password` 的 JSON 对象。解码后的密码非空，UTF-8 长度不超过 4 KiB，不含控制字符；保留空格，不修剪输入。密码值中的尾部换行拒绝，JSON 对象外的合法空白允许。文件缓冲与解码后的密码使用可清零容器。凭据来源和读取边界见[凭据文件](platform/credentials.md)。本地格式校验不能证明部署主机上的角色密码或证书正确。

`platform::database::credentials::Password` 拥有密码值校验，不实现 `Deserialize`。nucleus 与部署入口共用 `credentials::Input`，将密码反序列化为 `Zeroizing<String>`。`TryFrom<Input>` 显式调用 `Password::new` 构建。错误字段类型在文件解析时拒绝，无效密码由构造器拒绝。错误不回显提交值，`Debug` 隐藏密码。连接构造只接收已验证密码，不重复校验。

## 跨能力保护

Access、Center、Workforce 与文件所有者接入时仍使用部署与运行两个身份。初始化及停机指派用运行身份执行，迁移身份只交付结构与授权。机构指派固定来源及所选角色版本，来源、目标和动作遵守共同完成记录的封闭组合。账户注销在同一事务保存注销事实及 Account、Holder、未结束 Grant 的投影墓碑，并清理当前依赖。申请首提交与批准首尝试的循环引用，在共同事务内以延迟外键闭合。工号恢复须关联一至两项撤销，原值核对、指针和占用变化与完整事实共同提交。

永久工牌材料从全部业务引用反查保护。已有成品时，资源不得进入 `deleting`，所有者记录也不得删除。照片 ID 在全部状态下保持原定位，合法清理只改变字节状态。技术清理须先证明原任务结束、事务结局已知且期限已到；完整规则见[本地文件](storage/files.md)。

每个触发器只承担具体保护，并取得查询所需权限。不能在读取其他行的 CHECK 函数中实现跨行保护。运行身份须覆盖全部正常与拒绝分支，不能只检查触发器存在。

## 交付验证

每个业务切片交付其实际需要的结构、授权和保护，并在隔离数据库中以真实的运行身份验证正常与拒绝分支。验证包括结构重跑、权限目录、明文连接拒绝、跨主体引用、不可变事实、状态迁移、提交完整性和清理资格。涉及文件的提交与清理按[本地文件](storage/files.md)验证；Access、Center 与 Workforce 的权限及不变量随各自业务切片交付。

共享测试设施由独立的 `fixture` crate 提供，仅通过 `dev-dependencies` 引入。测试 PostgreSQL 固定为 18.4，版本由 [fixture/postgresql.version](../fixture/postgresql.version) 维护。[构建脚本](../fixture/postgresql.ts)从 PostgreSQL 官方下载源码，校验固定的 SHA-256，再使用主机开发库编译。`postgresql_embedded` 只管理这份本地构建的临时实例，不再下载第三方二进制。启动前核对实际二进制版本，缺失、版本不符或动态库不兼容均使测试失败。

[原生 package CI](engineering/verification.md#原生-package-检查) 在单个 Ubuntu 24.04 作业构建这份安装，并以同次运行的 artifact 供矩阵消费。tar 保留执行权限与符号链接；消费者核对摘要、候选、运行编号、版本和相同安装前缀，再实际执行四个程序的版本检查。产物只含安装，不含临时集群、证书或口令。矩阵使用非 root 用户、私有 TMPDIR、随机 loopback 端口与虚构数据，不读取真实 `.env` 或启动系统数据库服务。fixture 正常生命周期之外的 CI 泄漏检查只操作自己可核身份的实例；取消硬杀时不保证清理步骤执行。

隔离服务只监听回环地址并要求 TLS。fixture 拥有临时证书、管理员密码和服务清理，不依赖工作区业务或连接库。Platform、nucleus 和部署测试复用该设施，各自构造连接、准备角色并验证自身行为。

启动失败时，fixture 在清理前报告原始错误。上下文包括固定版本、回环地址和临时集群路径。诊断从 `data/start.log` 末尾最多读取 16 KiB 正文。截断时另读前一字节，判断窗口是否从完整行开始。完整行保留，不完整行舍弃，并隐藏 fixture 密码。日志缺失或无法读取时，同时保留启动错误和读取错误。诊断不读取密码文件或私钥，也不保留临时集群。`cargo test -p fixture --locked` 覆盖真实配置错误、日志不可用、截断与脱敏。测试还检查正常停止及启动失败后的目录清理。

每个数据库测试套件共用一个隔离服务，每项测试拥有独立数据库。使用实际迁移和运行身份验证所需结构与权限。共享服务仅由活动测试持有；全局可保留 Weak 引用，不保留静态强引用。最后持有者释放时停止服务并清理临时数据。证书、密码和角色均为虚构测试材料。所有数据库测试使用 `--locked`；连接库以 `cargo test -p platform --locked` 执行。

Domain 测试在每个服务首次需要测试库时建立一份模板库。模板使用固定的部署与运行角色，执行实际迁移和密钥元数据初始化，随后禁止连接。同一服务上的并发首次请求只由一项建库，其余等待同一结果。建库中断后，下一项先删除残留模板与固定角色再重建。服务按测试进程独立启动，不同进程不共享模板。每项测试随后从模板复制独立数据库。PostgreSQL 不复制库级权限，所以复制后重新执行角色检查与授权准备。同一服务的复制库共用固定角色，按角色定位后端时须同时限定当前数据库。需要专属角色的测试改用逐项建角色并执行全部迁移的路径。模板与固定角色随所属服务停止一并清除。

`domain::access::initialize::seed` 仅在测试或 `test-support` 特性下提供。它按指定历史时点建立完整初始化，包括四个系统角色、首个 Holder、首条指派及初始化完成的配对封印。夹具在服务建立锚定之前提交。当前消费者为 Domain 会话夹具、HTTP 数据库夹具和进程生命周期夹具。调用方负责提交事务。它不属于生产初始化入口，也不开放任意 State 或 Record 的构造。Domain 内的角色测试另用仅测试编译的 `seed_history`，在夹具提交后安装锚定。

Domain 的测试库随自身作用域结束回收，不等待共享服务退出。清理在独立线程的运行时内完成，最多等待 10 秒。它只删除本次生成的数据库及专属路径的两个角色，并结束该库的遗留连接。正常结束和断言异常都执行清理；失败不覆盖正在传播的原断言。

独立 SQL 验证库、专属角色及遗留后端已消失。复制库释放后，固定角色仍可登录其他测试库，另一活动测试库的数据也仍可读取。并发验证在私有服务上同时请求四个测试库。结果只留下一个禁止连接的模板，每个复制库均已迁移并恢复库级授权。清理会主动终止遗留连接，因此不能代替工作寿命验收。相关测试仍须在释放夹具之前确认受管工作、驱动与原后端实际结束。

已验证两笔独立事务并行、在线池耗尽时独立恢复建连、恢复连接额度、会话复用重置、失效会话替换及显式移除。还验证错误证书、主机名和密码拒绝、明文连接拒绝、TLS 拒绝不降级、握手等待超时，以及丢弃恢复会话后驱动结束。连接测试使用虚构角色 `fixture`，验证在线池和恢复连接均采用调用方指定身份。这些连接测试不构成业务权限与完整性验收；密钥元数据的迁移和权限由[部署测试](engineering/deployment.md#验证边界)覆盖。

在 Ubuntu 主机上先从本机发行版的官方源安装构建依赖，再构建测试数据库：

```bash
sudo apt-get update
sudo apt-get --no-install-recommends --no-remove install build-essential bison flex curl pkg-config libssl-dev libicu-dev libreadline-dev zlib1g-dev libxml2-dev
bun fixture/postgresql.ts
cargo test -p fixture --locked
```

构建保留 ICU、Readline 和 zlib 的默认支持。OpenSSL 与 XML 显式启用。二进制安装在 `target/postgresql/18.4`；临时构建全部成功后才发布该目录，不创建系统数据库服务。重复运行脚本核验并复用已有构建。主机升级导致动态库不兼容时，先确认没有测试运行，再移除这个生成目录并重新构建。源码版本与摘要更新必须一同审阅；不因官方源出现更新版本自动升级。

旧 Rust CI 的 package 与缓存入口已退役，其定义仅保留为[离线夹具](../tools/fixtures/retired-workflows/README.md)。本地准备与测试继续使用本节命令。每次运行 PostgreSQL 准备脚本时，脚本校验四个程序的版本和可执行性；测试夹具另行校验 `postgres` 版本。测试仍创建全新的隔离实例，不共享数据库数据、证书或密码。

原依赖镜像与 [package 环境 Action](../.github/actions/package-setup/action.yml) 保留供离线回归解释旧环境。它们不是当前自动运行的检查；缓存或历史运行成功不构成新候选验收。

Ubuntu 24.04 与 26.04 分别链接各自主机的库，无需安装跨发行版的兼容库。隔离验证不证明真实部署凭据、证书、主机环境或规模性能。已交付写入用例共用工作登记与进程生命周期，各自核对提交未知。HTTP 和进程信号已接入，具体运行证据与 systemd 限制见 [HTTP 入口](http/api.md#nginx-接入与传输目标)。

nucleus 以 `cargo test -p nucleus --locked` 验证固定文件来源、JSON 与密码边界、PEM 装载和诊断脱敏。装载测试通过虚构角色验证在线及恢复连接的身份与 TLS，以及错误密码和信任证书拒绝。生命周期测试另用实际迁移和运行身份验证共同启动、接纳、恢复与停止。所属行为证据见[短信认证](identity/authentication.md#首次接纳边界)和[正式注册](identity/registration.md#清理与验收)。
