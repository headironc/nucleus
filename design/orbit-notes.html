小程序分为公开首页与员工服务：文化、科普等公开内容无需登录。医院员工登录后办理工号、工牌及个人资料。邀请码用于加入员工服务，不表示人事入职。共 18 个页面组、29 张稿。本稿是设计材料，不是权威设计：页面范围、路由命名、名称与状态、分流及验收由 页面目标设计 及所属专题拥有，冲突时以那些文档为准。各页旁注与文末工程说明只把规则映射到客户端形态，正文与判定标准见对应所有者。

首页保留参考图的搜索、轮播、六个栏目入口与图文列表。公开页使用纸色背景与宋体专题标题；员工办理页使用浅色背景、系统字体和统一的表单组件。朱红用于主要操作，红色描边用于危险操作，普通说明不使用警示色块。工牌采用生产系统的正式底图与主备字体，姓名、工号及人物轮廓均为示例。字体字节属生产业务数据，不随仓库分发：把 badge-main.ttf 与 badge-fallback.ttf 放进 assets/fonts.local/ 后本页自动加载，缺失时页首提示并只用设备字体近似渲染。本稿未接入业务接口；浏览器排版用于设计核对，不作为打印成品。

登录

pages/authentication/login · 匿名 · 对应 POST /api/v1/sessions

动作

  • 主按钮：微信手机号授权；首次发送前固定 Operation-Id、secret 与 code。原操作重试沿用这些材料，不因重连再取 code
  • 次按钮：微信身份登录（login code，与手机号 code 是两套协议，不可互换）

认证结果与后续页面

  • session → 保存 token + expiresAt，读取本人资料与当前 Grant：可用时进入员工办理；无 Grant 时显示邀请码入口，暂停时显示暂停页。读取失败不解释为尚未加入
  • registration → 注册页，保留 id、token 与 expiresAt；progress → 保留原操作等待结果，不提前分流
  • mobile_unsupported → 拒绝说明页（403）
  • 已暂停账户 → 明确拒绝，不解释为「未注册」

失败处理

  • code 失效须重新授权并用新 Operation-Id，不重放旧 code
  • 响应丢失：按原 Operation-Id 读回原结论，同 code 至多一次外呼

正式注册（R2）

pages/registration/registration · 持待注册凭据 · 对应 POST /api/v1/registrations

规则

  • 新注册使用本次认证的 registration.id 与 token；尚未提交且凭据失效时重新认证。提交后隐藏填表倒计时，按原操作核对；原成功恢复优先于新办理凭据检查，不因倒计时结束丢弃原证明
  • 提交携带独立 Operation-Id；手机号或身份证号占用为保存的确定拒绝。格式错误只提示修改字段，不形成 Attempt；未知结局保留原材料核对，不重新开户
  • 成功：共同建立人员、默认头像、普通账户与 Session；注册不建立 Grant，按当前员工资格引导使用邀请码或联系管理员

约束

  • 注册前不创建账户、人员或实名资料
  • 同号重新注册不继承旧账户的资格与历史
  • 认证结果未提供脱敏手机号，本稿不显示号码；不从 token 推导，也不把客户端缓存当作可信号码

认证分流异常页

pages/authentication/outcome · 匿名

语义边界（不可互相伪装）

  • 按接口、应用码和办理阶段分流，不仅按 HTTP 状态判断原因。当前会话无效时重新登录；恢复请求的 authentication_invalid 仅表示原证明不成立，不清除另一有效会话
  • 号码不支持等可信业务拒绝按所属应用码展示；账户暂停页只用于已明确确认的暂停原因，不从本人读取的 401 推断账户暂停
  • verification_required 结束该次自动恢复并提供重新认证入口，不把原业务改写为失败，也不清除后来选定的有效会话
  • 依赖故障与结局未知分别处理；写入结局未知时按原 Operation-Id 核对，读取故障保留刷新入口，不伪装成业务拒绝或空数据

文案原则

  • 暂停不伪装成「未注册」；依赖故障不伪装成用户输入错误

首页（结构稿）

页面骨架

  • 沿用 参考图 的搜索、专题轮播、六个圆形栏目入口和图文列表
  • 保留米白、墨色与少量朱红；中式字体用于品牌、专题与栏目，正文使用系统字体
  • 轮播圆点可切换三组示意文案；主视觉和图文内容均为静态占位

功能边界

  • 搜索与六个栏目入口暂未接入功能；第六入口命名为「员工服务」，其余栏目保持公开展示。投稿及活动的实际操作范围另行设计，不在本稿虚构提交能力

  • 账户暂停遮蔽本人服务；仅领域暂停时，保留取消未发放申请与退出 Workforce 的合法入口

员工服务主页与结束态

本人服务入口 · 当前账户、Workforce 授权、工号与申请摘要

入口与状态

  • 从公开首页或欢迎页进入员工服务；登录与首次注册后按当前资格进入此页或邀请码页。
  • 本稿展示已有工号的正常态。无工号时显示「暂无工号」及「申请工号」；申请工牌入口引导先申请工号，不静默分配。
  • 最近申请来自可信列表。空集合显示「暂无申请」，读取失败显示「申请记录暂时无法加载」及刷新入口；加载期间不先显示空态。
  • 领域暂停转入前页暂停稿；本人读取的 401 仅引导重新登录，不推断账户暂停。政治面貌入口在「我的」，不作为工牌申请前提。
  • 可信 grant_absent 引导首次加入；terminated 显示「员工服务已结束」并提供重新加入入口。新授权不恢复原申请或旧工牌的增办来源资格。
  • 结束稿只在确认最近授权为 terminated 时展示，不推断本人退出或管理员结束的原因。隐藏办理入口，保留使用邀请码、我的账户、联系管理员和公开浏览；不是重新激活旧授权。账户入口不依赖员工服务资格，返回办理时仍按可信的当前状态分流。
  • 小程序只含本人服务，不复制生产版的管理控制台、邀请管理或管理审批入口。

统一内页结构

  • 手机框高度固定，顶部导航、底部操作与底部导航不随正文滚动。正文独立滚动，长表单不会把主要按钮推到屏幕外。
  • 办理、工牌、我的为一级页面；表单、照片、预览与详情使用返回导航，不叠加底部页签。
  • 底部保留手势安全区示意；正式原生页面按设备安全区尺寸布局。此稿的高度与安全区留白是设计参数，不代表真机验收。
  • 新主页链接仅跳转至同一设计板上的对应稿，不模拟登录、分配工号或提交申请。

邀请码接纳

pages/invitations/accept · 已注册、无未结束授权 · 接纳归 invitations 所有

规则

  • 「使用邀请码」明确提交接纳，建立唯一未结束的 Workforce 授权。用户界面将受限办理区称为「员工服务」，不把使用邀请码称为员工身份认证，也不表示入职或完整人事关系
  • 接纳者收到 invitation_unavailable 时统一提示「邀请码不可用，请联系管理员」，不披露过期、容量或邀请人状态；网络及依赖故障不能显示为邀请码不可用
  • 接纳是明确提交动作（Operation-Id），切页或重连不自动重放

边界

  • 准入管理者的「直接接纳」在网站办理，小程序只提供本人使用邀请码
  • 扫码为入口草案：二维码载荷格式和校验待补。建议只填入邀请码，由用户点击「使用邀请码」提交；本稿不执行扫码或接纳

工号

pages/numbers/numbers · 需有效授权 · 归 workforce/numbers

规则

  • 「申请工号」入口先选择人员类别，再明确确认自动分配工号，不新增审批环节；类别不预选，切页、重连、后台刷新不自动发号

  • 步骤条只示意提交、审核、发放的正常路径；驳回、取消和人工结束按真实阶段单独呈现。Render 的 active / successful / failed / aborted 分别说明工牌图片的生成结果，不推断实体制作进度；本人不显示重新生成入口
